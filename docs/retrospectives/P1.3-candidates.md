## RC-11 — State machine lacks task→ADR mapping; `awaiting_architect_accept` un-advanceable for tasks with ADRs

**Surfaced:** 2026-05-26, immediately on first non-self-referential task to exercise the `awaiting_architect_accept` state. Predicted by W-001 retrospective §8 specific prediction #1 — "If the harness only works for self-referential tasks, P1.3 surfaces the gap immediately." **Predicted gap surfaced exactly where predicted.**

### What happened

W-001-impl built the state machine. ADR-008 was Accepted *before* W-001-impl dogfood ran; the dogfood never exercised the `awaiting_architect_accept` state transition. P1.3 is the first task where:

1. Senior drafts an ADR (ADR-009) alongside the plan.
2. State machine should advance `awaiting_senior_plan → awaiting_architect_accept` when senior plan appears (auto-trigger; **this fired correctly**).
3. State machine should advance `awaiting_architect_accept → awaiting_junior_impl` when ADR-009 status flips from Proposed to Accepted on `origin/main` (auto-trigger; **this did NOT fire** even after PR #6 merged ADR-009 to main with status Accepted).

Root cause (architect-partner inferred from impl reading; not verified by reading source line-by-line): `_read_adr_status(task_id="P1.3", repo_root)` returns "none" or fails to identify ADR-009 as the relevant ADR for P1.3. The state machine has no `task_id → adr_id` mapping in `TaskState` schema; impl can't know which ADR's status to check.

### What we did about it (today)

Architect-partner used `workflow override` to manually advance state from `awaiting_architect_accept → awaiting_junior_impl` (commit `cfbf087`). Override reason field captures the link to RC-11 + the rationale ("ADR-009 actually Accepted on main; state machine can't detect"). Audit trail preserved in `override_history`.

This is a v1 workaround. The proper fix is in W-002 territory.

### Sibling bug surfaced during the override (sub-finding worth recording)

`record_override` incremented `cycle` from 1 to 2 on the manual override. Per ADR-008 Decision 11, cycle increments only on **rework** transitions (`awaiting_architect_decision → awaiting_junior_impl`). The override I performed was `awaiting_architect_accept → awaiting_junior_impl` — categorically NOT a rework. Cycle should have stayed 1.

The impl in `record_override` appears to increment cycle on every override regardless of from-state semantics. Captured here as part of RC-11 because both gaps point at the same area (state-machine impl assumes simpler cases than P1.3 exercises).

### Proposed resolution paths (W-001 close + W-002 territory)

**Schema-level fix (preferred long-term)**: extend `TaskState` Pydantic model with optional `adr_id: str | None = None` field. Plan publishing writes the field when an ADR is drafted alongside; `_read_adr_status` consults it to find the right ADR. Backwards-compatible (default None for tasks without ADRs). Schema-evolution-policy question (RC-6 from P1.2) intersects — adding a field to a frozen model is the exact category RC-6 wants codified before precedent is set.

**Convention-level fix (cheaper short-term)**: senior plan frontmatter declares `adr: ADR-NNN` if applicable; `_read_adr_status` parses the plan markdown to find it. No schema change. Less robust (regex / markdown parsing); good v1 mitigation while schema change is debated.

**Override-based forever (current state)**: every ADR Accept cycle requires manual `workflow override`. Audit trail captures intent, but the state machine never auto-handles the case. Acceptable if ADR Accept cycles are rare; gets noisy if P1.4+ has frequent new ADRs.

**`record_override` cycle-counter bug fix**: separate from the task→ADR mapping; fix is small (one if-branch in `record_override` to gate cycle increment on `from_state == awaiting_architect_decision`). Worth landing whenever the next workflow impl PR opens.

### Status

**Open.** Schema vs convention decision is W-002 architect call. Cycle-counter bug fix can land standalone in the next workflow-touching commit. Both folded into final P1.3 retrospective at close.
