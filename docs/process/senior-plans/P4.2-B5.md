# Senior plan: P4.2-B5 — mutation local tools (`apply_edit` / `send_email` / `git_push`)

**Inputs:** brief `docs/process/architect-briefs/P4.2-B5.md` (architect-RATIFIED all 5 decisions — plan to them, do not re-litigate); ADR-036 (this slice's ADR, drafted alongside this plan, status **Proposed**); predecessors ADR-028 D3, ADR-030 D1/D3, ADR-034, ADR-035. **Single-lens** (`requires_cross_family_review: false`): impl-stage review is **R0-A only** — no external-r0b-prompt.

## 1. Context

B5 is the **last** of the three serial P4.2 sub-slices (B3 subprocess ✅ → B4 network ✅ → **B5 mutation**) and closes P4.2. It implements the three deferred **mutation** local tools so an agent can finally **act on its investigation**: write a fix (`apply_edit`), send a notification (`send_email`), publish work (`git_push`). These are the `HARD`/`COUNTDOWN`-tier tools ADR-028 D3 called *"provably dead until confirm-then-execute lands"* — it landed in P3.6 (ADR-030), so they are unblocked.

B5 is **mostly wiring**: the confirm-then-execute path (`_post_confirm` → reconstruct `TOOL_CALL` → `execute_pending_tool_calls` → `_execute_local_call`), the per-pass caps, and the output-untrusted machinery **all exist**. The three impls are thin closures over reused primitives — `_check_path` (B5-1), the B4 `_NetworkToolFn` + `web_search` provider-config shape (B5-2), the B3 `run_scoped_command` + `scoped_env` + `_SubprocessToolFn` (B5-3). The genuinely-new surface is narrow but high-stakes (first irreversible + outward-facing): the **first WRITE containment** (`apply_edit`), the **`git_push` credential-vs-`scoped_env` tension**, and the **`send_email` exfil-by-recipient** vector. ADR-036 inscribes the posture; this plan sequences the impl.

**The carry-forward (ADR-036 §⭐⭐) is NON-NEGOTIABLE** — the executor stays tier-agnostic & tool-agnostic (no executor-side "mutations always confirm" override = downstream re-gating = t2/t4 violation); `_execute_local_call` stays **byte-frozen** (4th time); no new `LLMPurpose`; the gate-produced `TOOL_CALL` is the sole entry to actuation. **Verify these against ADR-036, not your recollection.**

**Resolved senior calls (not architect decisions, but surfaced — see §5):** (a) `apply_edit` → a new `tools/mutation_tools.py` (chosen to AVOID a constitution-test change to `local.py`'s read-only convention); (b) `send_email` provider = config-driven generic HTTP API mirroring `web_search` (architect ratifies the transport — push-back 2); (c) `git_push` credential = HOME-based ambient auth (already works under `scoped_env`) + a named `SSH_AUTH_SOCK` non-secret passthrough for ssh-agent (architect ratifies the allowance — push-back 1).

## 2. Tasks (atomic — one concept, one commit, one subject per RC-17)

### B5-1 — `apply_edit` impl: first WRITE tool, write-time-contained + `O_NOFOLLOW` + bounded + atomic
- **What:** new `src/orchestrator/tools/mutation_tools.py` with `_make_apply_edit(sandbox_root)` (an in-process `LocalToolFn`, no marker/cap) + `build_mutation_tool_registry(sandbox_root) -> dict[str, LocalToolFn]` returning `{"apply_edit": …}`.
- **Where:** new file `src/orchestrator/tools/mutation_tools.py`; reuse `_check_path` imported from `tools/local.py` (precedent: `subprocess_tools.py:29`). Unit tests `tests/tools/test_mutation_tools.py`.
- **Why:** ADR-036 D1/D3-i/D4; `tools.yaml:31-32` (`apply_edit` rev 2). Param allowlist `{path, content}` (a `_check_disallowed` mirror of B3/B4). Output `LocalToolOutput(content=f"wrote N bytes to <rel path>")` — **TRUSTED** (no `_*_TOOL_NAMES` membership).
- **Acceptance criteria:**
  - Param allowlist enforced (`{path, content}`); disallowed param → `LocalToolError`.
  - **Write-time containment:** the path is re-resolved via `_check_path` **at write time** (not only pre-checked); a path resolving outside `sandbox_root` (traversal / absolute / parent-symlink-escape) → `LocalToolError`.
  - **Symlink-write refusal (`O_NOFOLLOW`-class):** writing **through** an in-sandbox final-component symlink whose target escapes → refused (`LocalToolError`); use `O_NOFOLLOW` on the final write target (a plain `open(..., "w")` on the final target is forbidden — `t11` AST-guards it).
  - **Bounded content size:** `content` larger than `MAX_RESULT_BYTES` (reuse the constant) → `LocalToolError` **before** any write.
  - **Atomic write / no partial file:** write to a temp file inside the contained directory, `os.replace` into place; a mid-write failure leaves the original (or no file) intact — never a truncated target.
  - Output is `LocalToolOutput` (path + bytes written), success → `TOOL_RESULT`; any failure raises `LocalToolError` → `TOOL_FAILED` (rides `_execute_local_call` unchanged).
  - Tests cover: happy write (new file + overwrite), traversal-escape refused, parent-symlink-escape refused, final-symlink-escape refused, oversize refused, atomic (failure mid-write leaves no partial).
- **Out of scope:** `propose_edit` (rev 5, OUT — brief decision 1); any executor edit; registry wiring (B5-4); the constitution test (B5-5).

### B5-2 — `send_email` impl: fixed-provider HTTP send, recipient-allowlist, key-to-provider-only
- **What:** add `_make_send_email(provider_config)` (a `_NetworkToolFn`) to `src/orchestrator/tools/network_tools.py`; a `_load_email_config` mirroring `_load_web_search_config`; register `"send_email"` in `build_network_tool_registry`; add `"send_email"` to `_NETWORK_TOOL_NAMES` in `agents/selection.py`.
- **Where:** `src/orchestrator/tools/network_tools.py` (closure + registry + an `email_config_path` param on `build_network_tool_registry`); `src/orchestrator/agents/selection.py:111-116` (`_NETWORK_TOOL_NAMES`); new `config/email.yaml.example`. Tests in `tests/tools/test_network_tools.py` (or a new `test_send_email` section).
- **Why:** ADR-036 D1/D3-ii/D4; `tools.yaml:47-48` (`send_email` rev 3). Mirror the `web_search` shape exactly (fixed endpoint → plain `httpx.Client`, **not** `build_ssrf_client`; SSRF N/A).
- **Acceptance criteria:**
  - Param allowlist `{to, subject, body}`; disallowed param → `LocalToolError`.
  - **Fixed provider:** endpoint + `api_key_env` + `from_addr` + recipient allowlist read from `config/email.yaml` (the `web_search.yaml` pattern). Absent/unconfigured → fail-closed `LocalToolError("send_email not configured: …")` (mirrors `web_search`).
  - **Recipient allowlist:** a `to` outside the operator-configured recipient/`allowed_domains` allowlist → `LocalToolError` **before** send. (Allowlist shape per push-back 2 ratification.)
  - **Credential:** the api key (from `api_key_env`) is sent **only** in the provider auth header; never logged, never echoed into the result, never onto any other surface.
  - **Output:** provider send-status as raw `LocalToolOutput` → `TOOL_RESULT`; HTTP error / timeout / provider-error → `LocalToolError` with the class in the message (`network_timeout:` / `send_failed:` / `send_email not configured`), mirroring `web_search`. Bounded timeout (`httpx.Timeout`, the `web_search` granular shape).
  - `"send_email" ∈ build_network_tool_registry().keys()` **and** `∈ _NETWORK_TOOL_NAMES` (the existing b46 drift sync-test enforces the pair — it WILL fail if you add one and not the other).
  - `config/email.yaml.example` committed (NOT `email.yaml`); documents `endpoint`, `api_key_env`, `from_addr`, the allowlist — mirroring `config/web_search.yaml.example`.
  - Tests: happy send (stubbed transport), unconfigured fail-closed, recipient-outside-allowlist refused, key-in-header-only (assert key not in result/logs), excerpt-exclusion (extend the b46 behavioral test).
- **Out of scope:** raw SMTP via `smtplib` unless the architect routes push-back 2 that way; `apply_edit`/`git_push`; the registry merge (auto via the existing `build_network_tool_registry` call at `app.py:250` — no `app.py` edit needed for `send_email`).

### B5-3 — `git_push` impl: argv-never-shell, ambient-auth + `SSH_AUTH_SOCK` passthrough, no-force, remote-output-untrusted
- **What:** add `_make_git_push(sandbox_root)` (a `_SubprocessToolFn`) to `src/orchestrator/tools/subprocess_tools.py`; register `"git_push"` in `build_subprocess_tool_registry`; add `"git_push"` to `_SUBPROCESS_TOOL_NAMES` in `agents/selection.py`; add a named `_GIT_PUSH_ENV_PASSTHROUGH = frozenset({"SSH_AUTH_SOCK"})` overlaid via `scoped_env(extra_env=…)`.
- **Where:** `src/orchestrator/tools/subprocess_tools.py` (closure + registry + a per-tool timeout in `_SUBPROCESS_TIMEOUTS`); `src/orchestrator/agents/selection.py:95-103` (`_SUBPROCESS_TOOL_NAMES`). Tests in `tests/tools/test_subprocess_tools.py`.
- **Why:** ADR-036 D1/D3-iii/D4; `tools.yaml:49-50` (`git_push` rev 1, the most irreversible tool). Reuse `run_scoped_command` + `scoped_env` + `_dispatch`.
- **Acceptance criteria:**
  - Param allowlist `{remote, branch}` (constrained; defaults to the current branch's upstream if omitted, per push-back 1 ratification of scope). Disallowed param → `LocalToolError`.
  - **argv-never-shell:** argv is a fixed list `["git", "push", <remote>, <branch>]` (no shell-string) — the existing `t9` AST scan over `subprocess_tools.py` covers this **free** (re-assert in B5-5).
  - **No destructive flags:** argv NEVER contains `--force` / `--force-with-lease` / `-f` / `--mirror` / `--delete` (`t12` guards it). `remote`/`branch` are validated to be non-flag-shaped (reject values starting with `-`).
  - **Ambient-auth + named passthrough:** env = `scoped_env(extra_env={k: os.environ[k] for k in _GIT_PUSH_ENV_PASSTHROUGH if k in os.environ})`. `HOME` is already in `_SAFE_ENV_KEYS` (credential.helper + on-disk ssh keys work); `SSH_AUTH_SOCK` is overlaid for ssh-agent. **No credential/token/api-key VALUE is ever injected.** (Passthrough set per push-back 1 ratification.)
  - **Bounded:** rides `_dispatch` → `run_scoped_command` (bounded output `MAX_RESULT_BYTES`, kill-no-orphan); add a `git_push` entry to `_SUBPROCESS_TIMEOUTS` (e.g. 30s).
  - **Output:** push status (incl. remote hook/rejection text) as raw `LocalToolOutput` → `TOOL_RESULT` at any exit code; timeout/spawn-failure → `LocalToolError` (`subprocess_timeout:` / `subprocess_spawn_failed:`), mirroring B3.
  - `"git_push" ∈ build_subprocess_tool_registry().keys()` **and** `∈ _SUBPROCESS_TOOL_NAMES` (the existing b35 drift sync-test enforces the pair).
  - Tests: happy push (stubbed/local-remote), flag-shaped remote/branch refused, no-force-flag assertion, `SSH_AUTH_SOCK` overlaid when present (and absent → no key), excerpt-exclusion (extend the b35 behavioral test).
- **Out of scope:** real-credential (PAT/token) injection (deferred — ADR-036 D3-iii); `--force`/`--mirror`/branch-delete; `apply_edit`/`send_email`.

## 5. Where you'd push back (5 surfaces — architect routes)

**1. ⭐⭐ `git_push` credential — the `SSH_AUTH_SOCK` named passthrough (the load-bearing call).**
Verified: `scoped_env()`'s `_SAFE_ENV_KEYS` **already passes `HOME`** (`mcp/subprocess_trust.py:49-59`), so `git`'s ambient auth **already works under `scoped_env` for the common cases** — `credential.helper` (`~/.gitconfig` / `~/.git-credentials`) and **on-disk** SSH keys (`~/.ssh/id_*`, `config`, `known_hosts`). **The one gap is `ssh-agent`** (`SSH_AUTH_SOCK`, stripped). Recommendation: inscribe **`SSH_AUTH_SOCK` as a named, minimal, NON-secret passthrough** (a unix-socket path, not a credential value) via `scoped_env(extra_env=…)`. **Architect ratifies:** (a) **include the `SSH_AUTH_SOCK` passthrough now** [recommended — ssh-agent is the dominant dev auth; HOME-based on-disk keys also work; no secret value injected]; or (b) **HOME-only ambient** (on-disk keys / credential.helper), ssh-agent unsupported & documented. This widens B3's strip-everything posture (the c2 boundary), so it needs your ratification even though no secret is injected. **Real-credential (PAT/token) push stays deferred either way.**

**2. ⭐ `send_email` provider / transport shape.** The brief did not name a provider (B4 named Brave at brief stage, Y1). Recommendation: a **config-driven generic HTTP email API** — POST to an operator-configured fixed endpoint (`config/email.yaml`: `endpoint`, `api_key_env`, `from_addr`, recipient/`allowed_domains` allowlist), api key in a header, JSON body `{to, subject, body}`, fail-closed when unconfigured — mirroring `web_search` exactly (plain `httpx`, SSRF N/A). **Architect ratifies:** (a) **config-driven generic HTTP API** [recommended — leaner, no hardcoded provider, no response to parse]; or (b) a **named provider** (SendGrid/Mailgun-style) hardcoded like Brave; or (c) **raw SMTP via `smtplib`** (different shape — SMTP host/port/STARTTLS, not `httpx`; doesn't reuse the `web_search` shape). Also: confirm the **allowlist shape** (explicit recipient list vs `allowed_domains` vs both).

**3. `apply_edit` placement — `mutation_tools.py` (chosen) vs `local.py`.** Decision 4 asked me to surface if it's a constitution-test change. I chose **a new `tools/mutation_tools.py`** specifically to **AVOID** a constitution change: `t6` bans only *subprocess* in `local.py` (not writes), so `apply_edit` is *permitted* in `local.py` — but `local.py` is read-only-by-convention (t8 frames it so), and putting the first writer there would erode that + warrant a new "local.py may write" note. `mutation_tools.py` keeps `local.py` pristine (t6/t8 untouched), one new file, no constitution change, no lost reuse. **Confirm** you're fine with the one-tool module vs a `local.py`-write carve-out. (Senior call; proceeding with `mutation_tools.py` unless you object.)
