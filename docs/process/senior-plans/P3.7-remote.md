# Senior plan — P3.7-remote (Posture-B subprocess plugin executor + remote MCP transport)

## 1. Context

P3.7-remote is the **heavy/security half** of the architect-ruled P3.7 split — the project's first crossing from the **operator-curated/local** trust premise (P3.4 stdio MCP, P3.5 in-process Posture-A plugins) to **untrusted/remote provenance**. It invents no gate, executor, MCP client, or plugin loader — all exist (verified `origin/main` @ cbadf6d). It absorbs three deferrals: ADR-027 D1 (remote SSE/streamable-http "deferred to P3.7" → **B2**), ADR-029 D4 (Posture B "REQUIRED once provenance untrusted; reserved for P3.7" + the itemized A→B migration → **B1**), ADR-029 D5/scope (remote install/registry/fetch → **B1-coupled §a**).

**Architect rulings already settled (brief + ratification — do NOT re-route):** **(1) B-coupled** — the Posture-B executor **and** the actual remote fetch ship together (not executor-first); **(2) B1 reuses the MCP-server subprocess mechanism** (a plugin executable tool ≈ a local stdio MCP server; maximal reuse of ADR-027 D4's scoped-env / kill-no-orphan / bounded-timeout / fail-closed — **no second subprocess protocol**); **(3) B2 leans streamable-http**; **(4) two new Proposed ADRs** — ADR-031 (Posture-B executor / remote-plugin provenance) + ADR-032 (remote MCP transport); **(5) dual-lens R0-B mandatory** (`requires_cross_family_review: true`).

**The constitutional crux I inscribe (ADR-031, non-negotiable):** a fetched/remote plugin is **not operator-placed**, so curation — the *entire* basis of Posture A's ADR-029 D4 Accept — **no longer holds**; therefore **Posture A is constitutionally invalid for remote provenance** and **Posture B is REQUIRED, not optional** (the architect already ruled this in ADR-029 D4). B1 is the **enabling precondition** for any remote-plugin capability — hence coupled. The spine is unchanged: the gate stays the sole chokepoint; remote does not bypass the allowlist; self-asserted tier is never authoritative; remote results are *more* untrusted; credential-via-`api_key_env`; fail-closed everywhere. ADRs are RC-23-safe (Proposed; no literal `Accepted` substring until architect Accepts).

ADR drafts ship with this plan (`ADR-031`, `ADR-032`) per the senior-drafts-ADR rule. Architect Accepts after dual-lens.

## 2. Tasks (atomic — one task = one commit, RC-17)

### B2 — remote MCP transport (ADR-032)

**P3.7-remote-1 — Remote transport config schema.**
- **What:** Extend `MCPServerConfig` to admit a remote transport: `transport ∈ {"stdio","streamable_http"}`; new `url: str | None`; cross-field validation — `streamable_http` **requires** `url` with an **`https://` scheme** (reject `http://`/plaintext → `ConfigError`), `stdio` requires `command`. Frozen + `extra="forbid"` preserved; `MCPTimeouts` reused for the network bound.
- **Where:** `src/orchestrator/mcp/config.py` (the `MCPServerConfig` model + `load_mcp_servers_config`).
- **Why:** ADR-032 D1 (remote config contract + TLS/URL-allowlist knobs); ADR-027 D3/D4 lifted to remote.
- **Acceptance:** a `streamable_http` entry without `url` or with `http://` → `ConfigError`; a `stdio` entry unchanged-valid; tests assert both. The existing `config/mcp_servers.yaml` (all stdio) still loads.
- **Out of scope:** the transport runtime (-2); SSE (see §5).

**P3.7-remote-2 — streamable-http transport path.**
- **What:** Add the remote branch to `MCPTransport`: for `streamable_http` use the **non-deprecated `streamable_http_client(url, http_client=<host-built>)`** (R0-A Y1 → α — **NOT** the `@deprecated streamablehttp_client` at `:685-686`; the non-deprecated symbol is at `mcp/client/streamable_http.py:601` and takes **only** `http_client: httpx.AsyncClient | None`). The host **explicitly constructs** `httpx.AsyncClient(verify=True, headers={"Authorization": f"Bearer {secret}"}, timeout=<bounded>)` — `verify`/header/timeout are the host's explicit responsibility, not a factory default. Client yields a **3-tuple `(read, write, get_session_id)`** (bridge ignores `get_session_id`). Credential indirection: `api_key_env` → the `Authorization` header (not subprocess env — remote has no scoped-env surface). Reuse the transport-agnostic `asyncio.wait_for` bounded-timeout bridge (the `_async_bridge` seam from -4) + the `MCPTimeoutError`/`MCPConnectionError` fail-closed envelope.
- **Where:** `src/orchestrator/mcp/transport.py`.
- **Why:** ADR-032 D2 (transport) + D3 (remote trust knobs); ADR-027 D1 sync-bridge pattern carried forward.
- **Acceptance:** an `https://` streamable-http mock server lists+calls a tool through the sync bridge via the **host-built `httpx.AsyncClient(verify=True, …)`**; a TLS-verify failure / unreachable host / auth failure → `TOOL_FAILED` (fail-closed), never a hang/crash; a hanging mock → bounded-timeout fail-closed; **no `verify=False` anywhere** (enforced by the -9 constitution scan). Depends on -1; consumes the -4 `_async_bridge` seam (sequence: -4 before -2).
- **Out of scope:** SSE; the demo wiring (-3).

**P3.7-remote-3 — remote demo connector + e2e.**
- **What:** One `https://` streamable-http server entry in `config/mcp_servers.yaml` + an e2e proving the remote loop AUTO-executes a read-tier tool and the fail-closed paths refuse. Use a **hermetic local-TLS streamable-http mock** for CI (the "real public https:// endpoint" is documented config, not a network-dependent CI test — see §5.3).
- **Where:** `config/mcp_servers.yaml`, `tests/mcp/`, `tests/integration/`.
- **Why:** ADR-032 D4 (one-demo discipline, P3.4/P3.5 parallel); brief §e.
- **Acceptance:** e2e shows read-tier AUTO loop end-to-end + TLS-fail/unreachable/auth-fail/non-allowlisted-URL/unclassified-tool → refused/`TOOL_FAILED`. Depends on -2.
- **Out of scope:** Posture-B plugin demo (-8).

### B1 — Posture-B executor + remote provenance (ADR-031)

**P3.7-remote-4 — extract shared trust primitives (seam split by scope, R0-A G1).**
- **What:** Factor the machinery out of `mcp/transport.py`, **split by scope** (R0-A G1 — don't mis-name a transport-agnostic concern "subprocess"): **(a)** the **transport-agnostic** `asyncio.wait_for`-bounded sync bridge + fail-closed envelope → `mcp/_async_bridge` (reused by both stdio **and** the remote -2 path); **(b)** the **subprocess-only** `_build_scoped_env` + kill-no-orphan teardown → `mcp/subprocess_trust.py` (reused by stdio + the -5 Posture-B executor). **Add the orchestrator-level kill watchdog (R0-B Y1 → α)** into (b): after SDK teardown, check the child PID; if alive, force `SIGKILL` + reap (LAYER-1 backstop, never trust the SDK as sole killer). **Pure refactor for the common case:** MCP transport behavior unchanged.
- **Where:** `src/orchestrator/mcp/transport.py` → `mcp/_async_bridge` + `mcp/subprocess_trust.py`.
- **Why:** ADR-031 D2 (reuse-the-MCP-subprocess-mechanism + the watchdog + the seam split); ADR-029 D4 "≈ a bundled MCP server."
- **Acceptance:** all existing `tests/mcp/*` green unchanged (behavior-diff empty for the well-behaved case); (a) importable by the remote transport, (b) importable by `plugins/`; a SIGTERM-ignoring mock child is still reliably killed by the watchdog (no orphan — a discriminating test).
- **Out of scope:** the Posture-B executor itself (-5).

**P3.7-remote-5 — Posture-B plugin executor (the A→B migration).**
- **What:** Replace the in-process `importlib`/`exec_module` path in `plugins/code.py` (verified Posture A, `plugins/code.py:42-104`) with a **subprocess runner**: the plugin tool callable runs in a **child** process speaking the reused stdio MCP protocol (a generic harness wraps a `tool_impls` `<module>:<callable>` as a stdio MCP-server child; **the parent never imports plugin code**). Scoped env (via -4 (b)), bounded-timeout, **kill-no-orphan + the watchdog**, fail-closed → `TOOL_FAILED`. `load_plugin_code` now returns `LocalToolFn`s that are **subprocess-launching closures** — they drop into the **same** `local_tools` registry, so `tools/executor.py::_execute_local_call` runs them **unchanged** (the empty-executor-diff invariant holds; only what the `LocalToolFn` *is* changes). **Add `MAX_POSTURE_B_CALLS_PER_TURN` (R0-B Y6 → α):** the executor caps per-turn subprocess plugin calls (the MCP `MAX_MCP_CALLS_PER_TURN=10` analog, `tools/executor.py:43`), applied **only** to subprocess `LocalToolFn`s (Posture-A in-process tools exempt); excess → `TOOL_FAILED`.
- **Where:** `src/orchestrator/plugins/code.py` (substantially reworked) + a child-harness module + `tools/executor.py` (the cap constant + the subprocess-closure branch — note: the cap is an executor *mechanism* addition, not a decision-logic change; empty-decision-diff holds).
- **Why:** ADR-031 D1/D1a/D2 (Posture-B execution model + reuse + per-turn cap); ADR-029 D4 itemized A→B migration; restores ADR-028 D5 (killable = bounded).
- **Acceptance:** a plugin tool executes via subprocess → `TOOL_RESULT`; a hung/runaway plugin tool is **killed** (no orphan, incl. SIGTERM-ignoring → watchdog SIGKILL) and the call `TOOL_FAILED`s **without blocking the single writer past the bound** (D5 restored — a discriminating test); `>MAX_POSTURE_B_CALLS_PER_TURN` subprocess calls in one turn → excess `TOOL_FAILED` (cap test); the child env does **not** contain the orchestrator's secrets (env-leak probe, the c2 lesson); `_execute_local_call` decision path unchanged (empty-diff cite). Depends on -4.
- **Out of scope:** provenance/fetch (-6/-7).

**P3.7-remote-6 — remote-provenance + activation/consent.**
- **What:** Mark each plugin's **provenance by ORIGIN** in the loader (R0-A Y3 + R0-B Y3 → α): `load_plugins` gains a **second, segregated discovery root** `fetched_plugins_dir: Path | None`, **NOT under** the `plugins/` presence root — plugins under `plugins_dir` → `operator-placed`, plugins under `fetched_plugins_dir` → `fetched`. The disjoint roots make provenance **un-launderable** (a fetched bundle can never be re-discovered as operator-placed). **Enforce: `fetched` → Posture B forced** (curation void → Posture A **test-enforced unreachable** for fetched code — a runtime provenance guard + a discriminating test, *not* claimed "structurally unreachable", R0-B R2 → α). Add the **activation allowlist** (ADR-029 D5): a `fetched` plugin loads **only** if an operator activation entry pins it (source + integrity digest **+ an operator-authored `plugin_subprocess_env` of non-secret keys**); a fetched manifest **cannot self-request** env keys or `api_key_env` (R0-A Y4 + R0-B Y2 → α). Fail-closed on unverified provenance / missing activation / a fetched manifest naming a secret.
- **Where:** `src/orchestrator/plugins/loader.py` (the `fetched_plugins_dir` param + provenance-by-origin) + a new provenance/activation module.
- **Why:** ADR-031 D3 (provenance-by-origin, un-launderable) + D4 (activation/consent + operator-authoritative env); the inscribed crux.
- **Acceptance:** a `fetched` plugin with no activation entry → refused; a fetched bundle **cannot** be discovered as `operator-placed` (provenance-laundering test); a `fetched` plugin's `tool_impls` runs Posture B only (test-enforced-unreachable Posture-A test); a fetched manifest naming `api_key_env`/a secret → refused (env-authority test); an `operator-placed` plugin is unchanged (P3.5 behavior preserved). Depends on -5.
- **Out of scope:** the fetch transport (-7).

**P3.7-remote-7 — minimal remote-fetch mechanism.**
- **What:** Fetch one plugin bundle (a **single `.zip`/`.tar.gz` archive**, R0-B Y5) from a **pinned `https://` source** into the segregated `fetched_plugins_dir` (-6). **Digest-BEFORE-extract ordering (R0-B Y5 → α — the ordering IS the security property):** compute the digest on the **compressed bundle bytes BEFORE any extraction**; only a digest-matching bundle is then extracted; extraction is **path-traversal-guarded** (reject `..`/absolute/symlink-escape). **Atomic staging + cleanup (R0-B Y7 → α):** download → temp file → verify digest → extract → temp dir → validate members → **rename** into `fetched_plugins_dir`; **on any failure, delete the temp file / `rmtree` the temp dir** — `fetched_plugins_dir` is never touched by a failed fetch. **Minimal pinned-source fetch only** — **no registry/marketplace, no upgrade/version/uninstall lifecycle** (deferred P4, brief §Out).
- **Where:** new `src/orchestrator/plugins/fetch.py`.
- **Why:** ADR-031 D5 (remote-fetch contract: bundle format + digest-before-extract + atomic staging); ADR-029 scope deferral absorbed.
- **Acceptance:** a pinned source + matching digest → staged + loadable (provenance `fetched` by origin); a digest mismatch / TLS failure / unreachable / non-`https://` source → refused, **temp staging cleaned up, `fetched_plugins_dir` untouched**; a tampered/oversized/path-traversal bundle → rejected **before extraction** (digest-before-extract test); no orchestrator crash. Depends on -6.
- **Out of scope:** a registry service; multi-version coexistence.

**P3.7-remote-8 — remote/Posture-B plugin demo + e2e.**
- **What:** One fetched-and-Posture-B plugin run end-to-end: fetch (pinned source/digest) → activate → Posture-B subprocess execute → `TOOL_RESULT`; plus the fail-closed paths.
- **Where:** `plugins/<demo>/` (+ a staged-source fixture), `tests/plugins/`, `tests/integration/`.
- **Why:** ADR-031 D6 (one-demo discipline); brief §e.
- **Acceptance:** the demo proves the loop **and** fail-closed: subprocess crash/hang/timeout → `TOOL_FAILED` + kill-no-orphan (incl. watchdog); the env-leak probe asserts the child lacks orchestrator secrets **both** by default **and** when a fetched manifest *requests* a secret/`api_key_env` (→ refused); `>MAX_POSTURE_B_CALLS_PER_TURN` → excess refused; a fetched bundle **cannot** be discovered as `operator-placed` (laundering test); a tampered bundle rejected **before extraction**; an **unactivated** fetched plugin refused; a digest-mismatch refused (temp staging cleaned up). Depends on -7.
- **Out of scope:** GUI surfacing (frontend track).

## 3. Execution order

**Single-junior serial** (brief §Parallelism — the subprocess/trust surface wants one careful hand + the dual-lens, not fan-out). The chain:

`-1 (config) → -4 (extract primitives) → -2 (remote transport) → -3 (remote demo) → -5 (Posture-B executor) → -6 (provenance/activation) → -7 (fetch) → -8 (Posture-B demo) → -9 (constitution)`

`-4` precedes `-2` because both edit `transport.py` (the shared-file conflict forces sequencing; the extracted seam lands first, then the remote path consumes it). `-5..-8` are a strict dependency chain (executor → provenance → fetch → demo). **No parallel set** — every task either shares a file with its neighbour or consumes its output.

These are **not** in the plan as decided — they are the genuine architect calls remaining after the ratification:

**5.1 SSE — streamable-http only, or both?** The architect ratified "lean streamable-http; confirm one or both." **My lean: streamable-http only.** SSE is the legacy/deprecated MCP transport variant; both `streamable_http_client` and `sse_client` exist in the installed SDK (verified `mcp/client/{streamable_http,sse}.py`), so adding SSE later is additive. Shipping one transport keeps the trust surface (and the test matrix) minimal. **(R0-A Y1 resolved the related SDK-symbol question → α: the plan now pins the non-deprecated `streamable_http_client` + a host-built `httpx.AsyncClient`, independent of the one-or-both call.)** **Confirm: streamable-http only?**

**5.2 Remote-fetch consent/integrity model (posture nod, like ADR-027 D4's allowlist ruling).** Under B-coupled I must design the "fetching ≠ trusting" mechanism. **My design (ADR-031 D4/D5): an operator-pinned activation allowlist** — a fetched plugin loads only if the operator adds an explicit entry pinning its **source URL + an integrity digest**, and the fetched bundle must match the digest. This is the remote analog of presence=opt-in (ADR-029 D5) and keeps the consent operator-authoritative + fail-closed without a registry/marketplace (deferred P4). **Confirm this is the intended remote-consent posture** (vs. e.g. a signature/keyring model, which would be heavier).

**5.3 Remote demo reachability.** A *real external* `https://` MCP endpoint in a CI e2e is **non-hermetic** (network dependency + most public endpoints require auth/OAuth). **My lean: hermetic local-TLS streamable-http mock** for the fail-closed e2e tests, with the "real public https:// endpoint" captured as **documented config** (a manual/opt-in demo), not a network-gated CI test. This mirrors P3.4's posture (the filesystem demo runs via a local subprocess, not a hosted service). **Confirm the demo shape** (brief §e explicitly leaves the demo scope to the architect).

**5.4 Scope size note (not a decision — flagging).** B-coupled is a large serial slice (9 atomics, 2 ADRs, 2 untrusted-remote boundaries). The architect ruled it as P3's last cut; I am **not** re-routing. The dependency chain is genuinely serial, so the size lands as wall-time, not review-surface risk (each commit is reviewed on its own merits + the mandatory dual-lens). If junior context exhaustion is a risk on -5/-7 (the heaviest reworks), the recover-via-/clear-from-git-log path applies — but I do **not** propose splitting the atomics.
