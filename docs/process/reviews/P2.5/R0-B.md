## Synthesis

The impl is faithful to the Accepted ADR-021 and absorbed plan-stage routings. All four plan-stage yellows are correctly absorbed: Y1 (ARCHIVE_SUMMARY_RENDER in ADR), Y2 (import guard covers all four upstream layers), Y3 (new_since_leave first-visit → typed `[]`), Y4 (hygiene). The AST guards are function-scoped (not file-scoped), discriminating (planted violations caught, legitimate calls pass), and structurally enforce the Principle-11 boundary.

One net-new 🟡 (Y1): the `_parse_archive_summary` fallback silently persists garbled LLM output as a durable archive artifact. Unlike the ephemeral prose render (shown, not persisted), the archive summary is durably stored via `record_project_archive`. A garbled LLM output stored without degradation marker violates the project's fail-loud posture. The fix is small: either (a) raise on parse failure (fail-loud — the caller retries or logs), or (b) prepend a degradation marker like `"[fallback] "` to the persisted summary so downstream consumers know it's degraded. The content-gen nature of LLM output makes some tolerance appropriate, but silent persistence of garbled content into a durable artifact crosses the line from "defensive parsing" to "masking a bug."

The render-output seam (plan-stage G2 — "phrasing-only is prompt-enforced") remains at impl. The prose render's system prompt instructs "Do NOT add any facts" but no code validates the output. This is still the weakest link in the Principle-11 chain, acceptable for the MVP per the architect's ruling (deterministic `ReentryDigest` is the tested core; prose is non-asserted UX).
