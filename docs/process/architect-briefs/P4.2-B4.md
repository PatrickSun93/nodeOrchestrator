---

**Subject:** Build **P4.2-B4** — implement the 2 deferred **network local tools** so an agent can **fetch a URL** (`web_fetch`) and **run a web search** (`web_search`) mid-investigation — the open-web half of the flagship loop (look up an error string, read a referenced doc, check an upstream changelog) that B3's subprocess tools and P4.1's turn-loop set up. **`web_fetch` is the project's FIRST tool where the URL is agent-chosen** (LLM-proposed, prompt-injection-influenceable) rather than operator-configured — so it is the **SSRF / data-exfil** surface ADR-028 D3 named. It ships **BEFORE** the P4.3 syscall/egress sandbox, so it runs with an **app-level SSRF posture** (host/IP-range validation, scheme allowlist, DNS-rebind pinning, redirect re-validation, bounded size/time, credential-stripped) and leaves **one honest egress residual** — the **network half of `RB-FS/NET`**, now the *active* surface, Accepted exactly as ADR-031 D1a / ADR-034 D2 modelled it, retired by P4.3. Second of the 3 serial P4.2 sub-slices (B3 ✅ → **B4** → B5).

## The foundation P4.2-B4 completes (verified — what's missing, precisely)

After B3, an agent can run tests/lint/git and read files **in-turn** — but it **cannot reach anything off the local disk**. It can't pull the doc a stack trace references, check whether an upstream bug is fixed, or look up an unfamiliar API. B4 adds the **network** tool surface. The reusable parts already exist (httpx + bounded-timeout patterns; the executor's cap + the `_external_output_tool_result_call_ids` untrusted-output filter) — **but the load-bearing part is new**: every prior network fetch in this codebase targets an **operator-authoritative** URL (MCP server config, plugin source, LLM endpoint), so **there is no SSRF guard to reuse**. B4 is mostly **inscribing the network execution posture + building the one app-level SSRF validator** that makes "let the agent reach the web, before the egress sandbox exists" an Accepted boundary rather than an open door.

## ⭐⭐ Constitutional carry-forward (NON-NEGOTIABLE — inscribe in ADR-035; **not** decisions)

Per P4-roadmap §10 + the ADR-028/031/034 spine. The senior inscribes; the impl enforces; R0-A/R0-B probe each:

1. **Execution stays DOWNSTREAM of the gate (ADR-028 #1 / t4).** Web tools route the **unchanged** `process_tool_calls`→`emit_gate_decision` path; AUTO (rev 10) executes; the executor never re-gates. (If the architect re-tiers `web_fetch` to `COUNTDOWN` — decision (1)/(2) — that variant is confirm-gated, **not** executed in-loop.)
2. **No LLM judgment in the executor; no new `LLMPurpose` (t2/t3).** The network path is pure code; the SSRF decision is **code, not an LLM judgment** (never LLM-judge "is this URL safe"). **If** fetched content is interpreted (decision (3)(iii)), it reuses the existing content-gen `TOOL_OUTPUT_INTERPRET` — no new purpose.
3. **The network trust boundary is REAL for SSRF/credential/liveness, HONEST about egress.** App-level host/IP-range validation + scheme allowlist + DNS-rebind pinning + redirect re-validation (no internal-service/metadata reach), credential-stripped requests (no secret/cookie/auth-header leak — the c2 lesson at network scale), bounded size+timeout+per-turn cap (the ADR-028 D5 bound) — **but NOT a syscall/egress firewall**: the **network half of `RB-FS/NET`**, Accepted **exactly as ADR-031 D1a / ADR-034 D2 modelled it**, retired by P4.3.
4. **Reuse, don't rebuild — one network mechanism.** Reuse httpx + the bounded-timeout/`verify=True` patterns, the executor cap, and the `_external_output_tool_result_call_ids` filter. **The SSRF validator is the one genuinely new primitive** — build it **once**, in **one** place, consumed by `web_fetch` (and any future agent-URL tool); do not scatter URL checks.
5. **`tools/` stays a downstream leaf (t1); `_execute_local_call` stays byte-unchanged** (empty-executor-diff) — the per-turn network cap lives in the `execute_pending_tool_calls` **loop** (mirroring B3's subprocess branch `:171`), not in the byte-frozen dispatch fn.
6. **URL-validated, never blind-fetch — test-enforced.** No code path fetches an agent-supplied URL without the SSRF validator; **a constitution test asserts** private / link-local / loopback / **cloud-metadata** ranges are rejected and that the fetch path cannot bypass the validator (the ADR-034 t9 *"argv never shell"* / ADR-032 *"constitution test forbids `verify=False`"* precedent, applied to SSRF).

## Decision points (surface — ⭐ = architect's genuine call; do NOT self-decide)

### (1) MVP tool set + classification confirm — `web_fetch` and/or `web_search` (two DIFFERENT surfaces)

- **Both are pre-classified rev 10 → AUTO** (`tools.yaml:13-16`); at any agent they reach `AUTO_EXECUTE`. The classifications **stand as-is** unless re-tiered (see the `web_fetch` knob below).
- **They are NOT the same trust surface:**
  - **`web_fetch` = fetch an arbitrary, *agent-chosen* URL → the SSRF / data-exfil CORE.** No provider key; direct httpx; the whole posture work (decision (2)) exists for this tool.
  - **`web_search` = a query through a *fixed provider* API** (Brave/Bing/SerpAPI/…). **Different surface:** the egress target is a single operator-configured endpoint (low SSRF) — but it adds a **provider-API-key dependency** (credential surface + a new config/secret) and a **provider choice**, and its *results* are still untrusted external text (decision (3)).
- **Architect-partner lean: ship `web_fetch` this slice; surface `web_search` as a knob.** `web_fetch` is the irreducible network capability and carries the load-bearing SSRF call — do it properly once. `web_search` is *additive* and drags in a provider/key decision orthogonal to SSRF. **Your call:** (a) **`web_fetch` only** in B4, `web_search` as a thin follow-up (B4.1) once a provider+key policy is set; (b) **ship both** (define the provider + key-management now — note web_search reuses *none* of the SSRF validator, so it's near-independent work); (c) ship both but **re-classify `web_fetch` → COUNTDOWN** (rev↓) so agent-chosen-URL fetches are confirm-gated, not AUTO. Lean **(a)**; **(c)** is the conservative knob if you want a human in the loop on every agent-proposed URL.

### (2) ⭐⭐ SSRF defense posture — app-level guards now + honest residual **vs** reorder behind P4.3 (THE load-bearing call)

This is the lead decision, and **sharper than B3's**: B3's network residual was *latent* (pytest/ruff/git don't intend to egress); **B4's egress IS the tool's function**, and the URL is **agent-chosen**, so the SSRF guard is the *only* thing standing between a prompt-injected agent and the internal network — and it is **new security code with a notorious failure history** (DNS rebinding, IP-literal encodings, IPv6, redirects).

- **Option A (lean): ship B4 now with an app-level SSRF validator + inscribe the egress residual exactly like ADR-031 D1a / ADR-034 D2.** The validator's **non-negotiable floor** (inscribe; the senior pins the exact list + R0-B probes completeness):
  - **Host/IP-range denylist** — reject loopback `127.0.0.0/8` + `::1`, private `10/8 · 172.16/12 · 192.168/16` + `fc00::/7`, link-local `169.254.0.0/16` + `fe80::/10` (**incl. the cloud-metadata `169.254.169.254`**), and `0.0.0.0`/unspecified. This is the floor, not a knob.
  - **DNS-rebind defense — resolve-then-pin:** resolve the host, validate **the resolved IP(s)** against the denylist, then **connect to the pinned IP** (not re-resolve) — so a TOCTOU/rebind between check and connect can't slip an internal IP through. (httpx custom transport / resolver — in-process, decision (4).)
  - **Redirect re-validation:** every hop re-runs the full check (a `302 → http://169.254.169.254` must be re-rejected), **or** redirects-disabled-by-default. *(Genuine knob: re-validate-each-hop vs no-follow — surface.)*
  - **Scheme allowlist:** `https` (+ `http`?) only — reject `file://`/`gopher://`/`ftp://`/`data://`. *(Genuine knob: https-only (safest) vs http+https (http to public hosts is common, and the IP-range floor already blocks http-to-internal) — surface.)*
  - **Bounded response size + timeout** (reuse `MAX_RESULT_BYTES` + a bounded httpx timeout — the single-writer D5 bound) and **per-turn cap** (decision (4)).
  - **The honest residual:** even with the floor, **without a real egress firewall (P4.3)** there remain (i) **data-exfil to a *public* attacker URL** (`https://evil.com/?d=<secret>` — the IP-range floor can't catch it; decision (3)), (ii) exotic resolver/rebind/`CNAME` edges, (iii) any range the denylist misses. Accept this as the **network half of `RB-FS/NET`**, on the **same one retirement path** as B3 (P4.3 wraps the egress, doesn't re-do the app guard).
- **Option B: reorder B4 behind P4.3** — build the egress sandbox first; `web_fetch` is network-namespaced from day one (thinner app residual). **Cost:** blocks the web capability on the heaviest infra slice; inverts value-first sequencing (§7); and the app-level validator is *still wanted* even post-sandbox (defense-in-depth + metadata-range blocking the agent shouldn't reach regardless).
- **Architect-partner lean: Option A**, because the residual is a **standing-Accepted class** (ADR-031 D1a, twice-Accepted) and the app guard is the durable primitive either way. **But this is squarely your call** — it is a **residual-acceptance + sequencing** decision, and B4's residual is *more active* than B3's (egress-by-design + agent-chosen URL). You accept it via **ADR-035**. If the data-exfil residual (i) is unacceptable for the deployment, the tightening knob is an **operator egress allowlist** (fetch only approved hosts) — surfaced under (3).

### (3) Threat model — 4 sub-surfaces (inscribe in ADR-035)

- **(i) SSRF (internal-service / metadata reach) → the validator floor in (2).** The untrusted input is the **LLM-proposed URL**; the defense is resolve-then-pin + IP-range/scheme/redirect validation. *No real "choice" beyond the (2) knobs — but the senior pins the exact range list + the redirect/scheme policy; R0-B probes completeness (the classic SSRF-bypass checklist).*
- **(ii) Data-exfil (stolen data encoded in an agent-fetched URL) → the sharper, partially-residual threat.** A prompt-injected agent fetching `https://evil.com/?leak=<secret>` egresses to a **public** host the IP-floor permits. **Mitigations:** the output-untrusted framing + excerpt-exclusion (below) shrink the *injection* vector that induces it; full prevention needs an **operator egress allowlist** (too restrictive for general `web_fetch` — surface as an opt-in tightening) or the P4.3 egress firewall. **Lean: inscribe app-guards + framing now; Accept the public-host-exfil residual honestly (don't claim it's solved); name the egress-allowlist as the operator knob + P4.3 as the retirement.**
- **(iii) ⭐ Output-as-untrusted — fetched web content is the MOST untrusted output yet (extend the ADR-034 D3-iv pattern).** Open-web bytes are attacker-authorable by definition. Treat exactly like the B3 third trust class: **raw `TOOL_RESULT` + untrusted framing, NOT interpret→`OBSERVATION`** (the agent acts on precise bytes; an interpret costs an LLM call in the D5 block + a lossy summary). **The forced reconcile: widen `_external_output_tool_result_call_ids` to the web tools** — add `web_fetch`/`web_search` to the external-output set (a `_NETWORK_TOOL_NAMES` frozenset beside `_SUBPROCESS_TOOL_NAMES`, or fold both into one "external-output" set) so injected web text **cannot steer a re-dispatched agent** via `snapshot_excerpt`. The drift-sync test pattern (registry keys == name set) carries over. *Sub-lean: raw + framing + extend the filter. Alternative (interpret→OBSERVATION, symmetric with MCP, reuses `TOOL_OUTPUT_INTERPRET`) is surfaced but costs an LLM call per fetch + a summary the agent often can't act on.*
- **(iv) Credential-safety (no secret/cookie/auth leak to fetched hosts).** `web_fetch` requests carry **no `Authorization`, no cookies, no orchestrator env/api-key** — a stripped, anonymous client (the c2 env-leak lesson, network analog). `web_search`'s provider key goes **only** to the fixed provider endpoint, **never** onto a fetched URL. *Inscribe, not a choice — but the senior pins the exact stripped-header/redirect-credential-drop behavior (a cross-origin redirect must not forward auth).*

### (4) Where it executes — in-process httpx `LocalToolFn` + SSRF guards; confirm the constitution

- **Lean: `web_fetch` is an in-process httpx `LocalToolFn` with the SSRF-validating transport — NOT a subprocess.** Rationale: resolve-then-pin (2) is cleanest **in-process** (a custom httpx transport that validates the resolved IP and connects to it); a `curl` subprocess would re-introduce the SSRF surface inside the child and add a fork for no isolation gain (a subprocess is **not** a network namespace — that's P4.3). So B4, unlike B3, **does not need the subprocess/Posture-B path**.
- **Per-turn cap + liveness:** a network call adds a liveness term (**bounded timeout × the turn-loop's `N` passes**, like B3's forks). It needs a **per-turn network cap** — mirror B3 exactly: a counted branch in the `execute_pending_tool_calls` **loop** (a `MAX_NETWORK_CALLS_PER_TURN`, or generalize the existing subprocess cap to "external calls"; a marker like `_is_network_tool` beside `_is_posture_b_subprocess`). *This is a senior-design + small naming call; surfaced so you know B4 touches the executor **loop** (a cap branch) but keeps **`_execute_local_call` byte-frozen** — the empty-executor-diff invariant holds exactly as in B3.*
- **Confirm the carry-forward holds:** **t1** (`tools/` leaf), **t2** (no autonomy decision — the SSRF check is code), **t3** (no new `LLMPurpose`), **t4** (execute-on-`TOOL_CALL`-only) — all hold; the gate stays the sole chokepoint, downstream.

It inscribes: the **network execution posture** (in-process httpx, the SSRF validator floor, credential-stripping, bounded size/timeout/cap), the **threat model** (the 4 sub-surfaces above), the **honest egress residual** (the ADR-031 D1a / ADR-034 D2 `RB-FS/NET` model + the *active-not-latent* distinction + the P4.3 forward-watch + the data-exfil honesty), and the **executor placement + constitution carry-forward**. Plus **amend ADR-028 D3** ("the 2 web tools no-longer-deferred"; classification confirmed) — the same `[Amended P4.2-B4 → ADR-035, Accepted]` strike-through pattern B3 used on the subprocess line (`ADR-028:65`).
- **Mandatory dual-lens R0-B + plan-stage `external-r0b-prompt`** (P4-roadmap §8; `requires_cross_family_review: true`, ratified). The plan-stage external-r0b lenses to draft: **(a)** the **SSRF/exfil trust boundary** (the IP-range/scheme/DNS-rebind/redirect completeness against the standard SSRF-bypass checklist; credential-strip on cross-origin redirect; the data-exfil residual's honesty; the output-untrusted framing + filter extension), **(b)** **liveness** (bounded timeout + bounded response + per-turn network cap under the single writer, **× the P4.1 turn-loop's N passes**).
