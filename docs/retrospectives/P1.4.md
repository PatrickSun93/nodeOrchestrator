## 2. Meta-lesson — the harness held under shape change AND dual-lens R0-B paid for itself

**The defining fact of P1.4 is two simultaneous observations:**

### (a) The harness held under shape change

W-001 retro §9 staked: "The substrate works on non-self-referential work; does it hold under shape change?" P1.4 is the first cycle that put genuine shape-change pressure on the workflow harness:
- First concurrency-adjacent surface (sequential + sync dispatch with snapshot semantics; §2 first non-trivial use).
- First real agent yaml load (skeptic.yaml + prober.yaml).
- First multi-ADR-per-task (ADR-010 + ADR-011 drafted simultaneously).
- First all-6-category test-coverage exercise.
- Three new code-driven decision functions (decide_agents_for_room + should_agent_speak + dispatch_turn).

Harness behavior under that pressure:
- State machine fired 6 transitions; **one override required** (multi-ADR ADR Accept gate pre-W-002.5 — closed in same cycle's sibling work via W-002.5).
- Auto-trigger discipline held end-to-end except at the override site.
- Dual reviews (R0-A + dual-lens R0-B) absorbed via architect-routing into senior revisions; pattern stable.
- No mid-stream harness changes required.

**The harness substrate (W-001 + W-002 + W-002.5) is now empirically validated for shape-change work.** P1.5 + W-002.5 + P1.5.5-brief subsequent cycles confirmed this — three consecutive zero-override cycles followed.

### (b) Dual-lens R0-B caught what each lens alone would miss

This is the more interesting observation. Of 18 routing items absorbed:

- **Proxy-lens R0-B** (Claude subagent with contrarian prompt) caught:
  - 🔴#1 cooldown unit mismatch (s vs ms) — spec-level numeric bug; reviewer-as-text-analyzer
  - 🔴#2 StateChangeTrigger metadata gap — spec-level missing-schema-dependency; reviewer-as-graph-walker
  - 4 🟡 scope-discipline (Agent.priority, async-shape, build_agent_context, snapshot_excerpt)
- **True cross-family R0-B** (DeepSeek V4 Pro) caught:
  - 🔴#1 event_store.append failure path absent — runtime-integration; reviewer-as-failure-mode-tracer
  - 🔴#2 all-agents-fail caller contract — runtime-integration; reviewer-as-state-space-cover
  - 4 🟡 signature honesty + integration tests + naming + format defense

**The two lenses caught structurally different errors.** Proxy-lens (Claude prompted-contrarian) operates at the level of "is the spec text consistent?" — it catches numeric/symbolic inconsistencies. True cross-family (DeepSeek) operates at the level of "what happens when this call fails at runtime?" — it catches integration-error paths that look clean in spec but break under operational pressure.

**This is empirical evidence for the dual-lens pattern.** Without proxy, the cooldown unit bug ships (1000× silent error). Without DeepSeek, the event_store failure path ships (no recovery on persistence failure). Cost: ~$2 + ~40 minutes external session. ROI: 4 🔴-class production bug avoidances on the project's most architecturally consequential task to date.

**Captured as RC-15** (now codified): dual-lens R0-B is project standard for shape change. Architect judgment per task on whether to dispatch; not blanket-applied to all shape-change.

## 12. The shape-change cycle proved an architect-partner discipline observation worth naming

P1.4 ran at high density. The architect-partner role accumulated multiple in-session work products: brief + R0-A-on-plan + proxy R0-B + senior revisions (post-routing) + R0-A on impl + multiple verdict bumps + state advances + ADR Accept facilitation + P1.5 brief authorship + P1.5 R0-A-on-plan + P1.5 architect-routing + P1.5 R0-A on impl. Audit-item #8 (role collapse) captured the chronic risk.

**Observation worth naming for future cycles**: when a single architect-partner session accumulates ≥5 distinct role hats on the same task family within a calendar day, the risk of self-loop (architect-partner reviewing artifacts they themselves shaped) compounds. P1.4 + P1.5 ran clean despite this, but the cleanliness relied on:
- Senior + junior being external (genuinely distinct sessions; fresh-eye lens).
- Dual-lens R0-B for P1.4 (external true cross-family broke the in-family loop).
- The architect's explicit override discipline (e.g., reversing senior's "required no default" to "default per brief" on P1.5 Y1).

**Without those mitigations, role-collapse would have compounded faster.** Future cycles should preserve them: external sessions for senior/junior; dispatch dual-lens R0-B when stakes warrant; architect explicit override of architect-partner leans when they diverge from architect's actual position.

This is the **honest reflection on architect-partner-as-pinch-hitter pattern** that P1.4 made impossible to ignore. Captured for the retro because the pattern persists into P1.5.5 (which is in progress at this retro's writing) and will into P1.6.
