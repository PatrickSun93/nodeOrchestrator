## 1. Context

P1.3 turns `handoff.md` §3.3 ("Skills compatible with industry standard SKILL.md format") + §5.3 (10-skill MVP library) into a working loader plus a deterministic, code-driven matcher. The matcher decides which skills enter an agent's context window given `(agent_id, room_type, room_state, optional event-trigger)` — pure function, no LLM, per Principle 3.1. The body of each SKILL.md remains LLM-consumed (it's the instruction text); the *match* is code.

Three constraints from the brief and predecessors:

- **New top-level package `src/orchestrator/skills/`** sibling to `core/`, `llm/`, `autonomy/`, `workflow/`. First new top-level package since W-001-impl introduced `workflow/`. Layering: `skills → core` allowed; `core → skills` and `skills → llm` forbidden — locked by two new constitutional tests following the W-001-impl precedent.
- **ADR-009 drafted alongside this plan.** The frontmatter schema is contract-locking for every future skill author; the architect-partner lean ("probably an ADR") is accepted on senior reading. ADR-009 settles five entangled sub-decisions: format choice, required fields, `applies_to` shape, `room_states` semantic, decision-trace shape.
- **First task running entirely through the post-W-001-impl harness.** `.workflow/P1.3.yaml` exists at `awaiting_senior_plan`; this plan push advances it. The harness handling end-to-end is itself a W-001 retro §9 promise being tested in anger.

This plan deliberately scopes P1.3 to **plumbing**: data structure, loader, matcher, two sample skills, tests. The full 10-skill library is downstream content authoring, not architectural work. Agent-runtime integration (skills entering actual context windows) is P1.4.

  ```python
  from __future__ import annotations
  from typing import Literal
  from pydantic import BaseModel, ConfigDict, Field, field_validator
  from orchestrator.core.room import RoomType

  class AppliesTo(BaseModel):
      model_config = ConfigDict(frozen=True, extra="forbid")
      agents: list[str] = Field(min_length=1)
      room_types: list[RoomType] = Field(min_length=1)
      room_states: list[str] | None = None

      @field_validator("agents")
      @classmethod
      def _reject_mixed_star(cls, v: list[str]) -> list[str]:
          # ADR-009 Decision 3: ["*", "prober"] is forbidden — "*" is
          # exclusive with concrete ids. Reject at construction time.
          ...

      @field_validator("room_states")
      @classmethod
      def _reject_empty_list(cls, v: list[str] | None) -> list[str] | None:
          # ADR-009 Decision 4: empty list is rejected (use None to mean
          # "match all states"; list must be non-empty when explicit).
          ...

  class Skill(BaseModel):
      model_config = ConfigDict(frozen=True, extra="forbid")
      id: str = Field(min_length=1)
      category: Literal["general", "engineering", "business"]
      applies_to: AppliesTo
      priority: int = Field(ge=0, le=100)
      body: str = Field(min_length=1)  # markdown body; loader populates post-frontmatter; empty body rejected at schema time (R0-A-on-plan-4)

  class SkillMatchRecord(BaseModel):
      model_config = ConfigDict(frozen=True, extra="forbid")
      skill_id: str
      # No separate matched: bool field — derive from
      # rejection_reason == "matched". Single source of truth per
      # ADR-009 Decision 6 + R0-A-on-plan-1(a).
      rejection_reason: Literal[
          "agent_mismatch",
          "room_type_mismatch",
          "room_state_mismatch",
          "matched",
      ]

  class SkillDecisionTrace(BaseModel):
      model_config = ConfigDict(frozen=True, extra="forbid")
      considered: list[SkillMatchRecord]
      selected_count: int = Field(ge=0)
      rejected_count: int = Field(ge=0)

  class SkillSelection(BaseModel):
      model_config = ConfigDict(frozen=True, extra="forbid")
      selected: list[Skill]
      trace: SkillDecisionTrace
  ```

### P1.3-5 — Matcher (`decide_skills_for_context`) + tests

- **What**: implement `decide_skills_for_context(...) -> SkillSelection` in `src/orchestrator/skills/decision.py`. Pure function; reads only inputs; no I/O. Returns `SkillSelection` carrying `selected: list[Skill]` ordered by `(priority desc, id asc)` plus full `SkillDecisionTrace`.
- **Where**:
  - New: `src/orchestrator/skills/decision.py`.
  - New: `tests/skills/test_decision.py`.
- **Why**: ADR-009 Decisions 3–6 (matching predicates + tie-breaking + trace); brief in-scope §1; `contributing.md` Q2 (decision_trace mandatory).
- **Acceptance**:
  - Signature:
    ```python
    def decide_skills_for_context(
        agent_id: str,
        room_type: RoomType,
        room_state: str,
        *,
        available_skills: dict[str, Skill],
        triggering_event_type: EventType | None = None,  # P1.4+ hook; unused in P1.3
    ) -> SkillSelection: ...
    ```
  - Matching predicate (all three must hold for a skill to match):
    1. `agent_id in skill.applies_to.agents` OR `"*" in skill.applies_to.agents`.
    2. `room_type in skill.applies_to.room_types`.
    3. `skill.applies_to.room_states is None` OR `room_state in skill.applies_to.room_states`.
  - On match: `SkillMatchRecord(skill_id=..., rejection_reason="matched")`. No separate `matched: bool` field — match-ness derives from `record.rejection_reason == "matched"` (ADR-009 Decision 6 single-source-of-truth per R0-A-on-plan-1(a)).
  - On miss: `rejection_reason` = the first failing predicate (in 1,2,3 order). Test asserts the precedence — e.g., if agent fails AND room_type fails, `agent_mismatch` is reported.
  - Sort order: `selected_count` items returned in `selected`, ordered by `(-priority, id)` (descending priority, ascending id for ties).
  - `triggering_event_type` is accepted but unused in P1.3 (P1.4+ hook); a one-line docstring states this. **No silent behavior:** the parameter being non-None has no effect on the return value in P1.3.
  - Tests (≥ 10 covering): each of the 5 RoomType values × at least one agent matching scenario; an `agents: ["*"]` skill matching every agent; `room_states is None` skill matching every state; explicit `room_states=["open"]` matching only when room_state is `"open"`; explicit `room_states=["open"]` NOT matching `"closed"`; priority tie-breaking with two skills at priority 50 ordered alphabetically; empty `available_skills` returns empty `selected` with `trace.considered = []`; `triggering_event_type=None` and `=EventType.UTTERANCE` produce identical output. **§1 cross-module integration test**: build a Skill via the schema, pass through `load_skills` (using a tmp file), feed into `decide_skills_for_context`, assert `selected[0].id` equals the source skill's id AND differs from a sentinel default value (source ≠ sink).

## 5. Where I'd push back

Six push-backs / senior decisions logged for R0-A challenge.

1. **ADR-009 yes** (brief Architect-settled decision 3 invited senior judgement). The frontmatter schema is contract-locking for every future skill author; without an ADR, each new skill drifts and "why this shape?" relitigates in 6 months. Architect-partner lean accepted. Flag if you'd prefer a leaner alternative (e.g., README-only spec in `config/skills/README.md`).

2. **`applies_to.room_states` = `Optional[list[str]] = None`** (ADR-009 Decision 4). Lean was "empty list = all"; I'm choosing `None` = all (key omitted = all states; explicit list must be non-empty). Reason: empty list is a common authoring slip that becomes silently equivalent to "all" — worst-case footgun. The asymmetry with `agents` (where `["*"]` is the sentinel) is recorded in ADR-009 alternative C.

3. **Sample skills count = 2** (brief decision 4 invited push-back). Two is enough to exercise both `agents` shapes (`["*"]` + concrete list), both `room_states` shapes (None + explicit), both categories (general + engineering), and priority tie-breaking. Three+ adds test-bloat without exercising new schema branches; one is insufficient to test priority ordering. Flag if you want more.

4. **Tie-breaking = alphabetical by `id`** (brief decision 6 invited push-back). FS order is OS-dependent (non-portable). "Undefined-with-test-that-explicit-order-is-set-when-it-matters" punts the determinism question. Alphabetical is the deterministic + portable + greppable choice. Tested in P1.3-5.

5. **`triggering_event_type` is a P1.4+ hook, currently unused** (brief decision 6 / cross-file refs invited push-back). I kept the parameter on the signature now to avoid a P1.4 signature change; the parameter has documented "no effect in P1.3" semantic and a test asserting it.
