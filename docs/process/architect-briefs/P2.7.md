## The crux — S2 is a routing decision (Principle 5 / "never LLM-judge routing"); S3 is a trust boundary (decision c)

- **(c1, S2) The Layer-4 cost/quality override is a ROUTING decision → it MUST be deterministic code, never LLM judgment.** Choosing *which model* for a cost/quality goal is exactly "routing/gating/scoring/model-selection" — which `llm-layer.md:11-14` already pins as **code** ("the LLM never makes architectural choices"), and CLAUDE.md forbids "LLM-judge a routing decision." So Layer-4 must be a **declarative config knob → deterministic code transform** over the existing code router (e.g. a global `quality_tier`/`cost_ceiling` that deterministically caps/reorders/filters the `[default_model, *fallback_chain]` per code rules), a **pure function** `(override_config, available_models) → selected_model` — **not** an LLM "picking the best model." The `LLMPurpose` taxonomy has **no routing/judgment purpose** (verified P2.5/P2.6) — so there is nothing to misuse, and Layer-4 must add **no** LLM call to the selection path. **Architect: confirm the override is a deterministic config-driven code rule, and rule how it's *guaranteed* so** (the existing code-router + no-routing-purpose; a structural test that the override path makes no `LLMProvider.call`; how it composes with the Layer-3 `fallback_chain`/`required_capabilities`).
- **(c2, S3) Alt-backend = a security/trust boundary.** Pointing Claude Code at a **non-Anthropic** backend via `ANTHROPIC_BASE_URL` means conversation content + tool calls + an API key flow to a **third-party server** (privacy/exfil; credential handling; a malicious backend could return crafted responses). **Architect: rule the trust model** — user-opt-in-with-responsibility? a warning/confirmation? validation/allowlist of backends? what may flow? (The dev harness already runs a local role-rewriting proxy for r0b — a precedent for *local-trusted* proxies; an arbitrary third-party backend is a different trust tier.)
