This revision instantiates the dialed-up envelope as **11 atomics** (one unit = one commit): 4 agents, 3 skills, 2 connectors, 2 plugins. Each ships a **discriminating** test (it really registers / really gates / really fails-closed — not "renders something").

## 2. Tasks (atomic — one unit = one commit)

### Agents (P3.7-content-1..4)

Each: new `config/agents/<id>.yaml` (frozen ADR-024 `Agent` shape — responses stay `AGENT_RESPONSE` content-gen; activation stays code `should_agent_speak`), declared into the `ROOM_TEMPLATES` rosters below (keep `declared_agents` **alphabetical**), plus a discriminating activation test. **Common acceptance bar** (mirrors the P3.1 facilitator test, `tests/rooms/test_scaffold_activation.py`): yaml validates against the frozen schema (`extra="forbid"`); `applies_to.room_states` non-empty (`["*"]` ok — schema `min_length=1`); test asserts `should_agent_speak` returns `speak=True` on a constructed event in **each** declared room type, AND `load_room(<a non-declared type>)` reports the agent **absent** from the roster (present/missing partition). Triggers reference only `state_change.target_state` values valid for the declared room types' state machines, OR use room-state-agnostic `regex`/`event_type` triggers (verify any target_state exists). **Common out-of-scope**: any loader/schema change; new `LLMPurpose`.

- **P3.7-content-1 — `synthesizer`** (converges discussion / proposes consensus) → `research`, `code_review`, `idea_validation`. *Where*: `config/agents/synthesizer.yaml`; `templates.py` (3 rosters); test.
- **P3.7-content-2 — `planner`** (decomposes work into ordered steps) → `bug_fix`, `code_review`, `idea_validation`. *Where*: `config/agents/planner.yaml`; `templates.py` (3 rosters); test.
- **P3.7-content-3 — `verifier`** (checks a fix/conclusion actually holds before close) → `bug_fix`, `code_review`. *Where*: `config/agents/verifier.yaml`; `templates.py` (2 rosters); test. Triggers lean on the fix/validation transitions (e.g. `fix_proposed`/`validating` — **verify** they exist for those room types).
- **P3.7-content-4 — `mentor`** (explains / onboards / keeps free chat productive — a non-analytical companion role) → `free_chat`, `idea_validation`. *Where*: `config/agents/mentor.yaml`; `templates.py` (2 rosters); test.

### Skills (P3.7-content-5..7)

Each: new `config/skills/<category>/<id>.md` (frozen ADR-009 frontmatter + loader — `load_skills` `rglob`s recursively so new subdirs are discovered). **Common acceptance bar**: **filename stem == `id`** (ADR-009 D8 — loader enforces); non-empty body; validates against the frozen `Skill` schema; discriminating test asserts the skill **matches** (existing skills decision path) for a room/agent/state it declares and is **rejected** (`rejection_reason != "matched"`) for a non-declared room type. **Common out-of-scope**: changing the skills decision logic or schema.

- **P3.7-content-5 — business skill** (`config/skills/business/<id>.md`, `category: business`) → `idea_validation` (decision-framing / validation rubric). Fills the only empty `Skill.category` literal.
- **P3.7-content-6 — engineering skill** (`config/skills/engineering/<id>.md`) → `code_review` (review checklist). Rounds out the engineering domain's room coverage.
- **P3.7-content-7 — general skill** (`config/skills/general/<id>.md`) → `free_chat` (+ broadly applicable; e.g. facilitation/communication norms). Gives `free_chat` skill coverage.

### Local connectors (P3.7-content-8..9)

Each: new `servers:` entry in `config/mcp_servers.yaml` — a **purely-local** stdio server with a **partial** code-classified tool allowlist (ADR-027 D3 pre-classify-allowlist, reused). **Common acceptance bar** (mirror `tests/mcp/test_gating.py`): a classified read tool (`reversibility: 10`) resolves to AUTO_EXECUTE; a classified write/mutation tool (low rev) → HARD_CONFIRM (tier discrimination); a tool the server exposes **but not listed** → `UnknownToolError` → refused (discovery≠permission, HR#3). Config validates against the frozen connector schema. Tests gate **config/classification**, not a live `npx` subprocess. **Common out-of-scope**: remote transport (P3.7-remote); any product-side ADR-028 D3 deferred *tool* class.

- **P3.7-content-8 — `memory` connector** (lean: `@modelcontextprotocol/server-memory` — local knowledge-graph, no network). Classify e.g. `read_graph`/`search_nodes` (rev 10 → AUTO) + a `create_*` (low rev → HARD_CONFIRM); leave ≥1 exposed tool unlisted (→ refused).
- **P3.7-content-9 — `sqlite` connector** (lean: a local-file SQLite stdio server). Classify e.g. `read_query`/`list_tables` (rev 10 → AUTO) + `write_query`/`create_table` (low rev → HARD_CONFIRM); leave ≥1 unlisted (→ refused).

> **Note (not §b deferred-tools):** a connector's `write_query`/`create_*` are **MCP connector tools** routed through ADR-027's pre-classify-allowlist (exactly like the existing filesystem `write_file`/`move_file` → HARD_CONFIRM). They are **not** the product-side ADR-028 D3 deferred local *tools* (`*_edit`/`send_email`/`web_*`/`run_*`/`git_*` in `config/tools.yaml`). No new trust surface — the gate handles them as today.

### Local plugins (P3.7-content-10..11)

Each: new `plugins/<id>/` Posture-A bundle (`plugin.yaml` manifest + contributions), mirroring `plugins/demo/`. **Common acceptance bar** (mirror `tests/plugins/test_merge.py` + `test_failure_modes.py`): the plugin **loads + merges** (its contributed role/skill/tool/server appears in the merged registries); a host-pre-classified tool gates to its expected tier while a plugin-classify-only tool **caps to rev 0 / HARD_CONFIRM** (cannot self-raise above host cap, ADR-029 D5); and ≥1 **fail-closed** path is exercised for the new bundle (bad-manifest or name-collision → refused, host unchanged). **Common out-of-scope**: Posture-B subprocess isolation; fetched/registry plugins (P3.7-remote).

- **P3.7-content-10 — plugin bundle #2** (role + skill + tool; demonstrate both the host-pre-classify and plugin-classify-only tool paths, as `demo` does). *Where*: `plugins/<id>/{plugin.yaml,agents/,skills/,tools.yaml,tools_impl.py}`; `config/tools.yaml` **only** if adding a host-authoritative classification (host file authoritative per ADR-029 D5); test.
- **P3.7-content-11 — plugin bundle #3** (a **different contribution mix** — e.g. contributes an `mcp_servers` reference + a skill, fewer/zero tool_impls — to exercise a second merge shape). *Where*: `plugins/<id>/`; test (include its fail-closed path).

## 3. Execution order

Per brief §Parallelism: **single-junior serial** (additive content; no within-slice parallelism). The slice is larger now — junior should work it in **4 clean batches**, each batch's atomics committed individually:

1. **Batch A — agents (1→2→3→4)**: all four edit the shared `rooms/templates.py` roster lists, so serial avoids merge contention. Land agents first so `code_review`/`bug_fix` rosters are complete before downstream work.

**One atomic = one commit**, subject named after the atomic (`P3.7-content-N: <subject>`, per RC-17). Batches may land as separate pushes if junior context requires — each commit is independently reviewable.
