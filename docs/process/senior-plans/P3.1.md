### 2b. Per-state activation — the design fork (read carefully; it's the non-obvious part)

`applies_to.room_states` is a **flat per-agent list shared across all of an agent's room_types** (ADR-012 D3). Narrowing a *shared* agent's `room_states` would couple/regress the rooms it serves (esp. Research, which must stay unchanged). So per-state activation uses **two levers**, chosen to be backward-compat-safe:

1. **Room-level (which agents load):** `declared_agents` (2a) + reconciled `applies_to.room_types`:
   - `prober` → `[research, bug_fix, idea_validation]` (was default `["*"]`); `skeptic` → `[research, bug_fix, code_review, idea_validation]` (was default `["*"]`). Both **keep `research`** (backward-compat) and now exclude the rooms they don't serve. `operator` (`[research, bug_fix, code_review, idea_validation]`) and `divergence_mapper` (`[research, idea_validation]`) are **already correct** — no change. `logger` stays `["*"]` (universal recorder). `facilitator` is `[free_chat]` (new).
2. **State-level (when an agent speaks):** `speaking_triggers` (`StateChangeTrigger`, evaluated by `should_agent_speak` — code). **Key safety property:** every scaffold state name (`reproduced, diagnosed, fix_proposed, reviewing, changes_requested, approved, pitching, validating, decided, active`) is **unique to its room** — none occurs in Research — so a `state_change → <scaffold_state>` trigger fires **only** in that room. Adding these to shared agents is therefore **backward-compat-safe** (Research never enters those states). The per-(room, state) speak matrix:

| Room → state | Agent(s) that speak (via `state_change` trigger, added) |
|---|---|
| `bug_fix` → reproduced | prober |
| `bug_fix` → diagnosed | skeptic |
| `bug_fix` → fix_proposed | skeptic, operator |
| `code_review` → reviewing | skeptic, operator |
| `code_review` → changes_requested | skeptic |
| `idea_validation` → pitching | prober |
| `idea_validation` → validating | skeptic, divergence_mapper, operator |
| `free_chat` → active | facilitator |

   These are **additive** to each agent's existing triggers (skeptic keeps its regex + `hypothesis`; operator keeps `user_input`/`hypothesis`; prober keeps its `\?` regex; divergence_mapper has **no** existing triggers, so the `state_change→validating` is its *only* activator). The `facilitator` (ADR-024) also gates coarsely via `applies_to.room_states: [setup, active]` (unshared → safe to narrow) + an `event_type: user_input` trigger.

### 2b-net. Net per-(room, state) activation (Y1-α precision — the **full** picture, not just the new layer)

The §2b table lists only the *added* `state_change` triggers. But `should_agent_speak` evaluates against the turn's `current_event` (`dispatch.py:90`), and the reused agents' **existing** `event_type`/`regex` triggers also fire in a scaffold room once the agent is in-roster. The **net** activation per transition = (existing triggers firing on the *triggering event*) ∪ (`state_change` triggers firing on the appended `state_transition` event). Mechanics: each transition produces two consecutive `current_event`s — the **triggering event** (e.g. `HYPOTHESIS`) on which `event_type`/`regex` triggers match, then the **`state_transition` event** (`new_state=X`, `content=""`) on which only `state_change→X` matches (`content=""` matches no regex; `type=state_transition` matches no `event_type`). "Structural" below = fires deterministically from the event *type* (not content-dependent):

| Room → state (triggering event) | existing-trigger firings (structural) | `state_change→` | **NET structural activation** |
|---|---|---|---|
| **bug_fix** setup→reproduced (`OBSERVATION`) | — | prober | **prober** |
| bug_fix reproduced→diagnosed (`HYPOTHESIS`) | skeptic, operator (`hypothesis`) | skeptic | **skeptic, operator** |
| bug_fix diagnosed→fix_proposed (`DECISION`) | — | skeptic, operator | **skeptic, operator** |
| bug_fix fix_proposed→closed (`SUMMARY_SNAPSHOT`) | — | — | **— (logger in-roster but quiet; `→closed` deferred P3.7)** |
| **code_review** setup→reviewing (`OBSERVATION`) | — | skeptic, operator | **skeptic, operator** |
| code_review reviewing→changes_requested (`REJECTION`) | — | skeptic | **skeptic** |
| code_review changes_requested→approved (`DECISION`) | — | — | **— (quiet)** |
| code_review approved→closed (`SUMMARY_SNAPSHOT`) | — | — | **—** |
| **idea_validation** setup→pitching (`UTTERANCE`) | — | prober | **prober** |
| idea_validation pitching→validating (`HYPOTHESIS`) | skeptic, operator (`hypothesis`) | skeptic, divergence_mapper, operator | **skeptic, operator, divergence_mapper** |
| idea_validation validating→decided (`DECISION`) | — | — | **— (quiet)** |
| idea_validation decided→closed (`SUMMARY_SNAPSHOT`) | — | — | **—** |
| **free_chat** setup→active (`UTTERANCE`) | — | facilitator | **facilitator** |
| free_chat active→closed (`SUMMARY_SNAPSHOT`) | — | — | **—** |

**The §2b correction the net surfaces:** at the two `HYPOTHESIS`-driven transitions (`bug_fix→diagnosed`, `idea_validation→validating`), **operator co-fires** via its existing `hypothesis` trigger — so the net adds `operator` to `bug_fix→diagnosed` (the §2b table had skeptic only). All other transition triggers (`OBSERVATION`/`DECISION`/`REJECTION`/`UTTERANCE`/`SUMMARY_SNAPSHOT`) match **no** existing `event_type` trigger, so the net there equals the `state_change` layer.

**Off-transition / content-dependent firings (verified no *unintended* over-activation):**
- **operator on any `USER_INPUT`** (existing `user_input` trigger) — fires across its 3 analytical rooms whenever the user speaks; **intended** (operator acts on user requests; its Research-era role).
- **skeptic/operator on an ad-hoc `HYPOTHESIS`** even in `code_review` (which has no `HYPOTHESIS` *arc*) — a hypothesis can still be posted off the transition path; skeptic challenging / operator fetching on it is **role-appropriate**, not unintended. (Directly addresses the routed concern: it does **not** fire on `code_review`'s transition path — only on an ad-hoc hypothesis.)
- **prober `\?` / skeptic `assume|clearly|…` regex** — content-dependent (opportunistic), non-structural; the e2e controls content to keep transitions deterministic.
- **skeptic `state_change→research`** is a **pre-existing no-op** — no RoomType has a state literally named `research` (RESEARCH's states are `setup/exploration/divergence/convergence/snapshot_pending/closed`); it never matches anywhere. Out of P3.1 scope (not introduced here); noted.

**Verdict:** **no unintended over-activation** — every existing-trigger firing in a scaffold room is role-appropriate; the only net change vs §2b is operator co-firing on the two hypothesis transitions (intended). Design unchanged; this is precision completion.

3. **`logger`** stays unchanged (universal `["*"]`; existing `state_change → snapshot_pending` trigger). It is present in every roster as the recorder; scaffold-close logging (a `→ closed` trigger touches Research's shared `closed` state) is **deliberately deferred to P3.7** — not worth a Research-behavior change in a light slice. (Senior fork §5.)

### 2c. The new role — `facilitator` (ADR-024 + `config/agents/facilitator.yaml`, authored)

A light conversational host for `free_chat` (greets, asks open follow-ups, reflects, surfaces threads — non-adversarial, not a dissent role). Activation is code (`should_agent_speak` over `user_input` + `state_change → active`); response is LLM content-gen via `AGENT_RESPONSE` (no new purpose). `applies_to: room_types [free_chat], room_states [setup, active]`. Cheap model (`claude_code_haiku_45`), warm temp (0.7). No new skill (P3.7). Full rationale + alternatives in ADR-024.
