### W-003-1 — RC-16 fix: `_read_plan_frontmatter` reads `origin/main`, not working-tree

- **What**: replace `path.read_text(encoding="utf-8")` in `_read_plan_frontmatter` with a `git show origin/main:<rel_path>` subprocess call. Bug: a session with an uncommitted local plan modification can trigger bogus `workflow advance` state transitions. Fix: read from `origin/main` semantically; the merge IS the publish event.
- **Where**:
  - Modify: `src/orchestrator/workflow/io.py` — `_read_plan_frontmatter` body. Signature unchanged: `(path: Path) -> dict[str, Any] | None`.
  - Extend: `tests/workflow/test_io.py` (or equivalent) — new integration tests with synthetic git repo (working-tree vs `origin/main` divergence).
- **Why**: RC-16 (W-002.5 / PR #11 capture); brief In scope §W-003-1.
- **Acceptance**:
  - Signature `(path: Path) -> dict[str, Any] | None` unchanged. Internal switches to subprocess.
  - Implementation: convert `path` to repo-relative (`path.relative_to(repo_root)`); call `subprocess.run(["git", "show", f"origin/main:{rel_path}"], capture_output=True, text=True, timeout=10)`. On non-zero return code OR `stderr` indicating file-not-found, return `None` (matches existing "no frontmatter" fallback).
  - Frontmatter parse (existing `---` fenced block logic) operates on the subprocess `stdout` instead of `path.read_text()`. The parse logic itself is unchanged.
  - Backwards compat: plans currently on `origin/main` return their content as before (working-tree = origin/main for clean repos). Bug only affects sessions with uncommitted local mods.
  - **Edge case: plan on branch awaiting merge** (push-back #2 in §5). The fix treats "not on origin/main" as "no frontmatter" via fallback. This is correct per brief Architect-settled decision: if the plan isn't on origin/main, the state machine shouldn't advance based on it — the merge IS the publish event. Senior confirms this aligns with ADR-008 D1's gated-transition semantic.
  - **`_has_commit_since` related concern** (predicted self-discovery #1): senior investigates during W-003-1 impl. If `_has_commit_since` has the same working-tree-vs-origin issue, surface in commit body. If fix is mechanical (≤10 LoC), bundle into W-003-1. If larger, surface in §5 as new W-003-1b atomic. Lean: investigate during impl; report findings.
  - Tests (≥3):
    - Synthetic git repo with `senior-plans/SYNTH.md` on `origin/main` containing valid frontmatter (`task_id: SYNTH`); assert `_read_plan_frontmatter` returns the parsed frontmatter.
    - Same repo, locally modify `senior-plans/SYNTH.md` (uncommitted) to remove the `adr` key; assert `_read_plan_frontmatter` returns the **origin/main** content (still has `adr` key), NOT the working-tree content.
    - File doesn't exist on `origin/main` (e.g., new plan only on a branch); assert `_read_plan_frontmatter` returns `None`.
  - All 25+ existing workflow tests remain green. `ruff check` / `ruff format --check` / `mypy --strict` clean.
- **Out of scope**: rewriting `_read_plan_frontmatter`'s public contract; changing fallback path of `_read_adr_status` (which already handles `None` returns).
- **Number**: W-003-1.

### W-003-2 — RC-13 forcing function: `workflow verify-merge-readiness` CLI

- **What**: new `workflow verify-merge-readiness --task-id TASK` CLI subcommand. Checks impl branch has `plan-vs-impl.md` AND `R0-A.md` reviews present with `verdict: clean` frontmatter. Warn-don't-block; exit code 0; structured output.
- **Where**:
  - Modify: `src/orchestrator/workflow/cli.py` — new `cmd_verify_merge_readiness(args)` function + argparse subparser registration in `main()`.
  - Extend: `tests/workflow/test_cli.py` — new test class / functions for the new subcommand.
- **Why**: brief In scope §W-003-2; P1.4 PR #10 merged before reviews ran → state stuck; forcing function prevents recurrence.
- **Acceptance**:
  - CLI invocation: `uv run workflow verify-merge-readiness --task-id TASK_ID`. Returns exit code 0 unconditionally (warn-don't-block per brief Architect-settled decision 2).
  - Implementation:
    1. Locate `docs/process/reviews/<TASK_ID>/plan-vs-impl.md` AND `docs/process/reviews/<TASK_ID>/R0-A.md`.
    2. For each, check existence + parse frontmatter via existing `parse_verdict` helper.
    3. Build structured output:
       - If both reviews present + both `verdict: clean` → print "✓ TASK_ID merge-ready" + exit 0.
       - If a review file is missing → print warning naming which file + "merge not ready" + exit 0.
       - If a review has non-clean verdict → print warning naming the file + the verdict value + "merge not ready" + exit 0.
  - Output shape: structured single-line summary + 1-3 detail lines per warning. Matches existing `workflow status` output style (push-back #3 lean accepted).
  - Tests (≥5):
    - Happy path: both reviews exist, both clean → exit 0 + "merge-ready" message.
    - Missing plan-vs-impl.md → exit 0 + warning naming the missing file.
    - Missing R0-A.md → exit 0 + warning naming the missing file.
    - plan-vs-impl.md has `verdict: blocking` → exit 0 + warning naming non-clean verdict.
    - R0-A.md has `verdict: needs_architect` → exit 0 + warning naming non-clean verdict.
  - **§4 exception payload (light)**: malformed frontmatter (parse fails) → graceful — print "could not parse verdict from FILE" + treat as non-ready; exit 0.
- **Out of scope**: GitHub Actions integration (push-back #1 alternative; deferred to W-004+ if a real need surfaces); PR-template Q3 checkbox (deferred to architect-partner-direct doc work); auto-block-on-non-ready (warn-don't-block per Architect-settled decision 2).
- **Number**: W-003-2.

- **Where**:
  - Modify: `src/orchestrator/workflow/cli.py` — extend `cmd_verify_workspace(args)` body. The existing function already runs `git fetch origin` + `git status --short`; extension adds the state-file divergence check.

- **Why**: brief In scope §W-003-3; RC-7 (stale-workspace-as-truth) predecessor; W-002 §5 push-back #2 explicit deferral.
- **Acceptance**:
  - Existing `cmd_verify_workspace` git-status check preserved.
  - New behavior: for each `.workflow/*.yaml` file locally, run `git show origin/main:.workflow/<task-id>.yaml`. If subprocess returns content AND differs from local content → print warning naming the task + a short summary (e.g., "state field differs: local=awaiting_junior_impl vs origin/main=awaiting_senior_plan"). If subprocess returns non-zero (file not on origin/main — new local task) → skip silently (legitimate new-task case).
  - Output shape: structured, matches `workflow status` style. One warning line per diverged task; summary line at top if any divergences.
  - Exit code 0 unconditionally (warn-don't-block — brief Architect-settled decision 2).

  - Tests (≥4):

    - Same repo, locally modify state field; assert divergence warning printed naming the task + the field.
    - New local state file not yet on origin/main → skipped silently (no warning).
    - Both modes work together: clean state file + diverged state file → only diverged one warned.
  - All existing `verify-workspace` tests remain green (back-compat).
