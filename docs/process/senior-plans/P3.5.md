# P3.5 senior plan — Plugin system (manifest + loader + code-trust model)

## 1. Context

P3.5 is the **Wave-2 backend-track closer** (roadmap §4/§5): a `plugins/` package — a **manifest schema** + a **loader** that discovers / validates / registers a **distribution unit** bundling **roles + skills + tool-classifications + executable tool code + MCP-server config** — merging each contribution into the **existing** agents/skills/tools/local-tools/MCP registries at the existing `_build_context` merge point (`api/app.py:142–158`), **reusing the four existing loaders** (`load_agents`, `load_skills`, `load_tools_config`, the MCP config/adapter). It is the *convergence* of P3.1 (roles/skills) + P3.4 (MCP config), not a new leaf.

The design is inscribed in **ADR-029** (Proposed — read it first; this plan implements it). The **constitutional spine + trust boundary** (gate-unbypassed plugin tools; allowlist-unbypassed plugin servers; load-is-code-not-LLM; no-new-`LLMPurpose`; fail-closed loading; opt-in / manifest-validated / credential-safe third-party bundle) are **non-negotiable** (ADR-029 HR#1–5).

**The architect ruled `admit-plugin-code-now`** (ADR-029 D4), overriding the brief's declarations-only lean: a plugin may carry **third-party executable tool code** (Python, *loaded = runs*). This is the project's largest security surface. **The code-trust / isolation posture is RULED: Posture A (in-process, operator-curation = trust, A-now-B-later)** — with the full exposure inscribed (L1 no-isolation/zero-env, L1b import-time-ungated, L2 D5-bound-voided/server-wide DoS). See §5 + `architect-routing-on-plan.md`. The plan + ADR-029 D2 enforce the **security-load-bearing ordering** (collision-check before code import).

**Substrate verified `origin/main`** (claims-with-cites per pre-investigation discipline):
- Two distinct tool registries: `tools: dict[str, ToolMeta]` (gate classification, `app.py:145,154`) and `local_tools: dict[str, LocalToolFn]` (executor impls, `app.py:158`). Verified `tools/executor.py:308` `local_tools.get(tool_name)` → `impl(params)` wrapped fail-closed `:326–331`.
- `build_local_tool_registry(sandbox_root)` (`tools/local.py:131`) is hard-coded to 3 builtins — **no third-party-impl loader exists** (the only genuinely-new mechanism — P3.5-4).
- All four loaders' models are frozen + `extra="forbid"` (Agent `agents/schema.py:95`; Skill `skills/schema.py:43`; ToolMeta `autonomy/scoring.py:36`; MCPServersConfig `mcp/config.py:63`) — verified.
- The loaders take a directory/path arg (`load_agents(directory, *, models)`, `load_skills(directory)`, `load_tools_config(path)`, `load_mcp_servers_config(path)`) → reusable pointed at plugin subpaths.
- ADR-027 D5 pre-committed the `mcp_servers` plugin-block shape; ADR-028 D6 + `tests/tools/test_constitution.py` is the constitution-test template.

## 2. Tasks (atomic)

### P3.5-1 — Manifest schema (`plugins/schema.py`)
- **What:** the `PluginManifest` Pydantic model (frozen, `extra="forbid"`) per ADR-029 D1 — `schema_version`, `id`, `name`, `version`, `contributions{roles, skills, tools, tool_impls, mcp_servers}`, `dependencies{model_ids, room_types, min_host_contract}`; the `tool_impls` value shape `"<module>:<callable>"`.
- **Where:** new `src/orchestrator/plugins/schema.py` + `plugins/__init__.py`.
- **Why:** ADR-029 D1; inscribe-before-producer (brief Constraints — P3.7 binds this).
- **Acceptance:** frozen + `extra="forbid"` (an unknown manifest key → `ValidationError`); `schema_version` present + validated; all `contributions`/`dependencies` fields optional with safe empty defaults; mirrors the existing loaders' model style (`mcp/config.py`).
- **Out of scope:** the loader; any I/O. Pure schema.

### P3.5-2 — Discover + validate + dependency-check (`plugins/loader.py`, part 1)
- **What:** `load_plugins(plugins_dir, *, models, host_room_types, host_contract_version, sandbox_root)` discovery + manifest-validation + dependency-check half (ADR-029 D2 steps 1–2, D6) — iterate subdirs, parse+validate each `plugin.yaml`, check `dependencies` against `models`/`host_room_types`/contract; **fail-closed + per-plugin isolation** (a bad/unparseable manifest, unknown `schema_version`, or unmet dependency → refuse THAT plugin, log, continue; never crash bootstrap, never half-register).
- **Where:** new `src/orchestrator/plugins/loader.py`.
- **Why:** ADR-029 D2 (steps 1–2) + D6 + HR#5.
- **Acceptance:** unknown `schema_version` → refused; unmet `model_id`/`room_type` dependency → refused; one bad plugin does not block a sibling valid plugin; returns a typed partial result for the merge half (P3.5-3).
- **Out of scope:** the four-loader reuse + merge (P3.5-3); code loading (P3.5-4).

### P3.5-3 — Reuse the four loaders + **collision-check ALL names (incl. `tool_impls`) BEFORE code** + reversibility-cap → per-plugin intermediate (`plugins/loader.py`, part 2)
- **What:** for each valid plugin, in the **security-load-bearing order** (ADR-029 D2; R0-B R1): (i) **collision-check ALL declared contribution names from the manifest — `roles`/`skills`/`tools`/`tool_impls`/`mcp_servers` — against host registries + cross-plugin, fail-closed on any clash** (refuse that plugin); (ii) call the **existing** `load_agents`/`load_skills`/`load_tools_config`/`build_mcp_tool_registry_and_sessions_from_config` pointed at the plugin's subpaths (non-code surfaces; pure data); (iii) **cap plugin-asserted reversibility** (host-authoritative-or-default-0, ADR-029 D5 — never a raise; an unclassified plugin tool → default 0 → `HARD_CONFIRM`); (iv) **accumulate into a per-plugin intermediate `PluginLoadResult` — do NOT eagerly merge into host registries** (the merge is atomic at P3.5-5; HR#5 / R0-B Y4). The `tool_impls` **name** collision-check happens HERE (from the manifest, no import) so it gates the import in P3.5-4.
- **Where:** `src/orchestrator/plugins/loader.py`.
- **Why:** ADR-029 D2 (steps 3–7 ordering), D5 (advisory-cap + default-0), D6 (collision incl. `tool_impls`); brief Constraints (reuse, don't reimplement).
- **Acceptance:** no loader reimplemented (greps confirm `plugins/` calls the existing loaders); a colliding `role/skill/tool/server` name → plugin refused, host registry unchanged; **a plugin `tool_impl` named after a host builtin (`read_file`) → refused, host impl unchanged (the shadow-bypass test, R0-A Y1)**; a plugin claiming `rev=10` on an unclassified tool → capped to default-0 → `HARD_CONFIRM` (gate tier unchanged — a test asserts it); MCP block merges via the ADR-027 D5 path; **P3.5-3 does not mutate host registries (intermediate only)**.
- **Out of scope:** executable code loading/import (P3.5-4); the `_build_context` merge (P3.5-5).

### P3.5-4 — ⭐ Executable tool-code loading, Posture A in-process (`plugins/code.py`) — import ONLY after P3.5-3 collision-check
- **What:** the **new** mechanism to load a plugin's `tool_impls` into the executor's `local_tools` registry, **Posture A (ARCHITECT-ACCEPTED — in-process import, A-now-B-later; ADR-029 D4)**. `importlib` the plugin module, resolve `<module>:<callable>`, validate it is callable (load-time), register as a `LocalToolFn` in the per-plugin intermediate; **per-plugin load isolation** (import error → refuse that plugin, never crash bootstrap). **The import runs ONLY after P3.5-3 cleared validation + the `tool_impls` collision-check** (ADR-029 D2 step 5; R0-B R1 — import-time arbitrary code never runs before a refusal). Per-call fail-closed is inherited from the executor (`_execute_local_call` try/except → `TOOL_FAILED`). The exposure (L1 no isolation / zero-env, L1b import-time-ungated, L2 D5-bound-voided) is the Accepted posture — no in-process timeout/kill is attempted (impossible; it is documented, not engineered).
- **Where:** new `src/orchestrator/plugins/code.py` (+ loader wiring).
- **Why:** ADR-029 D4 (Posture A, the admit-code surface + the inscribed exposure).
- **Acceptance:** a valid plugin executable tool loads (post-collision-check) → registered in `local_tools` → **gates** via its host-side classification (P3.5-7) → **executes** via the existing `tools/executor.py::_execute_local_call` (**no executor edit**) → `TOOL_RESULT`; a **broken** variant (import error / raises) → **fail-closed** (refused at load / `TOOL_FAILED` at call, never crashes); import happens strictly after P3.5-3's checks (a test: a collision-refused plugin's module is never imported).
- **Out of scope:** Posture B / subprocess isolation (P3.7 untrusted provenance); any in-process timeout/kill (impossible — L2); remote-provenance code.

### P3.5-5 — Wire the plugin aggregation pass into `_build_context` (atomic per-plugin merge)
- **What:** add **one** aggregation pass in `api/app.py::_build_context` after the four loaders: call `load_plugins(...)`, then **atomically merge each fully-validated per-plugin `PluginLoadResult`** into `agents`/`skills`/`tools`/`local_tools`/`mcp_sessions` before `AppContext` construction. **A plugin that failed any stage (validate/collision/load/import) is never merged — host registries are never mutated by a partially-loaded plugin (HR#5 / R0-B Y4).** The gate, the executor, and the MCP client are **untouched** (empty-gate-diff + empty-executor-diff invariant).
- **Where:** `src/orchestrator/api/app.py` (`_build_context`, ~line 158).
- **Why:** ADR-029 D2 (merge point + atomic merge step 7); brief Constraints (feed the registries, don't change the gate/executor/MCP-client).
- **Acceptance:** `process_tool_calls` / `score` / `decide_tier` / `emit_gate_decision` / the executor / the MCP client diff is **empty** (a grep/diff check); a fully-valid plugin's role/skill/tool/server/impl appears in the respective registry post-bootstrap; **a plugin failing mid-load leaves NO trace in any host registry (atomic-merge test, R0-B Y4)**; absent `plugins/` dir → no-op (clean boot).
- **Out of scope:** any gate/executor/MCP-client logic change.

### P3.5-6 — `plugins/` constitution test (`tests/plugins/test_constitution.py`)
- **What:** the ADR-027 D2 / ADR-028 D6 analog — AST-assert `plugins/` does not reference `decide_tier`/`emit_gate_decision`/`score`/`gate`/`select_model_and_provider`, makes no `llm/` provider call, and the frozen `LLMPurpose` set is unchanged (no new purpose).
- **Where:** new `tests/plugins/test_constitution.py` (model on `tests/tools/test_constitution.py`).
- **Why:** ADR-029 D3 / HR#3–4; test-coverage-standard §6.
- **Acceptance:** the four/five assertions are real (not vacuous — each names the forbidden symbol set + asserts absence); passes on the P3.5 impl.
- **Out of scope:** behavioral tests (P3.5-8).

### P3.5-7 — The ONE demo plugin (`plugins/demo/`) — DISTINCT ids + host-side classification
- **What:** one bundle exercising **all five surfaces** (ADR-029 D7) with **distinctly-named content (NOT core re-exports — R0-A Y3 / D6 fail-closed-on-collision)**: `plugin.yaml` + a `demo_facilitator` role (modeled on `config/agents/facilitator.yaml` shape, distinct id) + a `demo-research` skill (distinct id) + the ADR-027 filesystem `mcp_servers` block + a tool-classification + **one executable tool** (a trivial pure/no-I/O/deterministic fn, e.g. `word_count`). **Plus a host-side `config/tools.yaml` classification entry** for the demo tool so it clears default-0 and **AUTO_EXECUTEs** (R0-B Y2 / ADR-029 D5/D7) — without it the tool defaults to `HARD_CONFIRM`.
- **Where:** new `plugins/demo/{plugin.yaml, agents/, skills/, tools.yaml, mcp_servers.yaml, <impl module>}` + a host-side `config/tools.yaml` entry for the demo tool.
- **Why:** ADR-029 D7; brief Scope (one demo, all surfaces + admit-code); R0-A Y3 (distinct ids); R0-B Y2 (host classification).
- **Acceptance:** the demo loads end-to-end with **distinct ids** (no core-name collision → not refused); all five contributions register; the executable tool — given its host-side classification — **gates → AUTO_EXECUTEs → returns a result**; a broken-variant (import error / raise) fails closed (covered in P3.5-8).
- **Out of scope:** many plugins (P3.7); a core-reexport carve-out (rejected — adds policy surface to a loud MVP).

### P3.5-8 — Cross-module + failure-mode + boundary tests (`tests/plugins/`)
- **What:** per test-coverage-standard §1/§3/§4/§6 (brief table) — §1 cross-module (load→merge→a plugin tool gates via `process_tool_calls`; an **unclassified** plugin tool defaults to 0 → `HARD_CONFIRM` → does NOT auto-execute; a host-classified plugin tool AUTO_EXECUTEs; a plugin server connects only via the allowlist; a plugin role activates via code `should_agent_speak`; a plugin skill loads as content); §3 failure modes (bad/unparseable manifest, unknown `schema_version`, missing dependency, **name collision incl. `tool_impls→local_tools` shadow**, broken executable code → all fail-closed; **partial bundle never half-registers — atomic merge**; **a collision-refused plugin's module is never imported**); §4 boundary (manifest frozen/`extra="forbid"`; reversibility advisory-cap default-0; the consent/opt-in boundary).
- **Where:** new `tests/plugins/test_loader.py`, `test_merge.py`, `test_failure_modes.py` (split as natural).
- **Why:** brief test-coverage table; ADR-029 HR#5 + D2 (ordering/atomic-merge) + D4–D6; R0-A Y1 + R0-B Y2/Y4.
- **Acceptance:** every fail-closed case asserts refusal + host-registry-unmodified; the **shadow test** (`tool_impl` named `read_file` → refused, host impl unchanged); the **default-0 test** (unclassified plugin tool over-claiming rev=10 → gate tier `HARD_CONFIRM`, unchanged); the **atomic-merge test** (a plugin failing mid-load → zero trace in host registries); the **import-ordering test** (collision-refused plugin not imported); admit-code fail-closed (import error / raise) covered.
- **Out of scope:** load/perf testing (out of MVP).

**⭐ (1) D4 code-trust / isolation posture — RULED: Posture A confirmed (in-process, operator-curation = trust, A-now-B-later; B reserved for P3.7 untrusted remote provenance).** The hinge resolved to **TRUSTED-tier-via-operator-curation**. The Accept is informed by the **full exposure now inscribed in ADR-029 D4** (the dual-lens + R0-A surfaced these; the architect Accepts the *real* surface): **L1** no technical isolation + **zero credential/env protection** (in-process plugin reads all host `os.environ`; ADR-027 D4 defenses are MCP-subprocess-only); **L1b** import-time code is **ungated by construction** (runs at boot before any gate exists; the D2 ordering ensures it runs only after the validate+collision gauntlet); **L2** Posture A **VOIDS (not "relaxes")** ADR-028 D5's absolute single-writer liveness bound for the plugin-local path — **server-wide blast radius**; one buggy (not even malicious) curated tool = a server-wide DoS (no cap — excludes local; no kill — in-process). The *"as trusted as a file in `src/`"* analogy is **retired** (R0-B Y1 / R0-A §3 — a category error on review-path: `src/` is review-gated, `plugins/` is operator-curated-third-party; Posture A **relocates** the trust gate from commit-time review to deploy-time curation). **(2) R0-B R1 🔴 (D2 step ordering) — RULED α.** ADR-029 D2 amended to **validate → collision-check → load non-code surfaces → load code → cap → atomic merge**; import-time code execution runs **only after** all validation + collision checks (P3.5-3 → P3.5-4). The fail-closed gauntlet is never pierced by an early import.

**(3) R0-A Y1 (`tool_impls → local_tools` shadow-bypass) — RULED α.** The collision namespace now covers **`tool_impls`** (D6 + P3.5-3): a plugin tool_impl named after a host builtin (`read_file`) → **refused**, host sandbox impl unchanged — closes the gate/sandbox-bypass + the HR#5 silent-degrade.

**(4) R0-B Y2 (reversibility default-0 semantics) — RULED α.** ADR-029 D5 clarified: an **unclassified** plugin tool defaults to **0 → `HARD_CONFIRM` → not AUTO**; the plugin's claimed value is never used as the value (only capped against a host classification). **(5) R0-B Y4 (atomic merge) — RULED α.** ADR-029 D2 step 7 + P3.5-3/-5: contributions accumulate into a **per-plugin intermediate**; the merge into host registries is **atomic per-plugin**; any-stage failure discards the whole intermediate — host registries never mutated by a partial plugin (HR#5).
