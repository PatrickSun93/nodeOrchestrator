## 1. Context

P2.2 is the **cross-room hypothesis matcher** — promotion rule (a): detect when the same claim (same canonical tag-set) is independently recorded across ≥N distinct rooms, and flip `Hypothesis.candidate_for_promotion = True` on those rows so the user is *shown* cross-room-corroborated candidates to (manually) promote. **Advisory only** — the matcher never promotes; `promote_hypothesis` (ADR-016) stays the sole, user-confirm promotion path. This is the first cross-room *intelligence* surface, and the first piece of code that makes a cross-room determination.

It is the matcher resequenced out of the original P2.1 (B3 decision): the **tag registry shipped first as P2.1 / ADR-018 (closed, merged on `main`)**, and the matcher is its consumer. I drafted this plan + a fresh ADR-017 **rebased on the merged registry, verified against `origin/main`** — not the superseded pre-registry matcher draft on `claude/P2.2-plan`. The rebase removed an entire atomic and changed the grouping internals:

- **No schema/migration atomic.** `Hypothesis.topic_tags` + its column + the `_ensure_hypothesis_topic_tags` ALTER are already on `main` (ADR-018). Verified `schema.py:94`, `store.py`. The old plan's schema atomic is **dropped** — a contributor writing an `ALTER TABLE` here has misread the rebase.
- **Reuse `normalize_tag`, not ad-hoc `.lower()`** — the central rebase point. The grouping key is `frozenset(normalize_tag(t) for t in topic_tags)` using the registry's function, so the matcher's canonical form equals the vocabulary the tags were stored under. Verified `tags.py:18` (`strip→lower→re.sub(r"\s+","-")`).
- **Normalize at read** (the one genuinely new decision — push-back #1): re-normalize each stored tag at match-time, mirroring lookup's both-sides (ADR-018 D7 / Y1→α).

Everything else (predicate, distinct-room threshold, advisory orthogonality, determinism/idempotency/monotonicity, reader, new-ADR-vs-amend) carries from the architect-steered old design — see ADR-017 + §5. The matcher activates `candidate_for_promotion` + `idx_hypothesis_status_candidate` (shipped unused since ADR-016; verified `store.py:41,48`).

### P2.2-2 — `run_matcher` (the matcher)

- **What**: `src/orchestrator/memory/matcher.py` — `run_matcher(conn, *, min_rooms=2) -> MatcherResult`. Pure code, no LLM.
- **Where**: new file `src/orchestrator/memory/matcher.py`. `from orchestrator.memory.tags import normalize_tag`; reuse `store._row_to_hypothesis` patterns / direct SQL on the `hypothesis` table.
- **Why**: ADR-017 D1-D5.
- **Acceptance criteria**:
  1. Scans only `status == 'pending'` rows.
  2. **Grouping key = `frozenset(normalize_tag(t) for t in json.loads(row["topic_tags"]))`** — reuses `normalize_tag` (NOT ad-hoc `.lower()`); **normalize-at-read** (re-normalizes stored tags, push-back #1). Empty canonical set excluded (never grouped/flagged).
  3. **Distinct-room threshold**: flag a group iff it spans ≥ `min_rooms` distinct `room_id`s (count distinct rooms, not rows). `min_rooms` default 2.
  4. **Write**: `UPDATE hypothesis SET candidate_for_promotion = 1 WHERE id IN (...) AND status = 'pending'` (defensive PENDING guard).
  5. **Determinism** (Principle 11): flagged id-set is a pure function of `{(id, room_id, canonical-tagset, status)}` — order-independent (set ops). Sort by `id` only for stable `MatcherResult` + UPDATE id-list. Test asserts flag-set stable across shuffled input (correctness-by-construction, not the sort).
  6. **Idempotency**: second run flips nothing further (`rows_newly_flagged == 0`).
  7. **Monotonic**: only `False → True`; never clears a flag.
  8. `min_rooms < 1` raises `ValueError`.
  9. Returns frozen `MatcherResult(groups_inspected: int, rows_newly_flagged: int)` — no promotion authority (push-back #3).
  10. The matcher's **only** write is the flag UPDATE; it does NOT call `promote_hypothesis`, insert into `verified_knowledge`, or call `event_store.append` (asserted in P2.2-4).
  11. **Untagged-across-rooms → zero-flagged (A → α; the dominant early-life case)**: a unit test records ≥ `min_rooms` PENDING hypotheses across ≥ `min_rooms` **distinct rooms**, all with `topic_tags=[]` (empty canonical set), then asserts `run_matcher` flags **zero** rows and `list_promotion_candidates` returns empty. This guards the empty-set exclusion (AC#2) — the matcher is "dormant-until-fed" and most rows are untagged until an auto-tagging producer ships, so a regression here would flag *every* untagged hypothesis across rooms (false-positive flood in the common case). No `src/` change — this test proves the exclusion the impl already specifies.
- **Out of scope**: Jaccard/≥K predicates; un-flagging; `cluster_id`; auto-run-on-record (forward hooks — ADR-017).

### P2.2-4 — e2e Scenario Y + constitutional orthogonality guard + handoff + landing

- **What**: the record→match→read→promote e2e; a structural orthogonality guard; `handoff.md` light-touch; landing (5-surface scan + gates).
- **Where**:
  - new test (e.g. `tests/integration/test_p2_2_e2e.py`), modeled on `tests/integration/test_p2_1_e2e.py:47` (`_make_store` / `_make_room` helpers).
  - `tests/memory/test_constitution.py` — confirm the no-LLM rglob auto-covers `matcher.py` (no new no-LLM test). **Add** a structural advisory-orthogonality guard that checks **code, not comments/docstrings** (B → α — must NOT be a whole-file substring scan; that would trip on the matcher's own orthogonality docstring and incentivize deleting it — the RC-23-family whole-file-substring fragility). Implement as a real **call/import AST check**: `ast.parse(matcher.py source)` and walk it to assert (a) no `import`/`from` of `promotion` / `promote_hypothesis`; (b) no `Call`/`Attribute` node named `promote_hypothesis` or `append` (e.g. `event_store.append` / `append_in_transaction`); (c) no `verified_knowledge` INSERT in a string-literal SQL node (inspect `ast.Constant` string values for `INSERT INTO verified_knowledge`, so comments are excluded). At minimum, strip comments + docstrings before any substring scan. The matcher's orthogonality docstring is **intentional and must survive the guard** (ADR-017 records this). (Widening the audit to the existing substring-scan constitutional tests is RC-24 — a retro candidate, NOT bundled into this product slice.)
  - `handoff.md` §4.5 — rule (a) matcher materialized; `candidate_for_promotion` now written by `run_matcher`. §7-P1.2-stale fix **NOT** bundled.
- **Why**: test-coverage-standard §1 (cross-module: record → match → read → promote, source ≠ sink) + ADR-016 D10 (no-auto-promote) + ADR-017 D5.
- **Acceptance criteria** (Scenario Y):
  1. ≥3 Research rooms. Record via `record_hypothesis(topic_tags=...)`:
     - **Cluster (cross-room)**: room1 `["LLM Cost"]`, room2 `["llm cost"]` — **different surface forms that normalize to the same canonical `{llm-cost}`** (proves the `normalize_tag` reuse — the payoff).
     - **Singleton**: room3 `["ml-ops"]` — 1 room.
     - **Same-room dup**: room1 has a second hypothesis with `["solo topic"]` and a third with `["solo-topic"]` (same canonical `{solo-topic}`, both in room1) — a group spanning **1 distinct room**.
     - **Untagged-across-rooms (A → α)**: room2 and room3 each get an additional hypothesis with `topic_tags=[]` (empty canonical set) — the dominant early-life case (untagged rows spanning ≥`min_rooms` rooms).
  2. `run_matcher(conn, min_rooms=2)`.
  3. Assert: the room1+room2 `{llm-cost}` rows flip `candidate_for_promotion=True`; the room3 singleton stays False; the **same-room `{solo-topic}` pair stays False** (proves distinct-room, not distinct-row, counting); the **untagged `[]` rows across room2+room3 stay False** (empty-set exclusion end-to-end — A → α; without this guard a regression would flag every untagged hypothesis across rooms).
  4. `list_promotion_candidates(conn)` surfaces exactly the `{llm-cost}` cluster (room1+room2), `id` ASC.
  5. **Determinism (scan-order independence)**: `run_matcher` on a **shuffled record order** produces the same flagged id-set. The shuffle of record/insert order is the **proxy for SQLite scan-order independence** (R0-A G4 — state this intent explicitly): flag correctness is by-construction via set operations, not the sort-by-id (which is only for stable `MatcherResult` + UPDATE id-list ordering).
  6. **Orthogonality (load-bearing)**: after `run_matcher`, **no VK row exists** and **no promotion `decision` event** was emitted by the matcher; and `promote_hypothesis` works on a **flagged** PENDING row (room1 `{llm-cost}`) **and** an **un-flagged** PENDING row (room3 singleton) — the flag does not gate promotion (ADR-016 D3/D10 hold).
  7. **Idempotency**: a second `run_matcher` returns `rows_newly_flagged == 0` and changes no flags.
  8. `min_rooms < 1` → `ValueError`.
  9. Structural orthogonality guard passes; the no-LLM constitution test stays green (covers `matcher.py`).
  10. Full gates: ruff + mypy --strict + pytest.
- **Out of scope**: agent auto-tagging; UI; the §7 handoff cleanup.

## 5. Where you'd (architect) push back — the five brief push-backs, resolved

All resolved in ADR-017; verified against `origin/main`. Speak up if any is wrong.

- **#1 Normalize-at-read vs trust-stored-canonical → normalize at read.** Stored Hypothesis tags are canonical today (`resolve_tags` at write; pre-registry rows `[]`), so trust-stored would work *now*. I lean **re-normalize at read** (ADR-017 D2): cheap (one `normalize_tag` per stored tag in a small scan), robust against any raw-insert path (test fixtures, future bulk import bypassing `record_hypothesis`), and it is **the same both-sides defense `lookup` chose** (ADR-018 D7 / P2.1 Y1→α) — keeping the two cross-room read paths consistent (a reader shouldn't need to know whether a row went through `resolve_tags`). The deciding argument is the parallel to lookup. **Flag if you'd rather trust-stored for the one-fewer-pass.**
- **#2 Grouping predicate → exact canonical tag-set equality.** Confirmed post-rebase (ADR-017 D3): the only equivalence relation of the candidates → a clean, order-independent partition, so "group spans ≥N rooms" is well-defined. Jaccard/≥K are non-transitive → similarity-graph components + magic threshold. Precision + determinism + simplicity converge. Brittleness acceptable (advisory + fail-safe); relaxation is a forward hook.
- **#3 `MatcherResult` shape → `(groups_inspected, rows_newly_flagged)`.** Minimal, observable, no promotion authority (ADR-017 D5). Confirmed.
- **#4 Reader location + signature → `list_promotion_candidates(conn) -> list[Hypothesis]` in `matcher.py`.** PENDING + flag=True, no scope arg (Hypothesis has no scope — schema.py:87-95), co-located with producer. Confirmed.
- **#5 New ADR-017 vs amend ADR-018 → new ADR-017.** Reserved number; standalone decision; ADR-018 closed/accepted, and amending it risks the RC-23 trap near its status region (same reasoning the registry used for not editing ADR-016 D6). Confirmed.

**No unresolved decision requiring an architect call** beyond ADR-017 accept + the dispatch confirmations (§6). If the architect disagrees with #1 (normalize-at-read) or #2 (predicate), those reopen.
