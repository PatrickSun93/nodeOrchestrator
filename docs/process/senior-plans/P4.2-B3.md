## 1. Context

P4.1 (ADR-033) gave an agent an in-turn investigation loop, but every tool it can chain is **in-process, read-only** (`os.walk`+`re`); ADR-033 carry-forward #6 forbade shelling out, deferring exactly this surface. B3 adds the first **subprocess** tool surface so an agent can run the project's tests + linter and read git history mid-investigation — the flagship *"re-investigate on a failed test"* step (P4-roadmap §7).

The architect ratified all five brief decision points; I have **not** re-litigated them. The plan implements: ship all 5 (D1); the lighter-inline posture reusing the ADR-031 D2 seam + the honest `RB-FS/NET`-class residual (D2); the 4-sub-surface threat model with output-as-untrusted rendered raw + the P4.1 excerpt-filter extension (D3); the existing Posture-B `LocalToolFn` executor placement with the cap generalised (D5); ADR-034 + the ADR-028 D3 amendment. ADR-034 is **drafted on this branch** (senior deliverable); the numbered tasks below are the **junior impl**.

**Key mechanism I verified (load-bearing — read before implementing):** excluding subprocess `TOOL_RESULT`s from `snapshot_excerpt` does **not** blind the acting agent. The re-dispatch loop passes the last result-class event of a pass as the **`current_event`** (LLM user message) of the next pass — a channel distinct from `snapshot_excerpt` (system block). Verified at `api/app.py:449-454` + `agents/dispatch.py:112-123`. The acting agent still gets the raw test output via `current_event`; the exclusion only removes it from the cross-agent system-block steering surface. The **single-call** flagship loop survives (`run_tests` issued as the focused/last call → its result is `current_event = result_events[-1]`).

**Known limitation (R0-A Y1; architect-accepted + inscribed in ADR-034 D3-iv):** when a pass batches multiple result-class events and the subprocess `TOOL_RESULT` is **not last**, it is excerpt-excluded **and** not `current_event` → invisible to the next pass. This is **asymmetric with MCP** (whose `OBSERVATION` survives in the excerpt) — the "minus the `OBSERVATION`" choice removes that carrier. Accepted MVP edge (single-call dominant); inscribed, not discovered. The tool-name-match keying (B3-5 / §5.2) is the exclusion mechanism.

**Interpreting the architect's ratified decisions where the brief left a design call to me** (all surfaced in §5): the output-untrusted reconcile uses a **tool-name match** (not a `ToolResultMeta` flag) *because* the flag would force a write inside the byte-frozen `_execute_local_call`; the cap is **fully renamed** to `MAX_SUBPROCESS_CALLS_PER_TURN`; the runner argv0 is **hardcoded** (`python -m pytest`, `ruff check`) for the Python MVP.

## 2. Tasks (atomic)

Per-tool argv templates + param allowlists are **pinned** in Task B3-2. All five run with `cwd=sandbox_root`, scoped env, bounded timeout + bounded output; the path that enters argv is always the **resolved absolute path** from `_check_path` (never the raw LLM string → never flag-shaped).

### B3-1 — `run_scoped_command` runner in `mcp/subprocess_trust.py`

- **What:** Add a single new entrypoint that runs an argv list and returns its exit code + bounded combined stdout/stderr, reusing the existing kill-no-orphan + watchdog machinery. No new subprocess mechanism (ADR-034 D4 / ADR-031 D2).
- **Where:** `src/orchestrator/mcp/subprocess_trust.py` (new fn + a `MAX_RESULT_BYTES`-bounded reader); `src/orchestrator/mcp/_async_bridge.py` reused (`run_sync`) for the sync wrapper.
- **Why:** ADR-034 D2/D4; carry-forward #4 (reuse, don't rebuild).
- **Acceptance:**
  - Signature ≈ `run_scoped_command(argv: list[str], *, cwd: Path, env: dict[str,str], timeout_s: float = 30.0, max_bytes: int = MAX_RESULT_BYTES) -> SubprocessResult` where `SubprocessResult` carries `exit_code: int`, `output: str` (combined stdout+stderr, truncated at `max_bytes`), `truncated: bool`. Default `timeout_s = 30.0` (callers override per-tool, B3-2 `_SUBPROCESS_TIMEOUTS`).
  - Spawns via `anyio.open_process([...], cwd=..., env=..., start_new_session=True)` — argv is a **list**; **never** `shell=True`, **never** a shell string.
  - Bounded read: stops accumulating at `max_bytes` **as it reads** (does not buffer an unbounded child log into the single writer).
  - Timeout: a hung child is killed via the **reused** `_terminate_subprocess(process, pid)` + `_kill_watchdog(pid)` (process-group SIGTERM→SIGKILL→watchdog); a timeout raises a distinct `SubprocessTimeout` — caller turns it into `TOOL_FAILED`.
  - **Shielded-finally kill (R0-A N3):** `run_sync`'s `asyncio.wait_for` **cancels** the coroutine on timeout (`_async_bridge.py:51-53`), so the child kill **must** run in a shielded `finally` (the `subprocess_mcp_stdio` pattern, `subprocess_trust.py:254-279`; `_terminate_subprocess` already wraps `CancelScope(shield=True)` at `:135`) — else a cancelled coro could orphan the child.
  - Scoped env is the caller's responsibility (Task B3-2 builds it via the `scoped_env()` core); this fn does not add `os.environ`.
  - Tests (`tests/mcp/`): echo round-trip (exit 0, output captured); non-zero exit captured (no raise); output > `max_bytes` → truncated + flag; timeout → child killed, no orphan (assert PID reaped), kill survives coroutine cancellation. **The orphan test covers the COMMON case** — a grandchild in the **same** process group (pytest-worker / git-subcommand shape); it does **NOT** assert the adversarial `setpgid(0,0)` escape, which is the Accepted kill residual inscribed in ADR-034 D4 (retired by P4.3). Document this scope in the test.
- **Out of scope:** changing `subprocess_mcp_stdio` / the MCP path (behaviour-unchanged); any `shell=True` convenience.

### B3-2 — the five subprocess tool closures + `tools/subprocess_tools.py`

- **What:** A new module building the five `LocalToolFn` closures, each: validates its param allowlist, resolves the path via `_check_path`, builds the fixed argv, calls `run_scoped_command` with a scoped env, and formats the result into `LocalToolOutput`. Each closure carries `_is_posture_b_subprocess = True`.
- **Where:** new `src/orchestrator/tools/subprocess_tools.py` exporting `build_subprocess_tool_registry(sandbox_root: Path) -> dict[str, LocalToolFn]`. **Do NOT** add these to `tools/local.py` (constitution t6 forbids subprocess there — keep `local.py` in-process-pristine).
- **Why:** ADR-034 D1/D3/D5; brief carry-forward #6.
- **Pinned per-tool argv + param allowlist** (path = resolved absolute under `sandbox_root`):

  | Tool | Params (allowlist) | argv |
  |---|---|---|
  | `run_tests` | `path` (optional, sandbox-rel test file/dir) | `[sys.executable, "-m", "pytest", "-q", <abs_path?>]` |
  | `run_lint` | `path` (optional, default `sandbox_root`) | `["ruff", "check", <abs_path>]` |
  | `git_blame` | `path` (**required**) | `["git", "blame", "--", <abs_path>]` |
  | `git_log` | `path` (optional), `max_count` (optional int, clamp `[1,100]`, default 50) | `["git", "log", "-n", <count>, "--", <abs_path?>]` |
  | `git_diff` | `path` (optional) | `["git", "diff", "--", <abs_path?>]` |

- **Pinned per-tool timeouts** (`_SUBPROCESS_TIMEOUTS` dict in `subprocess_tools.py`; passed as `run_scoped_command(timeout_s=...)`; R0-B B1 — closes the unbound term in the single-writer bound): `run_tests = 120`, `run_lint = 30`, `git_blame`/`git_log`/`git_diff` = `10` (seconds).
- **Acceptance:**
  - Any param key **not** in a tool's allowlist → raise `LocalToolError` (→ `TOOL_FAILED`). No flag passthrough (`-p`/`--pdb`/`-c`/refs/…) on any tool.
  - Path params resolved via the **reused** `_check_path(path_str, resolved_root)` (escape → `LocalToolError`); the **resolved absolute path** enters argv (never the raw string). git commands place `--` before the path.
  - **Scoped env — PINNED approach (R0-A/R0-B A1):** factor a `scoped_env(extra_env: dict[str,str] = {}, api_key_env: str | None = None) -> dict[str,str]` **core** out of `build_scoped_env` in `subprocess_trust.py`, preserving its **exact three-step behaviour** (safe-keys-from `os.environ` → overlay `extra_env` → conditional `api_key_env`). `build_scoped_env(server_cfg)` becomes a thin wrapper calling `scoped_env(server_cfg.env, server_cfg.api_key_env)`; the B3 closures call `scoped_env()` with **no** `extra_env`, **no** `api_key_env`. **Do NOT** construct an `MCPServerConfig(env={})` — `transport="stdio"` requires `command` and the call fails Pydantic validation (`config.py:67-69`). Existing MCP env tests must still pass (pure refactor). **New B3 env test:** subprocess env contains `PATH` (so `git`/`ruff`/`pytest` resolve) and contains **no** key from `os.environ` outside `_SAFE_ENV_KEYS` (seed a fake secret in `os.environ`, assert absent).
  - **Result semantics:** normal completion at **any exit code** → `LocalToolOutput` (content includes the exit code + bounded combined output) → lands as `TOOL_RESULT`. A failing test suite / lint finding (non-zero exit) is **expected output, NOT** `TOOL_FAILED`. (Rides `_execute_local_call` unchanged.)
  - **Distinct error classes (R0-B B4):** the closure **catches** the expected `run_scoped_command` failures and re-raises as `LocalToolError` carrying a **distinct** error class so the agent distinguishes "tests failed" (`TOOL_RESULT`, non-zero exit) from "couldn't start pytest" (`TOOL_FAILED`): timeout → `subprocess_timeout`; spawn-failure (e.g. `ruff` not on `PATH`) → `subprocess_spawn_failed`; path-validation / disallowed-param → the existing `LocalToolError` path. (Note `_execute_local_call:371` wraps a raised `LocalToolError` as `local_tool_error` unless the impl surfaces a specific class — confirm the error class reaches `ToolResultMeta`; if `_execute_local_call`'s generic wrapping cannot carry it without an executor edit, encode the class in the `LocalToolError` message — do **not** edit `_execute_local_call`.)
  - Output bounded at `MAX_RESULT_BYTES`; `output_truncated_at` set on truncation.
  - Each closure has `_is_posture_b_subprocess = True` readable via `getattr` (function attribute or a small callable class — match the `_PostureBFn` precedent in `plugins/code.py`).
  - Tests (`tests/tools/`): per-tool happy path (stub a tiny git repo / pytest file under a tmp sandbox); param-allowlist rejection; path-escape rejection; non-zero exit → `TOOL_RESULT` not `TOOL_FAILED`; timeout → `subprocess_timeout` `TOOL_FAILED`; spawn-failure → `subprocess_spawn_failed` `TOOL_FAILED`; `git_log max_count` clamp; a path starting with `-` cannot become a flag.
- **Out of scope:** configurable runner (non-pytest/non-ruff/non-Python workspaces — see §5); arbitrary git refs; line-range params.

### B3-5 — extend the `snapshot_excerpt` exclusion to subprocess results

- **Where:** `src/orchestrator/agents/selection.py:92-130` — generalise `_mcp_tool_result_call_ids` → `_external_output_tool_result_call_ids` (match `tool_name.startswith("mcp__")` **OR** `tool_name in _SUBPROCESS_TOOL_NAMES`); define `_SUBPROCESS_TOOL_NAMES: frozenset[str]` in `selection.py` (the consumer; **not** imported from `tools/` — t1 forbids agents→tools). (The test may import both; only the *test* crosses the layer, never runtime.)
