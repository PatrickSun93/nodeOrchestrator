## 1. Framing

P3.2 builds a **thin** FastAPI HTTP/WS server over the existing sync event store + `run_turn` + bootstrap so the P3.3 GUI can **read** a room (snapshot + live stream) and **send user intent** (append a user event → drive a turn). The backend decides everything; the API is a **view + intent transport, backend-authoritative**. The architect ruled the four decisions (ADR-025 absorbs them): (a) FastAPI + HTTP-read/WS-stream/in-process pub/sub; (b) dual-lens R0-B; (c) localhost-trust MVP; (d) single task, contract pinned first, raw wire. The **constitutional/security spine** (ADR-025 HR#1–4) is non-negotiable and inscribed: no decision surface, write-surface forge-prevention, state-machine 不暴露, trust boundary.

## 2. The contract + surface (ADR-025 D2/D5 — the first atomic)

**Endpoints (HTTP):**
| Method · path | Wraps | Returns |
|---|---|---|
| `POST /rooms` | `append_room(Room(type=…))` | `Room` |
| `GET /rooms/{id}` | `get_room` | `Room` (404 if absent) |
| `GET /rooms/{id}/events` | `get_room_events` (ordered) | `list[Event]` |
| `GET /rooms/{id}/snapshot` | `produce_snapshot(events, room, snapshot_at=now_ms())` | `Snapshot` |
| `GET /events/{id}/thread` | `get_thread` | `list[Event]` (404 on `EventNotFoundError`) |
| `POST /rooms/{id}/intent` | forge-check → `append(user_event)` → `run_turn` → cursor-diff → publish | `IntentResponse` |

**WS:** `GET /rooms/{id}/stream` — read-only; on connect **replay** current events (from a cursor) then **stream** newly-appended events as `StreamMessage{kind:"event", event}`.

**Wire models (`api/wire.py`):** `Event`/`Room`/`Snapshot` re-used **raw** (frozen, `extra="forbid"`); `IntentRequest{type, content, metadata?, parent_id?}` (**no author/id/timestamp** — D4); `IntentResponse{appended_event: Event, turn: TurnResult}`; `StreamMessage` discriminated envelope. **Contract artifacts** committed in atomic 1: the models + the FastAPI-generated **OpenAPI** JSON + a hand-authored **AsyncAPI** note for the WS channel.

## 3. The security spine — write-surface forge-prevention (ADR-025 HR#2/D4; the crux)

The single write chokepoint is `POST /rooms/{id}/intent`. The server **constructs** the `Event` (never trusts the client for identity):
- `author = "user"` **hardcoded** (the `IntentRequest` has no author field → unforgeable).
- `id = generate_event_id()`, `timestamp = now_ms()` server-stamped.
- `type ∈ {USER_INPUT, DECISION, RETRACTION}` (the allowlist, D4a) — else **`422` fail-closed** before any append. `UTTERANCE` excluded (agent speech-act; prevents driving `UTTERANCE`-keyed transitions).
- `metadata` validated via `validate_metadata(type, metadata)` → `422` on typed-metadata violation (`DECISION`→`DecisionMeta`, `RETRACTION`→`RetractionMeta`).
- `parent_id` (optional) validated by `append` (same-room/exists) → `422`/`404`.

→ A client **cannot** forge `author:"system"`/`"agent:<id>"` or a `STATE_TRANSITION`/`AUTONOMY_DECISION`/`AUTONOMY_REFUSAL`/`TOOL_*`. The backend stays the sole author of system/agent/transition events (they arise only inside `run_turn`/`dispatch_turn`). **No decision surface** (HR#1): the endpoint only appends + calls `run_turn`; state/activation/routing/autonomy stay backend. **No new `LLMPurpose`.**

## 4. Concurrency design (ADR-025 D6 — the new surface)

- **Serialized single-writer executor.** One dedicated single-thread executor holds the **one** `sqlite3` connection; async handlers `await loop.run_in_executor(core_executor, …)` for **all** core calls (store reads/writes, `run_turn`, the `llm_adapter`). Serializes DB/turn work on one thread (correct for append-only single-writer sqlite; sidesteps `check_same_thread`), frees the loop for WS fan-out, makes a turn's multi-append atomic w.r.t. other writers.
- **`RoomEventBus` pub/sub + cursor-diff.** Per-subscriber bounded `asyncio.Queue`s keyed by room. The write path (on the executor): capture the pre-turn cursor → `append`+`run_turn` → read newly-appended events (`get_room_events` past the cursor) → publish to the hub → fan out (on the loop). **No `EventStore` change** (cursor-diff observation, not an `append` hook — wrap-don't-reimplement). WS connect = **replay-then-subscribe** (no gap). A slow/disconnected subscriber is **dropped** (full queue / send raises → unsubscribe), never blocks the writer.
- **The `llm_router` gap (substrate finding).** No concrete `LLMRouterProtocol` exists. Atomic 4 adds `api/llm_adapter.py`: a thin sync adapter satisfying `.call(request)` by delegating the routing **decision** to the unchanged `select_model_and_provider` then invoking `provider.call` (sync-over-async on the executor). **Glue, not a decision surface** (HR#1) — it executes the backend's routing choice, makes none of its own.

## 5. Bootstrap integration (ADR-025 D1)

A `create_app(config_dir, db_path) -> FastAPI` factory composes the app context (shared by handlers): `load_and_validate_llm_layer` → the `EventStore` (one conn + `init_schema`) → `load_agents` (+`regex_registry`), `load_skills`, `load_tools_config` → the `llm_adapter` → the `core_executor` + `RoomEventBus`. Startup/shutdown manage the connection + executor lifecycle. A `uvicorn` entry (`api/__main__.py` or a `[project.scripts]` `serve`) binds `127.0.0.1` (D7).

## 6. Atomic graph (single task, serial — contract pinned first)

Single junior, serial (new infra, tightly coupled — ADR-025 d; no within-slice parallelism). Contract-first so P3.3 can start (the slice-level frontend∥backend track parallelism is the real lever — roadmap §5).

- **P3.2-1 — CONTRACT PIN (first).** ADR-025 (done, this plan) + `api/wire.py` (the wire models: `IntentRequest`/`IntentResponse`/`StreamMessage` + raw `Event`/`Room`/`Snapshot` re-export) + a stub FastAPI app exposing the **schema** (so OpenAPI generates) + commit the **OpenAPI JSON** + the **AsyncAPI** note. **§6 round-trip tests** (the wire models serialize/deserialize `Event`/`Room`/`Snapshot` frozen + `extra="forbid"`; `IntentRequest` rejects `author`/`id`/`timestamp` fields → `extra="forbid"` is itself a forge guard). Inscribe-before-producer artifact. No server logic.
- **P3.2-2 — read surface + bootstrap context.** `create_app` factory (§5) + the read endpoints (`GET room`/`events`/`snapshot`/`thread`, `POST /rooms` create) over the executor. **§1 read e2e** (create room → append via store → GET returns the events; 404 paths).
- **P3.2-3 — WS live stream + pub/sub.** `RoomEventBus` + the WS handler (connect→replay→subscribe→stream) + the `core_executor`. **§2 concurrency** (multiple WS subscribers receive a published event; replay-then-subscribe has no gap/dup; subscriber drop doesn't block).
- **P3.2-4 — intent/write path + forge-prevention + push.** `POST /rooms/{id}/intent`: the D4 forge chokepoint (server-stamped author/id/ts, allowlist, `validate_metadata`, fail-closed) → `append` + `run_turn` (on the executor) → cursor-diff → publish → `IntentResponse`. The `llm_adapter`. **§4 fail-closed + §1 write e2e** (post-intent → append + run_turn → resulting events stream to a WS subscriber; **forged-author/off-allowlist/typed-metadata-violation rejected**, discriminating).
- **P3.2-5 — failure modes + landing.** **§3** (WS drop mid-turn; `run_turn`/`append` raises → `5xx`, no partial-state leak, store consistent; sqlite busy/locked; malformed/oversized payload → `422`; client disconnect mid-stream → clean unsubscribe). Handoff (§899 UI-contract note) + 5-surface + OpenAPI re-gen + the `api` optional-dep.

## 7. Test plan (test-coverage-standard — heavier than P3.1)

- **§1 cross-module (load-bearing):** the full intent loop — `POST /intent` → `append(author:user)` → `run_turn` → state_transition + agent utterances appended → those events stream to a subscribed WS client. **Discriminating:** the *right* events surface (not just "some"); a **forged-author** attempt (client tries `author:"system"` — impossible via the schema, but assert the constructed event is `author:"user"`), an **off-allowlist type** (`STATE_TRANSITION`/`UTTERANCE` → `422`), and a **typed-metadata violation** (`DECISION` with bad `DecisionMeta` → `422`) are **rejected** with no append.
- **§2 concurrency (new):** N concurrent WS subscribers on one room all receive a published event in order; interleaved intents from concurrent clients serialize correctly (no lost/dup events; cursor-diff captures each turn's full event set); connection lifecycle (subscribe/unsubscribe under load); a slow subscriber's full queue is dropped without stalling the writer or other subscribers.
- **§3 failure modes (new):** WS drops mid-turn (the turn still completes + persists; reconnect replays); `run_turn`/`append` raises (→ `5xx`, the store stays consistent — append-only, no partial write surfaced as success); sqlite busy/locked (serialized executor avoids it; assert no `check_same_thread` crash); malformed/oversized intent payload (→ `422`, no append); client disconnect mid-stream (clean unsubscribe, no leak).
- **§4 boundary/validation:** the write allowlist + author-stamping fail-closed (D4) — discriminating per the §1 rejections; payload-size limit; `IntentRequest` `extra="forbid"` rejects unknown/identity fields.
- **§6 schema invariants:** the wire round-trips `Event`/`Room`/`Snapshot` (frozen, `extra="forbid"`); the committed OpenAPI matches the models (a drift test re-generates + diffs).
- **No new `LLMPurpose`** (grep-asserted); `api/` imports no routing/judgment surface; the constitution stays green.

## 8. Senior forks (pinned in ADR-025)

- **Intent over HTTP POST** (not bidirectional WS) — status-coded fail-closed forge boundary; WS stays read-only push. (ADR-025 D2.)
- **Sync-bridge = async handlers + a serialized single-thread executor** holding the one connection (not per-request conns, not sync `def` handlers) — correct + simple for sync single-writer sqlite + sync `run_turn` under concurrent async WS. (D6.)
- **Push = `RoomEventBus` pub/sub + cursor-diff capture + replay-then-subscribe**, bounded queues, drop-slow-subscriber — no `EventStore` change. (D6.)
- **Intent-type allowlist = `{USER_INPUT, DECISION, RETRACTION}`; `UTTERANCE` excluded** (agent speech-act; prevents client-driven `UTTERANCE`-keyed transitions). (D4a.)
- **The `llm_router` adapter** (the substrate gap) = thin glue delegating to `select_model_and_provider` — decision-free. (D3.)
- **Deps = optional `[api]` extra** (`fastapi`, `uvicorn[standard]`) — core stays importable without the server. (D1.)

## 10. Self-discoveries (verified `origin/main`)

- **No concrete `LLMRouterProtocol`** — only `select_model_and_provider` (async decision) + `provider.call` (async); every caller injects a mock. P3.2 is the **first** to need a real one → the thin decision-free `llm_adapter` (D3) — the one LLM-touching glue, explicitly not a decision surface.
- **`Event.author` permits `user|system|agent:<id>`** (`event.py:361`) — the schema alone is **not** the forge guard; the API must hardcode `author:"user"` + omit author from the wire (D4). This is the load-bearing security insight.
- **`run_turn` is sync + appends side-effect events** (state_transition + utterances) — the push must capture the *whole* turn's events (cursor-diff, not just the user event).
- **`room.state` is never mutated** — the room's live state is **derived** (the snapshot/state-machine reads events); the API never writes `room.state`.
- **store is sync `sqlite3`, caller-owns-conn, append-only by TRIGGER** — drives the serialized-executor design + the no-update/delete API surface.
- **`config/ui_strings/` absent + no `api`/`main.py`** — wire stays raw (GUI builds `ui_strings`, P3.3); the server + `[api]` extra are net-new.
- **`get_thread` raises `EventNotFoundError`; `get_room`/`get_event` return `None`** — the read endpoints map these to `404` consistently.
