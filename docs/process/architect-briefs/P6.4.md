## F — CONNECT-only proxy → plain-`http://` web_fetch 405s (R0-A N2)

**Verify-cited.** The host-side egress proxy handles **only** `CONNECT`; a non-CONNECT request → `405 Method Not Allowed` (`egress_proxy.py:140-141`, live HEAD). In-container `urllib` uses CONNECT for `https://` ✓ but sends an **absolute-form GET** for `http://` (no CONNECT) → 405 → the plain-http fetch **fails closed** (loud `TOOL_FAILED`, **no exfil, https unaffected** — the dominant path).

**Why it is an accepted residual, not a bug:**
- **Security-safe by construction.** Failing closed is *exactly* ADR-037 **D4** ("never silently unsandboxed; fail-closed default"). The egress contract is **honoured**, not breached. This is a minor *functional* limitation (plain-http unsupported in-sandbox), not a security hole.
- **Reviewer + architect already classified it.** R0-A flagged N2 **non-blocking** and handed the only open choice to the architect: *"Whether N2 warrants a follow-up slice or a one-line inscription correction is a minor call for the architect; it does not gate this merge"* (`R0-A.md:227`); round-3 verdict reaffirms *"remains a non-blocking inscription follow-up — does not gate clean"* (`R0-A.md:254`). P4.3 closed on that clean verdict.
- **The only honest gap** is documentary: the `egress_proxy.py:15` docstring still says `http(s): … → CONNECT`, slightly over-claiming plain-http, and N2 was **never inscribed into ADR-037 D5** (confirmed: D5 + Amendment-1 A1-1 "Honest D5 tails" list only nc/socat-image-dep + proxy-non-loopback-bind — neither mentions the 405).

## E — per-call bridge created without `--internal` (R0-B R0B-2-R1)

**Verify-cited.** `_create_network` runs `network create --driver bridge <name>` with **no `--internal`** (`spawn.py:226-230`, live HEAD) → Docker NAT/masquerade leaves the bridge internet-reachable.

**Why it is an accepted residual, not a bug:**
- **The round-1 🔴 was already retired; this is its bounded tail.** R0-B's round-1 `R0B-2` ("unrestricted internet on the bridge") was a **blocker** — **resolved** by the architect-ratified **CONNECT-proxy rework** (Amendment 1 **A1-1**): the proxy, not the bridge firewall, is now the enforcement and **all tool paths route through it**. R0B-2-**R1** is the residual: a process would have to (i) bypass the proxy env vars **and** (ii) already know a hardcoded arbitrary IP — while **DNS is disabled** (`--dns 0.0.0.0`), **`--cap-drop=ALL`** (no raw sockets), runs as **`nobody`**, on an **operator-controlled image** (`R0-B-cross-family.md:64`, :142).
- **Reviewer graded it "accepted D5 tail"** (`:143`) with a **conditional** direction: *"Add `--internal` **if** testing confirms `host.docker.internal` remains reachable on both Docker Desktop and native Linux; **otherwise document as an accepted residual**"* (`:144`) — and warned `--internal` *"may break `host.docker.internal` resolution"*, i.e. it can break the very proxy hop the egress boundary depends on. Left intentionally; never inscribed into ADR-037 D5.

## ⛔ The red line: any *behaviour* fix to E or F touches the load-bearing ADR-037 egress contract

This is the one thing that must **not** be routed routine:

- **F-as-behaviour-fix** (make plain-http work = proxy forwards absolute-form GET) **LOOSENS egress**: it flips F from *fail-closed* to *fail-open-for-http*, weakening the proxy's CONNECT-only filter. → **ADR-037 D2 amendment + relaxes the egress security face → architect escalation. NOT routine.**
- **E-as-behaviour-fix** (add `--internal`) *tightens* directionally, **but** changes the sandbox network-creation mechanism **and** risks breaking `host.docker.internal`→proxy reachability — i.e. it can break the whole egress path. → touches **ADR-037 D2 Network mechanism → architect escalation. NOT routine.**

So the egress contract gates **both** fix-paths. Only *no behaviour change* stays routine.
