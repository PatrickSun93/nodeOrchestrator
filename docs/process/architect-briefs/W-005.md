**Subject:** Implement W-005 — three coordinated state machine changes addressing gaps surfaced by the P1.6 cycle: (1) **Route B** — R0-A becomes mandatory regardless of plan-vs-impl verdict (currently skipped when verdict ≠ clean, breaking the cross-perspective audit the cycle-flow doc promises); (2) **`awaiting_senior_revision`** — new codified state replacing the current "implicit" senior-absorb-routing phase, enabling auto-trigger after architect routing artifact lands; (3) **cycle-boundary artifact filter** — `workflow advance` must not cascade through prior-cycle review artifacts when in cycle 2+ (P1.6 cycle-2 incident: advance read cycle-1 plan-vs-impl + R0-A files and inappropriately reached `awaiting_R0_A`).

All three lift directly from P1.6 cycle observations and accumulated workflow-overview.md/cycle-flow assertions. ADR-008 codifies the 9-state vocabulary + transitions; W-005 amends it (or adds a new ADR-016 if scope justifies) for state-set expansion (9 → 10) + transition-condition tightening + cycle-scoping.

## Scope

### In scope (W-005):

**W-005-1 — Route B: R0-A mandatory regardless of plan-vs-impl verdict.**

Current behavior (`src/orchestrator/workflow/transitions.py:161-165`):
```python
if current == WorkflowState.AWAITING_SENIOR_PLAN_VS_IMPL:
    if artifacts.plan_vs_impl_verdict == "clean":
        return WorkflowState.AWAITING_R0_A
    if artifacts.plan_vs_impl_verdict in ("blocking", "needs_architect"):
        return WorkflowState.AWAITING_ARCHITECT_DECISION  # skips R0_A
```

New behavior: **always transition to AWAITING_R0_A** when senior plan-vs-impl appears, regardless of verdict.

Downstream change at AWAITING_R0_A → next state: must now consider **both** `plan_vs_impl_verdict` AND `r0_a_verdict`:
- BOTH clean AND `merge_clean` → AWAITING_PR_MERGE
- BOTH clean AND NOT `merge_clean` → AWAITING_ARCHITECT_DECISION (merge conflict)
- ANY non-clean → AWAITING_ARCHITECT_DECISION

Rationale per project doc + P1.6 evidence:
- Cycle-flow doc in `docs/process/workflow-overview.md` §2 + `docs/process/architect-partner.md` claims R0-A always fires post plan-vs-impl. Current code contradicts this.
- P1.6 cycle-1: senior plan-vs-impl had `needs_architect` (2🟡). State machine skipped R0-A. r0b R0-B (which fired in parallel via notify-reviewers.sh) caught 1🔴 (`ToolCallRef anomaly handling` vs ADR-014 D2.3) that senior didn't see. Architect manually backfilled R0-A which surfaced 0🔴+2🟡+11🟢 — additional independent findings. Cross-perspective independence is real signal; the skip optimization had measurable cost.

Artifact snapshot change: rename `r0_a_verdict` → keep, no change. Senior must update `next_state` logic for the joint-verdict condition.

**W-005-2 — `awaiting_senior_revision` new state.**

Current behavior: after architect routes findings (`architect-routing-on-impl.md` lands), senior must absorb routing → revise plan/ADR/impl → bump verdicts (RC-10 protocol). The state during this window is "implicit" — no codified state captures it. The current state machine just stays at `awaiting_architect_decision` until architect manually overrides to `awaiting_junior_impl` (for code rework) or until verdicts bump back to clean (no explicit codified path).

New behavior: add `AWAITING_SENIOR_REVISION` to `WorkflowState` enum. Trigger: `architect-routing*.md` file appears in `docs/process/reviews/{task-id}/`. State machine:
```
AWAITING_ARCHITECT_DECISION
  → AWAITING_SENIOR_REVISION (architect-routing*.md appears)

AWAITING_SENIOR_REVISION
  → AWAITING_R0_A (senior pushed revision; verdicts bumped to clean per RC-10)
  → AWAITING_ARCHITECT_DECISION (verdicts still non-clean; rare)
  → AWAITING_JUNIOR_IMPL (if architect override dispatches cycle-N rework — preserves existing override semantics)
```

This enables future notify automation: when state transitions to `awaiting_senior_revision`, kick senior pane to start the absorption. Out-of-scope for W-005 (the trigger script extension), but the codified state is the prerequisite.

Note: `ArtifactSnapshot` needs a new field `architect_routing_exists: bool` (or similar). `cli.py:build_artifact_snapshot` extends to detect routing files.

**W-005-3 — Cycle-boundary artifact filter.**

P1.6 cycle-2 incident: at the cycle-2 dispatch override (`c2b7a12`), running `workflow advance` cascaded:
1. Cycle-1 `plan-vs-impl.md` exists → AWAITING_SENIOR_PLAN_VS_IMPL → AWAITING_R0_A (cycle-1 verdict)
2. Cycle-1 `R0-A.md` exists → AWAITING_R0_A → AWAITING_ARCHITECT_DECISION
3. Hit reality-check: "Cycle-2 impl + R0-A have not actually happened" — architect manually rolled back via second override.

Root cause: artifact freshness check uses `state.last_transition_at`, but **last_transition_at for cycle 2 is set at the cycle-2 dispatch override, while cycle-1 artifacts have older mtimes and exist on the impl branch**. The artifact-reading logic in `cli.py:build_artifact_snapshot` reads the latest file content unconditionally — no cycle scoping.

Fix shape (senior should think hard about this):
- Option A: filter review-file reads by git-log cycle scoping (only consider files committed/modified since cycle's last_transition_at). Mirror RC-19 `_has_junior_impl_commits` pattern.
- Option B: review files are bumped (RC-10 verdict bump) on each revision; a cycle's review reads should require the file to have been touched (by commit) since cycle's last_transition_at.
- Option C: tag review files with `cycle: N` in frontmatter; ArtifactSnapshot filters by cycle.

Architect lean: **Option B** (least invasive — uses existing git history; no schema change to review frontmatter). But senior should evaluate trade-offs in plan §5 push-back.
