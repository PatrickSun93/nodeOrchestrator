that lists **all** rooms (`id`/`type`/`state`/`created_at`) + a frontend sidebar list, so the

**Status of this doc:** a decision-surface with **leans, not decisions**. **Nothing escalates**

## 0. Verify-cited current state (`origin/main` @ `75ccea4`)

- **`GET /rooms` does NOT exist.** Existing room routes: `POST /rooms` (`api/app.py:1336`),
  `GET /rooms/{room_id}` (`:1343`), `/events` (`:1354`), `/snapshot` (`:1362`),
  `POST /rooms/{room_id}/intent` (`:1390`), WS `/stream`. The new endpoint mirrors **`_get_room`**
  (`api/app.py:1343-1352`): async handler, `run_in_executor(ctx.reader_executor, …)`, read-only.
- **The rooms table already has every field** the contract needs — `get_room` is a single
  `SELECT id, type, state, created_at FROM rooms WHERE id = ?` (`core/event_store.py:381-394`);
  table schema `id TEXT PK, type TEXT, state TEXT DEFAULT 'open', created_at INTEGER`
  (`event_store.py:49-54`). **No event-replay, no per-room computation** — `state` is a stored
  column.
- **`list_room_ids()`** (`event_store.py:396-403`) = `SELECT id FROM rooms ORDER BY created_at
  ASC`, returns `[]` on empty store; the countdown sweeper's `_discover_expired_pendings`
  consumes it (`api/app.py:487-501`). Note it selects **`id` only** — see §1.
- **`Room`** (`core/room.py:30-45`, `frozen=True, extra="forbid"`) + **`RoomType`**
  (`room.py:19-27`: `free_chat|bug_fix|research|code_review|idea_validation`) are **already in
  the frozen wire contract** (`GET /rooms/{id}` returns `Room`) → already in `openapi.json` and
  `ui/src/api/schema.ts`. A list endpoint returns `list[Room]` — **zero new wire type.**
- **Auth = fail-closed middleware, no per-endpoint code.** `AuthMiddleware`
  (`api/auth/middleware.py:48`) gates every path except `PUBLIC_PATHS = {"/login", "/health"}`
  (`middleware.py:36-41`); room routes carry **no** `Depends(...)`/`principal` param — they are
  protected purely by being outside the allowlist. So `GET /rooms` is auth-protected **by
  construction** the moment it is added (401 when unauthenticated); the allowlist stays
  `{/login, /health}` untouched.

## 1. BE impl shape — `list_rooms()` vs `list_room_ids()` + loop (routine; lean)

The brief names `list_room_ids()` as the reuse anchor, but it selects **`id` only**, so a
`GET /rooms` returning the full `Room` shape has two faithful realizations:

| | What | Cost |
|---|---|---|
| **(a)** literal reuse | `list_room_ids()` → loop `get_room(rid)` per id | **N+1** queries (1 for ids + N rooms) |
| **(b) — lean** | add `EventStore.list_rooms() -> list[Room]`: one `SELECT id, type, state, created_at FROM rooms ORDER BY created_at ASC`, build `Room` rows | **1** query; a 4-column sibling of `list_room_ids` + `get_room`; endpoint becomes a thin wrapper exactly like `_get_room` |

**Lean: (b)** — same table / same `created_at ASC` ordering / same read-only-on-reader-pool
posture the brief intends; it just returns the `Room` shape the endpoint already needs in one
round-trip instead of N. Both are trivial; this is an **impl-shape** sub-decision (not a scope
change), senior finalizes. (If you prefer (a) for literal-minimal-surface, the endpoint still
works; the only delta is N+1 reads.)

## 2. Where the enumeration residual is inscribed (your explicit question; lean)

The honest residual: **any authenticated user can enumerate all rooms.** This is a **read-surface
instance of an already-accepted posture, not a new decision** — `GET /rooms/{id}` already lets any
authenticated user read **any** room (no owner-scoping); `GET /rooms` only removes the
need-to-know-the-id friction. It is exactly the **`RB-AUTHZ`** residual already inscribed in
**ADR-039 D10** ("no least-privilege; **any authenticated account has full actuation**… flips
dangerous if members become non-fully-trusted", `ADR-039:80` + the D10 ledger `:107`).

**Lean — one line appended to ADR-039 D10**, naming room-enumeration as an `RB-AUTHZ`
read-surface instance (owner-scoping = future work), cross-referenced from the `GET /rooms`
docstring. Rationale:

- **Not a new ADR** — it flips no decision; it makes an accepted authz posture (DP3a
  all-or-nothing + ADR-025 D7 trust posture) *observable*. D10 is precisely the "honest residual
  set" ledger where `RB-AUTHZ`/TLS/rate-limit residuals already live.
- **Not ADR-025** for the *residual* — ADR-025 governs the **wire contract**; the residual is an
  **authz property** (ADR-039's domain). The *endpoint* itself is an **additive route reusing the
  frozen `Room` schema** → **no ADR-025 amendment** (additive, no frozen-schema change; same as
  P6.7 adding endpoint behavior without amending ADR-025).
- **No separate Accept gate** — a residual-note naming an instance of an accepted residual is the
  lightest amendment-in-place weight (the P6.x precedent). The dual-lens reviews that the
  inscription reads honestly. *(If you'd rather Accept it explicitly, say so — but by the
  no-new-ADR test it doesn't require it.)*
