## Lens preamble

Cross-family Principle-5/11 consumer stress-test + runtime/failure-mode lens per `external-r0b-prompt.md` probes. P2.5 is the **first consumer** of the entire read-side memory surface (P2.1–2.4 were all write-side plumbing), the **P2 acceptance milestone** ("AI 记得我"), and the project's **highest-risk Principle-5/11 surface yet** — a catch-up "experience" is exactly where it's tempting to let an LLM decide what matters. The cross-family lens traces: *is the LLM TRULY confined to phrasing, or does selection/ordering/relevance leak through the prompt/serialization boundary?* Also probed: the new cross-package layering edge (`reentry/` composes `memory/`+`derived/`+`llm/` for the first time), the leave-marker design (table vs event), tag-derivation failure modes (empty tag set → lookup crash), first-visit/empty-memory graceful degradation, and the AST guard's structural integrity. Over-correcting for Claude biases: sycophancy toward "the code/LLM boundary is a function boundary therefore airtight," the marker-as-table consensus (a Claude-family-authored plan), and the render's non-deterministic seam (acknowledged but not stress-tested).

## Synthesis

The design is sound on the major calls. The Principle-5/11 boundary — the reason this dispatch exists — is the **strongest expression yet**: `assemble_reentry` is LLM-free by AST guard, `render_reentry_prose` is the only LLM call (content-gen), and the tag-derivation is genuinely deterministic code. The cross-family lens independently confirms the boundary holds at the design level.

One 🟡 — `new_since_leave` on first visit is underspecified ("everything-or-empty per the rule" names no rule). The plan should pin the intended behavior explicitly so the e2e tests the right thing and the render doesn't produce misleading prose. Minor; the design doesn't change.

One cross-family structural note (G2): the render's "phrasing-only" constraint is prompt-enforced, not code-enforced. The LLM *can* drop/reorder facts and no code validates the output. This is a known, acknowledged seam — the deterministic `ReentryDigest` is the tested core, the prose is a UX layer — but it's the only place in the project where a constitutional invariant ("selection is code") is enforced solely by a natural-language instruction to an LLM. The architect should be aware of this as the weakest link in the Principle-11 chain. The mitigation (digest as deterministic core, prose as non-asserted render) is sound for the MVP.

No 🔴. The design is accept-worthy once Y1 is pinned.
