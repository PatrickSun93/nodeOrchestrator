## Architect-settled design decisions

### 1. Snapshot is a pure function over event stream; not a separately persisted entity

`produce_snapshot(events, room) -> Snapshot` is **pure** (Principle 1 — event log is truth). The `Snapshot` object is consumed in two ways:
- **Live**: agents / UI compute snapshot on demand from `event_store.get_room_events(room.id)`.
- **Persisted-via-event**: Logger agent calls `produce_snapshot(...)` and appends a `summary_snapshot` event whose `metadata` contains the snapshot's serialized form. **The event IS the persistence**; no separate snapshot table.

This honors ADR-001 + Principle 1 + ADR-008 D7 (event store as canonical observability path). Snapshots are derivable + cacheable; never authoritative independent of the event stream.

ADR-014 D1 inscribes the contract.

### 2. Decision log is derived live from event stream; not materialized

`produce_decision_log(events, room) -> DecisionLog` filters event stream for `decision` + `decision_pivot` + `rejection` + `retraction` event types into a structured chronological view. **No materialized decision log table**; derivation is cheap (single pass over event stream); cross-room agents query event_store directly.

ADR-015 D1 inscribes the contract.

### 3. Logger agent triggers snapshot production on `snapshot_pending` room state

Per ADR-012 room state machine, Research rooms transition `convergence → snapshot_pending` when convergence criteria met. The `snapshot_pending` state is currently a dead-end (no producer of `summary_snapshot` event exists; `snapshot_pending → closed` transition never fires). P1.6 wires Logger agent's `speaking_triggers` to include a new `state_change: snapshot_pending` trigger; Logger's response action is to call `produce_snapshot(...)` + append `summary_snapshot` event; rooms state machine fires `snapshot_pending → closed` per ADR-012.

**Logger agent dispatches the snapshot; doesn't compose its content semantically.** The `produce_snapshot` pure function is code-decided (Principle 5); LLM-augmented summary text is deferred per Out-of-scope #3.

### 4. Bounded snapshot vocabulary

Per Principle 9 (no orphan spec) — the snapshot vocabulary is FIXED at ADR-014 time. Initial architect-partner lean (senior pin exact shape):

```python
class Snapshot(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    room_id: RoomId
    room_type: RoomType
    room_state: str  # current state at snapshot time
    snapshot_at: int  # ms timestamp
    event_count: int  # total events at snapshot time
    decision_count: int  # count of decision-class events
    open_hypotheses: list[HypothesisRef]  # event-id-keyed references; no copy
    closed_decisions: list[DecisionRef]  # same
    tool_calls_pending_confirm: list[ToolCallRef]  # COUNTDOWN/HARD_CONFIRM tier events without subsequent confirmation
    last_state_transition: StateTransitionRef | None
    participants: list[str]  # agent_ids that emitted ≥1 utterance
```

**Fields are references (event_ids), not content copies** — preserves Principle 1 (event log is truth; snapshots don't duplicate canonical content). Senior may push back on initial vocabulary (push-back #1).

### 5. Decision log shape: structured chronological list of DecisionEntry

```python
class DecisionEntry(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    event_id: str
    event_type: Literal["decision", "decision_pivot", "rejection", "retraction"]
    timestamp: int
    author: str  # "user" / "agent:<id>"
    content_excerpt: str  # short snippet from event.content for log readability
    parent_event_id: str | None  # for rejection/retraction chains

class DecisionLog(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    room_id: RoomId
    entries: list[DecisionEntry]  # chronological strict; no reordering
```

ADR-015 D2 inscribes. Senior may propose richer shape (push-back #3).

### 6. End-to-end test is the load-bearing acceptance

Per joint retro §5.1 lesson ("substrate-cleanup cycles need their own forcing functions"): P1.6 is NOT a substrate-cleanup cycle, but the lesson generalizes — **load-bearing acceptance for a new architectural pattern is an end-to-end test** exercising the full source-to-sink flow. P1.6's e2e test:

1. SQLite-backed `EventStore` (existing).
2. Room loaded with operator + skeptic + logger agents (existing post-P1.5.5).
3. Sequence of user_input → utterance → hypothesis → decision events appended.
4. Room state advances through `setup → exploration → divergence → convergence → snapshot_pending` (ADR-012 state machine; existing).
5. Logger agent triggers on `state_change: snapshot_pending`; `produce_snapshot()` called; `summary_snapshot` event appended.
6. State machine fires `snapshot_pending → closed`; `state_transition` event appended.
7. `produce_decision_log(events, room)` derives DecisionLog from the same stream.
8. Test asserts: snapshot fields match expected shape; decision log entries match expected count + ordering; event stream remains the canonical source (snapshot is derivable from re-running `produce_snapshot` on the stored events).

**Source ≠ sink** across event-stream → produce_snapshot → summary_snapshot.metadata → DecisionLog derived view → assertions.
