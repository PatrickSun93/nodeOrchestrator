**Subject:** Build **P4.2-B3** — implement the 5 deferred **subprocess local tools** (`run_tests` / `run_lint` / `git_blame` / `git_log` / `git_diff`) so an agent can run the project's tests + linter and read git history **mid-investigation** — the flagship bug-fix / code-review loop's *"re-investigate on a failed test"* step that P4.1's turn-loop enabled but has nothing subprocess-shaped to call (P4-roadmap §7). They ship **BEFORE** the P4.3 syscall sandbox, so they run inline with a **lighter subprocess posture** (allowlisted argv, scoped env, bounded timeout + output, `cwd`=sandbox, killable) — **reusing the ADR-031 subprocess-trust seam** — and leave **one honest residual identical in kind to the already-Accepted `RB-FS/NET`** (the subprocess is **not** syscall-isolated; real isolation = P4.3). First of the 3 serial P4.2 sub-slices (B3 → B4 → B5).

## The foundation P4.2-B3 completes (verified — what's missing, precisely)

P4.1 closed the loop (an agent can `read_file` → `search_text` → `find_references` → re-investigate **in-turn**) — but every tool it can chain is **in-process, read-only** (`os.walk`+`re`); P4.1 carry-forward #6 **explicitly forbade** shelling out, deferring exactly this surface to B3. So today an agent **cannot run the tests it's trying to fix**, lint the code it's editing, or read the git history that explains a line. B3 adds the first **subprocess** tool surface. The executor already has the seams (the Posture-B `LocalToolFn` cap path; the `subprocess_trust` scoped-env + kill machinery) — B3 is mostly **wiring 5 fixed-argv commands through reused trust primitives**, plus inscribing the **posture + residual** that makes "shell out, but not yet sandboxed" an Accepted boundary rather than an oversight.

## ⭐⭐ Constitutional carry-forward (NON-NEGOTIABLE — inscribe in ADR-034; **not** decisions)

Per P4-roadmap §10 + the ADR-028/031 spine. The senior inscribes; the impl enforces; R0-A/R0-B probe each:

1. **Execution stays DOWNSTREAM of the gate (ADR-028 #1 / t4).** Subprocess tools route the **unchanged** `process_tool_calls`→`emit_gate_decision` path; AUTO (rev 9-10) executes; any `COUNTDOWN`/`HARD` variant is **not executed in-loop** (confirm-then-execute is out-of-band; the P4.1 turn-loop does not wait for confirm). The executor never re-gates.
2. **No LLM judgment in the executor; no new `LLMPurpose` (t2/t3).** The subprocess path is pure code. **If** subprocess output is interpreted (decision (3)(iv)), it reuses the existing content-gen `TOOL_OUTPUT_INTERPRET` — no new purpose, no routing/judgment.
3. **The subprocess trust boundary is REAL for env/secret + liveness/DoS, HONEST about FS/network.** Scoped env (no secret/credential leak — the c2 lesson), bounded-timeout + kill-no-orphan + per-turn cap (restores the ADR-028 D5 absolute bound), **but NOT a syscall sandbox** — the `RB-FS/NET`-class residual, Accepted **exactly as ADR-031 D1a modelled it**.
4. **Reuse, don't rebuild — one subprocess protocol (ADR-031 D2).** The scoped-env + kill-no-orphan + LAYER-1 watchdog already live in `mcp/subprocess_trust.py`; B3 **consumes** them. No second subprocess mechanism.
5. **`tools/` stays a downstream leaf (t1); `_execute_local_call` stays byte-unchanged** (ADR-031 HR#2 empty-executor-diff) **if** B3 rides the Posture-B `LocalToolFn` path (decision (4)).
6. **Argv, never shell — test-enforced.** No `shell=True` / no shell-string anywhere; a **constitution test forbids it** in the subprocess builder (the ADR-032 *"constitution test forbids `verify=False`"* precedent applied to command-injection).

## Decision points (surface — ⭐ = architect's genuine call; do NOT self-decide)

### (1) MVP tool set + classification confirm

- **All 5 are pre-classified high-rev → AUTO**: `run_lint`/`git_blame`/`git_log`/`git_diff` rev **10**, `run_tests` rev **9** (`tools.yaml:34-42`). At any agent with `threshold_auto ≤ 9` (e.g. the investigator's 8) all 5 reach `AUTO_EXECUTE`. The classifications **stand as-is** unless re-tiered (see the `run_tests` knob below).
- **Two natural trust tiers inside the set:** the **git-read trio** (`git_blame`/`git_log`/`git_diff`) + `run_lint` = *run a known tool that READS / parses* (no project-code execution); **`run_tests` = executes the project's own test code** (arbitrary code execution by design — rev 9 already hedges *"side effects rare in well-formed tests"*).
- **Architect-partner lean: ship all 5.** The flagship loop explicitly needs `run_tests` (*"re-investigate on a failed test"*, §7) **and** git history; once the subprocess machinery exists the marginal cost of the git trio + lint is ~nil; splitting wouldn't shrink the posture work. **But surface — `run_tests` carries the largest residual** (it runs workspace code, not just reads it) + the heaviest argv discipline. **Your call:** (a) ship all 5; (b) ship git-trio + `run_lint` in B3, defer `run_tests` to a B3.1; or (c) ship all 5 but **re-classify `run_tests` → COUNTDOWN** (rev↓) so it is confirm-gated, not AUTO. Lean (a); (c) is the conservative knob if you want a human in the loop on test-execution.

### (2) ⭐⭐ Execution posture — lighter-posture-now + honest residual **vs** reorder behind P4.3 (THE load-bearing call)

- B3 ships **before** P4.3's syscall sandbox, so the subprocess runs inline with a **lighter posture**: **allowlisted argv** (no `shell=True` / no shell-string), **scoped env** (`subprocess_trust._build_scoped_env` — no secret/credential leak, the c2 class), **bounded timeout + bounded output**, **`cwd`=sandbox root**, **killable** (kill-no-orphan + LAYER-1 watchdog). This neutralizes the two **sharpest** subprocess risks (command-injection + env-leak) and restores the ADR-028 D5 liveness bound.
- **The honest residual:** the subprocess is **NOT** syscall-isolated — it runs with the operator process's FS-read + outbound-network privilege (it can `open()` `~/.ssh/id_rsa`, `socket()` out). This is **identical in kind to the already-Accepted `RB-FS/NET`** (ADR-031 D1a) and **strictly narrower** (first-party fixed-argv commands over a *trusted* workspace, vs ADR-031's fetched/untrusted plugin code).
- **Option A (lean): ship B3 now + inscribe the residual exactly like ADR-031 `RB-FS/NET`** — Accept the *real* surface, not a softened one; inscribe the forward-watch that **P4.3's sandbox retires it** (wire B3 subprocess exec through the **same** sandbox interface A1 builds → **one** residual on **one** retirement path, not a second separately-tracked one).
- **Option B: reorder B3 behind P4.3** — build the syscall sandbox first; subprocess tools run sandboxed from day one (no residual). **Cost:** blocks the flagship capability on the heaviest container-orchestration slice; inverts the roadmap's value-first sequencing (§7); the residual is already an Accepted-and-gated class, not a new risk.
- **Architect-partner lean: Option A.** The residual is a **standing-Accepted class** (ADR-031 D1a) and B3's instance is narrower; the posture machinery **already exists** (reuse); value-first sequencing (§7). **But this is your call** — it is a **residual-acceptance + sequencing** decision (accept a second instance of the `RB-FS/NET` class now, vs pay the P4.3 cost first). You accept the residual via **ADR-034**.

### (3) Threat model — 4 sub-surfaces (inscribe in ADR-034)

- **(i) Command-injection → argv, never shell.** `argv` array, **no `shell=True` / no shell-string**; fixed/templated argv per tool; **params constrained** — e.g. `run_tests` takes a *sandbox-relative test path*, **not** arbitrary flag passthrough (`-p` / `--pdb` / `-c` …). **Test-enforced** (carry-forward #6). *No real "choice" — but the senior must pin the per-tool argv template + the param allowlist; surface any tool whose useful surface needs more than a path.*
- **(ii) Env-leak → scoped env allowlist.** Reuse `subprocess_trust._build_scoped_env`; **never** the orchestrator's full `os.environ`; **no** secret/credential/`api_key` keys — the c2 lesson ADR-028 D3 named.
- **(iii) Arbitrary-exec-within-perms → the residual** (decision (2)); Accept honestly; retired by P4.3.
- **(iv) ⭐ Output-as-untrusted — reconcile with ADR-028 D2 + P4.1 R2-N1.** Subprocess stdout is **external-process output** (a malicious commit message surfaced by `git_log`; attacker-influenced strings printed by `run_tests`; a crafted hunk in `git_diff`) — **NOT** "our own code" output. So it is **untrusted, like MCP `TOOL_RESULT`**, **not** local-trusted — which means ADR-028 D2's binary (MCP-untrusted-interpret / local-trusted-raw) gains a **third class**.
  - **Sub-lean: raw `TOOL_RESULT` + untrusted-framing, NOT interpret→`OBSERVATION`.** The agent's value is the **precise bytes** (a stack trace, a diff hunk) to act on — an interpreted summary would **lose** them. Reuse the **P4.1 R2-N1 untrusted-framing** (explicit delimiter; raw excluded from the `snapshot_excerpt`). **The reconcile this forces:** the P4.1 excerpt-exclusion filter (`selection.py::_mcp_tool_result_call_ids`, **`mcp__`-prefix-only today**) **must extend to subprocess `TOOL_RESULT`s** (a tool-name allowlist or an `external_output` metadata flag) so injected text in test/git output **cannot steer a re-dispatched agent** — the P4.1 Y1 surface, now widened to subprocess.
  - **Alternative (surface): interpret→`OBSERVATION` like MCP** (symmetric; reuses `TOOL_OUTPUT_INTERPRET` → no new `LLMPurpose`) — but costs an LLM call per result + a lossy summary the agent often can't act on, and adds an inline interpret to the D5 block.
  - **Lean: raw + untrusted-framing + extend the P4.1 filter.** The architect/senior reconciles in ADR-034.
- **Plus (inscribe, not a choice) — the liveness terms:** **bounded output** (truncate stdout/stderr at `MAX_RESULT_BYTES` — the `read_file`/search bounded-output analog; an unbounded test log OOMs the single writer, the ADR-028 D3 no-adversary memory-DoS); **bounded timeout + kill-no-orphan** (a hung `run_tests`/`run_lint` killed — restores the D5 bound); **per-turn subprocess cap** (reuse/mirror `MAX_POSTURE_B_CALLS_PER_TURN` — a fork-exhaustion bound; B3 calls are process forks).

### (4) Where it executes — reuse the ADR-028 executor; confirm the constitution

- The dispatch frames this as *"a new subprocess branch alongside mcp/local."* Two placements:
  - **(a)** a **new explicit subprocess branch** in `execute_pending_tool_calls` (a third route beside `mcp__`/local).
  - **(b)** **subprocess-backed `LocalToolFn` via the EXISTING Posture-B cap path** — a B3 tool is a non-`mcp__` local-registry entry whose `LocalToolFn` launches the subprocess and is marked `_is_posture_b_subprocess=True`; the executor **already** caps it (`MAX_POSTURE_B_CALLS_PER_TURN`) and runs it via the **byte-unchanged** `_execute_local_call` (`executor.py:158-202`). **No executor-decision edit** (ADR-031 HR#2 / ADR-028 D6 empty-executor-diff).
- **Architect-partner lean: (b)** — preserves the empty-executor-diff invariant, reuses the existing cap, and matches how Posture-B plugin tools already shell out. *(The cap constant likely wants generalizing — `MAX_POSTURE_B_CALLS_PER_TURN` → a `MAX_SUBPROCESS_CALLS_PER_TURN` shared by plugin + B3 forks — a plan-level naming call.)* Mostly a **senior design** call; surfaced so you know B3 likely needs **no executor-branch edit** (smaller, safer footprint than "a new branch" implies).
- **Confirm the carry-forward holds either way:** **t1** (`tools/` leaf), **t2** (no autonomy decision), **t3** (no new `LLMPurpose`), **t4** (execute-on-`TOOL_CALL`-only) — all hold; the gate stays the sole chokepoint, downstream.
