**Lessons captured from the chain:**

### 5.1 Substrate-cleanup cycles need their own forcing functions

RC-18 was a latent bug in the W-003 RC-16 fix. The 14 LoC change introduced one `path.relative_to(Path.cwd())` call that silently failed on relative paths. **The forcing functions that exist (5-surface scan + tracking table + verify-workspace + verify-merge-readiness)** all passed at W-003 close — none would have caught a "silent fallback returns None on edge case" bug. The bug only surfaces when CLI is invoked with the failing inputs.

**Mitigation candidate**: substrate-cleanup cycles (W-001, W-002, W-002.5, W-003, W-004) should have an **end-to-end dogfood** acceptance criterion — the cycle's own `workflow` CLI calls must exercise the new code paths post-merge. W-004-4 acceptance attempts this for RC-19 fix (per brief Architect-settled decision 7); precedent for future workflow-CLI fix cycles.

### 5.2 Trivial-fix routings can ripple to in-flight cycles' state machines

The RC-18 fix merge (`40ea1f9`) was a 1-line code fix on `claude/RC-18-fix`, dispatched + merged in ~3 minutes per the architect's "trivial-fix routing" pattern. The merge happened **between** P1.5.5 transitions (`awaiting_architect_accept → awaiting_junior_impl` at 22:21:40 → next advance at 22:25:36). The interim commit tripped `_has_commit_since` for an unrelated task.

**This is the architectural insight**: `_has_commit_since` reads "any commit since timestamp" — task-scope-blind. ANY architect work on main between cycle transitions can trip auto-advances of in-flight cycles. The bug is **inherent to the task-blind detection function**, not an artifact of RC-18 timing.

**Mitigation candidate (lands in W-004-1)**: task-scoped junior-impl detection via branch-presence filter. The actual RC-19 fix.

### 5.3 "Diagnose before fix" discipline candidate

Junior + senior diagnosed RC-19 as a timezone issue (false-negative on UTC-7 machine) and applied the Z-suffix fix. The diagnosis was **wrong**: the incident happened on a UTC machine where Z-suffix is a no-op; the actual bug was task-scoping. Architect-partner R0-A independently verified by checking `date` output + commit timestamps + walking the timeline; the mismatch was immediately visible.

**Pattern note**: when a bug is bundled into a cycle as a fix, the cycle's audit trail (commit body, plan-vs-impl narrative) should cite the **incident evidence** (what timestamp? what machine? what behavior?) rather than just the **fix description** (what code change?). The diagnosis cite would have surfaced the mismatch before the fix landed.

**Codification candidate (potential W-005 brief item, not W-004)**: when a fix is bundled into a cycle, the landing commit body must include an "incident evidence" subsection citing the observed behavior + verification path. The cite makes wrong-diagnosis fixes empirically detectable.

### 5.4 δ routing as legitimate option

P1.5.5 R0-A Y1 → δ was the **first δ routing** on an architect-partner R0-A 🟡 in 4 cycles. The routing-gradient runs α > β > γ > δ in roughly-decreasing-discipline order; δ ("skip + accept") is the lowest-discipline option but legitimate when:
- The finding is audit-trail-only, not code correctness.
- The deferred work has a real venue (W-004 brief existed by the time of routing).
- Architect's stakes-cost calculus suggests cost > value.

Architect's verbatim ("use UTC works. I am fine with any time lol") encoded all three. The routing was correct; W-004 exists as the venue; the actual RC-19 task-scoping fix lands at W-004-1.

**δ ≠ skip-forever; δ = defer-with-bounded-venue.** The discipline gradient permits the option; first instance documented.
