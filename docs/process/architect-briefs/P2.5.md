**Subject:** Build P2.5 — **room re-entry / 离开-回来追平**: (1) when a user leaves / a room closes, generate a **catch-up artifact**; (2) when they return, **explicitly catch them up** by reading the memory containers and assembling a "here's what you missed / here's what I remember" digest. This is the P2 acceptance experience **"AI 记得我"** and the **first consumer** of `lookup_verified_knowledge` + `ProjectArchive` + `Entity`/preferences + `snapshot`. It demos on **rule-b-promoted VK** (no producers needed — those are P2.6).

## The crux — Principle 5 + Principle 11: code decides *what* and *in what order*; the LLM only *phrases* (the lead constitutional check)

P2.5 is the first place all the read-side memory surfaces are *consumed and composed* into a user-facing experience. That makes it the highest-risk Principle-5/11 surface so far, because a catch-up "experience" is exactly where it's tempting to let an LLM decide what matters. The recurring rule applies a **fourth time** and the brief settles it as a constraint:

- **The catch-up's *decisions* are code** — *which* VK to surface (`lookup_verified_knowledge`'s deterministic scope+tag filter), *which* entities/preferences (`list_*` with code filters), *what's new since you left* (a code diff against the leave-time marker), and **all selection / ranking / ordering**. None of these may be an LLM judgment (Principle 11 — no-ground-truth ranking is drift).
- **The LLM may only do content-gen** — phrasing an **already-selected, already-ordered** fact-set into natural-language prose ("Welcome back. Since you left, the team decided X; your project Y has 2 open questions…"), and the leave-time `one_line_summary` / `spinoff_questions` (content-gen, passed *into* `record_project_archive` per ADR-020 D3). The LLM receives the digest and renders it; it does **not** choose what's in it. (If an LLM call ships, it must use a **content-gen `LLMPurpose`**, never a routing/judgment purpose — grep `LLMPurpose`, per CLAUDE.md.)

**A concrete instance the senior must pin (Principle-11 boundary):** `lookup_verified_knowledge` *requires* a non-empty `topic_tags` set — so the catch-up must **code-derive which tags to query** (e.g. from the project `Entity`'s tags, the room's tags, or the archive — a deterministic rule, **not** an LLM guessing "what's relevant to this user").

## Scope

**In scope (P2.5):**
- **(2) Re-entry catch-up assembly** — a **consumer-shaped reader** (the `assemble_reentry(...)`-style API ADR-020 forward-hooked) that composes `lookup_verified_knowledge` + `list_entities` + `list_preferences` + `get/list_project_archive` (+ `produce_snapshot` for "what changed") into a deterministic, ordered catch-up digest. **This is the milestone** — the "AI 记得我" demo.
- **(1) Leave-time catch-up generation** — at room close, compose the catch-up source (the `ProjectArchive` via `produce_decision_log` + a leave-time `snapshot`, plus the content-gen summary fields) and persist it. **How much of (1) is P2.5 vs deferred is decision point (a).**
- **Placement** — the catch-up consumer composes `memory/` readers + `derived/` + (maybe) an LLM call, so it **cannot live in `memory/`** (no-LLM rule). It's a **new module outside `memory/`** (senior pins where — e.g. `orchestrator/reentry/` or the rooms/agent layer); dependency direction respected.
- **ADR-021** — pins the catch-up contract, the code/LLM boundary (the crux), the consumer-reader shape, placement, and the leave/return markers.
- **e2e** — seed a rule-b-promoted VK + a `ProjectArchive` + entities/preferences (test-injected, producers are P2.6) → re-enter → assert the catch-up surfaces exactly the right facts, deterministically, source ≠ sink across all readers.

**Out of scope (defer):**
- **LLM extraction producers** (auto-populating entities/prefs from conversation) — **P2.6** (ratified: re-entry before producers). P2.5 injects directly.
- **Forgetting / 降级**, knowledge-graph **relations**, **team-scope** semantics — forward hooks.
- **State-machine evolution / LLM Layer 4** — P2.7.

## Architect-settled (fixed — chat-history / prior ADRs pin them)
1. **Principle 5/11** — code decides/selects/orders; LLM only phrases content; no LLM routing/judgment. The catch-up consumer lives **outside `memory/`**.
2. **Demo on rule-b-promoted VK** — no producers needed (P2.6).
3. **P2.5 precedes P2.6** (ratified 2026-05-31).
4. **Determinism** — the code-assembled digest (selection + ordering) is deterministic; only the LLM phrasing (if any) varies.
5. **Dependency direction** — consumer imports `memory/` + `derived/` (+ `llm/` if rendering); `memory/`/`core/` MUST NOT import the consumer.

## Constraints (do not violate)
- **No LLM in `memory/`** (rglob); the consumer is outside `memory/`. Any LLM call is **content-gen `LLMPurpose` only** — no routing/judgment (CLAUDE.md "never LLM-judge").
- **No LLM selection/ranking/ordering** (Principle 11) — code-driven, deterministic.
- **Determinism** — discriminating tests (assert the exact surfaced set by stable labels, not count-only; P2.2/P2.3/P2.4 precedent — RC-25 anti-pattern).
- **Empty/first-visit graceful** — no prior archive, no VK (remember `lookup_verified_knowledge` *raises* on empty `topic_tags` — the consumer must handle the "no tags to query" case, not pass `[]`).
