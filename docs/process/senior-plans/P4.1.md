## 1. Context

The runtime executes tools but the agent loop is **open at one end**: `execute_pending_tool_calls` appends `TOOL_RESULT`/`TOOL_FAILED`/`OBSERVATION` and returns; the agent reacts only on the *next* real turn (ADR-028 D4). So no in-turn "read file → search the symbol I found → open the reference." P4.1 closes the loop (**B1** turn-loop) and gives it read-only code-intel to chain (**B2** tools). All four brief decision points are architect-ratified: **(a)** bounded-loop ≤N, small documented N; **(b)** the 4 code-intel tools + `log_event` (in); **(c)** single-lens R0-A; **(d)** new ADR-033 + amend ADR-028/011. The constitutional carry-forward (§⭐⭐) is inscribed in ADR-033, not re-decided here.

The design rests on substrate facts I verified (they shape the tasks below, especially the loop's `current_event` rule and the cooldown constraint — see §5):
- `dispatch_turn` feeds the LLM only `current_event.content` (`agents/dispatch.py:112`); `build_agent_context` **ignores** the snapshot (`agents/selection.py:99`). → the loop must pass the **latest result event** as `current_event` for the agent to see it.
- `should_agent_speak` cooldown suppresses any `cooldown_seconds > 0` agent within the sub-second loop (`agents/speaking.py:71`). → multi-step chaining works only for `cooldown_seconds = 0` agents; **termination is independent of cooldown** (bound N + zero-new-`TOOL_CALL`).
- `run_turn` evaluates `next_room_state` (may append `state_transition`) before dispatch (`rooms/runtime.py:86`). → re-dispatch passes must call `dispatch_turn` **directly** (state machine once per turn), not re-run `run_turn`.

Read for full design rationale: **ADR-033** (this cycle) — D1 (shape/N), D2 (what re-dispatches + `current_event`), D3 (termination + confirm-gated), D4 (liveness/cap/cooldown), D5 (B2 tools + bounds + `log_event`), D6 (constitution + ADR-011 extension).

## 2. Tasks (atomic)

### P4.1-1 — Extract `select_dispatch_agents` from `run_turn` (behavior-preserving)
- **What**: Factor `run_turn`'s load-time + dispatch-time agent filter (`rooms/runtime.py:106-115`, steps 4-5) into a pure helper `select_dispatch_agents(room, available_agents) -> dict[str, Agent]`; `run_turn` calls it. No behavior change.
- **Where**: `src/orchestrator/rooms/runtime.py`; tests `tests/rooms/`.
- **Why**: ADR-033 D2 — the driver loop needs the same filtered set for re-dispatch passes without duplicating the filter (single source of truth).
- **Acceptance**: helper is pure (no I/O/LLM); `run_turn` produces identical dispatch behavior (existing `tests/rooms/` green); a direct unit test asserts the filter (load-time `applies_to.room_types` + dispatch-time `room.state ∈ applies_to.room_states` / `["*"]`).
- **Out of scope**: any change to `next_room_state` or dispatch logic.

### P4.1-2 — B2 read-only code-intel tools + bounded traversal + registry
- **What**: Implement in-process `search_text(query, scope=None)`, `search_code(pattern, scope=None)`, `find_references(symbol, scope=None)`, `find_definition(symbol, scope=None)` in `tools/local.py`; register in `build_local_tool_registry`. Shared `os.walk`-based traversal helper reusing `_check_path` (on `scope`), bounded output (`MAX_RESULT_BYTES`), and a **new files-scanned cap `MAX_SEARCH_FILES`** + bounded per-file read.
- **Where**: `src/orchestrator/tools/local.py`; tests `tests/tools/test_local.py`.
- **Why**: ADR-033 D5 / ADR-028 D3 amendment. carry-forward #6: in-process only (no `grep`/`rg`/`git grep`/language-server).
- **Acceptance**: each tool returns `file:line` hits (search/find) within the sandbox; `scope` escape (traversal/symlink/absolute) → `TOOL_FAILED`; output capped at `MAX_RESULT_BYTES` with `output_truncated_at`; traversal stops at `MAX_SEARCH_FILES`; **no subprocess** import/call in the impls (asserted, P4.1-5); `find_definition` matches `def/class/<name> =` heuristics; results are returned as `LocalToolOutput` (→ `TOOL_RESULT`, no `OBSERVATION`).
- **Out of scope**: AST/language-server precision; `read_file` `range=` param; the subprocess/network/mutation tools.

### P4.1-3 — `log_event` tool + registry
- **What**: Implement `log_event(content, type)` in `tools/local.py` (register in `build_local_tool_registry`): returns a `LocalToolOutput` recording the note + its `type` category → lands as a `TOOL_RESULT`. No `event_store` handle; no new `EventType`. Bounded note size (`MAX_RESULT_BYTES`).
- **Where**: `src/orchestrator/tools/local.py`; tests `tests/tools/test_local.py`.
- **Why**: ADR-033 D5 (the write companion; rev-8 triviality accepted; no per-pass write-cap this cycle — forward-watch named).
- **Acceptance**: `log_event` content+type are recorded in the returned output and appear as a `TOOL_RESULT` when run through the executor; the tool fn signature stays `dict → LocalToolOutput` (no store access); no new event type added (`core/event.py` `EventType` unchanged).
- **Out of scope**: a `MAX_LOCAL_WRITES_PER_PASS` cap (deferred per ADR-033 D5); a dedicated `NOTE` event type.

### P4.1-4 — B1 the driver turn-loop in `_write_and_turn`
- **What**: Wrap pass 0 (`run_turn` + `execute_pending_tool_calls`) in a bounded re-dispatch loop in `api/app.py::_write_and_turn`: constant `MAX_TURN_LOOP_PASSES = 4`; compute filtered agents once via `select_dispatch_agents`; each re-dispatch pass calls `dispatch_turn(filtered, room, current_event=<latest result-class event of prior pass>, ...)` then `execute_pending_tool_calls(<new window>)`. Terminate on zero-new-`TOOL_CALL` **or** no-new-result-event **or** N passes (ADR-033 D3). Publish the full accumulated window once at the end.
- **Where**: `src/orchestrator/api/app.py` (`_write_and_turn` only); tests `tests/integration/` + `tests/api/`.
- **Why**: ADR-033 D1/D2/D3/D4. The executor + `dispatch_turn` are reused **unchanged**.
- **Acceptance**: (§1 chain) with a `cooldown_seconds=0` test agent triggered on `TOOL_RESULT` whose mocked LLM returns `read_file` then `search_text` then nothing, a single `/intent` turn produces both tool results **in one turn** and terminates; (§2 termination) a pass with zero new `TOOL_CALL` exits the loop; the loop never exceeds `1+N` `dispatch_turn` invocations (assert call count); (§3 failure) a `TOOL_FAILED` mid-loop continues bounded; a `COUNTDOWN`/`HARD` call in a pass appends `TOOL_CALL_PENDING` (no `TOOL_CALL`) → loop terminates, is **not** executed in-loop, does **not** hang; (state) `next_room_state`/`state_transition` is evaluated exactly once per turn.
- **Out of scope**: a re-dispatch loop on the `_post_confirm` path (named future symmetry); `snapshot_excerpt` enrichment; any gate-logic change.

### P4.1-5 — Constitution + boundary test extensions for the loop & B2
- **What**: Extend `tests/tools/test_constitution.py` (and/or co-locate in `test_local.py`/integration): the loop adds **no** new `LLMPurpose` (t3 stays green); the driver loop path invokes **no** autonomy-decision symbol; **execute-on-`TOOL_CALL`-only holds per pass** (a pass with no `TOOL_CALL` → zero executions, under the loop); **B2 tools are in-process** (no `subprocess`/`os.system`/`Popen` in the code-intel impls); **B2/`log_event` results are trusted-not-interpreted** (no `OBSERVATION` appended for local tools, under the loop).
- **Where**: `tests/tools/test_constitution.py`, `tests/tools/test_local.py`.
- **Why**: ADR-033 D6 / test-coverage-standard §6 + §4.
- **Acceptance**: the four invariants above are asserted (AST/behavioral as appropriate); existing t1-t4 stay green.
- **Out of scope**: re-testing the unchanged executor internals (ADR-028 cycle-2 coverage stands).

## 5. Where I'd push back / surface

These are evidence-cited design facts the architect should see; I have designed to the available substrate and named the limits in ADR-033, but two border on scope — confirm or redirect:

1. **The agent's LLM prompt does not include event history** (`agents/dispatch.py:112` `messages=[current_event.content]`; `agents/selection.py:99` `_ = snapshot`). So "agent reacts to a tool result" is realized by passing the **latest result event** as `current_event` each pass (ADR-033 D2). Consequence: the investigating agent sees only the **latest** result per pass, not the full accumulated investigation. Richer context (`snapshot_excerpt` on `AgentContext`) was deferred at P1.4 and is **not** in P4.1 scope. **Confirm P4.1 ships the loop at this fidelity** (step-by-step chaining), or whether `snapshot_excerpt` should be bundled (I recommend separate — it is a context-builder enrichment, a distinct surface).

2. **Multi-step chaining requires `cooldown_seconds = 0`** (`agents/speaking.py:71`): a positive-cooldown agent is suppressed after its first utterance within the sub-second loop, so the chain would stall after one hop. The §1 chain test uses a `cooldown_seconds=0` test agent. **Whether to add/configure a real `cooldown=0` investigator/operator agent to the production roster is a separate config surface** — the loop mechanism + the test agent prove the capability in P4.1; I have **not** scoped a roster change. Confirm that is the intended boundary.

3. **`current_event` = the last result-class event in store order** when a pass produced several (ADR-033 D2). This is my senior-design call (driver-local, no `dispatch_turn` change); named so R0-A reads a decision, not an accident.

Termination/safety do **not** depend on any of the above — the bound `N` + zero-new-`TOOL_CALL` guarantee the loop terminates regardless (ADR-033 D3).
