## 1. Context

P1.4 ships 2 ADRs (ADR-010 + ADR-011). W-002-1's `_read_adr_status` only handles single-ADR plans (raises `WorkflowError` on `adr: [...]`). Without W-002.5, every P1.4 ADR Accept needs a manual override-then-revert sequence — accumulating 2-4 overrides on the project's young `override_history` and recreating the RC-11 pattern W-002 closed.

W-002.5 closes the gap before P1.4 hits it: extend the `adr` field to accept `str | list[str]`; `_read_adr_status` aggregates list entries with all-or-nothing semantic (all Accepted → "accepted"; any Proposed/missing → "proposed"/"none"). Same Literal return type; no new state; no new ADR.

This plan deliberately omits an `adr` key in its own frontmatter — dogfooding W-002-2b's no-ADR routing for the first time post-merge on main. If the state machine advances cleanly to `awaiting_junior_impl` on this plan's push, the no-ADR routing fix is empirically validated.
