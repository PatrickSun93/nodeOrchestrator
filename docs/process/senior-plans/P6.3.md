# P6.3 — bug-fix slice: record_preference resets created_at (G1) + fetch_plugin_bundle unbounded in-memory download (H1)

## 1. Context

Two code-review bugs, verify-cited against current `main` by the architect-partner
(`docs/process/architect-briefs/P6.3.md`) and ratified 2026-06-12 under the P6 bug-fix-backlog
delegation. Both are **pure bug-fixes that make code conform to / preserve an existing inscribed
decision** — neither changes a contract, so **no new ADR** (`plan_has_adr=false`). This slice ships
them as **two independent atoms, two commits, either order** (same shape as P6.1 / P6.2). Both carry
`requires_cross_family_review=true` → full impl-stage dual-lens; **H1 squarely earns the cross-family
lens** (it touches the plugin-fetch / bundle-integrity surface), **G1 rides it lighter**.

I re-verified both cites at HEAD (all accurate):

- **G1 — `record_preference` overwrites `created_at` on upsert-update.** `memory/entity.py:143-156`,
  the existing-preference UPDATE branch, writes `created_at = ts` (`ts = now_ms()`, `:125`) on every
  re-declaration → destroys the first-creation time **and** returns an `Entity(… created_at=ts)`
  reporting the new ts. The matched row's original `created_at` is in scope at the loop `break`
  (`row["created_at"]`, `:136-141`) but is **not captured** today. **There is no `updated_at` column
  anywhere** (DDL `store.py:73-80`, schema `schema.py:137`, `_row_to_entity` `store.py:355-362` — all
  `created_at`-only; `grep updated_at src/ tests/` = zero hits). Minimal fix = **preserve `created_at`,
  add NO `updated_at`** (adding one = schema migration + ADR-020 amendment = out of scope, NOT taken).

- **H1 — `fetch_plugin_bundle` reads the whole bundle into memory before the cap.** `_download`
  (`fetch.py:222-236`) returns `response.content` → httpx buffers the **entire** body into RAM
  (`:164`); the 50 MB `_MAX_BUNDLE_BYTES` cap (`:36`) is only checked **after** that buffer (`:171`,
  post-hoc) → a multi-GB body OOMs the process **before the cap ever runs**. The code **already stages
  to a temp file** (`tmp_bundle`, `:158-168`) — the fix streams *into* that existing file. httpx is
  `>=0.28.1` → `client.stream("GET", url)` + `response.iter_bytes()` are available. Governing contract
  is **ADR-031 D5** (digest-before-extract), **not ADR-038** (ADR-038 §Scope explicitly excludes the
  fetch mechanism). Streaming preserves D5 (incremental hash still covers the complete bytes, verified
  before extraction) and strengthens the cap (post-hoc → enforced-during-stream).

**Ratified design calls** (the senior's mechanism leans, all confirmed in the brief): G1 = **G-lean**
(preserve, don't add a column); H1 = **stream + incremental hash + cap-during-stream**, extraction
source = **DP-3 mechanism (a)** (read the now-verified ≤50 MB temp file back into memory, reuse the
existing `_extract_zip` / `_extract_tar` byte-taking extractors — the OOM vector was the *unbounded*
download; a capped ≤50 MB read-back is bounded-safe). DP-2 inscription weight = **code-comment +
docstring + test**, with an optional one-line ADR-020 D2 clarification note riding along (no Accept gate).

**Spine / invariants untouched:** no `_execute_local_call` / gate / COUNTDOWN-spine / `run_pipeline`
change; no new `LLMPurpose`; no ADR amendment; no schema/data-model migration. Both atoms are local
and contained.

## 2. Atom G1 — preserve `created_at` across preference upserts (`memory/entity.py`)

### Defect (conformance to ADR-020 D2)

ADR-020 D2 inscribes a preference re-declaration "**updates that row's value in place**" (pins value +
the one-row-per-`(user_id, key, scope)` identity), and the data model it carries has **only
`created_at`, no modification-time column**. Overwriting create-time on every upsert is therefore a
**deviation from "value in place"**; preserving it makes the code match the inscribed decision. Pure
bug-fix — no amendment.

### Change (G-lean, ~4 lines)

In `record_preference` (`src/orchestrator/memory/entity.py`):

1. **Capture the original create-time at the loop match.** In the scan loop (`:136-141`), when the
   matching row is found and `existing_id` is set, also capture:
   ```python
   existing_id = EntityId(row["id"])
   existing_created_at = TimestampMs(row["created_at"])
   break
   ```
   (`TimestampMs` is already imported, `entity.py:19`.)

2. **Drop `created_at` from the UPDATE … SET clause** (update only the mutable fields):
   ```python
   conn.execute(
       "UPDATE entity SET attributes = ?, evidence = ? WHERE id = ?",
       (json.dumps(new_attrs), json.dumps(new_evidence), existing_id),
   )
   ```
   (Rejected G-alt: `SET … created_at = existing_created_at` — same DB result, but a no-op rewrite of
   an unchanged column reads worse than dropping the column from the SET. Take G-lean.)

3. **Return the preserved create-time** in the upsert-branch `Entity`:
   ```python
   return Entity(
       id=existing_id,
       type=EntityType.PREFERENCE,
       attributes=new_attrs,
       scope=scope,
       evidence=new_evidence,
       created_at=existing_created_at,   # was: created_at=ts
   )
   ```

The INSERT (new-preference) branch and `ts = now_ms()` are **unchanged** — `ts` is still the
create-time for genuinely new rows.

### Inscription (DP-2 — light)

- **Mandatory:** a one-line code comment at the UPDATE explaining the invariant
  (`# created_at is immutable across upserts — only value/evidence mutate (ADR-020 D2)`), and a touch
  to the docstring (`:118-119`) so "updates the value in place" reads "updates the value in place;
  `created_at` is preserved (only value/evidence mutate)".
- **Recommended (rides along, no Accept gate):** a one-line clarification note on ADR-020 D2
  (*"created_at is immutable across upserts; only value/evidence mutate"*), same lightweight style /
  weight as P6.2's ADR-002 D4 "Implemented" note. No new ADR either way.

### Fail-on-revert test (contributing.md Q5)

Add `test_upsert_preserves_created_at` in `tests/memory/test_entity.py` (alongside
`test_upsert_same_key_yields_one_row`, `:227`):

```

e2 = record_preference("response_style", "verbose", user_id="peidong", conn=conn, now=2000)  # t2 > t1, same user/key/scope
```

**Fail-on-revert:** revert the SET clause to `… created_at = ?` (binding `ts`) and the return to

fail. The existing `test_upsert_same_key_yields_one_row` is **necessary but NOT discriminating** for
this bug (it asserts count + value, says nothing about `created_at` — passes before and after); the
new test is the real fail-on-revert. Keep the existing test green.

## 3. Atom H1 — stream-to-temp + incremental hash + cap-during-stream (`plugins/fetch.py`)

### Defect (preserve ADR-031 D5; strengthen the cap)

The 50 MB guard exists but sits **downstream of an unbounded `response.content` read** — it rejects an
already-materialized oversized buffer instead of bounding the download. The fix moves the cap **into**
the download (abort the moment the running byte-count exceeds `_MAX_BUNDLE_BYTES`), and computes the
sha256 **incrementally over the streamed bytes**. The D5 ordering (digest of the complete compressed
bytes, verified **before** any extraction) is **preserved** — the bytes and the verify-before-extract
sequence are identical to today; only the *where* of the size check changes (strictly stronger). No
contract touch (ADR-031 D5 unchanged; ADR-038 explicitly does not govern fetch; admission decoupled).

### Change

**(a) Rewrite `_download` to stream into the temp file, hashing + capping during the stream.** Change
its signature to take the destination path and return the incrementally-computed digest:

```python
# module constant near _MAX_BUNDLE_BYTES (:36) — explicit timeout while we restructure
_FETCH_TIMEOUT_S: float = 30.0

def _stream_to_file(source_url, http_client, dest_path) -> str:
    """Stream the body into dest_path, enforcing the size cap DURING the stream and
    computing sha256 incrementally over the complete bytes. Returns the sha256 hex."""
    hasher = hashlib.sha256()
    total = 0
    def _consume(response: httpx.Response) -> None:
        nonlocal total
        response.raise_for_status()
        with open(dest_path, "wb") as f:
            for chunk in response.iter_bytes():
                total += len(chunk)
                if total > _MAX_BUNDLE_BYTES:
                    raise FetchError(
                        f"bundle too large: > {_MAX_BUNDLE_BYTES} limit (capped during stream)"
                    )
                hasher.update(chunk)
                f.write(chunk)
    if http_client is not None:
        with http_client.stream("GET", source_url) as response:
            _consume(response)
    else:
        with httpx.Client(verify=True, timeout=_FETCH_TIMEOUT_S) as client:
            with client.stream("GET", source_url) as response:
                _consume(response)
    return hasher.hexdigest()
```

Design notes for the junior:
- The **size-cap `FetchError("…too large…")` must propagate unchanged** — do NOT let it get
  re-wrapped into `"download failed: …"`. In `fetch_plugin_bundle`, the current download try/except
  (`:163-166`) catches `Exception` and re-wraps; restructure so `FetchError` passes through (e.g.
  `except FetchError: raise` before the generic `except Exception as exc`, or scope the wrap to only
  the connection/transport failure). The "too large" substring must survive (the ft6 + new bounded
  test both `match="too large"`).
- **Respect a caller-supplied client's own timeout** (don't override it); only the default-client path
  sets `_FETCH_TIMEOUT_S`. (`http_client.stream` does not need an explicit timeout arg.)
- TLS `verify=True` on the default client is preserved (ADR-032 D2 parallel).

**(b) Rewire `fetch_plugin_bundle`** (`:163-187`). Replace the buffer-then-write-then-cap sequence:
```python
# OLD :164-175
bundle_bytes = _download(source_url, http_client)
tmp_bundle.write_bytes(bundle_bytes)
if len(bundle_bytes) > _MAX_BUNDLE_BYTES: raise FetchError("… too large …")  # post-hoc
actual_digest = _compute_sha256(bundle_bytes)
```
with the streamed form:
```python
# NEW — stream straight into the already-created tmp_bundle; cap + hash happen during the stream
try:
    actual_digest = _stream_to_file(source_url, http_client, tmp_bundle)
except FetchError:
    raise                              # size-cap / status errors propagate verbatim
except Exception as exc:
    raise FetchError(f"download failed from {source_url!r}: {exc}") from exc

_, expected_hex = _parse_digest(expected_digest)
if actual_digest != expected_hex:
    raise FetchError(f"digest mismatch for {source_url!r}: expected sha256:{expected_hex}, got sha256:{actual_digest}")

# DP-3 mechanism (a): the temp file is now verified AND bounded ≤ _MAX_BUNDLE_BYTES → safe read-back
bundle_bytes = tmp_bundle.read_bytes()
# Step 4 (extract) onward is unchanged — _detect_and_extract(bundle_bytes, tmp_staging, source_url)
```
- The standalone post-hoc cap check (`:171-174`) is **deleted** (now enforced during stream).
- The explicit `tmp_bundle.write_bytes(bundle_bytes)` (`:168`) is **deleted** (the stream writes it).
- `_compute_sha256` (`:58`) becomes unused by this path — leave it (harmless) or remove if no other
  caller; junior's call (a `grep _compute_sha256` decides). `_download`'s old signature is removed/renamed.
- **Cleanup (`:208-219`) is unchanged** — `tmp_bundle` / `tmp_staging` are still unlinked on
  failure and in `finally`; a stream aborted mid-way leaves a partial temp file that the existing
  cleanup removes (fetched_plugins_dir still never touched on failure — ft7 regression holds).

### Fail-on-revert test (contributing.md Q5)

Add a **bounded-consumption** test (the real discriminator) in `tests/plugins/test_fetch.py`. Use a
`MockTransport` whose response body is a **counting generator** (httpx streams an iterator passed as
`content=`), so the test can prove the download is bounded, not fully consumed:

```python
def test_ft9_oversized_bundle_capped_during_stream_bounded(tmp_path):
    """A body >> cap is aborted DURING the stream — consumption is bounded, not the full N (OOM fix)."""
    from orchestrator.plugins.fetch import _MAX_BUNDLE_BYTES
    chunk = 1024 * 1024                      # 1 MB chunks
    total_n = _MAX_BUNDLE_BYTES + 20 * chunk  # N >> cap
    pulled = {"bytes": 0}
    def _gen():
        produced = 0
        while produced < total_n:
            n = min(chunk, total_n - produced)
            produced += n
            pulled["bytes"] += n
            yield b"x" * n
    def _handler(request): return httpx.Response(200, content=_gen())
    client = httpx.Client(transport=httpx.MockTransport(_handler))
    fetched_dir = tmp_path / "fetched"
    with pytest.raises(FetchError, match="too large"):
        fetch_plugin_bundle(
            source_url="https://example.com/huge.zip",
            expected_digest="sha256:" + "a" * 64,
            plugin_id="huge", fetched_plugins_dir=fetched_dir, http_client=client,
        )
    # bounded: stopped within one chunk of the cap, did NOT pull the whole N
    assert pulled["bytes"] <= _MAX_BUNDLE_BYTES + chunk
    assert pulled["bytes"] < total_n
    assert not (fetched_dir / "huge").exists()       # fetched_plugins_dir untouched (ft7 parallel)
```

**Fail-on-revert:** revert `_download` to `response.content` (buffer-all) → httpx pulls the entire
generator before the cap is evaluated → `pulled["bytes"] == total_n` → the two bounded asserts fail.

**Plus a positive incremental-hash regression** (proves the streamed digest == full-bytes digest over
a multi-chunk body) — extend `_mock_client` (or reuse a generator) to serve a **valid multi-chunk**
zip bundle and assert it stages + the digest verifies (ft1 already covers single-shot; add a small
multi-chunk variant `test_ft10_valid_multichunk_streamed_stages` so incremental hashing is exercised
against a real digest match).

**Keep `ft6` green** (50 MB+1 still raises "too large"). Note for reviewers: **ft6 is necessary but
NOT discriminating** for the streaming fix — it passes both before and after (it only asserts the cap
*rejects*, not that the download is *bounded*); ft9 is the discriminating fail-on-revert test. ft1 /
ft7 / ft8 are regression anchors (valid stage / cleanup-on-failure / digest-before-extract ordering).
