## In scope

### #1 (mandatory) — Room state: derive from `state_transition` events + fix create-seed
- **Real bug, two parts.** (a) `rooms.state` column is never updated and state is
  not derived from events (`rooms/runtime.py` appends a `state_transition` event
  but the frozen `Room` + the `SELECT … state` column stay stale; every turn
  re-reads the stale column). (b) **Root cause the intake missed:** `_create_room`
  (`api/app.py:~1338`) seeds the model default `state="open"` — not the template's
  `"setup"` — so production rooms are wedged *below* `setup` and no `setup→…` rule
  can match.
- **Fix direction (ADR-mandated):** derive room state from the `state_transition`
  event stream (a pure reducer seeded from `default_initial_state`), used at the
  dispatch + snapshot sites; **and** fix `_create_room` to seed `setup`.
  **ADR-012 Rejected-Alternative-F explicitly rejects the "mutate `Room.state`
  column as source of truth" option** — so the column option is only legal as a
  *derived cache*, not authority. **Amend ADR-012** (its event-stream-truth
  contract); no new ADR.
- **Acceptance:** rooms transition through their template state machine in the
  real HTTP turn path; `_create_room` seeds `setup`; regression test exercises the
  **cross-turn** path (NOT the e2e trick of rebuilding `Room(state=…)` in memory,
  which is why this was masked). Effort: **M**.

### #5 (mandatory — HIGH-RISK, constitutional) — Offload the LLM call off the single writer
- **Real bug.** `writer_executor = ThreadPoolExecutor(max_workers=1)` serializes
  all appends; the **sync** `llm_router.call` runs *on* that writer thread
  (`dispatch.py` → `llm_adapter` nested loop), so a slow turn (up to the
  600 s provider timeout) head-of-line-blocks **every** room's appends. Same
  blocking on the pipeline runner's 3 `llm_router.call` sites.
  (Intake overstatements corrected: **reads are already decoupled** to a separate
  `reader_executor`; there is **no `/health`** endpoint.)
- **Fix direction:** offload **only the LLM provider call** to a separate bounded
  pool; **keep every `event_store.append` serialized on `writer_executor`** (the
  ADR-025 single-writer-append invariant is constitutional and MUST be preserved).
- **⚠ Architect decision inside this slice (surface in the plan/ADR):** whether to
  **retain per-turn append-atomicity** (writer held across the turn's appends →
  less unblocking) **or relax to per-append atomicity** (interleave turns at append
  granularity → more unblocking, but a real D6 guarantee change). The senior
  surfaces both; **you Accept** the chosen posture in the **ADR-025 D6 amendment**.
- **Acceptance:** a slow turn in room A does not block room B's user-event append;
  single-writer-append + cursor-diff race-freedom preserved; pipeline runner sites
  covered; the existing concurrency tests pass + new ones for cross-room liveness.
  Effort: **M**. This is the highest-risk atomic — plan it standalone.

### #6 — Bounded snapshot read [amend ADR-011]
- **Real but low-urgency.** `event_store.get_room_events` (`event_store.py:~358`)
  is an unbounded `SELECT … WHERE room_id=? ORDER BY …` (no LIMIT), called several
  times per turn over the full room → linear in-process read/materialize creep for
  long-lived rooms. **Not** an LLM/token leak (the excerpt is already capped at
  `MAX_SNAPSHOT_EXCERPT_CHARS = 8000`, ADR-033) and **not** a crash/OOM.
- **Fix direction:** add a bounded/windowed read + a `count` fast-path to
  `EventStore`; migrate the per-turn hot callers (snapshot read `runtime.py:~104`,
  `dispatch.py:~80`, the `len()` counts, the `[cursor:]` windows). **Preserve
  deep-history correctness** for `next_room_state` / trigger evaluation — bound the
  dispatch/excerpt path, not the state-machine evaluation that legitimately scans
  history. **Amend ADR-011** (snapshot-taken-once contract); no new ADR.
- **Acceptance:** per-turn read cost flat in room age on the hot path; state/trigger
  semantics unchanged; ADR-033 8k cap untouched. Effort: **S–M**.

### #2 (low-pri prereq) — Memory/reentry schema init [no ADR]
- **Real wiring gap, low severity** (the subsystem is runtime-dead, so the intake's
  "production crash" is false — nothing reaches it). `_build_context`
  (`api/app.py:~1074-1098`) inits events/auth/pipeline schemas but **not**
  `init_memory_schema` / `init_reentry_schema`.
- **Fix direction:** call both in `_build_context` on the **writer** conn, **after**
  `writer_store.init_schema()` (FK order: memory → reentry), both idempotent; add a
  test pinning the factory DB's schema set (closes the coverage hole). Fulfils
  **ADR-016 D5 / ADR-021 D5** — **no ADR amendment**. Effort: **S**.
- **Note:** this closes the prerequisite only; it does NOT wire memory into a
  runtime path (that is the deferred memory-wireup slice below).
