## Scope

**In scope (W-003):**

- **W-003-1 (RC-16 fix)**: `_read_plan_frontmatter` in `src/orchestrator/workflow/io.py` reads plan content from `origin/main` semantically, not from working-tree. Current bug: a session with an uncommitted plan file can trigger bogus `workflow advance` state transitions because the parser reads working-tree. Fix path:
  - Replace `path.read_text(encoding="utf-8")` with a `git show origin/main:<rel_path>` subprocess call (or equivalent via `subprocess.run` returning text).
  - If subprocess returns non-zero (file doesn't exist on `origin/main`), treat as "no frontmatter" → fallback per existing logic.
  - **Backwards compat**: working-tree-based reads STILL valid for plans that ARE on origin/main (the most common case). Bug only affects sessions running advance against uncommitted plans; the new code returns the same result in the common case (plan on main = working-tree matches origin).
  - Performance: one extra subprocess per `_read_plan_frontmatter` call. Cheap; same shape as other git subprocess calls in `workflow/cli.py`.
  - Tests: synthetic repo with plan on main + uncommitted local plan modification; assert `_read_plan_frontmatter` returns the origin/main content, not the working-tree content.
- **W-003-2 (RC-13 forcing function)**: new `workflow verify-merge-readiness --task-id TASK` CLI subcommand. Checks that the impl branch has both `plan-vs-impl.md` AND `R0-A.md` review files present with `verdict: clean` frontmatter, before architect merges via PR UI. Warning-not-blocking: prints structured output naming which reviews are missing or which verdicts are non-clean; exit code 0 always (architect can still merge if they explicitly choose; matches `verify-workspace`'s warn-don't-block discipline).
- **W-003-3 (verify-workspace divergence detection)**: extend existing `workflow verify-workspace` CLI subcommand (RC-7 mitigation; W-002 push-back #2 deferred) to detect divergence between local `.workflow/*.yaml` files and `origin/main`. For each state file locally, `git show origin/main:.workflow/<task-id>.yaml` and compare. Diverge → print warning naming the task + the divergence summary. Same warn-don't-block discipline.

Investigate: is this a SessionStart-hook issue (hook fails to install `uv`), a Python-env issue (junior session running in a container without `uv`), or a docs gap (junior session prompt doesn't mention to run verify-workspace pre-landing)? Surface findings + a minimal fix:

## Architect-settled design decisions

### 1. Pure-function semantics preserved through RC-16 fix

`_read_plan_frontmatter`'s signature stays `(path: Path) -> dict[str, Any] | None`. The internal implementation switches from `path.read_text()` to `git show origin/main:<rel_path>` (via subprocess), but the function-level contract is unchanged: pure-function-ish (no mutation), returns parsed frontmatter or None. The subprocess call doesn't break the function's purity invariant for callers (`next_state` etc.) — it makes the function more correct, not less pure.

### 2. Warn-don't-block discipline for both new CLI subcommands

`verify-merge-readiness` (W-003-2) + extended `verify-workspace` (W-003-3) both warn-don't-block. Exit code 0; structured output; architect/junior consume the output and decide. Matches the existing `verify-workspace` precedent from W-001-impl-4. Rationale: harness should surface signals; the human/architect retains the action decision. Auto-blocking creates rigid coupling between harness state + operational reality; warning is the right severity.

### 3. No new ADR expected

W-003 is mechanical workflow refinement (similar shape to W-002). No new architectural pattern; ADR-008 stays as the canonical state-machine ADR; W-003 fixes implementation gaps without changing the conceptual contract.

If senior surfaces a design surface I didn't anticipate (e.g., RC-16 fix has a subtle interaction with a state-machine semantic I missed), **draft ADR-014** per the senior-drafts-ADR rule (RC-3). Otherwise no ADR.

### 4. Workflow integration

Plan dogfoods W-002-2b no-ADR routing (frontmatter present + no `adr` key → skip `awaiting_architect_accept` → advance directly to `awaiting_junior_impl`). Same pattern as W-002.5 plan + P1.5.5 brief (when senior writes it). State machine transitions per ADR-008 D1.

### 5. Cross-package layering

W-003 lives entirely within `src/orchestrator/workflow/`. No new module; no new layering edge; no new constitutional test. The 4 existing `no_llm_calls_in_workflow_module` + reverse-import tests for the 5 modules remain green.

### 6. Architect-partner R0-A-on-plan dispatch (RC-9)

**Dispatch by default** for W-003 plan. Same reasoning as W-002 (small mechanical scope but the changes affect the substrate every other task depends on; partner lens catches subtle correctness issues in mechanical work). Lower-stakes than ADR-drafting cycles (no contract-locking decisions); but the verify-workspace + verify-merge-readiness shape choices benefit from independent review.

### 7. Cross-family R0-B for W-003
