**Subject:** Build P3.1 — give the four **scaffold rooms** (`bug_fix`, `code_review`, `idea_validation`, `free_chat`) working **agent rosters** so they run end-to-end conversations, via `RoomTemplate.declared_agents` + `agent.applies_to`. Add new agent/skill **content only as needed** (architect-gated, §Decisions). This is the Wave-1 content opener — it makes the P2.7 room-type state machines actually *do* something.

## The crux is small — and most of the wiring already exists

A clean substrate finding: the agents' `applies_to` was **forward-configured** for scaffold rooms, but the room templates were never populated — so the agents *say* they apply but never *load*:
- `logger` → `applies_to.room_types: ["*"]` (universal — already applies to all 4).
- `operator` → `[research, bug_fix, code_review, idea_validation]` (already 3 of the 4).
- `divergence_mapper` → `[research, idea_validation]` (already includes idea_validation).
- (`prober`/`skeptic` — senior verifies their current `applies_to`.)

So P3.1 is mostly: **populate each scaffold template's `declared_agents`** (which agents *load* for the room) **+ reconcile `applies_to`** (add scaffold room_types/room_states where an agent should be active) so the right agents activate in the right states. The selection machinery (`should_agent_speak`, `applies_to` filtering — all code) is unchanged; agent *responses* stay LLM content-gen. **No new infra, no new `LLMPurpose`, no constitutional surface.**

## Scope

**In scope (P3.1):**
- **Populate `declared_agents`** for `bug_fix` / `code_review` / `idea_validation` / `free_chat` (reuse the existing 5 agents; add to a template's roster the agents whose role fits + whose `applies_to` covers that room).
- **Reconcile `applies_to`** on the reused agents (add scaffold room_types / the relevant room_states so each activates in the right phase — e.g. an agent that should fire in `reviewing` but not `setup`).
- **New agent/skill content ONLY as needed** (architect-gated — §Decisions): if a room lacks a sensible roster from the existing 5, a new role (or a new skill in `config/skills/`) may be warranted. (`config/skills/engineering/debugging-workflow.md` + `general/research-decomposition.md` already exist and fit `bug_fix`/`idea_validation`.)
- **e2e**: each scaffold room loads its roster (`load_room`) + the agents activate in the expected states (discriminating — assert the right agent set per state, not just "roster non-empty"; mirror the Research-room test). The `rooms/` no-LLM constitution test stays green.

**Out of scope (defer):**
- The **API/server + GUI** (P3.2/P3.3), **MCP/plugins** (Wave 2), and **content *depth*** (many new roles/skills/connectors) — P3.7.
- The **Research** room (done) + the scaffold **state machines** (done, P2.7).
- Per-room agent-roster *richness* beyond a working MVP (unless the architect rules new roles now).
