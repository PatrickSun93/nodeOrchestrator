## 1. Context

P4.7-BE builds the **backend plugin-management endpoints** the two prior inscribe-before-producer ADRs were pinned *for*: `GET /plugins`, `POST /plugins/{id}/enable·disable·admit`, `DELETE /plugins/{id}` (the shape pinned in ADR-038 **D5** L97-110, the authz dimension pinned in ADR-039 **D9** L101-103). It is the first endpoint surface that **actuates both trust boundaries at once** — an authenticated HTTP request that mutates the plugin-admission registry. The architect ratified along the lean lines (ratification commit `4bc96bf`, brief `docs/process/architect-briefs/P4.7-BE.md`): **scope-A (plugin endpoints only)**, **DP1(a)** config-file write / boot-only, **DP1 admit=(i)** author-entry-only, **DP2** authenticated⇒allowed + plant seam #2 (admit gets its own finer seam), **DP3** ratify both halves (gauntlet never relaxed + validate-before-persist/atomic/reject-refuse-all), **DP4** no new ADR (amend at impl), **DP5** mandatory dual-lens.

The contract is **pinned but not built** (verify-cited `main` @ `4bc96bf`): no `/plugins` route exists; the registry has a **read path only** (`load_plugin_registry`, `provenance.py:230`); there is **no `write_plugin_registry`**; `config/plugins.yaml` does not yet exist on disk (authored on first write). This slice realizes the write side under the boot-only posture: **every write edits `config/plugins.yaml` and signals "effect next restart" — zero live mutation of the running `AppContext`** (ADR-038 D2/D5 verbatim).

Two pre-investigation discoveries shape the plan (both verify-cited, both surfaced in §5):

- **D-A — the resolved registry is discarded at boot.** `_plugin_registry` is a *local* in `_build_context` (`app.py:596`), consumed by `load_plugins` then dropped; it is **not** retained on `AppContext` (the dataclass at `app.py:103-127` has `sandbox_root` but no `config_dir` / registry). And `config_dir` is **not recoverable** from `sandbox_root` (`sandbox_root = config_dir.parent`, `app.py:580` — the parent, not a known child). So both GET and the writes need an explicit retained path → **add a `config_dir` field to `AppContext`** (T2).
- **D-B — the pinned GET column "last-load result" has no backing state.** ADR-038 D5 L103 specifies GET returns "id, provenance [derived], enabled, version, **last-load result**." `PluginLoadResult` (`loader.py:61`) carries only *merged contributions* (agents/skills/tools) — there is **no per-plugin load report** anywhere; boot load outcomes are logged, never structured. Faithfully reporting "last-load result" requires retaining a new boot-time per-plugin report on `AppContext`, which **touches `load_plugins`** — exactly the spine Lens B wants byte-frozen. **This is a real decision-point — see §5 push-back P1.** Plan default: GET returns id / provenance-(derived-read-only) / enabled / version / fetched-indicator; **last-load-result deferred as a named residual** unless the architect rules in a minimal additive report at plan-review.

This plan does not restate brief/ADR content — read the brief + ADR-038 D5 + ADR-039 D5/D9 + ADR-031 D5 by path. Five atomic tasks (T1–T5); the dual-lens `external-r0b-prompt.md` is authored at plan-stage (this commit), not a junior task.

## 2. Tasks

### T1 — `write_plugin_registry`: the fail-closed config-file writer (DP1a / DP3b heart)

- **What**: Add `write_plugin_registry(path: Path, registry: PluginRegistry) -> None` to `provenance.py` (sibling to `load_plugin_registry`, `:230`). Serialize the `dict[plugin_id → RegistryEntry]` to the `plugins:`-list YAML shape, **round-trip-validate** the serialized bytes back through `load_plugin_registry` **before** persisting, write **atomically** (temp in same dir → `os.replace`), and **abort the write (leave the existing file untouched) if the round-trip raises `(ConfigError, yaml.YAMLError)`** — the **same** exception set the boot refuse-all path catches (`_resolve_plugin_registry`, `app.py:506`), so the writer's guard provably mirrors the boot parse (G1 α-absorb, R0-A-on-plan).
- **Where**: `src/orchestrator/plugins/provenance.py` (new function + helpers); unit tests `tests/plugins/test_write_registry.py` (new).
- **Why**: DP3b (brief §3, ADR-038 D5 residual "registry only as fail-closed as its parser", extended to the write path). The round-trip-must-not-raise guard **is** the "reject any write whose result would REFUSE-ALL" requirement: refuse-all is triggered only by a `(ConfigError, yaml.YAMLError)` parse failure at boot (`_resolve_plugin_registry`, `app.py:506-510`, verified — the `except (ConfigError, yaml.YAMLError)` clause); a file that round-trips `load_plugin_registry` cleanly under that same catch set cannot trip the `REGISTRY_REFUSE_ALL` sentinel (`loader.py:630`). Atomic temp+rename prevents a torn write from producing a half-file. (`yaml.safe_dump → safe_load` cannot in practice emit a `YAMLError`, so catching `ConfigError` alone is sufficient *today* — but the exact-mirror set is robust to any future serializer change; G1.)
- **Acceptance criteria**:
  - Round-trips: `load_plugin_registry(written_path) == registry_input` (identity fidelity — enabled/version/source_url/digest/env preserved; `isinstance(enabled, bool)` survives serialization, not coerced to a string).
  - A registry that would serialize to YAML that fails `load_plugin_registry` (constructed test case, e.g. via a deliberately malformed serializer path or a monkeypatched validator) → the function **raises** (the round-trip catch set is `(ConfigError, yaml.YAMLError)`, mirroring `app.py:506`; G1), and the **pre-existing `config/plugins.yaml` is byte-unchanged** (no torn write, no temp left behind).
  - Atomicity: writes to a temp file in the same directory then `os.replace`; an interrupted write never leaves a partial `config/plugins.yaml`.
  - First-write: `path` absent → the function authors the file (creates `config/plugins.yaml`).
  - Empty-registry write (`{}`) is permitted and round-trips to `{}` (absent-defaults equivalent — **not** refuse-all; the validator returns `{}`, not the sentinel).
- **Out of scope**: any call site (T3 wires it); fetch/network (DP1-i); touching `load_plugin_registry`'s validator (byte-frozen — Lens B).

### T3 — The five management routes (boot-only, authz-inherited, seam #2 + admit-finer-seam)

- **What**: Register `GET /plugins`, `POST /plugins/{id}/enable`, `/disable`, `/admit`, `DELETE /plugins/{id}` in `app.py` (alongside the existing routes, `:699-1006`). All writes follow read-modify-write **on `ctx.writer_executor`** (max_workers=1, serialized — the existing write-endpoint pattern, `app.py:972`): `load_plugin_registry(ctx.config_dir/"plugins.yaml")` → mutate the dict → `write_plugin_registry(...)` → respond `{"effect": "next_restart"}`. `GET` runs its `load_plugin_registry(ctx.config_dir/"plugins.yaml")` (sync file read) **on `ctx.reader_executor`** to match the house non-blocking-I/O discipline of the sibling read routes (`app.py:758/769/778/795`; `middleware._resolve_principal`) (G2 α-absorb, R0-A-on-plan), and derives provenance read-only by which root dir contains the id (`sandbox_root/plugins/<id>` → operator_placed, `sandbox_root/fetched_plugins/<id>` → fetched; fallback for an id in **neither** root spelled out in the GET bullet — G3).
- **Where**: `src/orchestrator/api/app.py` (routes + Pydantic request bodies for `admit`).
- **Why**: ADR-038 D5 (the contract) + ADR-039 D9/D5 (authz). Endpoint semantics per ratified DPs:
  - **`GET /plugins`** — list declared entries: `plugin_id`, `enabled`, `version`, provenance (derived read-only), fetched-indicator (has source_url/digest). **`last-load result` deferred as a named residual — architect-ratified Y1=(a)** (R0-A-on-plan; keeps `load_plugins` byte-frozen, see §5-P1 + T5). Runs on `ctx.reader_executor` (G2). **Provenance fallback (G3 α-absorb):** an admitted-but-not-yet-fetched entry (the DP1-i residual) is in **neither** `plugins/` nor `fetched_plugins/` — root-based derivation has no defined branch there, so report it as **declared-not-yet-on-disk**, inferring the kind from the fetched-indicator: `source_url`+`digest` present ⇒ `"fetched (pending)"`, else ⇒ `"operator-placed (pending)"`. (Avoids an undefined `if/elif` branch that would mislabel or error.) `plugin_subprocess_env` values are **not** echoed (avoid surfacing operator-authored env wholesale; expose only key presence if needed).
  - **`enable` / `disable`** — upsert `enabled: true/false` on the entry (creating a minimal `{plugin_id, enabled}` entry if absent — valid for operator-placed; the writer's round-trip rejects any result that violates the fetched source_url+digest pairing, fail-closed).
  - **`admit`** (DP1-i, **author-entry-only**) — request body `{source_url, digest, version}` (Pydantic `extra="forbid"` forge-guard, mirroring `_LoginRequest` `:166` / `_ConfirmRequest`); upsert `RegistryEntry(plugin_id, source_url, digest, version)`. **No `fetch_plugin_bundle` call** — fetch stays out-of-band (ADR-038 D2 fetch≠admit). The digest-before-extract gauntlet (`fetch.py:121`) is **untouched and still mandatory** at the separate fetch step (DP3a).
  - **`DELETE`** — remove the entry; `404` if `plugin_id` absent from the registry.
  - **Authz (DP2)** — routes are **NOT** added to `PUBLIC_PATHS` (`middleware.py:36`) → auto-protected, `401` before the handler for an unauthenticated caller (fail-closed-by-default). Read the principal from `request.state.principal` (server-derived, **never** the request body — ADR-039 D7), mirroring seam #1 (`app.py:997`, `:1002`). Plant the **seam #2** named comment ("ADR-039 D5 checkpoint seam #2: authenticated ⇒ allowed; role check (DP3b) would gate here") on enable/disable; plant a **separate finer seam comment on `admit`** ("seam #2-admit: admit introduces new fetched code into the trust boundary — strictly higher-trust than enable/disable toggling already-vetted code; a future DP3b may gate who-may-admit stricter than who-may-toggle"). **Do not** build any role check (DP3b deferred).
- **Acceptance criteria**:
  - All five routes return the documented shapes; writes mutate `config/plugins.yaml` and respond with an explicit "effect next restart" signal; **no live `AppContext` mutation** (no re-call of `load_plugins`, no agents/tools/mcp_sessions rebuild — Lens B boot-only).
  - `GET` runs `load_plugin_registry` on `ctx.reader_executor` (G2) and returns the four columns (id / provenance-derived / enabled / version) + fetched-indicator — **not** `last-load result` (Y1=(a) deferred).
  - `GET` provenance fallback (G3): an entry present in neither root reports `declared-not-yet-on-disk` with kind inferred from the fetched-indicator (`source_url`+`digest` ⇒ `"fetched (pending)"`, else `"operator-placed (pending)"`) — no undefined branch / no error.
  - Unauthenticated request to any of the five → `401` (inherited middleware; route absent from `PUBLIC_PATHS`).
  - `admit` body with an extra field → `422` (extra=forbid); `admit` with no digest → rejected (the writer round-trip enforces the source_url+digest pairing, fail-closed).
  - Writes run on `ctx.writer_executor` (single-writer serialization — no concurrent-write race on the file).
  - Seam #2 + admit-finer-seam comments present; **no new `LLMPurpose`**; the autonomy gate / `_execute_local_call` untouched (admission stays a non-gated operator action, ADR-038 DP2c).
- **Out of scope**: live/hot reload (DP1b, deferred); fetch trigger (DP1-ii, not chosen); role checks (DP3b); rate-limiting (named residual); config-mgmt E3 endpoints (scope-B, deferred).

## 5. Where you'd push back

**P1 — RESOLVED: architect ruled Y1=(a) (R0-A-on-plan, plan-stage dual-lens).** ADR-038 D5 L103 pins GET's `last-load result` column, but there is **no backing state**: `PluginLoadResult` (`loader.py:61`) holds only merged contributions, and the resolved registry + boot outcomes are discarded (D-A/D-B). Faithfully reporting last-load-result requires a **new per-plugin boot load-report retained on `AppContext`**, which means **modifying `load_plugins`** — the exact spine Lens B is asked to certify byte-frozen. **The architect ratified option (a): defer `last-load-result` as a named residual** — GET returns id / provenance-derived / enabled / version / fetched-indicator (not the boot outcome), keeping `load_plugins` byte-frozen. (The alternative — funding a minimal additive `load_plugins` load-report — was **not** taken: it would widen the Lens-B surface for a single GUI display column.) T3 omits the column; T5's ADR-038 D5 amendment inscribes it as a named residual so the ADR stays honest about realized-vs-pinned. The rest of the plan was independent of this ruling (GET works either way; only that one column changes).

**P2 (GET file-vs-running divergence — inscribed, not blocking).** Under boot-only, after a write `config/plugins.yaml` (configured intent) diverges from the running plugin set (effective at next restart). GET reads the **document** (configured intent), and the response marks it "configured (effect next restart)," not "currently running." This is the boot-only residual made visible; I inscribe it (§6) rather than reconcile against running state (reconciling would require D-B's retained boot state). Flag if you want GET to instead report running-state — that pulls in the §5-P1 work.

**P3 (enable/disable on a registry-absent operator-placed plugin).** Presence=opt-in means an operator-placed plugin can load with **no** registry entry. `disable` then must *author* a `{plugin_id, enabled: false}` entry; `enable` on an absent entry is a no-op-but-author (`{plugin_id, enabled: true}`). The plan has the writer's round-trip enforce validity (a fetched-shaped half-entry is rejected, fail-closed). I judged this settle-able in-plan (T3) — not an architect decision — but flag if you read the toggle semantics differently.

## 6. Residual set — inscribe, don't soften

- **`RB-AUTHZ`** (ADR-039 D10) — endpoints are authenticated⇒allowed; any authenticated/compromised account can admit/enable/disable any plugin (the highest-trust actuator). Persists until DP3b (a role model at seam #2 / the admit-finer-seam).
- **`RB-ADMIT`** (ADR-038 D3) — admit-via-endpoint inherits no-author-identity / no-revocation / no-update-trust; the endpoint authors operator intent and does not change the integrity floor.
- **Boot-only / no-live-management** (ADR-038 D2, DP1a) — writes show intent that lands at next restart; GET renders configured intent, not live running state (§5-P2).
- **`last-load result` deferred** (§5-P1, **architect-ratified Y1=(a)**) — GET omits the boot-outcome column (returns 4 columns + fetched-indicator); `load_plugins` stays byte-frozen. T5's ADR-038 D5 amendment inscribes the dropped column for realized-vs-pinned honesty.
- **Config-mgmt E3 deferred** (scope-A) — MCP/agent/model/autonomy config endpoints have no pinned contract; a follow-on BE slice + ADR-041 if ever.
- **Rate-limiting** on the `POST`/`DELETE /plugins/*` write chokepoints — deferred named residual (ADR-039 D10; post-auth per-identity limiter applies when built).
- **admit-author-only → refused-at-boot-until-fetched** (DP1-i) — an admitted entry whose bytes aren't yet on disk is refused at next boot until the separate out-of-band fetch runs.
