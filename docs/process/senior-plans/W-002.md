## 1. Context

P1.3 was the first task to exercise `awaiting_architect_accept` with an ADR drafted alongside the plan. The harness surfaced exactly one cluster (RC-11) with two sub-findings, both predicted by W-001 retro §8 #1, both in the workflow-impl area. W-002 closes them.

**Sub-finding (a) — task→ADR mapping gap.** `_read_adr_status(task_id, repo_root)` in `src/orchestrator/workflow/cli.py:57` reads `docs/decisions/ADR-{task-id}.md`. For P1.3 this path is `ADR-P1.3.md` — which does not exist; the actual ADR is `ADR-009-skill-frontmatter-and-loading.md`. The function returns `"none"`, and the `awaiting_architect_accept → awaiting_junior_impl` auto-trigger never fires. Architect-partner used `workflow override` (P1.3 commit `cfbf087`) to unblock.

**Sub-finding (b) — `record_override` cycle-counter bug.** Per ADR-008 Decision 11, `cycle` increments **only** on rework transitions, defined as `awaiting_architect_decision → awaiting_junior_impl`. The current impl at `transitions.py:188-191` gates on `to_state == AWAITING_JUNIOR_IMPL` alone — ignoring the from-state. P1.3's override (`awaiting_architect_accept → awaiting_junior_impl`) matched the to-state, so cycle incremented to 2 for a single-cycle task. The final `.workflow/P1.3.yaml` reads `cycle: 2` and is the durable evidence of the bug.

**P1.3 retro §5.2 watch item.** `load_skills` raises on any `.md` file under `config/skills/` whose frontmatter is missing or non-dict, including a benign future `README.md`. Optional inclusion per brief.

This plan is **code-only**. No ADR is drafted (see §5 push-back #1 for resolution-path rationale). Three atomic impl tasks + one landing task = 4 commits. The optional `verify-workspace` state-file divergence detection (brief §3 optional inclusion) is deferred to W-003 (see §5 push-back #2).

### W-002-3 — `load_skills` graceful skip of non-skill `.md`

- **What**: `load_skills` skips files where YAML frontmatter is absent OR parses to a non-dict, logging a debug-level skip rather than raising. Designing `adr_id: str | None` today and migrating later is two migrations; designing the right shape now bundles ADR-010 PLUS pre-resolves the multi-ADR question, both out of scope per brief. **Either we under-design (single-ADR field that needs reshape in W-003) or we over-design (multi-ADR field plus the semantics of "awaiting Accept of N-of-M ADRs" which the brief explicitly defers to W-003).** Path β has no such fork: the `adr` frontmatter key trivially extends to `adr: [...]` later via the W-003 multi-ADR work without schema migration.
- **(c) Path γ (filename includes task-id) is rejected for the reasons the brief enumerates** — breaks ADR-NNN-slug convention, requires renaming ADR-009, doesn't scale to one-ADR-multiple-tasks. The brief's con-list is sufficient; senior adds no additional reason.
