## 2. Tasks

### P8-2 (low-pri prereq, no ADR) — initialize memory + reentry schema in `_build_context`

- **What:** Call `init_memory_schema` then `init_reentry_schema` on the writer
  connection in `_build_context`, after `writer_store.init_schema()`; add a test
  pinning the factory DB's schema set; fix the test fixture's parallel gap.
- **Where:**
  - `src/orchestrator/api/app.py:1085–1097` — after `writer_store.init_schema()`
    (and alongside the existing `_init_auth_schema` / `_init_pipeline_schema` calls),
    add `init_memory_schema(writer_conn)` then `init_reentry_schema(writer_conn)`.
    Import sites mirror the existing local-import idiom at `:1090`/`:1095`.
    Functions: `memory/store.py:133` `init_memory_schema(conn)`,
    `reentry/store.py:24` `init_reentry_schema(conn)` — both
    `CREATE TABLE IF NOT EXISTS` idempotent.
  - **FK order is load-bearing:** memory **before** reentry, and both **after**
    `init_schema()` — memory tables FK to `rooms`/`events` (`memory/store.py:49,67,68,92`);
    `reentry_marker` has no FK (`reentry/store.py`), so order memory→reentry is the
    conservative, FK-safe sequence the brief mandates.
  - `tests/api/conftest.py:82–90` — add the same two init calls to the `ctx` fixture
    so fixture-built contexts carry the full prod schema set (closes the coverage hole
    where integration tests had to hand-init memory/reentry).
- **Why:** Brief #2. Fulfils **ADR-016 D5 / ADR-021 D5** (schema-init obligation);
  **no ADR amendment**. The intake's "production crash" is false — the subsystem is
  runtime-dead (zero route/dispatch callers, verified) — so this is a prerequisite
  hygiene fix, **not** a memory-wireup (that is the deferred slice with #7/#8).
- **Acceptance criteria:**
  - `_build_context` initializes memory + reentry schema on the writer conn, in
    order init_schema → memory → reentry; both idempotent (a second build over the
    same DB does not raise).
  - A new test asserts the built context's DB contains the memory + reentry tables
    (e.g., the `hypothesis` / `verified_knowledge` / `reentry_marker` tables exist).
  - The `ctx` fixture initializes the same set; existing integration tests that
    hand-init memory/reentry continue to pass (idempotent double-init is safe).
- **Out of scope:** wiring memory/reentry into any runtime path (deferred slice);
  #7 promotion TOCTOU; #8 `events(type)` index — **do not touch dead-code internals**.

### P8-6 — bounded per-pass snapshot read [amend ADR-011]

- **What:** Add a `count` fast-path + a windowed read to `EventStore`, and migrate
  the **per-pass re-dispatch** hot callers that currently re-read the full room only
  to count it or to slice its tail. **Do not bound the once-per-turn state-machine
  snapshot** — `next_room_state` legitimately scans deep history.
- **Where:**
  - `src/orchestrator/core/event_store.py:358` — add two **additive** methods beside
    `get_room_events` (no change to the existing method):
    - `count_room_events(room_id) -> int` (`SELECT COUNT(*) FROM events WHERE room_id=?`)
    - a windowed read returning events after the Nth, e.g.
      `get_room_events_since(room_id, after_count: int) -> list[Event]`
      (`… ORDER BY timestamp ASC, rowid ASC LIMIT -1 OFFSET ?`) — same ordering
      contract as `get_room_events` (`event_store.py:376`).
  - Migrate the **pure-count** `len(get_room_events(rid))` cursor markers →
    `count_room_events`:
    `api/app.py:1469, 1481, 1540`; `pipeline/runner.py:149, 190`.
  - Migrate the **pure-tail** `get_room_events(rid)[cursor:]` windows →
    `get_room_events_since`:
    `api/app.py:1500, 1524, 1556, 1567`; `pipeline/runner.py:160, 181, 228`.
  - **Leave full-read callers untouched** (deep-history is correct there): the
    once-per-turn snapshots feeding `next_room_state` (`rooms/runtime.py:104`,
    `agents/dispatch.py:80`), the dedup/result scans in `tools/executor.py:114,308`,
    the approval/discovery scans (`app.py:417,482,502,646`), and the read-route dumps.
- **Why:** Brief #6 (low-urgency). The re-dispatch loop re-reads the **entire** room
  up to 4× per turn just to count or tail-slice it → read/materialize creep linear in
  room age. The once-per-turn `next_room_state` snapshot stays full (the brief's
  explicit guardrail: bound the dispatch/excerpt path, not state-machine evaluation).
  Not a token leak — `MAX_SNAPSHOT_EXCERPT_CHARS = 8000` already caps the LLM excerpt
  (`agents/selection.py:30,190`, ADR-033) and is untouched.
- **Acceptance criteria:**
  - Per-pass re-dispatch read cost is flat in room age (count via SQL `COUNT(*)`;
    tail via `OFFSET`, not full-fetch-then-slice).
  - `next_room_state` / trigger-evaluation semantics **unchanged** (still receives
    the full once-per-turn snapshot); `MAX_SNAPSHOT_EXCERPT_CHARS` cap unchanged.
  - The two new `EventStore` methods are additive (existing `get_room_events`
    byte-identical); behavior parity test: `get_room_events_since(rid, n)` equals
    `get_room_events(rid)[n:]`, and `count_room_events(rid)` equals
    `len(get_room_events(rid))`.
- **Out of scope:** bounding the `next_room_state` snapshot; any `events(type)`
  index (#8, deferred); changing the 8k excerpt cap; the read-route full dumps.

### P8-1 (mandatory) — derive room state from the event stream + fix create-seed [amend ADR-012]

- **What:** (a) Derive a room's current state from its `state_transition` event
  stream via a pure reducer seeded from the template `default_initial_state`, and use
  the derived state at the dispatch + snapshot sites (instead of the stale
  `rooms.state` column / stale in-memory `Room`). (b) Fix `_create_room` to seed the
  template's `setup`, not the model default `"open"`.
- **Where:**
  - **(a) reducer:** add a pure function deriving state from events — fold the
    `state_transition` events (`StateTransitionMeta.new_state`, `core/event.py:304`)
    in `(timestamp, id)` order, returning the latest `new_state`, else the seed.
    The seed is the room's `default_initial_state` (`rooms/templates.py`). Place it
    respecting layering (`rooms → core`/`agents` allowed; `core`/`agents`/`skills →
    rooms` forbidden, ADR-012 D7) — `rooms/` is the natural home; `derived/snapshot.py`
    already computes `last_state_transition` (`snapshot.py:185–196`) and may consume
    the reducer if the layering permits, else the turn driver derives and passes it.
  - **Use sites (replace stale reads):**
    - the HTTP turn path — `api/app.py:1465` fetches `room` once; derive current
      state from the event stream at turn entry and dispatch against the derived
      state (the frozen `Room` is rebuilt with the derived state, or the derived
      state is threaded to `select_dispatch_agents`).
    - `rooms/runtime.py:59,63` `select_dispatch_agents` reads `room.state` — must see
      the derived state.
    - `derived/snapshot.py:213` `room_state=room.state` — emit the **derived** state.
  - **(b) create-seed:** `api/app.py:1337` `_create_room` constructs
    `_CoreRoom(id=…, type=body.type)` → defaults `state="open"` (`core/room.py:42`).
    Seed `default_initial_state` instead (via `rooms/templates.py` `load_room` /
    `ROOM_TEMPLATES[type].default_initial_state` → `"setup"`).
- **Why:** Brief #1 (mandatory). **ADR-012 Rejected-Alternative-F** (lines 377–385)
  rejects "track state in `Room.state` only" — the event stream is the single source
  of truth (Principle 11); the `state` column is legal **only as a derived cache**,
  never authority. Today the column is seeded wrong (`"open"`, below `setup`) and
  never updated, so production rooms wedge below `setup` and **no `setup→…` rule can
  match** in the real cross-turn HTTP path. The amendment inscribes the derive-from-
  events contract + the cache (not authority) status of the column.
- **Acceptance criteria:**
  - In the **real cross-turn HTTP path**, a room transitions through its template
    state machine (e.g. research `setup → exploration` on first utterance) — the
    regression test exercises the HTTP turn path, **NOT** an in-memory `Room(state=…)`
    rebuild (the e2e trick that masked this; `tests/rooms/test_runtime.py:169–262`).
  - `_create_room` seeds `default_initial_state` (`"setup"`); a freshly-created room's
    persisted state column and its derived state both read `setup`.
  - Derived state == fold of the `state_transition` stream over the seed; the column
    is updated as a cache (or derived on read) — never read as authority where it
    could be stale (dispatch + snapshot sites).
  - `next_room_state` (pure reducer, unchanged) still drives transitions; no LLM in
    `rooms/` (constitutional test holds).
- **Out of scope:** changing transition rules / state sets; the four scaffold
  templates' agent rosters (separate content task per ADR-012 Amendment 2026-06-02);
  any column→event migration of historical rooms (none exist in prod).
