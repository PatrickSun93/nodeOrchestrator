# Senior plan — P6.8: GUI room list (`GET /rooms` + sidebar)

## 1. Context

Backlog #101, the **last** backlog feature. The GUI today only lets a user join an
existing room by typing its id (`RoomPicker`, `ui/src/components/RoomPicker.tsx`). This
slice adds a `GET /rooms` endpoint listing **all** rooms (`id`/`type`/`state`/`created_at`)
plus a frontend sidebar that renders the list, so the lobby can show existing rooms
instead of requiring a known id.

Scope is **architect-fixed (light)** per the brief Ratification (`docs/process/architect-briefs/P6.8.md`,
2026-06-15): list-all, **no `owner_user_id`, no owner-scoping this slice**. **No new ADR**
— the enumeration residual lands as a one-line note in ADR-039 D10's existing `RB-AUTHZ`
ledger (it makes an already-accepted authz posture observable, it flips no decision).
`plan_has_adr: false`; junior is dispatched directly after this plan, no Accept gate.

Two atoms, **BE → FE** (FE's `schema.ts` regen consumes BE's `openapi.json`):

- **P6.8-BE** — `EventStore.list_rooms()` + `GET /rooms` + openapi regen + the ADR-039 D10
  residual line. Touches the **auth-enumeration** surface → **full impl-stage dual-lens**
  (cross-family R0-A ∥ R0-B), per `requires_cross_family_review: true`.
- **P6.8-FE** — `listRooms()` client + sidebar list component. Established **light frontend
  track**: single-lens R0-A, **R0-B SKIP** per ADR-026.

Verify-cited against working tree @ HEAD `65dae89` (all brief §0 / §Cross-references claims
re-confirmed below; deltas from the brief noted inline).

## 2. Tasks

### P6.8-BE — `GET /rooms` (list all rooms), cross-family

**What**: add `EventStore.list_rooms() -> list[Room]` and a thin `GET /rooms` endpoint
returning `list[Room]`, regen `openapi.json`, inscribe the enumeration residual at ADR-039 D10.

**Where**:
- `src/orchestrator/core/event_store.py` — add `list_rooms()` directly after
  `list_room_ids()` (`event_store.py:396-403`). One query:
  `SELECT id, type, state, created_at FROM rooms ORDER BY created_at ASC`, build `Room` rows
  exactly like `get_room` (`event_store.py:381-394`) does per-row. Read-only; safe on a
  reader connection; returns `[]` on empty store. Docstring mirrors `list_room_ids`' shape.
- `src/orchestrator/api/app.py` — add `@app.get("/rooms", response_model=list[Room])` next to
  `_get_room` (`app.py:1343-1352`), **before** the `/rooms/{room_id}` route is fine (FastAPI
  matches the static path first regardless, but keep it adjacent for readability). Async
  handler, `run_in_executor(ctx.reader_executor, lambda: ctx.get_reader_store().list_rooms())`,
  return the list. **No `Depends`/principal param** — protected by being outside the
  middleware allowlist (`auth/middleware.py:36-41`, `PUBLIC_PATHS = {/login, /health}`), like
  every other room route. Docstring carries a one-line cross-ref to the ADR-039 D10 residual
  (the enumeration note).
- `src/orchestrator/api/openapi.json` — **regenerate** (dumped from `_make_test_app`,
  `app.py:2611`; title `"Orchestrator API [test]"`). No automated BE drift gate exists (brief
  §4, same as P6.7 C6) → a **deliberate impl step**. The only delta is the new `/rooms` GET
  path entry; `Room`/`RoomType` schemas already exist in the file.
- `docs/decisions/ADR-039-auth-identity-model.md` — append **one line** to the D10
  `RB-AUTHZ` bullet (the ledger at the `### D10` section, the `RB-AUTHZ` entry): name
  `GET /rooms` as a **read-surface instance** of the already-accepted `RB-AUTHZ` posture —
  any authenticated user can enumerate all room ids; `GET /rooms/{id}` already reads any room,
  this only removes need-to-know-the-id friction; owner-scoped visibility is future work. **Do
  not soften, do not reword the existing residual** — additive line only.

**Why**: brief §1 lean (b) (ratified — avoids the (a) `list_room_ids` + N×`get_room` N+1);
brief §2 (residual = ADR-039 D10 in-place note, **not** a new ADR, **not** an ADR-025
amendment — the route is additive and reuses the frozen `Room`); brief §4 (openapi regen).
`Room`/`RoomType` are already in the frozen wire contract (`core/room.py:19-45`,
`frozen=True, extra="forbid"`) → **zero new wire type**.

**Acceptance criteria**:
- `tests/api/test_read.py` — new test class (e.g. `§1.5 GET /rooms`): (a) lists all created
  rooms; (b) ordered `created_at ASC`; (c) **empty store → 200 `[]`** (not 404); (d) each item
  is a full `Room` (`id`/`type`/`state`/`created_at`). Follow the existing `client` fixture +
  `client.post("/rooms", ...)` setup pattern (`test_read.py:26-65`).
- **Store-level test** for `list_rooms()` (per brief §3, "if §1(b): a store-level test too"):
  empty → `[]`; multiple rooms → all returned in `created_at ASC`. Mirror existing
  `event_store` tests in `tests/core/`.
- **Auth assertion (the cross-family lens)**: add `("GET", "/rooms")` to `PROTECTED_ROUTES` in
  `tests/api/auth/test_constitution.py:195-204` so the parametrized `test_unauthenticated_gets_401`
  covers it (401 when unauthenticated). This is the load-bearing auth-enumeration assertion.
- `openapi.json` regenerated and committed; `git diff` shows **only** the additive `/rooms`
  GET path (no schema churn, no reordering of unrelated entries).
- ADR-039 D10 gains exactly one additive line; the existing `RB-AUTHZ` text is byte-unchanged.
- Full gate green: ruff + mypy (`files=src,tests`) + pytest.

**Out of scope**: any `owner_user_id` column / owner-scoping / per-user filtering; any change
to `PUBLIC_PATHS`; any write path; pagination / filtering query params; touching `_get_room`
or `list_room_ids`; any new `LLMPurpose` (this is a pure DB read, zero LLM); FE work.

### P6.8-FE — sidebar room list, single-lens R0-A (R0-B SKIP)

**What**: add a `listRooms()` API client function and a sidebar/list component that renders
all rooms and joins on click, augmenting the manual-id `RoomPicker` in the lobby.

**Where**:
- `ui/src/api/client.ts` — add `export function listRooms(): Promise<Room[]>` calling
  `request<Room[]>(\`${BASE}/rooms\`)`, mirroring `getRoom` (`client.ts:66-68`). `Room` is
  already imported/re-exported (`client.ts:5`).
- `ui/src/api/schema.ts` — **regenerate via `npm run codegen`** (consumes BE's `openapi.json`).
  `npm run codegen:check` (`package.json:18`) is the freshness lock and will fail if stale.
- `ui/src/components/RoomList.tsx` (new) — fetch via `listRooms()` on mount; render each room
  with **humanized** `type` and `state` through `roomTypeLabel` / `roomStateLabel`
  (`ui/src/uiStrings.ts:116-122`) — **no raw wire vocab** (the ADR-026 FE-checklist invariant).
  Click a room → join via `setRoom(room.id, room.type)` (`store.ts:33,104`), the same join
  action `RoomPicker` uses. Empty list → a friendly empty-state (humanized, no raw string).
- `ui/src/App.tsx` — render `RoomList` in the lobby block alongside `RoomCreate` + `RoomPicker`
  (`App.tsx:156-160`). The brief frames it as "augmenting/complementing" the manual-id
  `RoomPicker`; **keep `RoomPicker`** (replacement is not required — adding the list is the deliverable).

**Why**: brief §3 Atom 2 + §5 FE lens. Light frontend track (ADR-026): view+intent only,
binds-API-only, `ui_strings` no-raw-vocab, codegen-fresh.

**Acceptance criteria**:
- `ui/src/components/RoomList.test.tsx` (vitest): (a) renders rooms from a mocked `listRooms`
  with humanized type/state (assert the human label, not the raw key); (b) clicking a room
  calls `setRoom` with its id+type; (c) empty result → friendly empty-state. Follow the
  existing component-test pattern (`RoomView.test.tsx`, `ProgressPanel.test.tsx`).
- FE gate green: `npm run gate` (lint + format:check + typecheck + test + **codegen:check**).
- No raw wire vocabulary rendered (ADR-026 D3 / HR#3) — every `type`/`state` goes through
  `uiStrings`.

**Out of scope**: deleting/replacing `RoomPicker`; any new wire type or schema edit beyond the
codegen regen; routing/state-machine logic; owner/filtering UI; styling-system additions beyond
a CSS module mirroring existing components.
