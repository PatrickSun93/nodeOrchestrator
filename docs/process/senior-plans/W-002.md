## 1. Context

P1.3 was the first task to exercise `awaiting_architect_accept` with an ADR drafted alongside the plan. The harness surfaced exactly one cluster (RC-11) with two sub-findings, both predicted by W-001 retro §8 #1, both in the workflow-impl area. W-002 closes them.

**Sub-finding (a) — task→ADR mapping gap.** `_read_adr_status(task_id, repo_root)` in `src/orchestrator/workflow/cli.py:57` reads `docs/decisions/ADR-{task-id}.md`. For P1.3 this path is `ADR-P1.3.md` — which does not exist; the actual ADR is `ADR-009-skill-frontmatter-and-loading.md`. The function returns `"none"`, and the `awaiting_architect_accept → awaiting_junior_impl` auto-trigger never fires. Architect-partner used `workflow override` (P1.3 commit `cfbf087`) to unblock.

**Sub-finding (b) — `record_override` cycle-counter bug.** Per ADR-008 Decision 11, `cycle` increments **only** on rework transitions, defined as `awaiting_architect_decision → awaiting_junior_impl`. The current impl at `transitions.py:188-191` gates on `to_state == AWAITING_JUNIOR_IMPL` alone — ignoring the from-state. P1.3's override (`awaiting_architect_accept → awaiting_junior_impl`) matched the to-state, so cycle incremented to 2 for a single-cycle task. The final `.workflow/P1.3.yaml` reads `cycle: 2` and is the durable evidence of the bug.

**P1.3 retro §5.2 watch item.** `load_skills` raises on any `.md` file under `config/skills/` whose frontmatter is missing or non-dict, including a benign future `README.md`. Optional inclusion per brief.

This plan is **code-only**. No ADR is drafted (see §5 push-back #1 for resolution-path rationale). **Four** atomic impl tasks + one landing task = **5 commits** (revised from original 4 to absorb architect-routing Y2→β; see §5 push-back #3 for the new W-002-2b atomic). ### W-002-3 — `load_skills` graceful skip of non-skill `.md`

- **What**: `load_skills` skips files where YAML frontmatter is absent OR parses to a non-dict, logging a debug-level skip rather than raising. Files with frontmatter that parses to a dict but fails schema validation **continue to raise** — the distinction is "no frontmatter at all" vs "broken frontmatter."
- **Where**:
  - Modify: `src/orchestrator/skills/loader.py` — `_parse_frontmatter` currently raises `SkillError` on (a) missing opening fence, (b) unclosed fence, (c) non-dict YAML. Change semantic: (a) and (c) now signal "not a skill file, skip" (return a sentinel `None` or a typed `_NotASkillSentinel`); (b) — unclosed fence — continues to raise (a file that opens a fence and never closes it is malformed, not a non-skill file). The caller `load_skills` checks for the skip sentinel and uses `logging.getLogger(__name__).debug(...)` to record the skip with the path.
  - Extend: `tests/skills/test_loader.py` — add tests for the three new behaviors: a `README.md` with no frontmatter is skipped (load returns the other valid skills, no raise); a file whose frontmatter parses to a scalar string is skipped (debug log emitted); a file whose frontmatter parses to a valid dict but fails schema validation still raises (regression test).
  - **No change to `docs/decisions/ADR-009-skill-frontmatter-and-loading.md`** — Decision 1's prose says "Each skill is one file under `config/skills/<category>/<id>.md`"; treating non-skill files as skips is consistent with that decision, not contradictory (non-skill files are not skills; the loader correctly omits them from the returned dict). If R0-A-on-plan flags this as needing an ADR-009 amendment, I'd accept — but my read is no.
- **Why**: brief Architect-settled decision §4 (optional skills fix); P1.3 retro §5.2 (non-skill `.md` finding watch).

- **Acceptance**:
  - `load_skills(directory)` returns the same dict shape as today; the only behavioral change is which files contribute to it.
  - Sentinel design: I prefer a typed sentinel class (`class _NotASkillFile: pass`) over `None` because `None` collides with "valid dict but empty" (which Pydantic would reject downstream anyway, but the boundary is cleaner with a distinct type). One module-level `_NOT_A_SKILL = _NotASkillFile()` singleton; `_parse_frontmatter` returns `tuple[dict[str, Any] | _NotASkillFile, str]`; `load_skills` checks `isinstance(..., _NotASkillFile)`.
  - Debug logging: `logger = logging.getLogger(__name__)`; the skip emits `logger.debug("skipping non-skill file: %s", md_path)`. **No stdout pollution** (brief requirement). Default Python logging level is WARNING, so the debug message is invisible unless the operator configures DEBUG. Tested via `caplog.at_level(logging.DEBUG)`.
  - Unclosed-fence files (a file that starts with `---` but never closes) **continue to raise** `SkillError` — these are malformed-not-absent. Tested.
  - Schema-validation failure (frontmatter present and parses to dict, but Pydantic rejects) **continues to raise** `SkillError`. Tested.
  - File-id-mismatch (frontmatter present, parses, validates, but `id != filename stem`) **continues to raise** `SkillError`. Tested.
  - Duplicate-id (two valid skills with same `id` field) **continues to raise** `SkillError`. Tested.
  - All 75 existing skills tests remain green.

- **Out of scope**:
  - Plugin or external skill source discovery (P3 territory).
  - A CLI to list skipped files (informational only at the loader; if surfaced operationally, that's a separate task).
