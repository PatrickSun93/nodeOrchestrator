# P6.2 — bug-fix slice: OpenAI empty tool-args (C1) + missing call-time transient fallback (D1)

## 1. Context

Two code-review bugs, both verify-cited against current `main` by the architect-partner
(`docs/process/architect-briefs/P6.2.md`) and ratified 2026-06-11. Both are **pure bug-fixes
that make code conform to an existing inscribed decision** — neither changes a contract, so
**no new ADR** (`plan_has_adr=false`). This slice ships them as **two independent atoms,
two commits, either order**. Both carry `requires_cross_family_review=true` → full impl-stage
dual-lens; **D1 squarely earns the cross-family lens** (it touches the LLM fallback-audit
boundary the agy-cli review just hardened).

- **C1 — OpenAI-compatible empty tool_call arguments.** `_parse_chat_completion`
  (`src/orchestrator/llm/providers/openai_compatible.py:273-274`) does `json.loads(args_raw)`
  on the raw arguments string. The OpenAI-compat *no-arg* convention emits `arguments: ""`
  (vLLM / some DeepSeek / Ollama tool modes); `json.loads("")` raises `JSONDecodeError`
  → re-raised as `PermanentProviderError("malformed tool_call")` at `:282`. Because it is
  **Permanent**, it also defeats fallback (ADR-002 D4) → a no-arg tool call kills the turn.
  Empty/blank is **not** malformed; it means "no parameters" = `{}`.

- **D1 — missing call-time transient fallback.** ADR-002 **Decision 4**
  (`docs/decisions/ADR-002-llm-three-layer-config.md`, "Fallback only on transient / unhealthy
  errors") inscribes: *"the router walks the chain on … (at call time) `TransientProviderError`
  from the call itself."* Only the **health_check (pre-call)** half is implemented + tested
  (`tests/llm/test_e2e_fallback.py`). `RealLLMRouter._async_call` (`src/orchestrator/api/llm_adapter.py:62-74`)
  calls `provider.call()` **exactly once** and lets any `TransientProviderError` propagate;
  `grep` confirms **nothing in `src/` catches it** (only docstrings + raise sites reference it).
  A 429 / 5xx / timeout on an otherwise-healthy primary kills the turn even when a healthy
  fallback is configured. The fix makes code do what D4 already says → **conformance, not
  amendment.**

Architect ratification (brief §"Architect ratification — 2026-06-11"): C-lean for C1 (keep
`PermanentProviderError` for a *missing* `arguments` key — `None ≠ empty-string`); chain-exhaustion
**(b)** for D1 (`NoSuitableModelError` + trace); a lightweight ADR-002 D4 "Implemented" note for D1
(no Accept gate); slice = C1 + D1. **Mechanism for D1 is the senior's design call — settled in §5
as D-mech-A.**

## 2. Tasks

### P6.2-C1 — empty/blank tool_call arguments string → `{}`

- **What**: In `_parse_chat_completion`, treat an empty- or whitespace-only `arguments`
  *string* as "no parameters" (`{}`); preserve `PermanentProviderError` for genuinely
  malformed JSON and for a *missing* `arguments` key.
- **Where**: `src/orchestrator/llm/providers/openai_compatible.py:273-274` (the
  `args_raw = …` / `arguments = …` lines inside the `for tc in message.get("tool_calls")` loop).
- **Why**: ADR-002 D4 (a spurious `PermanentProviderError` defeats fallback + kills the turn);
  `ToolCall.arguments` is a non-optional `dict[str, Any]` (`src/orchestrator/llm/types.py:152-161`),
  so `{}` is the only structurally valid target for "no params". The existing `None`/falsy branch
  already normalizes to `{}`; this extends that normalization to empty/blank strings. Architect-ratified
  **C-lean**.
- **Acceptance criteria**:
  1. A `strip()`-style guard is added so `json.loads` runs only on a **non-blank** string;
     `""` and `"   "` → `{}`. Illustrative shape (not prescriptive on formatting):
     `arguments = json.loads(args_raw) if (isinstance(args_raw, str) and args_raw.strip()) else (args_raw or {})`.
  2. A genuinely malformed body (e.g. `"{bad"`) **still** raises `PermanentProviderError`
     (the `except (KeyError, json.JSONDecodeError, ValidationError)` at `:282` is untouched).
  3. A **missing** `arguments` key still raises `PermanentProviderError` (do **not** widen —
     `None`/absent ≠ empty-string; this is the ratified scope boundary).
  4. Fail-on-revert test (contributing.md Q5) in `tests/llm/test_openai_compatible_provider.py`:
     a `tool_calls` entry with `arguments: ""` (and a second with `"   "`) → assert the parsed
     `ToolCall.arguments == {}` and **no** `PermanentProviderError`; keep a `"{bad"` case asserting
     `PermanentProviderError` still fires. **Reverting the guard must fail the empty-args assert.**
- **Out of scope**: the missing-`arguments`-key case (stays `PermanentProviderError`); any change
  to `ToolCall` / `types.py`; the `except` clause at `:282`; anything in the `.call()` HTTP path.

### P6.2-D1 — call-time transient fallback in `RealLLMRouter._async_call`

- **What**: When the selected provider's `.call()` raises `TransientProviderError`, walk to the
  next viable model in the chain (ADR-002 D4 call-time half). `PermanentProviderError` propagates
  unchanged (no fallback). All-viable-transient → `NoSuitableModelError` + decision_trace
  (ratified exhaustion option **(b)**). Plus the ADR-002 D4 "Implemented" note.
- **Where**:
  - `src/orchestrator/llm/router.py` — add a function exposing the **ordered list of all viable
    routes** for the effective chain (suggested name `select_viable_routes`), each a `RouteResult`
    with `model_id_requested = chain head` (= `agent_config.default_model`). Empty viable set →
    raise `NoSuitableModelError` with the same trace shape as the existing exhaustion raise
    (`router.py:284-287`).
  - `src/orchestrator/api/llm_adapter.py:62-74` (`RealLLMRouter._async_call`) — iterate the viable
    routes, calling each `.call()` until success / `PermanentProviderError` / exhaustion.
  - `docs/decisions/ADR-002-llm-three-layer-config.md` — append a dated "Implemented" amendment note
    under `## Amendments` (style/weight of the existing ADR-023 / agy-cli notes).
- **Why**: ADR-002 D4 (call-time `TransientProviderError` → next-in-chain — currently dead code-path);
  the audit contract `model_id_requested(head) != model_id_used(fallback)` (`RouteResult` docstring
  `router.py:55-66`; `LLMResponse` `types.py:223-230`) the agy review hardened; no-double-actuation
  is guaranteed by ADR-003 + the constitutional spine (a transient `.call()` produced **no**
  `LLMResponse` → nothing actuated; tool execution is downstream of the LLM response, never inside
  `provider.call()`).
- **Mechanism (senior's call): D-mech-A** — see §5 for the rationale and the back-compat constraint
  on `select_model_and_provider`.
- **Acceptance criteria**:
  1. **Router stays pure**: the new `select_viable_routes` makes **zero** `provider.call()`
     (health_check only), exactly like `select_model_and_provider`. The `.call()` loop lives in the
     **adapter** (call-path), not the router — `router.py:15` ("zero LLM calls") and the constitution
     tests (`tests/llm/test_constitution.py::test_constitution_override_path_makes_no_llm_call`, and the
     `select_model_and_provider`-absent structural tests across `tests/{mcp,plugins,tools}/test_constitution.py`)
     must still pass unchanged.
  2. **`select_model_and_provider`'s observable contract is preserved exactly** — same first-viable
     `RouteResult`, same `decision_trace` content, same `NoSuitableModelError` on exhaustion. Its
     ~30 callers in `tests/llm/test_router.py` + `tests/llm/test_e2e_fallback.py` must pass untouched.
     (Junior may factor the shared per-candidate evaluation into a private helper, or have
     `select_model_and_provider` delegate to `select_viable_routes(...)[0]` — **only** if first-route
     behavior + trace are provably identical. Either factoring is acceptable; the constraint is the
     unchanged observable contract, not the internal shape.)
  3. **Adapter loop semantics**: on `route.provider.call(...)` raising `TransientProviderError` →
     continue to the next viable route; on `PermanentProviderError` → **do not catch** (propagates,
     no fallback — D4 permanent semantics); on success → return that `LLMResponse`. Each route is
     called with `model_id_requested=route.model_id_requested` (= chain head).
  4. **All-transient exhaustion**: every viable route raised `TransientProviderError` → raise
     `NoSuitableModelError` with a `decision_trace` listing one entry per attempted route
     (`{model_id, provider_id, accepted: False, reason: "call-time transient: …"}`, mirroring the
     `RouteCandidate.asdict` shape consumed by audit) — ratified option **(b)**, not a re-raised
     transient.
  5. **Audit invariant**: when a fallback answers, the returned `LLMResponse` has
     `model_id_requested(head) != model_id_used(fallback)` — guaranteed by `RouteResult.model_id_requested`
     always being the chain head.
  6. **Fail-on-revert test** (contributing.md Q5), exercising `RealLLMRouter._async_call` end-to-end
     (suggested new home `tests/api/test_llm_adapter.py`; `tests/llm/test_e2e_fallback.py` already
     covers the *health_check* half — this covers the dead *call-time* half):
     - chain `[primary, fallback]`, **both health-pass**, primary `.call()` raises
       `TransientProviderError`, fallback returns content → assert the response is the **fallback's**
       and `response.model_id_requested(head) != response.model_id_used(fallback)`.
     - primary `.call()` raises `PermanentProviderError` → it **propagates**, fallback is **not**
       called (assert no fallback invocation).
     - **all** routes raise `TransientProviderError` → `NoSuitableModelError` is raised (with a
       non-empty `decision_trace`).
     - **Reverting the loop** (single `.call()`) must make the first sub-case fail (primary's
       transient propagates instead of the fallback answering).
     - Implementation note: this needs a provider double that raises a chosen `ProviderError`
       subclass on `.call()`. Either extend `MockProvider` with an error-injection knob or use a
       small local fake in the test — junior's call; do not add provider-error behavior to
       production code.
  7. **ADR-002 D4 "Implemented" note**: append a dated amendment note recording (i) the call-time
     transient fallback is now implemented (D4's call-time half), and (ii) it is safe because
     `LLMProvider.call()` is side-effect-free content-gen (no double-actuation — a transient call
     produced no response, and tool actuation is downstream of the response, never inside `call()`;
     ADR-003). Same style/weight as the existing `2026-06-11 (agy-cli-provider) — Implemented` note.
     **This is a one-line clarification on an already-Accepted decision — `plan_has_adr=false`, no
     Accept gate.**
- **Out of scope**:
  - **Same-provider retry / backoff** — D4's semantic is *degrade to the next model*, not *retry the
    same one N times*. Backoff-retry would be new behavior (its own ADR) — explicitly **not** this fix.
  - **D-mech-B / D-mech-C** — not chosen (see §5). Do not put the `.call()` loop inside the router.
  - Any change to `provider.call()` error classification (the 429/5xx/timeout → `TransientProviderError`
    mapping at `openai_compatible.py:211-227` is already correct).
  - Enriching the router's pre-call `decision_trace` with call-time outcomes beyond the exhaustion
    `NoSuitableModelError` (the audit need is met by criteria 4-5).

## 5. Where I'd push back / design calls I'm making

**No blocking push-back.** The brief is fully ratified on all four decision points; the only open
item was mine to settle:

- **Mechanism = D-mech-A (router exposes ordered viable routes; adapter iterates).** Reasoning:
  1. **Health-checks the chain once up-front.** D-mech-B (re-invoke `select_model_and_provider`
     with an exclude-set per transient) re-runs `health_check` and re-walks the chain on *every*
     fallback step — O(N²) health probes for a chain of N, and a real provider's `health_check`
     may be a network probe. Mech-A health-checks the whole viable set once.
  2. **Router stays pure.** The `.call()` loop lives in the adapter (call-path); `select_viable_routes`
     makes zero `.call()` (health_check only), so `router.py:15` and the constitution tests hold.
     D-mech-C (loop inside the router) is rejected for exactly this reason.
  3. **Audit correct by construction.** Every `RouteResult.model_id_requested` is the chain head
     already (`router.py:150,280`), so a fallback answer yields `requested != used` with no extra
     plumbing — the same invariant the agy review guarded, now reachable on the *call-time* path.
  4. **Simpler control flow.** A pre-computed ordered list consumed linearly — no exclude-set state
     threaded across re-invocations.

- **Back-compat constraint I'm imposing (verify-cited):** `select_model_and_provider` has **30+
  test callers** (`tests/llm/test_router.py`, verified via grep) plus constitution-test references
  (`tests/llm/test_constitution.py:267`, `tests/{mcp,plugins,tools}/test_constitution.py`). Its
  observable contract MUST stay byte-identical (criterion D1.2). I left the *internal factoring*
  (standalone vs delegate-to-`select_viable_routes(...)[0]`) to the junior because both can preserve
  the contract; the constraint is the contract, not the code shape. If the junior finds the contract
  *cannot* be preserved under either factoring, that's a "decision you didn't make" → halt + surface,
  don't improvise.

- **Verify-cites for §1 claims** (pre-investigation discipline (a)):
  - "nothing in `src/` catches `TransientProviderError`" — verified: `grep -rn TransientProviderError src/`
    returns only `exceptions.py` (definition/docstring), provider *raise* sites
    (`openai_compatible.py`, `claude_code_cli.py`, `agy_cli.py`), and docstrings — **zero** `except`.
  - "`select_model_and_provider` called exactly once, transient propagates" — verified at
    `src/orchestrator/api/llm_adapter.py:62-74` (single `await route.provider.call(...)`).
  - "ADR-002 D4 inscribes call-time transient → walk the chain" — verified at
    `docs/decisions/ADR-002-llm-three-layer-config.md` Decision 4 ("(at call time)
    `TransientProviderError` from the call itself").
  - "amendment-note precedent" — verified: ADR-002 `## Amendments` already carries
