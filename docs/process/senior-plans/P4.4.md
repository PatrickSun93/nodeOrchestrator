## 1. Context

P4.3 (ADR-037) put a real per-call container under the *execution* of fetched plugin code. P4.4 is the orthogonal half: **how code is declared, enabled, version-managed, and admitted** — the *admission* boundary, not the *execution* boundary. The sandbox lowers the cost of being **wrong** about admission (bounded blast radius); it does not decide admission. A4 is still the load-bearing trust call.

The architect ratified all five DPs along the **lean** lines:

- **DP1+DP2 (coupled):** a **config-file registry MVP** that generalises today's fetched-only activation allowlist (`provenance.py::load_activation_registry`) into **one operator-authored YAML covering both roots** (`plugins/` operator-placed + `fetched_plugins/` fetched), with **boot-time-only** lifecycle (effect at next restart, zero new runtime-mutation surface). Hot-reload + runtime-store are **named, deferred residuals**. Admission = operator-authored registry entry (**consent-by-authoring**, NOT routed through the autonomy gate — it is an operator action, not an agent op, ADR-029 D3 / DP2c).
- **DP3 (A4) ⭐⭐:** keep the **shipped operator-admit + pinned-digest floor** (options b+c, `fetch.py` digest-before-extract + operator-authored entry). Signature/keyring is an **additive, separately-justified upgrade path — NOT default, NOT built in P4.4**. The **no-author-identity / no-revocation residual MUST be inscribed exactly as `RB-FS/NET` was** (ADR-031 D1a discipline).
- **DP4 (A5):** auto-namespace cross-plugin contributions `<plugin_id>__<name>` so they **coexist** (amend ADR-029 D6); keep the **per-call sandbox** (ADR-037 D3 already gives per-call inter-plugin isolation); persistent sandboxed-plugin process is a **deferred forward-watch**. **Pin the P4.7 management-endpoint contract in ADR-038, build no UI / no endpoint code.**
- **DP5:** new **ADR-038** (the inscribe-before-producer contract); plan-stage writes `reviews/P4.4/external-r0b-prompt.md` with two lenses (a: admission trust boundary; b: registry/lifecycle state-machine correctness).

**What exists today, verified (the substrate each atomic extends):**

- **One discovery seam, two roots:** `load_plugins(plugins_dir, fetched_plugins_dir=…, activation_registry_path=…)` (`loader.py:494`). Operator-placed = directory presence (ADR-029 D5, no entry). Fetched = activation entry required (`loader.py:359-367`, fail-closed if absent, ADR-031 D4). Provenance is **host-set-by-which-root** and **un-launderable** (disjoint-root guard, `loader.py:531-550`; ADR-031 D3).
- **Proto-registry (fetched only):** `ActivationEntry{source_url, digest, plugin_subprocess_env}` + `load_activation_registry` (`provenance.py:43-137`) raises `ConfigError` on malformed YAML.
- **Collision = fail-closed refuse:** `_collision_check` (`loader.py:194-289`) refuses a second plugin re-declaring any role/skill/tool/tool_impl/mcp_server name — both host-collision **and** cross-plugin. The host-shadow check (a plugin tool_impl shadowing a host `local_tool` like sandboxed `read_file`) is the security-load-bearing one (`loader.py:253-262`).
- **`version` is dead weight:** `PluginManifest.version: str` (`schema.py:69`) is parsed but **never read** by any consumer. A3 makes it load-bearing.
- **Boot-time-only is already reality:** `load_plugins` runs once in `_build_context` (`app.py:255`). **And the fetched path is NOT bootstrap-wired** — `app.py:255-267` calls `load_plugins` with **no** `fetched_plugins_dir` and **no** `activation_registry_path`, so fetched plugins are currently **unreachable in production**. P4.4 wiring fixes this (P4.4-4).

### P4.4-1 — Unified plugin registry schema + loader (generalise the activation allowlist)

- **What:** Generalise `provenance.py`'s fetched-only allowlist into a **unified `PluginRegistry`** covering both roots. Rename `ActivationEntry`→`RegistryEntry`; add `enabled: bool` (default **true** — consent-by-authoring) and `version: str | None`; keep `source_url`/`digest`/`plugin_subprocess_env` as **fetched-only** fields. Add `load_plugin_registry(path) -> dict[plugin_id, RegistryEntry]` with **fail-closed validation** following the **existing `isinstance` discipline at `provenance.py:100-129`**: malformed YAML → raise `ConfigError`; an entry carrying `source_url`/`digest` is a **fetched** admission proof and an entry carrying neither is **operator-placed-shape** — but the entry does **NOT** declare provenance (provenance stays host-derived-by-root; an entry can never forge it).
  - **(absorbed R0-B b6a) Explicit runtime type-validation — frozen-dataclass type hints are NOT enforced at runtime.** `enabled` MUST pass `isinstance(enabled, bool)` (else YAML `enabled: "false"` → a non-empty **string**, truthy → **silent fail-open enable**; live-confirmed `isinstance("false", bool) is False`); `version` MUST be `str` or `None` (reject other types); each entry MUST **reject unknown keys** (`extra="forbid"` equivalent) — all three mirror the per-field `isinstance` guards already at `provenance.py:100-129`.
  - **(absorbed R0-B b6b) List format + duplicate-`plugin_id` detection.** The registry YAML is a **list** under a top-level key (matching today's `activations:` list shape, `provenance.py:91-99`), **not** a `plugin_id`-keyed mapping — PyYAML **silently keeps the last** value on a duplicate mapping key (live-confirmed). When building `dict[plugin_id, RegistryEntry]`, a **duplicate `plugin_id` raises `ConfigError`** (fail-closed; a mapping shape could not detect this).
- **Where:** `src/orchestrator/plugins/provenance.py` (+ `tests/plugins/test_provenance.py`). Keep `check_fetched_activation` semantics (fetched still requires digest-bearing entry).
- **Why:** DP1a/DP1b; ADR-038 D1. Generalises the proven shape (the brief's lean) without a runtime store.
- **Acceptance:** `RegistryEntry` is frozen, `enabled` defaults true, `version` optional; `load_plugin_registry` returns `{}` for absent/None path, raises `ConfigError` on malformed; a fetched entry missing `digest` or `source_url` raises (fail-closed); **`enabled` non-bool raises; `version` non-(str\|None) raises; an unknown entry key raises; a duplicate `plugin_id` raises** (all fail-closed, test-asserted incl. the `enabled: "false"` quoted-string case); strings-only env preserved; **no provenance/posture field is accepted from the YAML** (un-spoofable invariant, test-asserted). Pure data + validation — no loader-merge or app wiring yet.
- **Out of scope:** the enabled-gate in `load_plugins` (P4.4-2); namespacing (P4.4-3).

### P4.4-2 — enabled-gate + version-coherence in `load_plugins` (the boot-evaluated lifecycle)

- **What:** Thread the `PluginRegistry` through `load_plugins`. Per discovered candidate: look up its entry by `plugin_id`; **skip (do not load) any plugin whose entry sets `enabled: false`** — both roots. Preserve **operator-placed presence=opt-in**: an operator-placed plugin with **no** entry stays **enabled** (ADR-029 D5 unchanged). Preserve **fetched fail-closed**: a fetched plugin still requires a digest-bearing entry (absent → refused, ADR-031 D4 unchanged). **Provenance-coherence guard:** an entry whose admission-proof shape mismatches its plugin's host-derived root → **refuse that plugin** (loud). **Version-coherence (makes `version` load-bearing, A3):** for a fetched plugin, if the entry's `version` is set it MUST equal the bundle `manifest.version` → mismatch refuses. **NOTE the digest — not `version` — is the integrity anchor:** `manifest.version` is plugin-self-asserted, so this is an **operator-intent / update-consistency check** (catches the operator pinning the wrong version label for a digest), **not** a security barrier; `version` absent → no check is **fail-safe** (the digest still binds the bytes). **Malformed-registry posture:** a registry file that fails to parse → `load_plugins` loads **zero plugins** (refuse-all, loud) — the P4.3 `_resolve_sandbox_posture` parse-fail→fail-closed precedent at registry granularity; the *graceful* (no-crash) mechanism is wired in P4.4-4 (absorbed R0-B a3). **Absent registry** → today's shipped defaults (operator-placed by presence; fetched none).
- **(absorbed R0-A Y1) ⭐ Pin the enabled-gate PLACEMENT — short-circuit in the `load_plugins` LOOP, before `_load_plugin` is called.** Resolve the entry → on `enabled: false` **`continue`** in the candidate loop (`loader.py:588`), so `_load_plugin` is **never invoked** for a disabled plugin and **no non-code surface is ever constructed** — critically **no MCP session** (`_load_plugin` step 4 spawns a live `build_mcp_tool_registry_and_sessions_from_config` stdio subprocess *before* it returns; two live plugins ship MCP servers — `demo`→`demo_filesystem`, `insights`→`insights_db`). "Built-then-not-merged" is **not** acceptable: it would leak a started subprocess. Disabled = `_load_plugin`-never-called.
- **Where:** `src/orchestrator/plugins/loader.py` — the **enabled-gate in the `load_plugins` candidate loop before `_load_plugin`** (`loader.py:588`); the version/shape-coherence refusals inside `_load_plugin` (which already returns `None` before the outer `seen_*`/`merged` update, preserving atomic-merge) (+ `tests/plugins/test_loader.py`).
- **Why:** DP2a/DP2b; ADR-038 D2. The "state machine" is **registry-expressed, boot-evaluated** — no runtime transition engine (DP2b boot-only ⇒ no mid-turn `MCPSession` teardown; that is the liveness argument the boot-only lean rests on).
- **Acceptance:** disabled plugin (either root) is absent from the merged result **AND `_load_plugin` is never entered for it** (no MCP session started, no subprocess spawned — asserted in P4.4-5); operator-placed-no-entry still loads (backward-compat test); fetched-no-entry still refused; fetched version-mismatch refused (and version-absent → loads, fail-safe); malformed registry → empty result + WARNING (no crash, per P4.4-4); absent registry → identical to pre-P4.4 behaviour. The lifecycle is **boot-only** — no code mutates a running `AppContext`.
- **Out of scope:** namespacing; the composition-root wiring (P4.4-4).

### P4.4-3 — A5: cross-plugin namespacing `<plugin_id>__<name>` (coexistence, single-lens)

- **What:** Replace **cross-plugin** fail-closed-on-collision with deterministic **always-namespace**: every plugin contribution name (roles/skills/tools/tool_impls/mcp_servers) is merged as `<plugin_id>__<name>` (the MCP-namespacing analog). **KEEP fail-closed** for: (i) **host-collision** (a plugin name colliding with a host registry name — incl. the shadow-bypass check that a tool_impl must never shadow a host `local_tool`), and (ii) **within-plugin duplicate** names. Only the **cross-plugin** branch of `_collision_check` relaxes to namespacing.
- **(absorbed R0-A Y4 / R0-B b1 — architect resolved the mechanism) ⭐ Order-of-operations: host-collision + within-plugin checks evaluate the BARE name and REFUSE; namespacing applies ONLY to the cross-plugin merge.** The host-collision check — including the **shadow-bypass** guard `impl_name in host_local_tool_names` at `loader.py:253-262` — runs on the **bare** declared name *before* any prefixing. A plugin declaring `tool_impl: read_file` is **refused loudly** (it shadows the host sandboxed `read_file`), *not* silently coexisted as `plugin__read_file`. (The architect ratified the **conservative bare-name refusal** over R0-B's prefix-first "structurally-impossible-so-allow" reading: a plugin shadowing a host name is an authoring error the operator must rename, surfaced as a loud refusal.) Namespacing the cross-plugin set is a separate, later step.
- **(absorbed R0-A Y3) Re-characterise A5: gate-tier re-binding (fail-safe) + UX — NOT "UX-only."** Always-prefix **orphans host-pre-classifications** in `config/tools.yaml`: `word_count` (`config/tools.yaml:53`, rev-10→AUTO, the `demo` plugin's host-pre-classify path) becomes `demo__word_count` and the bare classification is orphaned → the demo's documented **AUTO_EXECUTE path silently downgrades to default-0 → HARD_CONFIRM**. Same for `context_summary` (`config/tools.yaml:57`, rev-10, the `context` plugin's `tool_impls` host-pre-classify path) → `context__context_summary`. Fail **direction is safe** (orphan → more gating, never less) so it is **not a trust finding** — but it is a real functional regression that the promotion-impact grep + re-binding MUST cover.
- **Where:** `src/orchestrator/plugins/loader.py` (`_collision_check` + the merge in `load_plugins`) (+ `tests/plugins/test_loader.py`). Run the **promotion-impact grep** (forcing function), **explicitly including the `config/tools.yaml` host-pre-classification re-binding**: `word_count`→`demo__word_count`, `context_summary`→`context__context_summary`; plus agent configs, test fixtures, docs binding any bare plugin contribution name. Update the re-bound `config/tools.yaml` classifications in this atomic.
- **Why:** DP4a; amends ADR-029 D6. **Single-lens but functionally-loaded** (gate-tier re-binding + UX), not purely cosmetic.
- **Acceptance:** two plugins declaring the same `echo` tool_impl **coexist** as `pluginA__echo` + `pluginB__echo`; a plugin tool_impl shadowing a host `local_tool` (e.g. `read_file`) → **the plugin is REFUSED** (assert the *plugin's rejection*, not merely "host `read_file` unchanged"); within-plugin dup still refused; namespacing is **deterministic** (always-prefixed, name independent of sibling collisions); the promotion-impact grep result is recorded and `config/tools.yaml` re-bound; **each demo's documented gate path still resolves post-namespacing** — `demo__word_count` resolves **AUTO** (re-bound host classification) and `demo`'s plugin-classified `text_stats`→`demo__text_stats` stays **HARD** (default-0, no host classification — fail-safe). **Caveat inscribed:** namespacing changes the tool names agents see (content/UX ripple) — confirmed by architect (§5 #3).
- **Out of scope:** runtime inter-plugin isolation (that is ADR-037 D3, unchanged — out of A5).

### P4.4-4 — Composition-root wiring (the registry + fetched root, fail-closed)

- **What:** Wire the unified registry into `_build_context`: pass the resolved registry + the `fetched_plugins/` root into the `load_plugins` call (today **both unpassed**, `app.py:255-267`). Extract a small `_resolve_plugin_registry(config_dir)` helper (the P4.3 RW4 / `_resolve_sandbox_posture` precedent, `app.py:172-198`) so the **parse-fail→fail-closed** branch is driven by a real function the wired-whole test exercises — not re-implemented inline.
- **(absorbed R0-B a3) ⭐ Graceful malformed → empty + WARNING, NOT a bootstrap crash.** `load_plugin_registry` *raises* `ConfigError` on malformed input; that exception is **caught in `_resolve_plugin_registry`** which logs a `WARNING` and returns an **empty registry** (exactly the `_resolve_sandbox_posture` pattern at `app.py:192-196`). The refuse-all posture (§5 #2) is achieved by **empty-registry → no fetched plugins activated + every operator-placed plugin still gated by its (now-absent) entry**; it must **not** propagate uncaught through `_build_context` (`app.py:255`) and crash the app. *(Refuse-all blast radius is the operator-confirmed cost — §5 #2 — but the failure mode is a loud graceful refusal, not a crash.)* **The wired-whole test drives the real `_resolve_plugin_registry`** (not a hand-built dict — the RW8-2 lesson).
- **Where:** `src/orchestrator/api/app.py:247-275` + the new `_resolve_plugin_registry` helper near `_resolve_sandbox_posture` (`app.py:172`) (+ `tests/plugins/` or `tests/sandbox/`-style wired-whole test that drives `_resolve_plugin_registry`).
- **Why:** DP1/DP2; ADR-038 D2. Without this, the fetched path stays unreachable (brief §0) and the registry has no production effect.
- **Acceptance:** `_build_context` passes both roots + the resolved registry; a wired-whole test drives `_resolve_plugin_registry(config_dir)` (not a hand-built dict) and asserts: absent `config/plugins.yaml` → today's defaults; **malformed → empty registry + WARNING + no exception escapes** (refuse-all, graceful); valid → entries applied. Disjoint-root guard (`loader.py:531`) still holds with the real `fetched_plugins/` path.
- **Out of scope:** any management endpoint (contract-only in ADR-038); a runtime-store overlay (deferred).

## 5. Where you'd push back (architect sub-decisions surfaced — I drafted a choice, confirm or redirect)

These are genuine forks the ratified leans did not nail to the field-level. I drafted the **conservative, shipped-posture-preserving** option for each so the junior can execute; **each is the architect's to confirm** (none is mine to decide):

1. **⭐ Registry default semantics (the biggest fork).** "Generalise the activation allowlist to cover both roots" admits two readings: **(A, my draft)** *preserve* operator-placed **presence=opt-in** — an entry is optional and defaults `enabled:true`; an entry can only *disable* (and carry future fields). Fetched stays entry-required (digest). vs **(B)** *uniform require-entry* — both roots need an entry to load; presence alone no longer admits. **I chose (A)** because (B) **reverses ADR-029 D5** (a shipped, ratified posture), forces a migration (every existing operator-placed plugin needs an entry or it stops loading), and the ratification language ("generalise", "annotate D5 presence→registry") reads **additive**, not reversing. **If you want the single uniform mental model (B), say so — it changes P4.4-2 + needs an explicit ADR-029 D5 amendment + a migration note.**

2. **Malformed-registry blast radius.** I chose **refuse-ALL plugins** (incl. operator-placed) on a parse-failure — the strict fail-closed posture, matching P4.3's parse-fail→fail-closed. The cost: one typo in `config/plugins.yaml` kills all plugins (loud). Alternative: refuse-fetched-only (operator-placed still load by presence). **Confirm refuse-all** — it is the safest but the most operationally brittle.

3. **Namespacing: always vs on-collision.** I chose **always-prefix** `<plugin_id>__<name>` (deterministic, MCP analog, matches the `<plugin>__<id>` form). The cost: it changes the names of **already-shipped** plugin tools, rippling into any `config/tools.yaml` pre-classification that binds a bare plugin tool name (P4.4-3 grep quantifies it). Alternative: namespace-only-on-collision (backward-compatible bare names, but a tool's name then changes when a sibling is added — non-deterministic). **Confirm always-prefix + accept the bare-name ripple.**

4. **`version` coherence assertion.** To make `manifest.version` load-bearing (A3) I introduced a **fetched** check: `registry.version`, if set, must equal `manifest.version` → mismatch refuses (fail-closed). This is a small new check **not explicitly in the brief**. **Confirm you want it** (it is the cleanest way `version` becomes load-bearing for the update model; without it `version` stays a label).

5. **Management endpoints: contract-only, zero impl.** I read DP4c as "**pin** the endpoint shape in ADR-038, build **no** UI **and no endpoint code** this slice."
