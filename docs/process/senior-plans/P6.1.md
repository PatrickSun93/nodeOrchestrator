# P6.1 — senior plan (event-order doc-drift + TOOL_FAILED excerpt leak)

## 1. Context

Two bugs were handed in from an earlier code-review and verify-cited by the
architect-partner in `docs/process/architect-briefs/P6.1.md`. The architect
ratified scope at the brief's tail (§"Architect ratification — 2026-06-11").
This plan implements exactly that ratified scope — **no new ADR, no Event-model
change, no rowid field, no substantive ADR-014/015 amendment**.

- **Bug A → A-i (close-as-already-decided + A0 doc-drift fix).** The derived-layer
  `(timestamp, id)` lexicographic tie-break is the **inscribed P1.6 decision**
  (`ADR-014 D2.5` / `ADR-015 D4`). The architect judged D4's precondition **not**
  invalidated by `ADR-030`'s position-anchored scan, so there is **no ordering bug
  to fix**. The only defect is documentation drift in one **store-layer** docstring.

- **Bug B → pure bug-fix + one-line ADR-note.** `agents/selection.py`'s
  excerpt untrusted-output exclusion is keyed on `TOOL_RESULT` only; an untrusted
  tool's `TOOL_FAILED` (clearest: MCP) leaks attacker-authorable bytes into the
  cross-agent system-block steering surface. Symmetric one-clause fix; tightens
  `ADR-034 D3-iv` / `ADR-035 D3-iii` intent.

**Resolved interpretation (read before A0 — flagged so reviewers don't mis-flag):**
the architect's ratification says "make the docstrings/comments match the inscribed
`(timestamp, id)` ordering." That phrasing names the **derived-layer** convention.
The A0 drift is in a **store-layer** docstring — `EventStore.get_room_events`
(`core/event_store.py:358-368`) — whose actual SQL is `ORDER BY timestamp ASC,
rowid ASC` (the **store's** inscribed insertion-order tie-break from the P1.5 R1
fix, commit `307a8fa`; design comment at `event_store.py:69-73`). So A0's correct
target for this docstring is **`(timestamp, rowid)`**, NOT `(timestamp, id)`. The
two layers carry **two deliberately different** orders: store = `(timestamp,
rowid)` (insertion-order), derived/API = `(timestamp, id)` (lex). The derived-layer
comments are **already correct** (`snapshot.py:186`, `decision_log.py:75`,
`digest.py:104`) and must NOT be touched. This is the one place the literal
ratification wording and the brief's A0 spec must be read together; the brief
(`P6.1.md` A0, lines 82-86) is explicit and authoritative.

Verify-cited findings (all confirmed against HEAD this turn):
- `get_room_events` docstring is wrong: claims `(timestamp ASC, id ASC)` (SQL is
  `(timestamp, rowid)`), names index `idx_events_room_ts_id` (real index is
  `idx_events_room_ts` on `(room_id, timestamp)`, `event_store.py:72`; the `_id`
  variant **does not exist** — grep-confirmed).
- `selection.py:170-176` exclusion checks `e.type == EventType.TOOL_RESULT` only;
  `TOOL_FAILED ∈ _EXCERPT_EVENT_TYPES` (`:86`) so it renders by default.
- Both `TOOL_FAILED` append sites carry `call_id` via `ToolResultMeta`
  (`mcp/execution.py:132-141`, `tools/executor.py:452-464`), and
  `_external_output_tool_result_call_ids` keys on the **TOOL_CALL's** `tool_name`
  (result-type-agnostic) — so widening the type set to `{TOOL_RESULT, TOOL_FAILED}`
  correctly excludes an untrusted tool's failure while leaving trusted-local
  failures rendered.

## 5. Where you'd push back

  reviewer note):** the `get_room_events` docstring target is `(timestamp, rowid)`,
  not `(timestamp, id)`. A reviewer skimming the architect's "match `(timestamp,
  id)`" wording could mis-flag the corrected docstring as wrong, or a junior could
  "fix" it the wrong direction (changing the SQL, or keeping `id`). Both are errors.
  The store's inscribed order is insertion-order via `rowid` (P1.5 R1, `307a8fa`);
  the brief A0 spec is explicit. I am proceeding on the brief's reading, not
  halting — this is disambiguation, not a new decision. If the architect intended
  the docstring to keep saying `id`, that would contradict the SQL and the brief;
  surface before merge if so.

  precondition stands; I am **not** planning any of the 9 sort sites, any `Event`
  change, or A-ii/A-iii. If a reviewer argues `ADR-030`'s position-anchored scan
  reopens the precondition, that is an **architect** routing call (A-ii separate
  slice), not in-cycle work — surface, do not absorb.
