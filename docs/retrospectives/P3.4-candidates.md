## RC-27 — No "replan-rework" state-machine transition (cycle++ only lands at `awaiting_junior_impl`)

**Surfaced:** 2026-06-03, at P3.4 cycle-1 → cycle-2 transition (Y2 → α wire-now ruled; the runtime tool-executor is a re-*design*, not a junior re-implement). Dev-harness (ADR-008). Surface only — worked around this cycle via a 3-step override; **a transition/CLI fix is the candidate**.

**Routing:** dev harness (`docs/decisions/ADR-008-workflow-state-machine.md` Decision 11; `src/orchestrator/workflow/transitions.py::record_override`).

**Observation:** ADR-008 Decision 11 increments `cycle` **only** on the rework override `awaiting_architect_decision → awaiting_junior_impl` (both `from`/`to` must match — `transitions.py:230-241`), and that same transition is the **only** one that re-stamps `cycle_started_at` (the cycle-boundary the artifact filter keys on, Decision 16). But a cycle-2 that is a **re-design** (new ADR + senior plan needed, not just a junior patch — the P3.4 Y2 case) must land at `awaiting_senior_plan`, not `awaiting_junior_impl`. There is **no** codified `awaiting_architect_decision → awaiting_senior_plan` rework transition, and `override` has no `--cycle` flag.

**Workaround used this cycle (recorded in `.workflow/P3.4.yaml` override_history):** a **3-step override sequence** — (1) `awaiting_junior_impl → awaiting_architect_decision` (restore true post-review state); (2) `awaiting_architect_decision → awaiting_junior_impl` (**the rework override — fires cycle++ → 2 AND re-stamps `cycle_started_at`**); (3) `awaiting_junior_impl → awaiting_senior_plan` (redirect to the plan stage; cycle 2 retained). This works (cycle=2 + boundary re-stamped) but is non-obvious and easy to get wrong (e.g. skipping step 2 leaves cycle at 1 and the boundary stale).

**Candidate remedies:**
- **(a)** Add a codified **replan-rework** transition `awaiting_architect_decision → awaiting_senior_plan` that also `cycle++` + re-stamps `cycle_started_at` (mirror the Decision 11 logic for the plan-stage target).
- **(b)** Add a `--cycle`-bumping flag (or a dedicated `workflow recycle` subcommand) so a re-design rework is one auditable step instead of a 3-override dance.

**Trigger to revisit:** the next time a cycle-N+1 is a re-design (needs a fresh plan/ADR), not a junior patch.

**Cross-references:** `.workflow/P3.4.yaml` override_history (the 3-step sequence + reasons); ADR-008 Decision 11 + Decision 16; `transitions.py::record_override`; `docs/process/reviews/P3.4/architect-routing-on-impl.md` (the stay-open-cycle-2 packaging).

## RC-28 — Plan-stage transition + ADR-status checks are NOT cycle-filtered → cycle-2 auto-advance cascades on stale cycle-1 plan/ADR

**Surfaced:** 2026-06-03, immediately after the RC-27 override sequence committed `awaiting_senior_plan` (cycle 2) on `main`. Dev-harness (ADR-008 / `cli.py` snapshot). Surface — observed the wrong advance, reverted via `git restore`; **a cycle-filter extension is the candidate**. Direct descendant of the P1.6 cycle-2 cascade (ADR-008 §530) that Decision 16 / RC-22 only **partially** closed.

**Routing:** dev harness (`src/orchestrator/workflow/cli.py::build_artifact_snapshot`; ADR-008 Decision 16).

**Observation:** W-006 / RC-22 (Decision 16) cycle-filters the **impl-stage** review reads (`plan-vs-impl.md`, `R0-A.md` — via `_review_file_in_cycle` against `cycle_started_at`, `cli.py:344-349`). But the **plan-stage** signals are **not** cycle-filtered: (i) the senior-plan-exists check and (ii) the ADR-status read (`_read_adr_status`). So with a freshly re-stamped cycle-2 boundary at `awaiting_senior_plan`, the **stale cycle-1 plan** (`senior-plans/P3.4.md`) + **already-Accepted cycle-1 ADR-027** still satisfy `awaiting_senior_plan → awaiting_architect_accept`. **Observed:** the post-commit hook's `workflow advance` wrongly advanced `awaiting_senior_plan → awaiting_architect_accept` on the very commit that recorded the override. Worse, since ADR-027 is **Accepted**, the *next* advance would cascade `awaiting_architect_accept → awaiting_junior_impl` — bypassing the cycle-2 plan + ADR-028 entirely.

**Compounding:** the cycle-2 plan is authored at a **distinct path** (`senior-plans/P3.4-cycle2.md`, per the cycle-2 brief's artifact-separation) — but the state machine keys the plan-exists check on `senior-plans/{task-id}.md` = `P3.4.md`. So the **real** cycle-2 plan is invisible to the transition, while the **stale** cycle-1 plan drives it. Net: **cycle-2 plan-stage state must be babysat manually** (restore stray hook advances; override to `awaiting_architect_accept` only once ADR-028 is Proposed + cycle-2 plan landed).

**Candidate remedies:**
- **(a)** Cycle-filter the plan-stage signals too: gate the senior-plan-exists check on a plan commit **since `cycle_started_at`**, and have `_read_adr_status` consider only the ADR referenced by the **in-cycle** plan (so a stale Accepted ADR from cycle-1 can't drive cycle-2).
- **(b)** Make the state machine cycle-path-aware: read `senior-plans/{task-id}-cycle{N}.md` for cycle N>1 (aligns the transition with the artifact-separation convention).
- **(c)** Minimum: document the "cycle-2 needs manual plan-stage state management" hazard in `.workflow/README.md` so the next operator doesn't trust auto-advance here.

**Trigger to revisit:** any cycle-2+ that re-enters the plan stage (RC-27's path). Until fixed, the operator must `git restore` stray hook advances and drive the plan→accept→impl transitions by override.

**Cross-references:** ADR-008 Decision 16 + §530 (the P1.6 cycle-2 cascade precedent RC-22 partially closed); `cli.py::build_artifact_snapshot` / `_review_file_in_cycle` / `_read_adr_status`; this cycle's `.workflow/P3.4.yaml`; [[statemachine-debt-status]] (orchestrator memory).
