# Senior plan — P4.3: container syscall/egress sandbox (the RB-FS/NET retirement)

## 1. Context

P4.2 shipped the heavy tool surfaces (B3 subprocess / B4 network / B5 mutation) and ADR-031 the Posture-B fetched-plugin executor — **each Accepting an honest `RB-FS/NET`-class residual on one named retirement path: the sandbox WRAPS the existing exec; the app-level scoping does not reverse** (ADR-031 D1a Reversibility; ADR-034 D2 forward-watch; ADR-035 D2). P4.3 is that retirement: it does **not** rebuild the execution substrate — it wraps it in an **OS container** with a real FS/net/syscall/UID/resource boundary. This is the Wave-2 opener (P4-roadmap §4) and the foundation P4.4 depends on.

**The architect ratified all 5 decision-surface points (DP1–DP5) — plan to these, do not re-litigate.** The load-bearing override of the brief: **DP1 = OS containers (Docker/podman), cross-platform** — Linux-only jailers (bwrap/nsjail/raw-ns) rejected because the product deploys cross-platform (mac/win/linux). The ratified set is inscribed in **ADR-037** (task P4.3-0).

**Plan-stage dual-lens absorbed (architect-routed 2026-06-05; `reviews/P4.3/R0-A-on-plan.md` 0🔴/2🟡, `R0-B-on-plan.md` 1🔴/5🟡).** The spine was confirmed sound + faithful to all 5 DPs; the 🔴 was the egress-allowlist **mechanism** (left as a §5.1 open call) — now ratified + pinned in this revision (the egress-constraint atomic P4.3-3 + ADR-037 D2/D3). ### P4.3-1 — Runtime detection + abstraction (`sandbox/runtime.py`)
- **What:** Detect the container runtime (`podman` then `docker`; prefer rootless/podman userns), probe daemon **liveness** (`<runtime> info` with its **own short timeout, ~2s** — R0-B Y3b), expose `SandboxRuntime` with `available() -> bool`, `run(spec) -> SubprocessResult`-shaped, a kill primitive (`<runtime> kill` + `rm -f`), and the per-call network/firewall primitives consumed by P4.3-3. Daemon-down → `available()==False` (does not raise); a hung `info` is bounded by the probe timeout (never hangs the writer).
- **Where:** `src/orchestrator/sandbox/runtime.py` (+ `__init__.py`); `tests/sandbox/test_runtime.py`.
- **Why:** ADR-037 D1; cross-platform.
- **Acceptance:** Detection probes podman→docker, first live wins; `available()` is **liveness, not CLI-presence** (present CLI + dead daemon → `False`); the probe has its own ~2s timeout; no exception escapes; container CLI is the only mechanism touched. Tests mock the probe (no live daemon in CI): both-absent, docker-present-daemon-down, podman-present-live, **probe-hangs→bounded-by-timeout**.
- **Out of scope:** Building container args (P4.3-2); the egress constraint (P4.3-3); posture (P4.3-5).

### P4.3-2 — Isolation profile builder + seccomp asset + mount stance (`sandbox/profile.py`)
- **What:** Build per-call container args from a `SandboxProfile`: FS (`--read-only` rootfs; **bind-mount ONLY `sandbox_root` rw**, nothing else; **`/var/run/docker.sock` NEVER mounted**; `/sys` read-only [Docker default]; private PID-ns [Docker default] + mask sensitive `/proc` paths e.g. `/proc/sysrq-trigger`); net (`--network none` deny-default OR an egress spec from P4.3-3); seccomp (see below) + `--cap-drop=ALL` + `--security-opt no-new-privileges`; `--user`/userns nonroot; `--memory`/`--cpus`/`--pids`; `--rm`. **Seccomp strategy (R0-B Y1 — PINNED): Docker/runtime default seccomp profile (curated blocklist baseline) AUGMENTED** with an explicit additional-deny set — a full default-deny allowlist is rejected (first-party pytest/ruff/git need a broad syscall set; an allowlist is brittle + high-maintenance — noted as the stronger-but-deferred tail, ADR-037 D5). **Enumerated additional denials (ship the concrete JSON asset):** `unshare`, `clone` (with `CLONE_NEWUSER`/`CLONE_NEWNET`/`CLONE_NEWNS`), `bpf`, `io_uring_setup`, `add_key`, `request_key`, `keyctl`, `ptrace`, `mount`, raw `socket`/`AF_PACKET`.
- **Where:** `src/orchestrator/sandbox/profile.py`; `src/orchestrator/sandbox/seccomp.json` (asset); `tests/sandbox/test_profile.py`.
- **Why:** ADR-037 D2; R0-B Y1 (seccomp pin), Y2 (mount stance).
- **Acceptance:** deny-default profile emits `--network none`; the FS profile bind-mounts only `sandbox_root` rw and emits **no** docker-sock bind; seccomp asset is the augmented profile denying every enumerated syscall; `--cap-drop=ALL` + `no-new-privileges` + nonroot + resource limits always present. Tests assert the arg-list shape per variant (no live container) + that the seccomp asset denies each enumerated syscall + that no profile variant ever emits a `/var/run/docker.sock` bind.
- **Out of scope:** Spawning (P4.3-4); the pinned-IP egress mechanism (P4.3-3).

### P4.3-3 — Egress-constraint mechanism: parent-pinned-IP per-call container egress (`sandbox/egress.py`)
- **What:** The load-bearing network-isolation boundary (R0-B 🔴 R1; architect-ratified §5.1 option (a)). Per call, constrain container egress to **exactly the parent-validated pinned IP:port**: (a) the parent computes the single validated pinned IP via `_resolve_and_validate` (`net_trust.py:79-122`) — for `web_fetch` the target, for `git_push` the resolved remote host; (b) the per-call container has **internal DNS disabled** (`--dns 0.0.0.0` / no resolver — DNS would bypass the pin); (c) egress is permitted to **only** that pinned IP:port via a **per-call ephemeral network + a daemon-side nftables/iptables egress rule** on the bridge forward chain; (d) **single-family pin** — the one resolved family (v4 or v6) is allowed, the other family's egress is blocked (no dual-stack escape). **Cross-platform honesty (ratified §5.1(d)):** on **native Linux** (rootless podman / native docker) the host-side per-call firewall is fully viable; on the **Docker Desktop VM** (mac/win) where the host orchestrator cannot reach the VM's firewall, `web_fetch` (http/https) routes through a **host-side filtering forward-proxy** constrained to the pinned IP, and any (runtime × tool) combination where neither a pinned firewall nor a proxy is viable (e.g. `git_push` over ssh on Docker Desktop) is **deny-default → fail-closed** (the tool fails loudly on that runtime — never silently unconstrained).
- **Where:** `src/orchestrator/sandbox/egress.py`; `tests/sandbox/test_egress.py`.
- **Why:** ADR-037 D2 (Network) + D3 (web_fetch reversal); R0-B 🔴 R1.
- **Acceptance:** Given a pinned IP:port, the builder emits a per-call network spec + the egress rule permitting only that IP:port; `--dns` disabled; the non-pinned family blocked; a non-viable (runtime × tool) combination resolves to deny-default→fail-closed (a typed signal the posture resolver surfaces loudly), never an unconstrained network. Tests (runtime mocked): pinned-IP rule shape; DNS-disabled present; v6-blocked-when-v4-pinned; Docker-Desktop-ssh→fail-closed path.
- **Out of scope:** The SSRF floor itself (reused from `net_trust`, unchanged as defense-in-depth); the proxy implementation detail beyond the allowlist contract.

### P4.3-4 — The one sandboxed-spawn interface (`sandbox/spawn.py`)
- **What:** `sandboxed_run(argv, *, cwd, env, timeout_s, max_bytes, profile) -> SubprocessResult` — build the container invocation (runtime + profile + egress), spawn **reusing the existing bounded-read + `run_sync` timeout + shielded-kill machinery** (`run_scoped_command`'s pattern — the timeout wraps the whole `docker run` incl. startup, so setup is inside the deadline), re-home the kill to **container kill** (`<runtime> kill` + `rm -f` — the subtree-kill retiring R3, **teardown shielded** so a timeout-cancel still reaps the container — no leaked container), **measure + log setup/teardown latency against a 3s-p95 target** (R0-B Y3a; the plan-vs-impl gate), and create/tear-down the per-call egress network (P4.3-3). **Daemon-dies-at-spawn** (available-at-probe but dead at run) raises `SandboxUnavailableError` and follows the same posture path (R0-B Y3b).
- **Where:** `src/orchestrator/sandbox/spawn.py`; `tests/sandbox/test_spawn.py`.
- **Why:** ADR-037 D3 (one seam, per-call, budget); D2 (subtree-kill → R3); R0-B Y3.
- **Acceptance:** Returns the `SubprocessResult` shape `run_scoped_command` returns (callers substitutable); bounded read at `max_bytes`; timeout kills the **container** (not a host pgid) and teardown is shielded (no leaked container on cancel); setup/teardown duration logged against the 3s-p95 target; per-call egress network created + torn down; runtime-unavailable **or** daemon-dies-at-spawn → `SandboxUnavailableError` (never a raw host spawn). Tests (runtime mocked): result-shape parity, timeout→container-kill, shielded-teardown-on-cancel, max_bytes bound, unavailable→raises, daemon-dies-at-spawn→raises.
- **Out of scope:** The posture decision (P4.3-5); wiring callers (P4.3-6/7/8).

### P4.3-5 — Posture + fail-mode + config (`sandbox/posture.py` + `config/sandbox.yaml.example`)
- **What:** The posture resolver: **default-on where the runtime is available**; **fail-closed by default** when unavailable (`SandboxUnavailableError` → `TOOL_FAILED`, loud surfaced log); explicit operator opt-in (`degraded_app_level: true`) to the today posture (raw `run_scoped_command` / in-process SSRF / current `apply_edit`) **LOUDLY LOGGED (`WARNING`) + surfaced on every degraded call** — never silent. **`available()` cached per turn (short TTL ~30s) so a wedged daemon fails fast — the first unavailable probe blocks subsequent calls in the turn without re-probing** (R0-B Y5b). **Config-parse failure (malformed `sandbox.yaml` / invalid `runtime` / missing keys) → FAIL-CLOSED** (same as runtime-unavailable + no opt-in — never a default that fails open) (R0-B Y5a). Config schema: `runtime` (auto|docker|podman), `image`, `egress_allowlist`, `degraded_app_level`.
- **Where:** `src/orchestrator/sandbox/posture.py`; `config/sandbox.yaml.example`; `tests/sandbox/test_posture.py`.
- **Why:** ADR-037 D4; R0-B Y5.
- **Acceptance:** available → sandboxed; unavailable + no opt-in → fail-closed (no host exec); unavailable + opt-in → degraded + `WARNING` every call; **config-parse failure → fail-closed** (test-asserted); `available()` cached per turn (repeated unavailable calls fail fast, no per-call probe timeout stack-up). A test asserts no path reaches a raw host spawn when unavailable-and-not-opted-in. The `.example` documents the opt-in as a conscious unsandboxed choice (ADR-031 D4 analog).
- **Out of scope:** The wiring (P4.3-6/7/8).
