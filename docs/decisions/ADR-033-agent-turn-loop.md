# ADR-033: Agent Turn-Loop — In-Turn Tool-Result Re-Dispatch + Loop Bound

**Status:** Accepted — 2026-06-04 (architect Peidong; senior-drafted for P4.1, the P4 capability opener). **Revised 2026-06-04 absorbing R0-A-on-plan architect-routing (`reviews/P4.1/R0-A-on-plan.md`, plan_commit a181f56 — 0R/3Y/10G, spine verified sound): Y1 → α, the liveness bound enumerated with ADR-028-D5 rigor + an overall turn-loop wall-clock deadline (D3/D4); Y2 → β, a minimal `cooldown_seconds=0` investigator agent bundled so the flagship chain runs live on landing (D5 roster note); Y3 → `snapshot_excerpt` bundled — the P1.4 deferral resolved so a re-dispatched agent sees its accumulated investigation (D2/D6 + the ADR-011 amendment).** Bundles proposed amendments accepted together with this ADR: **ADR-028 D3/D4** (code-intel tools + `log_event` → local MVP set; re-dispatch deferral resolved) and a **substantive ADR-011 amendment** (snapshot-per-pass + `snapshot_excerpt` populated-and-fed-to-the-LLM, resolving the P1.4 deferral). **R0-A-on-plan round-2 cleared the absorption (0R/1Y/6G + 1 forward-note); the architect routed R2-Y1 → pin the investigator's `autonomy_thresholds` explicit + conservative (`threshold_auto: 8`, D5) and R2-N1 → the `snapshot_excerpt` framing-intent note (D6).** Accepted 2026-06-04 by the architect after R0-A-on-plan round-2 cleared the absorption ("nothing blocks the ADR-033 Accept"); the ADR-028 D3/D4 + ADR-011 amendments are accepted together with this ADR. The impl-stage dual-lens R0-B (`requires_cross_family_review: true`) re-probes the widened liveness + `snapshot_excerpt` surfaces on the implementation.

**Scope:** Governs the **agent turn-loop** — the driver-level mechanism that feeds a turn's tool results back to the agent **within the same turn**, so an agent can chain *investigate → read-result → act → re-investigate* (the flagship bug-fix / code-review scenario, `handoff.md` §toolset 第一/二层). Inscribes: the loop **shape** (bounded-loop ≤N, the architect's §(a) ruling) and the documented bound `N` (D1); **what re-dispatches**, the per-pass `current_event` (the trigger), and `snapshot_excerpt` (the accumulated-investigation context fed to the LLM) (D2); the **termination test** — including an overall **wall-clock deadline** — + the confirm-gated-call interaction (D3); the **total single-writer liveness bound** enumerated with ADR-028 D5 rigor (the dominant `agents × provider timeout_s` term, the cross-room head-of-line block, the wall-clock deadline), the per-pass cap reconciliation, and the cooldown interaction (D4); the **B2 read-only code-intel tools** (`search_text`/`search_code`/`find_references`/`find_definition`) + `log_event`, in-process + sandboxed + bounded-traversal + trusted-not-interpreted, **and the minimal `cooldown_seconds=0` investigator agent** that exercises the loop live (D5); the **constitutional invariants under the loop** + the **substantive ADR-011 amendment** (snapshot-per-pass + `snapshot_excerpt` resolution) (D6). Does **NOT** govern: the autonomy gate decision logic (`score`/`decide_tier`/`emit_gate_decision`/`process_tool_calls` — **unchanged**; the loop re-runs the gate per pass, never changes it); a separate execution lane off the single writer (ADR-028 D5 — stays deferred); the heavier tool surfaces (subprocess B3 / network B4 / mutation B5 — each its own P4.2 slice); a post-confirm re-dispatch loop on `_post_confirm` (named future symmetry).

## Context

ADR-028 (the runtime tool-executor) shipped tool **execution** but left the agent loop **open at one end**: `execute_pending_tool_calls` appends `TOOL_RESULT`/`TOOL_FAILED`/`OBSERVATION` and **returns** — the agent reacts only on the *next* real turn's snapshot (ADR-028 D4's no-re-dispatch MVP). So an agent **cannot** do "read file → see contents → search for the symbol I found → see hits → open the reference" inside one turn. ADR-028 D4 deferred re-dispatch precisely to *"a follow-up that explicitly inscribes the loop bound — an ADR-011 touch-point."* This is that follow-up.

The substrate P4.1 reuses (verified `origin/main`, d878f26):
- `api/app.py::_write_and_turn` — the turn driver: `append(user_event)` → `run_turn(...)` → `execute_pending_tool_calls(window)` → publish. The loop lives **here** (the driver), wrapping `run_turn`/`dispatch_turn` + the executor; neither the executor nor `dispatch_turn` is rewritten.
- `rooms/runtime.py::run_turn` — snapshot → `next_room_state` (may append a `state_transition`) → load-time + dispatch-time agent filter → `dispatch_turn`.
- `agents/dispatch.py::dispatch_turn` — re-takes its own snapshot at entry (`event_store.get_room_events(room.id)`), evaluates `should_agent_speak` per agent, calls the LLM with `messages=[user: current_event.content]`, appends `UTTERANCE`, and routes any tool calls through the **unchanged** `process_tool_calls` (gate) → `TOOL_CALL` (AUTO) or `TOOL_CALL_PENDING` (COUNTDOWN/HARD).
- `agents/speaking.py::should_agent_speak` — cooldown is event-stream-driven: `elapsed_s = (current_event.timestamp − last_utterance.timestamp)/1000`; if `< cooldown_seconds` and `cooldown_seconds > 0`, the agent is suppressed (ADR-010 D2).
- `tools/local.py` — 3 read-only local tools (`get_current_time`/`read_file`/`list_files`) + the ADR-028 D3 sandbox-root trust boundary (`_check_path` resolve-then-containment, bounded read/output). `config/tools.yaml` already classifies `search_text`/`search_code`/`find_references`/`find_definition` at **rev 10 → AUTO** + `log_event` at **rev 8 → AUTO**, all currently `not_implemented` (fail-closed). ADR-033 builds the in-process impls.

**A substrate fact that shapes D2 (verified, load-bearing):** as shipped, `dispatch_turn` feeds the LLM **only** `current_event.content` (`agents/dispatch.py:112`); `build_agent_context` **ignores** the snapshot (`agents/selection.py:99` — `_ = snapshot`; `snapshot_excerpt` was deferred at P1.4). So as shipped, the only way an agent's LLM prompt *sees* a tool result is for that result event to be passed as `current_event`. **P4.1 resolves this (Y3 absorption):** it populates `AgentContext.snapshot_excerpt` and feeds it to the LLM, so a re-dispatched agent sees its **accumulated** investigation, not only the latest result. D2 keeps the latest result event as the per-pass **trigger** (`current_event`) and adds `snapshot_excerpt` as the **context** — the two roles are distinct.

## ⭐⭐ Constitutional carry-forward (NON-NEGOTIABLE — inscribed, not decided; per P4-roadmap §10)

The senior inscribes; the impl enforces; R0-A probes each.

1. **The loop is CODE-driven (routing = code).** The loop condition — *"did this pass append a new `TOOL_CALL` event, and are we under the bound N?"* — is **pure driver code**. **No LLM judges "should I loop again."** The LLM only generates content **within** each dispatched turn (which may contain tool calls). The re-dispatch trigger, the bound, and the termination test are all code.
2. **No new `LLMPurpose`.** A re-dispatched pass reuses the existing `AGENT_RESPONSE` turn primitive (`dispatch_turn`); the MCP interpret (if any pass calls an MCP tool) reuses the existing content-gen `TOOL_OUTPUT_INTERPRET`. "Agent reacts to a tool result" is **not** a new purpose — it is `dispatch_turn` re-run against a snapshot that now **includes** the appended result events. No new event type, no new purpose.
3. **Every pass routes the gate — the loop NEVER bypasses or re-decides autonomy.** Each pass's tool calls go through the **unchanged** `process_tool_calls`→gate→`AUTO_EXECUTE`-only-appends-`TOOL_CALL` path; the executor's `t4` (execute-on-`TOOL_CALL`-only) holds **per pass**. A `COUNTDOWN`/`HARD` call in a pass appends a `TOOL_CALL_PENDING` (no `TOOL_CALL`) → is **not** executed in-loop → uses the existing confirm-then-execute flow (ADR-030) out-of-band; **the loop does NOT wait for human confirm** (D3).
4. **Single-writer invariant preserved (ADR-028 D1/D5).** Re-dispatch stays **inline on the single writer** (the D5 MVP posture); a separate execution lane stays deferred. The loop multiplies the per-pass block by `(1+N)` — that bounded multiplier is the **named, inscribed** liveness surface (D4), not an accident.
5. **The loop TERMINATES and the single-writer block is absolutely BOUNDED.** Termination via the bound `N` **and** early-exit when a pass appends zero new `TOOL_CALL`s (D3); liveness via `(1+N) ×` the per-pass bound (D4).
6. **B2 = read-only, in-process, sandboxed, trusted-not-interpreted (D5).** In-process only (`os.walk`+`re`; **no** `grep`/`rg`/`git grep`/language-server — shelling out would smuggle in the deferred B3 subprocess surface); reuse the ADR-028 D3 trust boundary (sandbox root, `_check_path`, bounded output) + a **new bounded traversal** cap; local results are trusted → **not** interpreted (no `OBSERVATION`).

## Decisions

### D1. Loop shape — bounded-loop ≤N; `N = MAX_TURN_LOOP_PASSES = 4` (a documented constant)

Per the architect's §(a) ruling: the turn-loop is a **bounded-loop**, not a single-re-dispatch. After `run_turn` + the executor finish the initial turn (**pass 0**), the driver **re-dispatches repeatedly** until a pass appends no new `TOOL_CALL`s **or** `N` re-dispatch passes elapse. `N = 4` (`MAX_TURN_LOOP_PASSES`, a module-level constant in the driver). Total `dispatch_turn` invocations per turn ≤ **1 + N = 5**.

**Why bounded-loop, not single-re-dispatch:** the flagship investigation (`read_file` → `search_text` → `find_references` → `find_definition`/`log_event`) is a ≥3-hop chain; single-re-dispatch gives the agent exactly **one** reaction and cannot chain. **Why N = 4:** it covers the 第一/二层 flagship chain with one hop of headroom, while keeping the single-writer multiplier small and the liveness cost conservative (D4). `N` is the **inscribe-before-producer** constant every P4.2+ tool slice rides on; it is tuned by amending this ADR, never by ad-hoc code.

### D2. What re-dispatches — `dispatch_turn` per pass; the state machine runs once; `current_event` = the latest result of the prior pass

- **Pass 0** is the existing `run_turn` (snapshot → `next_room_state` → filter → `dispatch_turn`) followed by `execute_pending_tool_calls`. **Passes 1…N** call **`dispatch_turn` directly** (not `run_turn`): the state-machine evaluation (`next_room_state`, which may append a `state_transition`) runs **exactly once per turn** (pass 0). Re-running `run_turn` per pass would re-evaluate `next_room_state` against the unchanged (frozen) `room.state` and risk a **duplicate `state_transition`** — and is conceptually wrong: a state transition takes effect on the **next** turn (ADR-011 D2), not mid-loop. The in-turn loop is *within one room state*.
- **Filtered agents.** `dispatch_turn` needs the load-time + dispatch-time-filtered agent set that `run_turn` computes inline. P4.1 **extracts** that filter into a pure helper `select_dispatch_agents(room, available_agents)` in `rooms/runtime.py` (behavior-preserving); `run_turn` calls it (unchanged behavior) and the driver calls it once before the loop. This avoids duplicating the filter in the driver — single source of truth.
- **`current_event` (the trigger) per pass.** On re-dispatch pass `k`, the driver passes the **most-recent result-class event** (`TOOL_RESULT` / `TOOL_FAILED` / `OBSERVATION`) appended during pass `k−1`'s execution as `current_event`. Rationale: `current_event` is what `should_agent_speak` evaluates and what anchors the turn; the new result is the event the agent is reacting **to**. If a pass appended multiple results, the **last in store order** is chosen (deterministic). If a pass appended **no** result-class event, the loop terminates (D3).
- **`snapshot_excerpt` (the context) per pass — Y3 absorption, resolves the P1.4 deferral.** `dispatch_turn` re-takes its own snapshot at entry, so the full updated event log is visible. P4.1 populates `AgentContext.snapshot_excerpt` from that snapshot (a **bounded** rendering of the recent event slice — most-recent events up to a documented char cap `MAX_SNAPSHOT_EXCERPT_CHARS`) and `dispatch_turn` feeds it into the LLM prompt (in the system block, alongside persona + skill bodies). So a re-dispatched agent sees its **accumulated** investigation (`read_file` content → `search_text` hits → `find_references` …) in one prompt, not only the latest result. This is a `build_agent_context` (`agents/selection.py:99`) + `dispatch_turn` (`agents/dispatch.py:112`) change + an `AgentContext` field — the **substantive ADR-011 amendment** (D6). **Trust framing unchanged:** the excerpt is *context*, not a gate input; every tool call the agent then emits still routes the unchanged gate (carry-forward #3); local results stay trusted-not-interpreted, MCP results stay interpreted (`OBSERVATION`) exactly as before — `snapshot_excerpt` only brings the already-in-room events into the in-turn prompt one pass earlier.

**Reconciliation (trigger vs context):** `current_event` = the latest result (the per-pass **trigger** that fires `should_agent_speak` + anchors the turn); `snapshot_excerpt` = the bounded recent history (the **context** the agent reasons over). Both are needed: the trigger makes the agent *speak* this pass; the excerpt lets it reason over *all* prior-pass results, not just the last.

### D3. Termination test + confirm-gated-call interaction

The loop terminates when **any** of:
1. **Zero new `TOOL_CALL` events** were appended by the just-completed pass (the agent stopped calling tools — investigation done). This is the primary early-exit.
2. **No new result-class event** exists to pass as the next `current_event` (defensive: e.g., every new `TOOL_CALL` was a double-execution-guard skip → nothing fresh to react to).
3. **`N` re-dispatch passes** have run (the hard pass-count bound, D1).
4. **The wall-clock deadline `MAX_TURN_LOOP_WALL_CLOCK_S` is reached** (Y1 absorption — the absolute wall-clock bound). The driver stamps `loop_start = time.monotonic()` before pass 0 and, **at each pass boundary** (before starting a re-dispatch pass), exits if `time.monotonic() − loop_start ≥ MAX_TURN_LOOP_WALL_CLOCK_S`. **`MAX_TURN_LOOP_WALL_CLOCK_S = 120.0`** (a documented constant). This bounds the loop's **absolute** wall-clock — not merely the `(1+N)` *factor* (D4) — so the single-writer occupancy is capped even if each pass's agent-LLM term is large. **Honest scope of the guarantee:** the deadline is checked **between** passes, not mid-pass (an in-flight LLM call is not interrupted — the project has no async cancellation surface here, ADR-011 D1), so the absolute wall-clock is ≤ `MAX_TURN_LOOP_WALL_CLOCK_S` + **one** final pass's worst-case block (D4). A still-incomplete investigation simply continues on the **next real turn** (matches the existing causality — a deferred reaction is not lost, it lands next turn).

`TOOL_CALL` (condition 1) means the gate's `AUTO_EXECUTE` record. A pass producing **only** a `COUNTDOWN`/`HARD` call appends a `TOOL_CALL_PENDING` (no `TOOL_CALL`) → condition 1 fires → the loop **terminates**; the pending call is resolved later via the confirm endpoint (ADR-030) on a **future real turn** (out-of-band). The loop **never blocks on human confirm** and stays synchronous + terminating (carry-forward #3). The confirm path (`_post_confirm`) itself is **unchanged** and stays a single execute (a post-confirm re-dispatch loop is a possible future symmetry — out of scope, named).

### D4. The total single-writer liveness bound (extends ADR-028 D5) + per-pass cap + cooldown interaction

- **The bound (the claim, enumerated with ADR-028 D5 rigor — Y1 α).** Worst-case single-writer block per turn ≤ **`(1 + N) × [ (speaking agents) × (provider timeout_s) + ADR-028 D5 per-pass execution bound ]`**, where:
  - **`(speaking agents) × (provider timeout_s)` is the dominant term** — the `dispatch_turn` block (`agents/dispatch.py:116`, sequential `llm_router.call`, no inline timeout wrapper) is bounded **only** by the per-provider call timeout: **`claude_code_cli` `timeout_s = 600.0`** (`providers/claude_code_cli.py:84`, `asyncio.wait_for`) — the worst case — and **`openai_compatible` `timeout_s = 60.0`** (`providers/openai_compatible.py:67`, `httpx.TimeoutException → TransientProviderError`). So a single pass can occupy the writer for up to `agents × 600s`, and the loop multiplies that by `(1+N) = 5×`.
  - **ADR-028 D5 per-pass execution bound** is that section verbatim (`MAX_MCP_CALLS_PER_TURN × (MCP-call timeout + interpret timeout)` + negligible local-tool time).
  - **This is a CROSS-ROOM head-of-line block, not just this room's.** The turn runs on the single-writer `ThreadPoolExecutor(max_workers=1)` (`api/app.py:171`, "serializes all writes") — so per ADR-028 D5's own framing the block stalls **every** room's writes, not only this room's turn. P4.1 multiplies that cross-room occupancy by `(1+N)`.
  - **The wall-clock deadline (D3 condition 4) makes the ABSOLUTE wall-clock bounded, not just the factor.** Without it the `(1+N)` framing reads as small while the multiplicand is a minutes-scale, all-rooms-blocking term; with it, the loop's wall-clock occupancy ≤ `MAX_TURN_LOOP_WALL_CLOCK_S` + one final pass overrun, **independent** of `agents × timeout`. `N` bounds the pass *count*; the deadline bounds the *wall-clock*; both are inscribed constants.
- **The ratified posture (architect Accepts via this ADR).** `N = 4` re-dispatch passes, **inline on the single writer**, with the `120s` wall-clock deadline, is the ratified P4.1 liveness posture — the conservative MVP, consistent with ADR-028 D5's "inline-on-writer, every dependency bounded." A separate execution lane (freeing the writer for other rooms during a loop) stays **deferred** (ADR-028 D5 — a concurrency redesign). The **new** liveness cost of this ADR is the bounded `(1+N)` multiplier **capped further** by the wall-clock deadline.
- **Per-pass cap reconciliation.** `MAX_MCP_CALLS_PER_TURN` / `MAX_POSTURE_B_CALLS_PER_TURN` are **per-`execute_pending_tool_calls`-invocation** counters (locals reset at function entry). A pass = one invocation → the caps reset **per pass** (the chosen semantics). Total MCP/Posture-B calls across the loop ≤ `(1+N) ×` the per-pass cap — still **absolutely bounded** by the constants. The executor is **unchanged**; "per turn" is honestly "per pass" under the loop, and the loop bound caps the number of passes.
- **Cooldown interaction (load-bearing for whether the loop *progresses*).** `should_agent_speak` suppresses an agent whose last utterance is within `cooldown_seconds` (ADR-010 D2). Loop passes are sub-second, so **any** `cooldown_seconds > 0` agent re-speaks **at most once** per loop (cooldown is its per-agent backstop). An agent that should chain multi-step must be configured **`cooldown_seconds = 0`**. **Termination is independent of cooldown** — it relies on the bound `N` + zero-new-`TOOL_CALL` (D3), never on cooldown. Cooldown + the zero-new-`TOOL_CALL` early-exit + `N` together prevent a non-tool-calling agent from a speak-loop (the ADR-011 backstops).

### D5. B2 — read-only code-intel tools + `log_event` (impl + wire; reuse the ADR-028 D3 boundary + a new traversal bound)

P4.1 builds the **in-process** impls for the already-classified names and registers them in `build_local_tool_registry`:

| Tool | tools.yaml | Semantics | Implementation (in-process; **no subprocess**) |
|---|---|---|---|
| `search_text(query, scope=None)` | rev 10 AUTO | literal/substring text search | `os.walk` over the sandbox (or `scope` subdir) + substring match; `file:line` hits |
| `search_code(pattern, scope=None)` | rev 10 AUTO | regex search | `os.walk` + `re.search(pattern, line)`; `file:line` hits |
| `find_references(symbol, scope=None)` | rev 10 AUTO | identifier usages (heuristic) | `os.walk` + word-boundary regex on the identifier; **not** a language server |
| `find_definition(symbol, scope=None)` | rev 10 AUTO | definition site (heuristic) | `os.walk` + regex for `def <symbol>` / `class <symbol>` / `<symbol> =`; **not** a language server |
| `log_event(content, type)` | rev 8 AUTO | agent records a finding | returns a `LocalToolOutput` recording the note → lands as a **`TOOL_RESULT`** via the executor's local path |

**Trust boundary (reused + extended).** All four search/find tools reuse the ADR-028 D3 boundary: the **same operator-configured sandbox root**, `_check_path` resolve-then-containment on the optional `scope` (reject traversal/symlink/absolute escape → `TOOL_FAILED`), and **bounded output** (`MAX_RESULT_BYTES`). **New: bounded traversal** — the FS-walk liveness analog of `read_file`'s bounded read: a files-scanned cap `MAX_SEARCH_FILES` (a documented constant) bounds the walk, and each file is read bounded (never load a multi-GB file fully). This keeps every B2 call **fast + absolutely bounded**, so it adds no unbounded inline block to the single writer (D4). Local results are **trusted → not interpreted** (no `OBSERVATION`; ADR-028 D2) — they stand in the next pass's snapshot.

**The minimal `cooldown_seconds=0` investigator agent (Y2 β — roster addition, so the loop runs LIVE on landing).** Multi-step chaining requires `cooldown_seconds = 0` (D4); the shipped roster's tool-caller (`config/agents/operator.yaml`) has `cooldown_seconds: 10`, so it cannot chain in the sub-second loop. To avoid shipping the capability **dormant** (live in tests only), P4.1 bundles **one minimal production agent** — `config/agents/investigator.yaml` — wired into the roster (auto-loaded by `load_agents(config_dir/"agents")`; `api/app.py:176`):
- `cooldown_seconds: 0` (the chaining prerequisite);
- `speaking_triggers`: an `event_type: user_input` trigger (to start an investigation) **and** an `event_type: tool_result` trigger (to re-fire on each result the loop feeds back as `current_event`, D2) — `tool_result` is a valid `EventType` for `EventTypeTrigger`;
- `required_capabilities: [tools]`; a persona scoped to **read-only** investigation (`read_file`/`search_text`/`search_code`/`find_references`/`find_definition`, recording findings via `log_event`) — no mutation;
- `applies_to.room_types`: the investigation rooms (`bug_fix`/`code_review`/`research`); `room_states: ["*"]` (architect-confirmed as-is — the live β demo; no narrowing);
- **`autonomy_thresholds` — explicit + conservative (R2-Y1 absorption, architect-routed):** `threshold_auto: 8`, `threshold_confirm: 3`, `user_intent_modifier: 0`. This is the roster's **first always-on `cooldown_seconds=0` agent**, so its autonomy floor is **pinned explicitly** (least-privilege), not left to a default. **Mechanics + justification (verify-cite `autonomy/scoring.py:185` — `score_value >= eff_auto → AUTO_EXECUTE`, so `threshold_auto` is the AUTO floor; *higher* = more conservative):** `threshold_auto: 8` AUTO-fires **exactly** the investigator's read-only toolset (`read_file`/`search_*`/`find_*` rev 10, `log_event` rev 8 — all `≥ 8`) while forcing **every** mutation/lower-reversibility tool through human confirm (`propose_edit` rev 5 → COUNTDOWN, `send_email` rev 3 → COUNTDOWN, `apply_edit` rev 2 → HARD, `git_push` rev 1 → HARD). It is therefore **strictly more conservative than `operator` (`threshold_auto: 6`)**, which would AUTO-fire `propose_edit` only at rev≥6 but still admits a wider AUTO band. `user_intent_modifier: 0` means inferred user-intent does **not** relax the floor for this always-on agent (the most conservative posture). The gate backstops regardless — this pin is true-minimality, not a new trust surface.

It is deliberately **minimal** — the loop + the tools are the value; the agent merely exercises them live. Outside the bounded loop it cannot speak-loop: `tool_result` is the `current_event` **only** during in-turn re-dispatch (a fresh user turn anchors on `user_input`), and the loop is bounded (D1/D3). This is the only roster change in P4.1; broader investigator-agent tuning is a later content surface.

**`log_event` (the one write — included; rev-8 triviality accepted).** `log_event` is a *write*, but it writes **only to our own event log** by returning a `LocalToolOutput` that the executor appends as a normal `TOOL_RESULT` — **no `event_store` handle is given to the tool fn** (the `dict → LocalToolOutput` contract is preserved) and **no new event type** is added. The durable "log" is the `TOOL_RESULT` event, visible in the next pass's snapshot (flagship: investigate → log finding). **Loop-write interaction:** local tools have no per-turn cap (ADR-028 D5 exempts them as fast/bounded), so over `(1+N)` passes an agent could emit several `log_event`s. This is **accepted as rev-8 trivia**, because: (i) `log_event` lands via the pure local path — sub-ms, **no single-writer block** → zero liveness impact (the D4 bound is untouched); (ii) the only cost is event-log row growth, itself bounded by `(1+N) ×` per-pass agent generation and harming only the emitting agent's own room snapshot (no cross-room effect); (iii) rev-8 = trivially prunable. **Forward-watch:** if bloat is ever observed, the Posture-B cap pattern (`_is_posture_b_subprocess` attribute → `MAX_*_PER_TURN`) is the ready extension point for a `MAX_LOCAL_WRITES_PER_PASS` — deferred until observed, named here so this is a posture, not an oversight.

### D6. Constitutional invariants under the loop + the ADR-011 extension

- **No new `LLMPurpose`** (`tests/tools/test_constitution.py` t3 stays green). **No autonomy decision in the loop** — the driver loop calls `dispatch_turn` + `execute_pending_tool_calls`; it never calls `score`/`decide_tier`/`emit_gate_decision`. **Execute-on-`TOOL_CALL`-only holds per pass** (executor t4 unchanged; the loop re-invokes the same executor). **B2 trusted-not-interpreted** (local code-intel/`log_event` results append no `OBSERVATION`).
- **Substantive ADR-011 amendment (snapshot-per-pass + `snapshot_excerpt` resolution).** Two coupled changes, inscribed in the ADR-011 amendment note:
  1. **Snapshot-per-pass within a turn.** In-turn re-dispatch re-runs `dispatch_turn` against the **growing** event log within the **same** turn — each pass re-takes the per-turn snapshot at `dispatch_turn` entry, so pass `k` sees pass `k−1`'s appended results. This **extends** ADR-011 D2 (snapshot-per-turn) to snapshot-per-pass. Cross-turn causality is unchanged (state transitions take effect next turn — `next_room_state` runs once, pass 0). The speak-loop backstops (cooldown + zero-new-`TOOL_CALL` + `N` + the wall-clock deadline) keep the per-turn pass count + wall-clock bounded.
  2. **`snapshot_excerpt` populated + fed to the LLM (the P1.4 deferral resolved).** ADR-011 D4 / `AgentContext` deferred `snapshot_excerpt` "until a concrete consumer drives the shape" (`agents/schema.py`, `agents/selection.py:99` `_ = snapshot`). The turn-loop **is** that consumer: without accumulated context a re-dispatched agent cannot reason over its own prior-pass results. P4.1 adds `snapshot_excerpt` to `AgentContext`, populates it in `build_agent_context` (bounded by `MAX_SNAPSHOT_EXCERPT_CHARS`), and feeds it into the `dispatch_turn` LLM prompt (`agents/dispatch.py:112`). This is **additive** (a new optional field + a populated prompt block), introduces **no new `LLMPurpose`** (still `AGENT_RESPONSE`) and **no new `EventType`**, and preserves the trust framing (D2 — the excerpt is context, not a gate input).

  **Framing-intent forward-note (R2-N1):** when the excerpt renders tool results, it should **prefer the interpreted/trusted view** (for MCP results, the `OBSERVATION` that the existing untrusted-framed content-gen interpret already produced) or otherwise **carry explicit untrusted-result framing** around raw external result content — so injected text in a result reads as *data the agent observed*, not as instructions. The gate still routes every tool call the agent then emits (so injection cannot bypass autonomy, D2); this note records the **rendering** intent. The **deep untrusted-injection probe** (can crafted result text steer the re-dispatched agent) is **owned by the impl-stage external R0-B** — already tasked in `reviews/P4.1/external-r0b-prompt.md` lens (B).

## Considered alternatives

- **Single-re-dispatch (one extra pass).** Rejected (D1, architect §(a)): terminates trivially but gives the agent only one reaction — cannot chain the ≥3-hop flagship investigation.
- **Re-run the full `run_turn` each pass.** Rejected (D2): re-evaluates `next_room_state` per pass against the frozen `room.state` → risks a duplicate `state_transition` and contradicts ADR-011's "transition takes effect next turn." `dispatch_turn`-per-pass keeps the state machine once-per-turn.
- **Narrowed re-dispatch (only the tool-calling agent re-evaluates).** Rejected (D2 / senior-design surface): a new narrowed dispatch primitive; full `dispatch_turn` is ADR-011-consistent and multi-perspective, with the same termination backstops.
- **Give `log_event` an `event_store` write handle / a new `NOTE` event type.** Rejected (D5): breaks the `dict → LocalToolOutput` local-tool contract and widens the surface; the `TOOL_RESULT`-as-log shape is durable with zero new vocabulary.
- **Per-loop accumulate caps (one budget across all passes).** Rejected (D4): the executor's per-invocation counters give per-pass reset for free; `(1+N) ×` the per-pass cap is already absolutely bounded — accumulate would require changing the (reused-unchanged) executor.
- **No wall-clock deadline — rely on the `(1+N)` factor alone (the original D4).** Rejected (Y1 α): the factor is finite but the multiplicand (`agents × up-to-600s`, cross-room) is minutes-scale; only an **absolute** wall-clock deadline (D3 condition 4) bounds the felt single-writer occupancy independent of provider timeouts. This follows the ADR-028 D5/R1 precedent — name + bound every inline blocking term, don't leave the dominant one as an unquantified symbol.
- **Ship the loop dormant-in-production (test agent only) / ship latest-result-only context (the R0-A Y2/Y3 leans).** Overridden by architect routing: **Y2 → β** (bundle the minimal `cooldown=0` investigator so the flagship runs live on landing, D5) and **Y3 → bundle `snapshot_excerpt`** (resolve the P1.4 deferral so the agent reasons over accumulated context, D2/D6). The "inscribe-mechanism-before-producer" deferral was viable but the architect chose live-on-landing + full-fidelity for the capability opener.
- **Give `snapshot_excerpt` the full snapshot (unbounded).** Rejected (D2/D6): the excerpt is bounded (`MAX_SNAPSHOT_EXCERPT_CHARS`, most-recent slice) — an unbounded prompt would blow context windows + cost; the bounded recent slice carries the in-turn investigation.

## Consequences

**Easier:** the flagship multi-step bug-fix / code-review scenario **actually runs live on landing** — the bundled `investigator` agent chains `read_file → search_text → find_references → …` within one turn, reasoning over its accumulated investigation (`snapshot_excerpt`). The loop bound `N` + the wall-clock deadline are the inscribed constants every P4.2+ tool slice rides on. The B2 sandbox + bounded-traversal pattern is established for future read tools.

**Harder:** a `(1+N)` single-writer multiplier over a minutes-scale, cross-room-blocking per-pass term (named + enumerated + capped by the wall-clock deadline — D4); a new FS-walk traversal bound; a `snapshot_excerpt` rendering + prompt-assembly change touching the load-bearing `dispatch_turn`/`build_agent_context` (the P1.4 deferral resolved — D6); multi-step progression still requires `cooldown_seconds = 0` (the bundled investigator has it; the existing `operator` at `cooldown_seconds: 10` does not chain — D4/D5).

**Neutral:** the executor and `dispatch_turn`'s **gate/dispatch** path are reused unchanged; the new code is the driver loop (+ wall-clock deadline) + the `select_dispatch_agents` extraction + the 5 tool impls + the `snapshot_excerpt` field/population/feed + one minimal agent yaml. confirm-gated calls stay out-of-band (D3). The gate decision logic is untouched.

## Reversibility

| Decision | 6-month reversal cost |
|---|---|
| D1 bounded-loop + `N` | **Low** — `N` is one constant; reverting to no-loop removes the driver while-loop (the executor/dispatch are untouched). |
| D2 `dispatch_turn`-per-pass + `select_dispatch_agents` + `current_event`=latest-result | **Low** — the extraction is behavior-preserving; the `current_event` choice is a driver-local rule. |
| D2/D6 `snapshot_excerpt` populated + fed to the LLM | **Medium** — additive field + a `build_agent_context`/`dispatch_turn` prompt change; reverting drops back to current_event-only context. Resolves the P1.4 deferral (ADR-011). |
| D3 termination test (incl. wall-clock deadline) | **Low** — driver-local conditions; `MAX_TURN_LOOP_WALL_CLOCK_S` is one constant. |
| D5 minimal `investigator` agent (roster) | **Trivial** — one yaml; removing it leaves the loop+tools intact (capability reverts to dormant). |
| D4 liveness bound / per-pass cap / cooldown | **Medium** — moving caps to per-loop-accumulate, or moving execution off the writer, is a concurrency change (ADR-028 D5 territory). |
| D5 B2 tools + sandbox + traversal bound | **Medium** — the tool set is additive; relaxing the sandbox/traversal bound is a trust-surface decision (architect-gated). |
| D5 `log_event`-as-`TOOL_RESULT` (no new event type) | **Low** — additive; a future `NOTE` type or a local-write cap is additive on top. |
| D6 constitution invariants + ADR-011 extension | **Do-not-reverse** — the code-driven-loop / no-new-purpose / gate-per-pass spine is the carry-forward. |
