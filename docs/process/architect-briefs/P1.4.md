**Subject:** Implement P1.4 — **Skeptic agent + multi-agent dispatch infrastructure**. Code that decides (a) which agents are loaded into a room, (b) which loaded agents speak on a given turn (`should_agent_speak`), (c) how summoning a new agent into a room is decided. Per `handoff.md` §3.1, **all three decisions are code, not LLM-judgment**. The agent's response content itself (the markdown body of the LLM call) is LLM-generated.

P1.4 is the **first project task with categorical shape change**. Cross-family R0-B is mandatory (see §"Cross-family R0-B for P1.4" below).

## Scope

**In scope (P1.4):**

- **Agent loader** at `src/orchestrator/agents/loader.py` (or wherever senior places it; module structure is senior's call): parallel to skill loader. Reads `config/agents/*.yaml`, parses the schema per `handoff.md` §4.4, returns `dict[str, Agent]`. Pure-function loader.
- **`Agent` data structure** in `src/orchestrator/agents/schema.py`: Pydantic model covering `id`, `role`, `persona`, `dissent_dimensions`, `cross_domain_borrowing`, `forbidden_behaviors`, `speaking_triggers`, `cooldown_seconds`, `llm_config`, `output_schema`. Frozen + extra-forbid per the project pattern. **Senior decides which fields are required vs optional** in plan.
- **`decide_agents_for_room(room_type, room_state, *, available_agents) -> list[Agent]`** — selection of which agents are loaded into a given room template. Parallel to `decide_skills_for_context` from P1.3. Pure function; no LLM. Returns `AgentSelection` (or whatever shape includes a decision trace per `contributing.md` Q2).
- **`should_agent_speak(agent, room_event_stream, *, current_event) -> SpeechDecision`** — pure-function decision per `handoff.md` §4.4 `speaking_triggers` (regex / event_type / state_change). Returns enough trace info to explain why an agent was (or wasn't) selected to speak. **No LLM in this function.** This is the load-bearing new decision point P1.4 introduces.
- **Cooldown enforcement** — `speaking_triggers` matching must respect `agent.cooldown_seconds` against the agent's last-spoke timestamp (read from the event stream).
- **Summon decision function** — code-driven decision to bring a NOT-currently-loaded agent into a room mid-session. Initial shape (senior decides exact API): based on the unfolding event stream + room state, the dispatch layer can summon `skeptic` mid-session into a `research` room if (e.g.) hypothesis density exceeds a threshold. **Pure function; no LLM in the summon decision itself.** Senior decides whether summoning is in P1.4 scope at all (see push-back hooks).
- **Multi-agent turn-dispatch primitive** — the function that runs the per-turn loop: read `current_event`, ask each loaded agent's `should_agent_speak` whether they want the turn, resolve conflicts (multiple agents want to speak), dispatch the chosen agent's LLM call (per its `llm_config`). The "resolve conflicts" sub-decision is itself code, not LLM. **Senior designs the conflict-resolution semantics** in plan/ADR.
- **Skeptic agent YAML** at `config/agents/skeptic.yaml`. First non-prober agent with full role contract (dissent_dimensions, forbidden_behaviors populated, opus-tier llm_config per `handoff.md` §5.5 example). - **Skill→agent integration touch point.** P1.3 deliberately stopped at `decide_skills_for_context`; the consumer (agent runtime) was deferred to P1.4. P1.4 wires the skill selection into the agent's context window construction. **Senior decides exactly where the wire lives** — most likely in the turn-dispatch primitive: when an agent is chosen to speak, the dispatch layer calls `decide_skills_for_context(agent.id, room_type, room_state)` and includes the resulting skill bodies in the LLM prompt.

## Architect-settled design decisions

### 1. All three decisions are code (handoff §3.1)

- `decide_agents_for_room` — code (room_type + room_state → loaded agent set).
- `should_agent_speak` — code (agent.speaking_triggers + current_event + cooldown → speak/don't-speak).
- Summon decision (if in scope) — code (room event stream + room state → summon agent X).

**No LLM in any of these.** Constitutional test enforces. The LLM call only fires AFTER a code decision selects an agent to speak; the LLM generates the agent's response content, not the gating logic.

This is the cleanest expression of `handoff.md` §3.1 to date — three new decision functions, all explicitly code.

### 2. Cooldown semantics — event-stream-driven, not wall-clock

`agent.cooldown_seconds` is enforced by reading the event stream for the agent's most recent `utterance` event and comparing the elapsed time. **Not a wall-clock timer** — the event stream is the source of truth. This matches Principle 4.1 (event stream as single source of truth).

Implication: cooldown survives crashes, session restarts, multi-session interleaving. A senior who proposes wall-clock cooldown should be pushed back.

### 3. Multi-agent concurrency model — senior decides; brief specifies the boundaries

**Boundary (a):** if dispatch is concurrent (multiple agents called in parallel), the resulting events must be appended to the event stream in a deterministic order (sorted by agent priority or by completion order; senior picks and defends in ADR). Race conditions in event-stream append are unacceptable.

**Boundary (b):** if dispatch is sequential, the ordering rule across agents that all want to speak on the same turn must be code-deterministic (not LLM). Architect-partner lean: priority field on Agent (default 50, lower number = earlier dispatch); alphabetical id as tie-break.

**Boundary (c):** snapshot-vs-live event-stream reading — when agent N is computing `should_agent_speak`, can agents 1...N-1 from this turn already have appended events that agent N sees? Architect-partner lean: each turn computes `should_agent_speak` for ALL loaded agents against the same event-stream snapshot (the snapshot at turn start). Multi-agent turn responses are appended atomically after all decisions are made. This avoids the "agent 2 sees agent 1's response and chains off it within a single turn" complication.

Senior pushes back on any of these if a cleaner alternative surfaces in the design.

### 4. Skeptic agent contract — first full instance of Agent schema

Skeptic is the first agent with:
- Non-empty `dissent_dimensions` (per `handoff.md` line 187).
- Non-empty `forbidden_behaviors` (per line 189).
- `speaking_triggers` shape that exercises all three trigger types if possible (regex, event_type, state_change).
- Higher-tier `llm_config` per `handoff.md` §5.5 example (`claude_code_opus_47` default).
- `required_capabilities`: empty (skeptic is pure-thinking, doesn't call orchestrator tools per `handoff.md` line 530).

**Senior populates the YAML based on the architect-partner-curated description in `handoff.md`** + the to-be-drafted Skeptic role doc (likely in plan §X or as a follow-up content task). If `dissent_dimensions` content isn't crisp enough to write in P1.4, **placeholder TODO entries are acceptable** — the schema validation is in scope; the content tuning is a P1.5+ concern.

## Constraints (do not violate)

- **`handoff.md` §3.1 compliance.** Three new decision functions: `decide_agents_for_room`, `should_agent_speak`, summon (if in scope). All three are code. Constitutional test forbids LLM imports in the entire `src/orchestrator/agents/` module.
- **Event stream as single source of truth.** Cooldown is event-stream-driven (Architect-settled decision 2). Multi-agent dispatch does not introduce side-state that the event stream doesn't reflect.
- **No regression in `purposes.py` discipline.** New LLM calls (the agent response generation) MUST use `LLMPurpose.AGENT_RESPONSE` with `caller_agent_id` discriminating. No new `LLMPurpose` enum values added unless an ADR explicitly justifies one (per `handoff.md` §5.5).
- **Layering** per "Cross-package layering" above. Three new constitutional tests added.
- **Decision-trace pattern** per `contributing.md` Q2. Every new gating/selection function returns enough info to explain its choice.
- **Skill integration is read-only.** `decide_agents_for_room` and `should_agent_speak` must not mutate the skill set or the skill matching logic. The wire is one-directional: agent dispatch → skill selection → LLM prompt.
