### W-003-1 — RC-16 fix: `_read_plan_frontmatter` reads `origin/main`, not working-tree

- **What**: replace `path.read_text(encoding="utf-8")` in `_read_plan_frontmatter` with a `git show origin/main:<rel_path>` subprocess call. Bug: a session with an uncommitted local plan modification can trigger bogus `workflow advance` state transitions. Fix: read from `origin/main` semantically; the merge IS the publish event.
- **Where**:
  - Modify: `src/orchestrator/workflow/io.py` — `_read_plan_frontmatter` body. Signature unchanged: `(path: Path) -> dict[str, Any] | None`.
  - Extend: `tests/workflow/test_io.py` (or equivalent) — new integration tests with synthetic git repo (working-tree vs `origin/main` divergence).
- **Why**: RC-16 (W-002.5 / PR #11 capture); brief In scope §W-003-1.
- **Acceptance**:

  **`_git_show` helper extract (architect routing Y2 → α — pre-pinned, not deferred to impl-time):**

  Add `_git_show` helper in `src/orchestrator/workflow/io.py` BEFORE refactoring `_read_plan_frontmatter`. Helper centralizes subprocess error handling for git-show callers (W-003-1 + W-003-3 both consume; future call sites inherit):

  ```python
  # src/orchestrator/workflow/io.py
  def _git_show(rel_path: str, ref: str = "origin/main") -> str | None:
      """Return file content from a git ref via subprocess. None if not found.

      Centralizes subprocess error handling (timeout; non-zero exit;
      missing-file return-None semantic) for git-show callers.
      """
      try:
          result = subprocess.run(
              ["git", "show", f"{ref}:{rel_path}"],
              capture_output=True,
              text=True,
              timeout=10,
          )
      except subprocess.TimeoutExpired:
          return None
      if result.returncode != 0:
          return None
      return result.stdout
  ```

  **`_read_plan_frontmatter` refactor (consumes helper):**

  - Signature `(path: Path) -> dict[str, Any] | None` unchanged. Internal switches to `_git_show` call.
  - Implementation: convert `path` to repo-relative (`path.relative_to(repo_root)`); call `content = _git_show(rel_path)`. On `None` (file not on origin/main OR subprocess failure), return `None` (matches existing "no frontmatter" fallback).
  - Frontmatter parse (existing `---` fenced block logic) operates on `content` instead of `path.read_text()`. The parse logic itself is unchanged.
  - Backwards compat: plans currently on `origin/main` return their content as before (working-tree = origin/main for clean repos). Bug only affects sessions with uncommitted local mods.
  - **Edge case: plan on branch awaiting merge** (push-back #2 in §5). The fix treats "not on origin/main" as "no frontmatter" via fallback. This is correct per brief Architect-settled decision: if the plan isn't on origin/main, the state machine shouldn't advance based on it — the merge IS the publish event. Senior confirms this aligns with ADR-008 D1's gated-transition semantic.

  **`_has_commit_since` investigation result (architect routing Y1 → α — pre-resolved at plan revision, not deferred to impl-time):**

  Senior investigated `_has_commit_since` in `src/orchestrator/workflow/cli.py` (lines ~340-355). Function reads `git log --oneline --after=<since>` from local repo (no ref specified). Caller `build_artifact_snapshot` uses it to set `junior_impl_commit_present` — the signal that drives `next_state` advancing `awaiting_junior_impl → awaiting_senior_plan_vs_impl`.

  **Verdict: correct-by-design. No fix needed; no W-003-1b atomic.**

  Rationale — the asymmetry from RC-16 is **intentional**:
  - **Plan content** (`_read_plan_frontmatter`) needs the **publish event** → origin/main read. The merge IS the publish; reading working-tree lets uncommitted local mods bogus-fire state advance (the RC-16 bug).
  - **Junior impl activity** (`_has_commit_since`) needs the **work event** → local-commit read. Junior commits locally, then runs `workflow advance` to push state. Reading from origin would force a 2-step push-impl-then-push-state-advance flow; junior would have to push impl, wait for the local repo to see origin update, then push state. The current local-read enables the natural single-step: commit impl → advance state → push both.

  Documented as intentional asymmetry: the workflow harness deliberately consumes different surfaces for plan-content (publish-event) vs impl-activity (work-event). Future readers should not "fix" `_has_commit_since` to read from origin — that's a regression of the intentional design.

  **Tests (≥4 — `_git_show` helper-level tests + W-003-1 integration tests):**

  Test the helper:
  - Existing ref + existing file → returns content string.
  - Existing ref + missing file → returns None.
  - Timeout (mock subprocess raises TimeoutExpired) → returns None.

  Test `_read_plan_frontmatter` via the helper (mock `_git_show`, not raw subprocess):
  - Helper returns plan content with valid frontmatter → returns parsed dict (`task_id: SYNTH`).
  - Helper returns plan content WITHOUT frontmatter → returns None (fallback path).
  - Helper returns None (file not on origin/main) → returns None.

  Tests use `monkeypatch.setattr` on `_git_show` for the `_read_plan_frontmatter` tests; the helper itself has its own subprocess-level tests with `subprocess.run` mocked. Cleaner than W-002.5's inline subprocess mocking pattern.

  All 25+ existing workflow tests remain green. `ruff check` / `ruff format --check` / `mypy --strict` clean.
- **Out of scope**: rewriting `_read_plan_frontmatter`'s public contract; changing fallback path of `_read_adr_status` (which already handles `None` returns).
