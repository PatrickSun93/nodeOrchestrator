## Synthesis

Both plan-stage yellows are correctly absorbed at impl. The Principle-11 AST guard (Y1→α) is a genuine `ast.NodeVisitor` that prevents any future `memory/` module from referencing `EntityType.PREFERENCE` outside the three allowed functions — structurally consistent with the matcher/validation AST guard precedent. The preference upsert (Y2→α) correctly implements upsert-by-(user_id, key, scope) — one row per preference key, latest-wins on re-declaration, no non-deterministic tiebreak.

The cross-family impl-stage lens traces the actual execution through every write path and finds no 🔴, no 🟡. The Principle-11 boundary holds at runtime: `record_entity` rejects PREFERENCE before touching the DB; `record_preference` gates on non-empty `user_id` before touching the DB; the AST guard prevents future bypass. The entity migration is correct and round-trip-tested. The e2e covers all three containers end-to-end with discriminating determinism assertions. Seven greens — the impl genuinely checks out across all invariants both lenses traced.
