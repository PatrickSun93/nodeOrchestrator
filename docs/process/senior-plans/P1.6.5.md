**Acceptance**:
- `init_memory_schema(conn)` idempotent (call twice; no error). All 3 tables + indexes present after first call.
- **FK enforcement is INSERT-time, not CREATE-time** (per proxy Y3 / external Y8 → α): SQLite records forward FK refs at `CREATE TABLE` regardless of whether `events`/`rooms` exist, so `init_memory_schema` against a connection lacking them succeeds at CREATE and fails only at first INSERT (`no such table`). Init order (`EventStore.init_schema` first) is recommended convention for INSERT correctness, not a CREATE-time hard requirement. Test asserts the **INSERT-time** failure on wrong init order — NOT a CREATE-time raise (the prior "calling before EventStore.init_schema raises" wording is removed; that test cannot pass since CREATE succeeds).

from typing import Annotated
from pydantic import model_validator

class DecisionMeta(_BaseMeta):
    based_on: list[EventId] = Field(min_length=1)
    trade_offs: dict[str, str] = Field(default_factory=dict)
    # P1.6.5 / ADR-016 D8 — promotion-flavored decisions.
    # hypothesis_id + vk_id are `str | None` per deliberate-duplication
    # (ADR-014 D5 precedent + test_constitution_core_does_not_import_memory
    # guard P1.6.5-1 ships): core/event.py MUST NOT import memory/schema.py.
    # Field(pattern=…) enforces id-prefix shape (proxy Y5 → α (a)) — closes
    # swapped-id / event-id / empty-string bypasses the co-presence validator
    # does not catch.
    promotion: bool = False
    hypothesis_id: Annotated[str, Field(pattern=r"^hyp_[0-9a-f]{32}$")] | None = None  # semantic: HypothesisId
    vk_id: Annotated[str, Field(pattern=r"^vk_[0-9a-f]{32}$")] | None = None            # semantic: VKId

    @model_validator(mode="after")
    def _promotion_co_presence(self) -> "DecisionMeta":
        if self.promotion and (self.hypothesis_id is None or self.vk_id is None):
            raise ValueError(
                "promotion=True requires both hypothesis_id and vk_id"
            )
        if not self.promotion and (self.hypothesis_id is not None or self.vk_id is not None):
            raise ValueError(
                "hypothesis_id/vk_id forbidden when promotion=False"
            )
        return self

**Module surface — promotion.py:**

```python
def promote_hypothesis(
    hyp_id: HypothesisId,
    user_id: str,
    *,
    scope: VKScope,
    topic_tags: list[str] | None = None,
    evidence: dict[str, Any] | None = None,
    event_store: EventStore,        # no `conn` param (external Y7 → α (b))
) -> VerifiedKnowledge:
    """User-confirm promotion of a Hypothesis row → VerifiedKnowledge.

    Steps (per ADR-016 D3 + D11 atomicity):
      0. conn = event_store.conn  # single connection for all 3 writes — the
         conn≠event_store.conn atomicity-loss hazard is unrepresentable.
      1. Load Hypothesis by hyp_id. Raise HypothesisNotFoundError if absent.
      2. Check status == PENDING. Raise PromotionEligibilityError otherwise.
      3. Generate vk_id; construct DecisionMeta with promotion=True,
         hypothesis_id=hyp_id, vk_id=vk_id, based_on=hypothesis.source_event_ids;
         decision event room_id = hypothesis.room_id (Y5).
      4. Within a single `with conn:` block:
           a. event_store.append_in_transaction(decision_event)
           b. INSERT VK row  (UNIQUE on promoted_from_hypothesis_id — Y9 backstop)
           c. UPDATE hypothesis SET status='verified' WHERE id=hyp_id
      5. Return VerifiedKnowledge model (loaded from inserted row OR
         constructed from input values; same shape either way).
    """
```

**Two senior self-discoveries beyond the 8 push-back invitations** (per W-004-2 (a) claims-without-cites verification + ADR-016 D5 + D11):

**S1 — Schema-init placement (ADR-016 D5; deviates from brief D5 wording)**: brief says "extend the event-store init SQL with `CREATE TABLE IF NOT EXISTS`" — read literally, that places memory-table DDL in the SCHEMA constant at `core/event_store.py:48-102`, violating the layering invariant (`core/` MUST NOT know about `memory/` — same rule that yields ADR-014 D5 deliberate-duplication + the constitutional `_does_not_import_memory` guards added by P1.6.5-1). Architect-settled #4 atomicity invariant preserved (same file, same connection, single transaction). **Implementation-level pin; does not contradict any architect-settled decision.** Surfaced to architect for awareness.

**S2 — Transaction-atomicity mechanism (ADR-016 D11; resolves brief pre-investigation gap)**: brief pre-investigation note ("Verify event_store's append API supports being called inside an externally-managed transaction") flagged the issue without resolving. `EventStore.append` at `src/orchestrator/core/event_store.py:185-272` wraps its body in `with self.conn:` (line 211), which on Python sqlite3's default isolation level begins-and-commits its own transaction. Nesting `with conn: ... event_store.append(...) ...` from `memory/promotion.py` would either commit inner-most first (breaking outer atomicity) or raise `OperationalError`. ADR-016 D11 pins option A: extract `EventStore.append_in_transaction(event)` as a new public method (no outer `with self.conn:`; entry-guarded with explicit `RuntimeError` per proxy Y2); existing `append` becomes a thin wrapper. `memory/promotion.py` uses `append_in_transaction` inside `with event_store.conn:` (no separate `conn` param per external Y7). Atomicity guaranteed via single outer transaction. **Refactor lands in P1.6.5-2**; verified backward-compat via existing test suite (6 EventStore.append callers across `agents/` + `autonomy/` + `rooms/`; all call the wrapper, unchanged behavior).
