## 1. Context

P2.1 was resequenced (architect decision B3, 2026-05-29): the **shared tag registry** is the real foundation of cross-room memory intelligence and ships first as its own slice; the matcher I previously planned is now P2.2 (the downstream consumer; ADR-017 reserved for it, superseded plan preserved in git history). This plan + ADR-018 replace that work.

The matcher's blocking problem was tag *consistency* — matching on tags only works if the same claim gets the same tags across rooms, and free-form tags paraphrase and never match. The registry makes consistency a **structural property**: one canonical vocabulary both `Hypothesis` and `VerifiedKnowledge` resolve their `topic_tags` through. The split is the project's standing controlled-vocabulary instinct: **LLM proposes tag content (a later agent slice); code owns structure** (normalize + register + match). `memory/` never calls an LLM.

**Honest ceiling** (carried into ADR-018 §Context, and the plan does not over-claim): the registry is *best-effort* — it makes reuse *possible and cheap* but does not *force* it. Identical-after-normalization tags collapse to one canonical form; semantic near-misses do not. The reuse-pressure (showing an agent existing tags) is a later slice. P2.1 ships the mechanism only: the `tag` table, `normalize_tag`, `resolve_tags` (auto-register), `Hypothesis.topic_tags` + its ALTER migration, write-path wiring for both producers, and the lookup normalization that refines ADR-016 D6. **No matcher, no agent wiring.**

All five push-backs are resolved in ADR-018 and §5 below; every claim was verified against the working tree during pre-investigation (cites inline).

### P2.1-3 — `normalize_tag` + `resolve_tags` (registry core)

- **What**: `src/orchestrator/memory/tags.py` — `normalize_tag(raw) -> str`, `resolve_tags(proposed, conn) -> TagResolution`, the `TagResolution` result. Pure code, no LLM.
- **Where**: new file `src/orchestrator/memory/tags.py`.
- **Why**: ADR-018 D3 + D4.
- **Acceptance criteria**:
  1. **`normalize_tag`**: `strip()` → `lower()` (NOT `casefold()`) → `re.sub(r"\s+", "-", s)` (collapse+hyphenate whitespace). No punctuation strip, no Unicode NFC. Boundary tests (§5 test-coverage): `"LLM Cost"`→`"llm-cost"`, `"  ML "`→`"ml"`, `"Foo  Bar"`→`"foo-bar"`, `"llm-cost"`→`"llm-cost"` (idempotent), `"   "`→`""`, `"C++"`→`"c++"` (punctuation preserved). Deterministic.
  2. **`resolve_tags`**: normalize each; **raise `ValueError`** if any normalizes to `""` (fail-loud; symmetric with lookup's empty-tags guard, ADR-016 D6); dedup preserving first-occurrence order; split existing vs new; auto-register new via `INSERT OR IGNORE INTO tag (canonical, created_at) VALUES (?, ?)`; return `TagResolution(canonical: list[str], newly_registered: list[str])`.
  3. **Transaction-neutral**: `resolve_tags` does NOT commit — runs SELECT + `INSERT OR IGNORE` on the passed `conn`; the caller owns the transaction (ADR-018 D4). Test both standalone (caller commits) and that no implicit commit occurs.
  4. **Concurrency / idempotent insert** (§2): resolving the same new tag twice does not double-insert (PK + `INSERT OR IGNORE`); `newly_registered` reflects only the genuinely-new-this-call set.
  5. `resolve_tags` boundary: empty proposed list → empty `TagResolution` (no error — empty input is valid; only a tag *normalizing to empty* errors); all-new / all-existing / mixed.
  6. Determinism (Principle 11): same proposed list + same registry state → same `canonical` order + same registry effect.
- **Out of scope**: synonym/alias merging, curated gating, backfill (ADR-018 D8); FK storage.

## 5. Where you'd (architect) push back — the five brief push-backs, resolved

All resolved in ADR-018; verified against source. Speak up if any is wrong.

- **#1 `normalize_tag` exact rules → strip + `lower()` + whitespace→`-`; no punctuation/Unicode normalization.** The whitespace→hyphen rule is *required* by the brief's own worked example (self-discovery: `"LLM Cost"` must hit `"llm-cost"`). `lower()` not `casefold()` (casefold over-normalizes: `ß→ss`). Conservative on punctuation (`c++`≠`c`) and Unicode (no NFC) — minimal floor, avoids distinct-concept collisions. Boundary tests in P2.1-3 AC#1. **Flag if you want richer normalization despite the collision risk.**
- **#2 ADR-016 D6 refinement mechanism → ADR-018 records it + cross-links D6; ADR-016 NOT edited.** Avoids touching the closed/accepted ADR and the RC-23 trap near its status region; keeps the audit trail where the change is decided (ADR-018 D7).
- **#3 Backfill → emergent-only, no backfill.** Confirmed — no consumer needs historical tags (the P2.2 matcher reads row `topic_tags`, not the `tag` table). ADR-018 D8.
- **#4 `tag` table shape → `canonical TEXT PRIMARY KEY` + `created_at`; no `usage_count`, no surrogate id.** PK gives UNIQUE for free; surrogate adds a join with no consumer (storage is denormalized canonical strings, #5). ADR-018 D2.
- **#5 `resolve_tags` return + storage form → `TagResolution(canonical, newly_registered)`; store canonical denormalized strings.** Two pieces of info fixed (canonical list to store + which were new); denormalized strings = minimal change, FK ids deferred. ADR-018 D4 + D6.

**No unresolved decision requiring an architect call** beyond ADR-018 accept + the two dispatch calls (§6). If the architect disagrees with #1 (normalize rules) or #2 (D6 mechanism), those reopen.
