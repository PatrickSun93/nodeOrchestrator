## 1. Context

P2.1–2.3 built promotion rules a (`run_matcher`) and c (`list_externally_validated_candidates`); both ship **dormant** — `run_matcher` excludes untagged hypotheses (`matcher.py:72`), and the rule-c reader returns nothing until a connector produces `external_validation` events. P2.6 ships the **first producers** that feed them: **(B1)** a rule-a tagging producer, **(B2)** rule-c external connector(s), **(B3)** refuted/inconclusive handling. The rules themselves are **unchanged** — P2.6 feeds them.

The constitutional crux (the recurring rule, a **fifth time**): code + external ground truth decide; the LLM only generates content / interprets external evidence; nothing inferred is durable without code-derivation or user-confirm. ADR-022 draws the two boundary lines (c1 descriptive-tagging, c2 evidence-anchored verdicts) and carries the full design; this plan is its atomic execution. All substrate verified against `origin/main` (cites §5/§7).

**Architect-ruled (a/b/c) — written here, not re-surfaced:** (a) **one slice with parallel atomics** (prelude → B1∥B2∥B3 → e2e); (b) **dual-lens R0-B dispatched** (`requires_cross_family_review: true` + external prompt); (c1) **LLM-tagging is descriptive content-gen** (LLM never selects/ranks/gates); (c2) **connector verdict is `evidence_ref`-anchored** (LLM-if-used interprets evidence, not the bare hypothesis; `EventStore.append` only). B3: rule-c **never mutates status** (ADR-019 push-back #4). §5 records these + the four senior forks I pinned.

- **All `LLMPurpose` values are content-gen** — `HYPOTHESIS_TAG_PROPOSAL` is content-gen (tag proposal); no routing/judgment purpose exists or is added.
