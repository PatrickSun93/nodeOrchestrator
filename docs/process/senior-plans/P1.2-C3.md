## 5. Where I'd push back

**1. `UnknownToolError` location: `scoring.py`, not `autonomy/exceptions.py`.**
The LLM module's `exceptions.py` houses 5+ classes — the file earns its keep. The autonomy module has 1 exception in C3, plausibly 1-2 more in P1.3 (Hard Guards may raise `RefusalError` or similar). One file per one exception is premature abstraction. Recommendation: keep in `scoring.py`. If P1.3 adds 2+ more autonomy exceptions, refactor to `autonomy/exceptions.py` then (and update `from … import UnknownToolError` callsites — one-line edits).

**2. §6 coverage granularity: scorer-direct-output priority.**
Six Pydantic classes in `scoring.py` after C2 freeze. C3 directly produces two (`AutonomyScore`, `DecisionTrace`). The other four:

- `AutonomyTier` — `StrEnum`; no Pydantic validation surface to test under §6.
- `Operation` — C2 freeze, behavior unchanged in C3; §6 coverage doesn't gain ground in C3.
- `ToolMeta` — `Field(ge=0, le=10)` trivially exercised by C3-6 group (a) reading reversibility values; explicit §6 test would duplicate the bound check.
- `ThresholdConfig` — `d20ad0b` constitutional test (`test_constitution_threshold_auto_strictly_greater_than_confirm`) covers the cross-field invariant. Frozen + `extra="forbid"` is exercised indirectly by every existing config_loader test that constructs one.

Recommendation: C3 §6 covers `AutonomyScore` + `DecisionTrace` only. C3-10 commit message Q4 line explicitly itemizes the deferred coverage and the reason ("vacuously held by C2 + `d20ad0b`"). Architect can override (cost: ~6-8 boilerplate tests added in C3-8).

**3. Rule-Literal sync mechanism: extend constitutional test, not extract alias.**
Brief decision 4 offered options (a) extract alias vs (b) extend constitutional test. Option (a) requires the alias to live somewhere: if in `scoring.py`, then `core/event.py` must import from `autonomy` — breaks the layering preserved by the C2 deliberate-duplication design (see `AutonomyDecisionMetadata` docstring lines 209-211). If in `core/event.py`, then core owns a concept (rule names) that semantically belongs to the scorer. If in a new shared module, that introduces a third layer for one Literal. Option (b) is pure test-layer, preserves layering, sits next to the existing field-parity assertion (literally same test function). Recommendation: option (b), encoded as a one-line extension in C3-2. Architect override to option (a) requires a follow-up ADR on cross-module Literal aliasing (not in scope for C3).

**4. ADR-006 commit shape: own commit before C3 impl commit.**
Two options: (i) C3-1 lands ADR-006 as its own commit (status `Accepted`); C3-2..C3-10 land impl in a second commit. (ii) ADR-006 + impl fold into one commit. I lean (i) because (a) git bisect cleanliness (ADR vs impl bug separation); (b) the architect Accept step is a visible event in history before code lands; (c) precedent: ADR-005 landed as its own commit in C1, code came later in C2. Easy switch to (ii) if architect prefers; bundle is 90% the same work either way.

Architect's suggested text in §"Architect-settled design decisions" decision 2 reads cleanly. The phrase "is the destructive-action refusal layer, not the scorer's HARD_CONFIRM tier" is the load-bearing clause. No refinement needed. Senior accepts verbatim.
