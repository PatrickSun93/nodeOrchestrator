**Subject:** Implement P2.1 — the **cross-room hypothesis matcher (promotion rule (a))**: detect when the same claim is independently recorded across ≥N distinct rooms and flip `Hypothesis.candidate_for_promotion = True` on those rows, so the user is *shown* cross-room-corroborated candidates to (manually) promote. **Advisory only** — the matcher never promotes; `promote_hypothesis` (P1.6.5) remains the sole promotion path and stays user-confirm. This is the first cross-room memory *intelligence* slice on top of P1.6.5's persistence substrate.

## The gating design decision (architect-settled 2026-05-29)

P1.6.5 deferred this matcher for one reason (ADR-016 D7 / out-of-scope #8): the matching-signal question was unresolved — *"code-only matching is weak (exact-string match passes tests, fails in practice); LLM semantic matching may violate Principle 5 (`handoff.md` §3.1 promotion-eligibility-is-code)."* That fork is now settled.

**Verified facts that shaped the call:**
- Hypothesis's only cross-room-comparable field today is free-text `content` (`topic_tags` lives on VerifiedKnowledge, **not** Hypothesis). So pure-code matching on existing fields collapses to fuzzy content-string match — exactly the "misleadingly weak" matcher ADR-016 rejected.
- No embeddings infrastructure exists (`grep -ri embed src/orchestrator/` → 0; the LLM layer is `call()`/chat-completion only). A semantic matcher would need a new embeddings-provider abstraction **first**.
- `tests/memory/test_constitution.py` bans LLM deps in `memory/`. An embedding call from `memory/` trips it without a constitutional amendment.

**Decision: structural / code, on a structured key.** Add `topic_tags` to `Hypothesis` (mirror VK), assigned **upstream at record-time** by the recording agent/user — that is content-generation (the allowed LLM surface, in the agent layer, *outside* `memory/`). The matcher itself does pure **tag-overlap in code**: no LLM, no embeddings, deterministic, constitution intact.

**Why this is NOT the weak matcher ADR-016 rejected** (senior must inscribe this reconciliation in the ADR, or it reads as doing the forbidden thing):
1. It matches on **deliberate, structured tags**, not paraphrase-prone raw content.
2. It is **advisory** — it flips a flag that *surfaces a candidate for the user to review*, never drives promotion. A false positive costs a declined suggestion; a false negative costs a missed suggestion the user can still promote manually. The quality bar is far lower than for a matcher that gated promotion (which is what ADR-016's deferral reasoning implicitly worried about).

## Scope

**In scope (P2.1):**

- **`Hypothesis.topic_tags: list[str]` schema addition** (`memory/schema.py`) — mirrors `VerifiedKnowledge.topic_tags`. Default empty list (push-back #3). The structured matching key.
  - `memory/store.py`: `hypothesis` table gains a `topic_tags TEXT NOT NULL DEFAULT '[]'` column (JSON list, per the §5.8 TEXT-stored-JSON pattern). **First ALTER-not-CREATE in `memory/`** — `init_memory_schema` must idempotently add the column to a pre-existing `hypothesis` table (`CREATE TABLE IF NOT EXISTS` will NOT add a column to an existing table). See self-discoveries.
  - `record_hypothesis(...)` gains a `topic_tags` parameter (keyword-only, optional, default empty — preserves existing callers; push-back #3).

- **`src/orchestrator/memory/matcher.py`** — the matcher. Single explicit, on-demand batch API (push-back/lean — not auto-on-record):
  ```python
  def run_matcher(conn, *, min_rooms: int = 2) -> MatcherResult:
      """Scan PENDING hypotheses; group by topic_tag overlap; for any group
      whose rows span >= min_rooms DISTINCT room_ids, set
      candidate_for_promotion=True on those rows. Pure code, no LLM.
      Deterministic (order-independent). Idempotent (re-run is a no-op on
      already-flagged rows). Monotonic in P2.1 (only flips False->True)."""
  ```
  - Only `status == PENDING` rows are eligible.
  - "≥ N rooms" counts **distinct `room_id`s** in the matched group (same claim re-recorded in one room is not cross-room corroboration).
  - The tag-overlap **predicate** (what overlap = "same claim": exact tag-set equality / Jaccard ≥ θ / ≥K shared tags) is senior's to propose — push-back #2; lean toward precision.

- **Thin reader so the flag is end-to-end consumable**: `list_promotion_candidates(conn) -> list[Hypothesis]` (location: `matcher.py` or `lookup.py` — senior's call). Returns PENDING + `candidate_for_promotion = True` rows — index-covered by the existing `idx_hypothesis_status_candidate`. Without this, the matcher writes a flag nothing reads.

- **End-to-end test (Scenario Y)**: ≥3 Research rooms.
  1. Record hypotheses with `topic_tags`: a matching claim in rooms 1 & 2 (overlapping tags); a non-matching singleton in room 3.
  2. `run_matcher(conn, min_rooms=2)`.
  3. Assert: the rooms-1&2 rows flip `candidate_for_promotion=True`; the room-3 singleton stays False; a same-room duplicate does NOT count toward the room threshold.

  6. Idempotency: a second `run_matcher` run changes nothing.

## Architect-settled design decisions

1. **Matching = structural / code on a structured key.** Add `Hypothesis.topic_tags`; match on tag-overlap; no LLM, no embeddings in `memory/`. Tag assignment is upstream content-gen (agent layer), outside `memory/`. (Gating fork — settled in chat.)
2. **Advisory-only.** `run_matcher` flips `candidate_for_promotion`; it does NOT promote and does NOT gate `promote_hypothesis`. ADR-016 D3 (promotion eligibility = `status==PENDING`, flag-independent) and D10 (no auto-promote) are preserved unchanged.
3. **N = ≥2 distinct rooms** (`min_rooms` parameter, default 2; "distinct" = distinct `room_id`).
4. **Trigger = explicit on-demand batch** `run_matcher(conn, ...)`. Not auto-on-`record_hypothesis` (mirrors `lookup`/`promote` explicit-API pattern + ADR-014 D3 producer-trigger intuition).
5. **No canonical event on flag.** Flagging is derived advisory state, not a user decision — it emits nothing into the event stream. Only promotion (the user act) emits a `decision` event, unchanged from P1.6.5.
6. **Output = boolean flip, monotonic** (False→True). Cluster-identity persistence + un-flagging defer.
7. **Ship the reader** (`list_promotion_candidates`) so the flag is consumable end-to-end.

## Constraints (do not violate)

- **No LLM in `memory/`** (`handoff.md` §3.1 + §4.5; `tests/memory/test_constitution.py`). The matcher is pure code. Tag *content* may originate from an LLM, but only via the agent-layer content-gen path — never an LLM call inside `memory/`.
- **No auto-promote** (ADR-016 D10; `handoff.md` §4.5 "不自动晋升"). The matcher must not create a VK row or emit a promotion `decision` event. Orthogonality is load-bearing — the e2e asserts it.
- **Determinism** (Principle 11). Same hypothesis set → same flag outcome regardless of row/scan order. Sort before grouping; deterministic test.
- **Dependency direction** unchanged: `memory/` may import `core/`; `core/` MUST NOT import `memory/`. No new cross-package edge (matcher lives in `memory/`).
- **ADR-016 D3/D10 preserved.** If senior amends ADR-016 rather than writing ADR-017, the amendment must state explicitly that D3 (flag-independent eligibility) and D10 (no auto-promote) are unchanged.
