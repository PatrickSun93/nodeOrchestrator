## 1. Framing

P3.3 is a **read-mostly React/TS GUI** (top-level `ui/`) that **reads** a room (HTTP snapshot + WS live stream) and **sends user intent** (`POST /intent`), binding the **frozen ADR-025 contract** (`api/openapi.json` + `api/asyncapi.md`). It adds **zero Python** — the HTTP/WS API is the sole boundary. The demonstrable loop: type a message → `POST /intent {type:"user_input", content}` → watch the agents' responses arrive on the WS. The architect ruled the stack (React+Vite+TS+Zustand, restrained CSS-modules+Tabler), top-level `ui/`, GUI-owned `ui_strings`, codegen-HTTP + hand-written-WS, the FE gate, single-lens R0-A (no dual-lens). The **constitutional spine** (ADR-026 HR#1–5) is non-negotiable: view+intent only, **binds-API-only (no Python/DB backdoor)**, **状态机不暴露 via `ui_strings`**, partial-turn correctness, no-forge. **Because there is no FE to pattern-match, this plan spells out the patterns** (structure, API client, WS client, store, ui_strings) for the junior.

## 3. API client (ADR-026 D2 — codegen HTTP)

`src/api/schema.ts` is generated by `openapi-typescript ../../src/orchestrator/api/openapi.json -o src/api/schema.ts` (an `npm run codegen` script; regenerated when the contract changes — drift-proof). `src/api/client.ts` is a thin typed `fetch` wrapper exposing: `createRoom(type)`, `getRoom(id)`, `getEvents(id)`, `getSnapshot(id)`, `getThread(eventId)`, `postIntent(roomId, {type, content})` → returns `IntentResponse` | throws a typed `IntentError` (with `stage`). The wire is **raw snake_case** (`parent_id`/`room_id`/…) — the client passes it through untouched; humanization is `uiStrings` only. **`client.ts` + `stream.ts` are the only modules that touch `fetch`/`WebSocket`** (HR#2; eslint-enforced).

## 4. WS client (ADR-026 D2 — hand-written; the real integration surface)

`src/api/stream.ts`: a typed client over the `StreamMessage` envelope honoring `asyncapi.md` exactly. Lifecycle (the load-bearing pattern):

```
connect ws://<base>/rooms/{id}/stream
  → phase = 'loading'
  → on StreamEventMessage (replay phase): applyEvent(event)   // ordered, dedup by id
  → on StreamReplayCompleteMessage:        phase = 'live'
  → on StreamEventMessage (live phase):    applyEvent(event)   // dedup by id (overlap with replay)
  → on StreamErrorMessage:
        stage="turn" → mark intent landed; reconcile via replay; DO NOT re-post (HR#4)
        stage="append" → safe to retry
  → on {"kind":"ping"} keepalive: no-op (tolerate the non-envelope frame)
  → on close/error: phase = 'reconnecting' → backoff reconnect → re-replay (dedup against seenIds)
```

**Dedup by `event.id`** is centralized in the store's `applyEvent` (replay, live, and reconnect-replay all funnel through it), so an event seen in replay **and** the live overlap (or re-seen after reconnect) renders **once**. The client is typed against hand-written WS message types mirroring `wire.py`'s `StreamMessage` (codegen covers HTTP only). This is the highest-risk surface → the heaviest vitest coverage (§7).

## 5. Store (ADR-026 D5 — Zustand)

`{ roomId, roomType, events: Event[] (ordered, deduped), seenIds: Set<string>, phase: 'idle'|'loading'|'live'|'reconnecting'|'error', pendingIntent: {content, status}|null, lastError: {stage,reason}|null }`. `applyEvent(e)` is the single dedup+order chokepoint (skip if `seenIds.has(e.id)`; else insert by `timestamp` then arrival). `phase` drives `ConnectionStatus`. `pendingIntent`/`lastError` drive the compose box's partial-turn UX (a `stage:"turn"` failure marks the intent landed — the Composer does **not** offer re-post; a `stage:"append"` failure offers retry).

## 6. ui_strings + read view + intent (ADR-026 D3; the MVP)

- **`uiStrings.ts`** (the 不暴露 mapper, HR#3): `eventTypeLabel(EventType)` (19 values → human; the MVP renders `user_input`/`utterance`/`decision`/`hypothesis`/… as conversation; the rest get safe labels), `authorLabel(author)` (`"user"`→你 · `"system"`→系统 · `"agent:<id>"`→agent human name via an id→name sub-map, unknown→助手), `roomTypeLabel(RoomType)` (free_chat→闲聊 · bug_fix→修复问题 · research→研究 · code_review→代码评审 · idea_validation→想法验证), `roomStateLabel(state)` (raw state-machine states → human progress; e.g. setup→准备中 … closed→已结束). **Never returns the raw key; unknown → a safe generic, never the raw string.** Internal-only vocab (skill / state machine / autonomy level / dissent dimension) is **不暴露** — the MVP surfaces conversation + room state + room type only.
- **Read view:** `RoomView` drives `useRoomStream(roomId)` (snapshot/events seed optional; the WS replay is the source of truth) → `MessageList` renders `events` as messages (`MessageItem`: `authorLabel` + `eventTypeLabel` chip + `content`), `ConnectionStatus` shows `phase`.
- **Intent:** `Composer` → `useIntent` → `postIntent(roomId, {type:"user_input", content})`; on success the appended event + the agents' replies arrive via the WS (rendered live); on `IntentError`, branch on `stage` (HR#4). `RoomCreate`/`RoomPicker`: minimal `POST /rooms` + pick a `RoomType`.

## 10. Self-discoveries (verified `origin/main`)

- **The contract is fully frozen + codegen-able for HTTP** (`openapi.json` has `Event`/`Room`/`Snapshot`/`Intent*`/`TurnResult`; 19 `EventType` + 5 `RoomType` enums) — the GUI types track it via `openapi-typescript`. **WS types are NOT in `openapi.json`** (they live in `asyncapi.md` + `wire.py`'s `StreamMessage`) → the WS client + its types are hand-written.
- **The wire is raw snake_case** (`parent_id`/`room_id`/`state_transition`/…) — humanization is **entirely** the GUI's (`ui_strings`); this IS the 状态机不暴露 duty (HR#3).
- **The server sends a `{"kind":"ping"}` keepalive** (`app.py` WS handler) — a non-`StreamMessage` frame the client must tolerate (no-op), else it errors on every keepalive.
- **`IntentRequest` omits `author`/`id`/`timestamp`** (`openapi.json`) — no-forge is **type-impossible** on the client (HR#5); the GUI only sets `type:"user_input"` + `content`.
- **`config/ui_strings/` does not exist + no frontend dir** — `ui_strings` is GUI-owned (D3); `ui/` is net-new top-level.
- **No node toolchain in the Python gate** — the FE gate (eslint/tsc/vitest/prettier) is separate, in `ui/`; the Python ruff/mypy/pytest don't touch `ui/` (mirrors the P3.2 `[api]`-extra scoped-sub-gate pattern).
- **Binds-API-only is structurally checkable** in a node app — no DB/fs runtime dep + `fetch`/`WebSocket` confined to `src/api/` (eslint + a test) makes the no-backdoor invariant enforceable, not just convention.
