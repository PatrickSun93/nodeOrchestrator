## Architect-settled design decisions

### 1. HARD_CONFIRM dead branch is by design (Q1=b)

When `effective_threshold_confirm` is clamped by `max(0, …)` to 0, HARD_CONFIRM becomes structurally unreachable for any score ≥ 0. This is the deliberate consequence of ADR-005 §5(c): the floor exists so HARD_CONFIRM is unreachable rather than the alternative (negative threshold making HARD_CONFIRM unreachable in a confused way). Hard Guards (P1.3) is the real refusal layer for destructive operations; the scorer's HARD_CONFIRM tier is **not** the destructive defense.

**Plan must include:** a new constitutional test locking the invariant. Suggested name `test_constitution_hard_confirm_unreachable_when_effective_confirm_clamped` (not a mandate; rename if you prefer). Location `tests/autonomy/test_constitution.py` (already exists from `d20ad0b`). Test should fire concurrent decisions across a representative range of operator + user_intent combinations and assert: when `effective_confirm == 0`, no produced `AutonomyScore.tier == HARD_CONFIRM` regardless of score.

### 2. `git_push + user_explicit_intent=True` lands on COUNTDOWN_CONFIRM is the correct semantic (Q2=ii)

Specifically: with `operator` thresholds (`auto=6, confirm=3, modifier=3`) and a `git_push` tool whose reversibility=1, `user_explicit_intent=True` produces `effective_confirm=0`, so score=1 ≥ 0 → COUNTDOWN_CONFIRM rather than HARD_CONFIRM. This is non-obvious — readers will assume "user said push to main + irreversible action → strict prompt". The point is: user_intent reduces the gap by design; the destructive-action refusal lives in Hard Guards, not in the scorer.

**Plan must include:**

- A boundary test pinning the semantic. Suggested name `test_git_push_with_user_intent_lands_on_countdown_not_hard` (rename freely). Lives wherever the main `decide_tier` tests live (your call: `tests/autonomy/test_scoring.py` likely).
- **ADR-005 §5(c) revision** — one sentence appended. Suggested text (architect-drafted, not finalized): *"Concrete example: a `git_push` (reversibility=1) called by `operator` (modifier=3) with `user_explicit_intent=True` lands on COUNTDOWN_CONFIRM, not HARD_CONFIRM — Hard Guards (P1.3) is the destructive-action refusal layer, not the scorer's HARD_CONFIRM tier."* Senior may refine the wording before architect accepts.

### 3. Unknown `tool_id` raises `UnknownToolError` (Q3=b → ADR-006)

Semantic split clarified:

- Tool **in** registry but `reversibility` field missing → Pydantic default 0 (already enforced at schema level via `ToolMeta.reversibility = Field(default=0, …)`).
- Tool **not in** registry at all → `score()` raises `UnknownToolError`.

The split addresses Principle 4 (structured uncertainty — empty/default must not impersonate well-defined values) and Principle 9 (term audit — "unknown" and "irreversible" are distinct semantics).

**Plan must include:**

- New exception class `UnknownToolError`. Location is **your call**: `src/orchestrator/autonomy/exceptions.py` (new file, mirrors LLM module's `exceptions.py` habit) or appended to `src/orchestrator/autonomy/scoring.py` (one file fewer). Surface your choice in "Where you'd push back".
- `score()` signature documentation update: "Returns `int` 0..10. Raises `UnknownToolError` if `operation.tool_id` is not in the tools registry."
- `gate()` propagates `UnknownToolError` unwrapped — do not catch it and convert to a default tier. The caller (C4 event-emission code) decides what to do.
- §4 test coverage applies (see table below). Test asserts `UnknownToolError` carries the failing `tool_id` as a structured attribute (not just in `str(e)`) so log-based diagnosis is possible per `test-coverage-standard.md` §4.
- **New ADR-006** "Unknown tool_id semantics" — **you draft**. Context, Decision, Considered alternatives (default 0 vs raise vs trace-flag), Consequences, Reversibility. Architect reviews and accepts. This is the first non-bootstrap application of the senior-drafts-ADR rule.

### 4. Rule Literal cross-class sync — R0-A item #4 into C3

Currently `DecisionTrace.rule` (in `scoring.py`) and `AutonomyDecisionMetadata.rule` (in `core/event.py`) each declare the same three Literal values verbatim. The constitutional test `test_constitution_autonomy_decision_event_carries_trace` syncs the field **set** but not the Literal **values** — a future change to one but not the other would still pass.

**Plan must include one of the two options below; your call which:**

- (a) Extract a module-level `Literal` alias both classes reference. Lives in `scoring.py` (preferred — autonomy is the source of truth; `core/event.py` already explains the deliberate duplication is to preserve layering).
- (b) Extend `test_constitution_autonomy_decision_event_carries_trace` to also assert the `rule` field's annotation matches between classes.

(a) eliminates the drift surface; (b) catches it earlier in CI. Surface which you chose and why in "Where you'd push back".

## Constraints (do not violate)

- **No LLM imports in the autonomy module.** `test_constitution_no_llm_calls_in_autonomy_module` is load-bearing.
- **`decision_trace` mandatory** per `contributing.md` Q2. `score()` returns `int`, `decide_tier()` returns `AutonomyScore` carrying full `DecisionTrace`, `gate()` returns `AutonomyScore`.
- **Layering.** Autonomy module must not import from `orchestrator.llm` (constitutional test enforces). `orchestrator.core` must not import from `orchestrator.autonomy` either (C2 freeze decision; preserved via deliberate `DecisionTrace` ↔ `AutonomyDecisionMetadata` duplication).
- **Pure functions.** scoring.py's three functions perform no I/O, no clock calls, no event emission. The event emission is the caller's responsibility (lands in C4).
