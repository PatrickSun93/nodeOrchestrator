## 5. Where I'd push back

### Architect-predicted push-back items

**1. `emission.py` location: `src/orchestrator/autonomy/emission.py`.**
Architect-partner's lean is correct. Emission decides which event type to write based on the autonomy outcome — that decision belongs at the autonomy layer, not the agent layer (P1.4 territory). Future agent runtime will compose `autonomy.emission.emit_gate_decision(...)` without needing to know which EventType corresponds to which outcome. Putting it in `agents/` would force the agent to own the "if UnknownToolError then refusal event" branching, which is autonomy-layer logic. Accept architect lean unchanged.

**2. Event store dependency direction: documented in C4-5 commit message + proposed constitutional test (see §4).**
C4-5 introduces the first `autonomy → core` import edge. ADR-007 Decision 4 records the layering rule explicitly; C4-5 commit message reiterates it; my proposed constitutional test (in §4 forcing functions) would enforce the reverse direction stays forbidden. Architect decides whether to land the constitutional test in C4-5 or defer to a separate hygiene PR. Senior leans **land in C4-5** — the test is cheap and the rule is being established this very commit, so co-locating the enforcement makes audit trivial.

**3. `autonomy_refusal` event type name: accept general name.**
ADR-007 Decision 1 records the rationale. Specific name (`unknown_tool_attempted`) would force new EventType per P1.3 refusal class — EventType bloat ADR-001 deliberately makes costly. General name with `refusal_reason` discriminator preserves vocabulary at the cost of one Literal extension per future ADR. Senior strongly recommends general.

**4. §6 commit boundary: keep C4-6 as own commit (not folded into C4-4 or C4-5).**
C4-6 is debt-repayment work (architect-acked C3 deferral). Bundling debt-payment with new-feature commits muddies bisect — if a §6 boundary test happens to interact unexpectedly with new code, separate commit lets us isolate cleanly. The marginal cost of one extra commit is small; the bisect-clarity benefit is large enough on a 7-commit batch. Recommendation: keep separate.

**5. Refusal metadata field count: 4 fields, no timestamp.**
Architect-partner's lean is correct. Event itself carries timestamp at append time via `EventStore.append()`; duplicating in metadata would be redundant (Principle 4 — fake precision). If a future Hard Guards refusal needs more context (e.g., the operation params that failed), add fields via ADR amendment then; do not pre-bloat.
