## 2. Tasks

### P7-1 (mandatory) — skills loader: drop redundant rglob + `StopIteration` footgun

- **What:** In the duplicate-id branch, name the earlier path from an in-pass
  `id → path` map instead of re-traversing the tree with `next(... rglob ...)`.
- **Where:** `src/orchestrator/skills/loader.py` — `load_skills()`. Add a
  `seen_paths: dict[str, Path] = {}` beside `skills` (`:91`); record
  `seen_paths[skill.id] = md_path` at the same point the skill is registered
  (`:131`); rewrite the duplicate branch (`:121-129`) to read the existing path
  from `seen_paths[skill.id]`. Delete the `next(p for p in directory.rglob("*.md")
  ...)` expression (`:122-124`) entirely.
- **Why:** Brief #1. Two defects: (a) a redundant full `rglob` on the error path;
  (b) `next()` has no `default` → bare `StopIteration` masks the real `SkillError`.
  The map is keyed by `skill.id`; because the loader already enforces
  `stem == id` immediately above (`loader.py:113-119`, ADR-009 D8), the
  id-keyed map is exactly the stem→path map the brief describes.
- **Acceptance criteria:**
  - Duplicate-id detection still raises `SkillError` (not `StopIteration`),
    citing **both** the earlier and the current path, with the same
    `path=` / `field="id"` kwargs as today.
  - No `directory.rglob(...)` (or any re-traversal) remains on the error path.
  - The raise-on-duplicate contract and ADR-009 D8 (`stem == id`) are unchanged.
  - Existing skills tests still pass.
- **Out of scope:** the `load_skills` docstring wording; the `stem != id` branch
  (`:113-119`); any change to load ordering or the `sorted(... rglob ...)` discovery
  pass at `:93`.

### P7-6 — autonomy config: cross-field validator `window_s >= sweep_interval_s`

- **What:** Add a Pydantic `model_validator` to `CountdownAutoFireConfig`
  rejecting `window_s < sweep_interval_s` at load.
- **Where:** `src/orchestrator/autonomy/config.py` — `CountdownAutoFireConfig`
  (fields at `:28-29`). Add a `@model_validator(mode="after")` that raises
  `ValueError` when `window_s < sweep_interval_s`. The existing loader
  (`load_countdown_auto_fire_config`, `:52-55`) already wraps `ValidationError`
  from `model_validate` into a `ValueError` with the `countdown_auto_fire:` prefix,
  so the new check inherits the refuse-start path with no loader change.
- **Why:** Brief #6. A sweep coarser than the window lets COUNTDOWN auto-fire
  overshoot the cancel window by up to one sweep interval — and auto-fire is the
  human-out-of-loop path (RB-AUTOFIRE), so overshoot matters. Consistent with
  ADR-040 D7's fail-closed refuse-start posture and D1's fire-latency semantics
  (fire latency is one `sweep_interval_s` tick within the window, which presumes
  `sweep_interval_s <= window_s`).
- **Acceptance criteria:**
  - A config with `window_s < sweep_interval_s` raises `ValueError` at load.
  - A valid config (incl. the equal case `window_s == sweep_interval_s`) loads.
  - The defaults (`window_s=300`, `sweep_interval_s=30`, verified at
    `config.py:28-29`) still satisfy the constraint and load unchanged.
  - `frozen=True` / `extra="forbid"` model config is untouched.
- **Out of scope:** any ADR-040 amendment note (see §5); `reversibility_floor`;
  `enabled`; the loader function body beyond what the validator requires.

### P7-7 — autonomy scoring: document the `eff_confirm` floor (doc-only)

- **Where:** `src/orchestrator/autonomy/scoring.py:178` (`eff_confirm = max(0,
