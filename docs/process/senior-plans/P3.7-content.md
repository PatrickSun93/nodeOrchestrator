# Senior plan — P3.7-content (content depth → 完整 breadth)

## 1. Context

The architect ratified the brief's leans wholesale (all four): **(a)** breadth = round out the existing 5 room types' rosters + per-domain skill coverage + 1–2 local connectors/plugins (a *coherent* breadth target, not an open-ended dump); **(b)** the deferred local *tools* (ADR-028 D3 network/subprocess/mutation) are **out**; **(c)** single-lens R0-A, no dual-lens; **(d)** no new ADR. This is the **P3.1 class of work** — additive content + established-pattern code on the **frozen** loaders (`load_agents` / `load_skills` / `ROOM_TEMPLATES` / `load_mcp_servers_config` / plugin loader). Nothing here reshapes a loader, adds an `LLMPurpose`, touches the gate/executor, or introduces a trust surface — all remote/Posture-B work is the sibling P3.7-remote.

Concrete instantiation of the §a envelope (the one architect-confirmable **dial** — see §5): **2 new agents** + roster placements, **2 new skills** (one fills the empty `business` category; one rounds out `code_review`), **1 new local stdio connector**, **1 new local Posture-A plugin**. Each unit ships with a **discriminating** test (it really registers / really gates / really fails-closed — not "renders something").

Substrate verified @ `ab5af6b`: 6 agents (`facilitator`/`operator`/`prober`/`skeptic`/`divergence_mapper`/`logger`); 5 populated rosters in `rooms/templates.py` (`code_review` is the thinnest analytical roster — 3 agents); 2 skills (`engineering/`, `general/` — `business/` absent); 1 demo connector (`filesystem`); 1 demo plugin (`plugins/demo/`).

## 2. Tasks (atomic — one unit = one commit)

**P3.7-content-1 — Add `synthesizer` agent + roster placement.**
- *What*: New `config/agents/synthesizer.yaml` (converges discussion / proposes consensus), declared into `ROOM_TEMPLATES` for `research`, `code_review`, `idea_validation` (keep `declared_agents` alphabetical).
- *Where*: `config/agents/synthesizer.yaml`; `src/orchestrator/rooms/templates.py` (3 roster lists); `tests/rooms/test_scaffold_activation.py` (or a sibling test module).
- *Why*: brief §Scope "more agents + roster placements"; reuses the frozen ADR-024 Agent shape (responses stay `AGENT_RESPONSE` content-gen, activation stays code `should_agent_speak`).
- *Acceptance*: yaml validates against the frozen `Agent` schema (`extra="forbid"`); `applies_to.room_states` non-empty (use `["*"]`, per schema `min_length=1`); **discriminating test** mirrors the P3.1 facilitator pattern — `should_agent_speak` returns `speak=True` on a constructed event in **each** declared room type, AND `load_room(<a non-declared type>)` reports it **absent** from the roster (present/missing partition). Triggers reference only states valid for the declared room types' state machines, OR use room-state-agnostic regex/event_type triggers (verify any `state_change.target_state` exists).
- *Out of scope*: any loader/schema change; new `LLMPurpose`; adding it to `bug_fix`/`free_chat`.

**P3.7-content-2 — Add `planner` agent + roster placement.**
- *What*: New `config/agents/planner.yaml` (decomposes the task into ordered steps), declared into `bug_fix`, `code_review`, `idea_validation`.

**P3.7-content-3 — Add `business`-category skill.**

- *Acceptance*: **filename stem == `id`** (ADR-009 D8 — loader enforces); validates against frozen `Skill` schema; **discriminating test** — the skill **matches** (via the existing skills decision path) for a room/agent/state it declares, and is **rejected** (`rejection_reason != "matched"`) for a non-declared room type. Non-empty body (schema rejects empty).

**P3.7-content-5 — Add a 2nd local stdio MCP connector.**
- *What*: New `servers:` entry in `config/mcp_servers.yaml` — a **purely-local** stdio server (lean: `@modelcontextprotocol/server-memory` — local knowledge-graph, no network, no subprocess-shell trust surface), with a **partial** code-classified tool allowlist demonstrating tier discrimination (a read tool `reversibility: 10` → AUTO_EXECUTE; a write/mutation tool low rev → HARD_CONFIRM).
- *Where*: `config/mcp_servers.yaml`; gate test in `tests/mcp/` (mirror `test_gating.py`).
- *Why*: brief §Scope "more local connectors … each with its code-classified tool allowlist" (ADR-027 D3 pre-classify-allowlist, reused).
- *Acceptance*: **discriminating test** — a classified tool resolves to its expected gate tier (read→AUTO, write→HARD_CONFIRM); a tool the server exposes **but not listed** raises `UnknownToolError` → refused (discovery≠permission, HR#3). Config validates against the frozen connector schema. Tests gate **config/classification**, not a live `npx` subprocess.
- *Out of scope*: any network/subprocess/mutation tool from ADR-028 D3 (§b — not this slice); remote transport (P3.7-remote). If the chosen server's only useful tools fall into a deferred trust class → **surface**, don't substitute silently.

**P3.7-content-6 — Add a 2nd local Posture-A plugin bundle.**
- *What*: New `plugins/<id>/` bundle (`plugin.yaml` manifest + a contributed role + skill + tool), mirroring `plugins/demo/`. Demonstrate the host-pre-classify vs plugin-classify-only tool paths (ADR-029 D5/D7) as the demo does.
- *Where*: `plugins/<id>/{plugin.yaml,agents/,skills/,tools.yaml,tools_impl.py}`; `config/tools.yaml` only if adding a **host-authoritative** classification for a contributed tool (host file is authoritative per ADR-029 D5); plugin test in `tests/plugins/`.
- *Why*: brief §Scope "more local Posture-A plugins"; reuses the ADR-029 manifest + fail-closed loader unchanged.
- *Acceptance*: **discriminating test** (mirror `test_merge.py` + `test_failure_modes.py`) — plugin **loads + merges** (its role/skill/tool/server appear in the merged registries); its host-classified tool gates to the expected tier while a plugin-classify-only tool **caps to rev 0 / HARD_CONFIRM** (cannot self-raise above host cap); and at least one **fail-closed** path is exercised for the new bundle (bad-manifest or name-collision → refused, host unchanged).
- *Out of scope*: Posture-B subprocess isolation; fetched/registry plugins (P3.7-remote).
