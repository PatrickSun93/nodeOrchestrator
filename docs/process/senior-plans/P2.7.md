## 2. The four sub-items (design + scope + acceptance)

### S1 — room-SM scaffold buildout (product room SM; ADR-012 amendment)

**What.** Give the four scaffold RoomTypes (`bug_fix`, `code_review`, `idea_validation`, `free_chat`) real, event-triggered transition tables, replacing the always-`None` `_next_scaffold_state` (`state_machine.py:219-231`). State sets + arcs are pinned in the **ADR-012 amendment** (each mirrors `_next_research_state`'s idiom: pattern-match `room.state` + `current_event.type` → `_guard_valid_state` → typed `RoomStateTransition`).

**Files (footprint):** `rooms/state_machine.py` (the four new `_next_<type>_state` fns + `_VALID_STATES` + `next_room_state` dispatch) + `tests/rooms/test_state_machine.py`. **Cleanly disjoint** — separate `rooms/` package, touches no `llm/`.

**Acceptance.** (1) Each RoomType's lifecycle transitions on its trigger and **only** its trigger — discriminating per-arc tests (RC-25): the arc fires on the right `current_event.type`, and a *wrong* event type in the same state returns `None`. (2) Pure code, no LLM — the existing `test_constitution_no_llm_calls_in_rooms_module` still passes (no new `llm/` import). (3) `_guard_valid_state` rejects an out-of-set state (defensive contract preserved). (4) `setup` + `closed` preserved in every set (backward-compat; existing replay valid). (5) Decision-trace (`rule_matched`) present per transition (Q2). **Note:** populating the four scaffold templates' agent rosters (`templates.py:11-12`, currently `[]`) is *separate content work* — flagged for architect scope, not bundled here (the state machine is the code deliverable; per-state agent activation already works via `applies_to.room_states`).

### S2 — LLM Layer-4 global cost/quality override (the c1 constitutional crux; ADR-023 D1–D3 + ADR-002 amendment)

**What.** An optional, deployment-global override (`config/llm_override.yaml` → frozen `GlobalLLMOverride`: `quality_tier` + `cost_ceiling_per_1m_output` + **`on_unknown_cost: Literal["keep","drop"] = "keep"`**) applied by a **pure function** `apply_global_override(chain, override, models) -> chain` that deterministically filters (by cost ceiling) + reorders (by quality tier) the candidate `[default_model, *fallback_chain]` **before** the router walks it. Composes with — never bypasses — Layer-3 (the transformed chain still runs the router's capability/provider/tools/health filters). Empty chain ⇒ `NoSuitableModelError` (fail-loud, with the override reason in the trace).

**Y1-α (R0-A + R0-B convergent — unpriced models vs a cost dial).** Unknown-cost candidates (`cost_per_1m_output is None`) under a set ceiling are governed by **`on_unknown_cost`**: `"keep"` (**default — behavior unchanged**, the soft ceiling) or `"drop"` (hard ceiling, fail-closed). **Either way the softness is made visible**: every unknown-cost candidate met under a ceiling gets a `decision_trace`/`RouteCandidate` entry (kept-despite-unknown-cost or dropped-as-unknown-cost) — so a user never silently believes an unpriced model was cost-bounded. No ceiling set ⇒ `on_unknown_cost` inert. ADR-023 D1/D2.

**Files:** `llm/router.py` (integration at chain-construction `:164-166`; `override` param on `select_model_and_provider`, default `None`) + `llm/config_loader.py` (load + validate `llm_override.yaml`) + `llm/types.py` (the `GlobalLLMOverride` model) + `config/llm_override.yaml` (sample) + `tests/llm/test_router.py` + `tests/llm/test_constitution.py` (the c1 structural test). ⚠️ **co-edits `config_loader.py` with S4.**

**Acceptance.** (1) **c1 structural test** (RC-24): a spy provider asserts `provider.call` count == 0 across every `quality_tier`/`cost_ceiling` combination through `apply_global_override` + `select_model_and_provider` (selection consults only sync `health_check()`); + an AST guard that the override module references no provider `.call`. (2) **No new `LLMPurpose`** (grep — the override adds none; taxonomy stays content-gen-only). (3) Deterministic + discriminating (RC-25): a `cost_ceiling` below model X's cost **drops** X (and a test proves the unfiltered chain would have selected X); `quality_tier=economy` reorders to cheapest-first (discriminating vs `balanced` identity). (3b) **`on_unknown_cost` (Y1-α)**: with a ceiling set + an unknown-cost (`None`) model, `on_unknown_cost="drop"` **drops** it while `"keep"` (default) **keeps** it — discriminating; **both** emit the unknown-cost `decision_trace` entry (assert the entry is present in each mode, so the softness is never silent). (4) Composition: a model passing the override but **failing** `required_capabilities`/health is still rejected by the router (override didn't bypass Layer-3). (5) Cleanup (test-coverage §3): absent `llm_override.yaml` ⇒ routing **byte-identical** to pre-S2. (6) Schema §6: `GlobalLLMOverride` frozen + `extra="forbid"`. (7) Empty-chain ⇒ `NoSuitableModelError` with the override filter reason in `decision_trace`.

### S3 — Claude Code alt-backend (the c2 security boundary; ADR-023 D4–D6)

**What.** `providers/claude_code_cli.py` gains `base_url: str | None = None`, plumbed to the subprocess env (`ANTHROPIC_BASE_URL`). Opt-in (unset = Anthropic default). **Fail-closed allowlist**: a `trusted_base_urls: list[str]` in the provider config; a set `base_url ∉ trusted_base_urls` (or empty allowlist) ⇒ `ConfigError` at startup. Credentials via the existing `api_key_env` indirection.

**Y2-α MUST-FIX (R0-B security — subprocess-env inheritance).** The `claude` subprocess must **never inherit** `ANTHROPIC_BASE_URL` from the parent process — otherwise an ambient parent value (OS / wrapper / container) reaches the child **without passing the allowlist**, silently bypassing the whole c2 boundary. The provider builds the child env **explicitly** in all cases: `base_url` set+allowlisted ⇒ child gets `ANTHROPIC_BASE_URL=<base_url>`; `base_url` **unset** ⇒ `ANTHROPIC_BASE_URL` is **explicitly cleared/removed** from the child env (a parent value is dropped, never forwarded). The redirect can take effect **only** through the allowlisted config path. ADR-023 D4.

**Files:** `providers/claude_code_cli.py` (the field + env plumbing + allowlist check) + `llm/config_loader.py`? (allowlist validation — **minor** touch; senior fork: keep the validation *inside* the provider's construction to avoid the `config_loader.py` co-edit with S2/S4 — see §3) + `llm/types.py` (`ProviderConnection.params` doc) + `config/llm_providers.yaml` (sample) + `tests/llm/providers/test_claude_code_cli.py`. **Mostly its own file.**

**Acceptance.** (1) `base_url` set + ∈ allowlist ⇒ env carries `ANTHROPIC_BASE_URL` (round-trip test). (2) **Fail-closed** (test-coverage §5 boundary validator): set `base_url` ∉ allowlist (incl. empty allowlist) ⇒ `ConfigError` — discriminating (a planted untrusted URL raises; a trusted one passes). (2b) **Env-inheritance fail-closed (Y2-α MUST-FIX, discriminating)**: parent env `ANTHROPIC_BASE_URL=<untrusted>` + config `base_url=None` ⇒ the **child** subprocess env does **not** carry `ANTHROPIC_BASE_URL` (asserts the parent-inheritance bypass is closed). (3) Cleanup (§3): unset `base_url` ⇒ no env var, default Anthropic, behavior unchanged. (4) Credentials never inline (key via `api_key_env`). (5) The trust tier is documented (what flows; higher tier than the local r0b proxy — ADR-023 D6).

### S4 — friendly startup errors + pinned boot entry (ADR-023 D7–D8)

**What.** Pin the boot home at new `src/orchestrator/bootstrap.py` — `load_and_validate_llm_layer(config_dir)` sequencing load_providers → load_models → load_agent_llm_config → **load override (S2)** → validate_full_config → check_all_providers, catching `ConfigError`/health failures and raising a `StartupError` with a **rendered, actionable** message (`render_startup_error`). Covers the **new** S2 (override) + S3 (allowlist) failure modes — hence **sequenced last**.

**Files:** `src/orchestrator/bootstrap.py` (new) + `llm/exceptions.py` (`StartupError`) + `llm/config_loader.py` (clearer error messages) + `tests/test_bootstrap.py` + `tests/llm/test_exceptions.py`. ⚠️ **co-edits `config_loader.py` with S2; cross-cutting.**

**Acceptance.** (1) **Message content asserted** (test-coverage §4, load-bearing): over-tight `cost_ceiling` renders the ceiling + dropped models + the fix; un-allowlisted `base_url` renders the URL + the `trusted_base_urls` field to add; missing provider renders the file + field. (2) `render_startup_error` handles each of `ConfigError.violations`, `NoSuitableModelError.decision_trace` (incl. the override reason), and `ProviderHealth.error`. (3) `bootstrap.py` composes (does not duplicate) the existing loaders + `check_all_providers`. (4) Fail-loud (ADR-002 D5) — accumulates violations, one rendered `StartupError`.

## 3. ⭐ Slice structure + workflow orchestration (the lead deliverable; architect ruled — decision a = batched)

### File-boundary truth (verified `origin/main`)

| Sub-item | Primary files | Shared-file contention |
|---|---|---|
| **S1** | `rooms/state_machine.py` + tests | **none** (separate package) |
| **S2** | `llm/router.py` + `llm/config_loader.py` + `llm/types.py` + config | `config_loader.py` ↕ S4 |
| **S3** | `providers/claude_code_cli.py` + `llm/types.py`(doc) + config | minimal; allowlist check kept **in-provider** to avoid `config_loader.py` |
| **S4** | `llm/config_loader.py` + `llm/exceptions.py` + `bootstrap.py`(new) | `config_loader.py` ↕ S2 |

**Disjointness verdict (honest):** S1 (`rooms/`) ∥ S2 (`llm/router.py`+`config_loader.py`) ∥ S3 (`providers/`) are **file-disjoint** and run concurrently. **S4 ↕ S2 contend on `config_loader.py`**, and S4 must render friendly errors for the *new* S2/S3 config — so **S4 sequences last**. (`types.py` is touched by S2 [new model] + S3 [doc only] — non-conflicting; if worried, a 1-line prelude lands the `types.py` skeleton, but the doc-vs-model edits don't collide.)

### Architect-ruled (decision a): **one P2.7 task, batched atomics** (resolves R0-A Y2)

The architect ruled **batched** — one P2.7 task, not four split tasks (R0-A Y2 flagged that 4 full ADR-008 lifecycles would re-derive a brief + plan per sub-slice for designs **already** impl-ready here in ADR-023 + the amendments + this plan §2; batching avoids that duplication, keeps one audit trail + one merge, and the dual-lens is dispatched on the S2/S3 atomics within the single review). The atomic graph:

```
ONE P2.7 task (single .workflow/P2.7.yaml, single review chain, single merge):

  PRELUDE  (P2.7-1)  resolve config_loader.py shared structure + types.py skeleton
                     (the GlobalLLMOverride model stub + the override-load hook seam)
        │
        ├──────────────┬──────────────┐   ← S1 ∥ S2 ∥ S3 file-disjoint atomics
        ▼              ▼              ▼     (junior MAY subagent-parallelize — architect-authorized
   S1 (P2.7-2)    S2 (P2.7-3)    S3 (P2.7-4)    for these independent slices; the no-junior-parallelism
   rooms/         llm/router+    providers/     default is carved out for P2.7-style disjoint atomics)
   state_machine  config_loader  claude_code_cli
        └──────────────┴──────────────┘
                       ▼
                 S4 (P2.7-5)  LAST — config_loader error msgs + exceptions.py + bootstrap.py;
                              MUST render friendly errors for S2's override + S3's allowlist
                              failure modes (so it follows S2/S3)
                       ▼
                 e2e + handoff + landing (P2.7-6; 5-surface reconcile)
```

- **Why the prelude:** S2 + S4 co-edit `config_loader.py`; the prelude lands the shared structure (the override-load seam + `types.py` `GlobalLLMOverride` skeleton) **once**, so the S2/S3/S1 atomics stay one-commit-each + conflict-free (RC-17), and S4 then only *adds error messages* to an already-settled config_loader.
- **Why S4 last:** its `render_startup_error` must cover the **new** S2 (override — incl. the Y1 unknown-cost trace) + S3 (allowlist + the Y2 env-inheritance) failure modes; those land in S2/S3 first.
- **Parallelism:** S1 (`rooms/`) ∥ S2 (`llm/router.py`+`config_loader.py`) ∥ S3 (`providers/`) are file-disjoint (the prelude having settled the shared `config_loader.py`/`types.py` seams), so junior may run them as parallel subagents (architect-authorized for these P2.7-style independent atomics). S4 is serial-last.
- **RC-17:** one atomic = one commit; the prelude resolves the shared files so each atomic is conflict-free.
- **Dual-lens R0-B:** dispatched within this **single** review chain on the **S2** (routing-is-code) + **S3** (alt-backend trust) atomics; S1/S4 ride single-lens. `requires_cross_family_review: true` (set). External R0-B prompt drafted (`reviews/P2.7/external-r0b-prompt.md`).
- **ADR:** ADR-023 is the umbrella (S2/S3/S4) + the ADR-002 (4th layer) and ADR-012 (S1) amendments — all under the one task.
- **P2 closes** when this one P2.7 task closes.
