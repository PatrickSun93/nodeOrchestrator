## TL;DR for the architect

- **Bug C (OpenAI empty tool_call args)** — **real, clean, contained, single atom.** `_parse_chat_completion`
  does `json.loads(args_raw)` on the raw arguments string. An empty/whitespace `arguments: ""` (the
  OpenAI-compat *no-arg* convention — emitted by vLLM / some DeepSeek / Ollama tool modes) hits
  `json.loads("")` → `JSONDecodeError` → re-raised as `PermanentProviderError("malformed tool_call")`.

  provider docstring say a **call-time `TransientProviderError` walks to the next model in the chain**.
  It doesn't. `RealLLMRouter._async_call` calls `provider.call()` **exactly once** and lets any
  `TransientProviderError` (429 / 5xx / timeout / network) propagate. **Nothing in `src/` catches
  `TransientProviderError`.** Only the **health_check pre-call** half of D4 is implemented; the
  **call-time** half is dead code-path. A 429 on the primary kills the turn even when a healthy fallback
  is configured.

## Bug C — OpenAI-compatible empty tool_call arguments

### Verify-cited state

`src/orchestrator/llm/providers/openai_compatible.py:273-274` (in `_parse_chat_completion`; the original
review said "~274" — accurate at HEAD post-churn):

```python
args_raw = tc["function"]["arguments"]
arguments = json.loads(args_raw) if isinstance(args_raw, str) else (args_raw or {})
```

The `try` wraps lines 272-281; the `except (KeyError, json.JSONDecodeError, ValidationError)` at `:282`
maps every failure → `PermanentProviderError("malformed tool_call")`. Behavior by input:

| `arguments` value | Path | Result |
|---|---|---|
| `"{}"` | `json.loads("{}")` | `{}` ✓ |
| `""` (empty) | `isinstance str` → `json.loads("")` | **`JSONDecodeError` → `PermanentProviderError`** ✗ |
| `"   "` (blank) | `json.loads("   ")` | **`JSONDecodeError` → `PermanentProviderError`** ✗ |
| `None` | not str → `(None or {})` | `{}` ✓ |
| `{...}` (pre-parsed dict) | not str → `(dict or {})` | dict ✓ |
| key absent | `tc["function"]["arguments"]` → `KeyError` | `PermanentProviderError` (see sub-q) |

`json.loads("")` raising `JSONDecodeError` is confirmed empirically. So the **specific defect** is: an
**empty- or whitespace-only `arguments` string** → spurious `PermanentProviderError` → the call fails
permanently *and* skips fallback (Permanent, per D4). `arguments: ""` is the standard OpenAI-compat
encoding for "call this tool with no parameters"; it is **not** malformed.

### Why `{}` is the only correct target (downstream, verify-cited)

`ToolCall.arguments` is `dict[str, Any]`, non-optional, `frozen`, `extra="forbid"` (`types.py:152-161`).
Downstream `agents/tool_dispatch.py:81/116/157` passes `tc.arguments` straight through as `params=`.
So "keep as-is" (`""`) is structurally impossible (Pydantic rejects a str for a `dict` field), and `{}`
= "no params" is exactly what an empty-arg tool call means. The existing `None`/falsy branch *already*
normalizes to `{}`; the fix just extends that normalization to empty/blank strings.

### Contract touch — none

No ADR governs the arguments-string parse; `ToolCall.arguments: dict` is the only constraint and `{}`
satisfies it. Pure bug-fix.

### Fix options

- **C-lean — normalize empty/blank string to `{}`.** Guard the `json.loads` on a non-blank string, e.g.
  `arguments = json.loads(args_raw) if (isinstance(args_raw, str) and args_raw.strip()) else (args_raw or {})`.
  One line; covers `""` and whitespace; a genuine malformed body (`"{bad"`) still raises
  `PermanentProviderError`.
- **C-alt — narrow try/except around `json.loads`** mapping empty→`{}`. More lines, same effect;
  rejected-lean (the `strip()` guard reads clearer and keeps the malformed-JSON failure intact).

**My lean: C-lean.** One minor sub-question (senior-granularity, surfaced for completeness): the
**missing-`arguments`-key** case (the `KeyError` row) — keep it as `PermanentProviderError` (absent field
≠ empty field; **my lean: keep**), or also normalize to `{}`? I would **not** widen the fix past the
verified empty-string case, but flag it so the senior doesn't silently pick.

## Bug D — missing call-time transient fallback (touches ADR-002 D4)

### Verify-cited state (the load-bearing finding)

**The contract** — three citations, all say *call-time transient → walk the chain*:

- **ADR-002 D4** (`docs/decisions/ADR-002-*.md:81-98`): "The router walks the chain on: … **(at call
  time) `TransientProviderError` from the call itself.**"
- `llm/exceptions.py:12,16-18`: "`TransientProviderError` (retry may help; **router tries fallback**) …
  causes the router to try the next model in the fallback chain."
- `llm/providers/openai_compatible.py:154-156`: "429 → `TransientProviderError` (rate-limited; **router
  may try fallback**)."

**The implementation** — `api/llm_adapter.py:62-74` (`RealLLMRouter._async_call`):

```python
route = await select_model_and_provider(agent_config, request, ...)   # picks ONE route (health_check pre-filter)
return await route.provider.call(                                     # called EXACTLY ONCE
    request, route.model, model_id_requested=route.model_id_requested,
)
```

`select_model_and_provider` (`router.py:110-287`) walks the chain **only for pre-call filtering**
(registry / capability / tools / **health_check**) and returns the **first** viable `RouteResult`. It
makes **zero** `provider.call()` by design (`router.py:15` "This module contains zero LLM calls. Routing
is decision-path code"). The adapter then calls that one provider **once**; a `TransientProviderError`
it raises **propagates straight up**. `grep` confirms **nothing in `src/` catches
`TransientProviderError`** — only docstrings and the raise sites reference it.

**So:** the **health_check (pre-call)** half of D4 works and is tested (`tests/llm/test_e2e_fallback.py`
— unhealthy anthropic → falls to deepseek, `requested != used`). The **call-time `TransientProviderError`**
half of D4 is **unimplemented and untested** — `test_e2e_fallback.py` never raises a transient from
`.call()`; it only exercises the health_check skip. A 429/5xx/timeout on an otherwise-healthy primary
kills the turn even when a healthy fallback exists in the chain.

### The ADR-002 question you flagged (load-bearing) — conformance, not amendment

1. **Does the fix touch the contract?** It *fulfills* it. ADR-002 D4 already specifies
   call-time-transient → next-in-chain; the fix makes code match the inscribed decision. →
   **pure bug-fix; no substantive amendment, no new ADR.** (Same shape as P6.1 Bug B: code made
   consistent with an existing decision.)

2. **`model_id_requested` vs `model_id_used` audit (the agy-emphasized contract) — already correctly
   wired; the fix must preserve it.** `RouteResult.model_id_requested` is hardcoded to the chain head
   (`agent_config.default_model`, `router.py:280`); `provider.call()` stamps `model_id_used = model.id`
   (`openai_compatible.py:309-310`); `LLMResponse` docstring (`types.py:223-230`) requires both so the
   audit shows "what was asked vs what answered." **Constraint on the fix:** the call-time fallback must
   call the next provider with the **original chain head** as `model_id_requested` (not the fallback
   model's id). Under both mechanisms below this holds, because `model_id_requested` is always re-derived
   as the chain head. → audit stays correct; the fix makes `requested != used` finally reachable via the
   *call-time* path, exactly as the health_check path already does.

3. **Double-actuation risk — none, and the reason is the constitutional spine.** A
   `TransientProviderError` from `provider.call()` means **no `LLMResponse` was produced** → no
   `tool_calls` → nothing actuated. Tool *execution* / actuation happens **downstream of the LLM
   response** (the gate / `tool_dispatch` / `_execute_local_call`), never inside `provider.call()` —
   every provider `call()` is **pure content-gen** (OpenAI-compat POSTs to `/chat/completions`, which
   returns tool-call *proposals* and executes nothing; `claude_code_cli` + `agy_cli` set
   `can_use_orchestrator_tools()=False` and actuate nothing — ADR-003). So even a "server processed it
   but the response timed out" yields at most a wasted completion — **never** a repeated side effect.
   Retrying on the next provider is safe **because `LLMProvider.call()` is side-effect-free content-gen**
   — the same spine the agy review guarded. (Worth a code comment + test asserting it; whether to
   *inscribe* it as an ADR-002 D4 clarification is your call — decision point 1.)

### Mechanism options (senior's design call — I surface, senior picks)

The loop must live in the **call-path (adapter)**, not the router — putting `provider.call()` inside
`select_model_and_provider` breaks its inscribed "zero LLM calls" purity (`router.py:15`) and the
constitutional structural tests that keep routing decision-only.

- **D-mech-A (lean) — router exposes the ordered viable candidates; adapter iterates.**
  `select_model_and_provider` already computes the viable set; expose it (return the ordered viable
  routes, or a follow-on yielding each `(model, provider)`), and have the adapter try each `.call()`
  until success or `PermanentProviderError`. Router stays pure (still zero calls); health checked once
  up-front.
- **D-mech-B — adapter re-invokes `select_model_and_provider` with an exclude-set** after each
  `TransientProviderError`. Smaller surface change, but re-runs health_check and re-walks the chain each
  attempt.
- **D-mech-C — loop inside the router. REJECT** (breaks router purity + the structural tests).
- **Scope OUT: same-provider retry/backoff.** D4's semantic is *degrade to the next model*, not *retry
  the same one N times*. Adding backoff-retry would be **new behavior** (its own ADR if ever wanted), not
  this bug-fix. Keep P6.2 to "walk to next on transient."

### Chain-exhaustion semantics (small decision — senior, or you if you want it pinned)

When **every** viable provider raises `TransientProviderError` at call time, the caller should see:
**(a)** re-raise the last `TransientProviderError`, or **(b)** raise `NoSuitableModelError` with a
`decision_trace` of the per-model transient failures (consistent with the existing exhaustion raise at
`router.py:284` and preserving the audit trace). **My lean: (b)** — matches the existing exhaustion shape
and keeps the audit trail. Senior can settle this; flag if you want it pinned in the brief.
