## 1. Context

P4.1 (ADR-033) gave an agent an in-turn investigation loop, but every tool it can chain is **in-process, read-only** (`os.walk`+`re`); ADR-033 carry-forward #6 forbade shelling out, deferring exactly this surface. B3 adds the first **subprocess** tool surface so an agent can run the project's tests + linter and read git history mid-investigation — the flagship *"re-investigate on a failed test"* step (P4-roadmap §7).

The architect ratified all five brief decision points; I have **not** re-litigated them. The plan implements: ship all 5 (D1); the lighter-inline posture reusing the ADR-031 D2 seam + the honest `RB-FS/NET`-class residual (D2); the 4-sub-surface threat model with output-as-untrusted rendered raw + the P4.1 excerpt-filter extension (D3); the existing Posture-B `LocalToolFn` executor placement with the cap generalised (D5); ADR-034 + the ADR-028 D3 amendment. ADR-034 is **drafted on this branch** (senior deliverable); the numbered tasks below are the **junior impl**.

**Key mechanism I verified (load-bearing — read before implementing):** excluding subprocess `TOOL_RESULT`s from `snapshot_excerpt` does **not** blind the acting agent. The re-dispatch loop passes the last result-class event of a pass as the **`current_event`** (LLM user message) of the next pass — a channel distinct from `snapshot_excerpt` (system block). Verified at `api/app.py:449-454` + `agents/dispatch.py:112-123`. The acting agent still gets the raw test output via `current_event`; the exclusion only removes it from the cross-agent system-block steering surface. The flagship loop survives. (Parity with the existing `mcp__` treatment, minus the `OBSERVATION`.)

**Interpreting the architect's ratified decisions where the brief left a design call to me** (all surfaced in §5): the output-untrusted reconcile uses a **tool-name match** (not a `ToolResultMeta` flag) *because* the flag would force a write inside the byte-frozen `_execute_local_call`; the cap is **fully renamed** to `MAX_SUBPROCESS_CALLS_PER_TURN`; the runner argv0 is **hardcoded** (`python -m pytest`, `ruff check`) for the Python MVP.

## 2. Tasks (atomic)

Per-tool argv templates + param allowlists are **pinned** in Task B3-2. All five run with `cwd=sandbox_root`, scoped env, bounded timeout + bounded output; the path that enters argv is always the **resolved absolute path** from `_check_path` (never the raw LLM string → never flag-shaped).

### B3-1 — `run_scoped_command` runner in `mcp/subprocess_trust.py`

- **What:** Add a single new entrypoint that runs an argv list and returns its exit code + bounded combined stdout/stderr, reusing the existing kill-no-orphan + watchdog machinery. No new subprocess mechanism (ADR-034 D4 / ADR-031 D2).
- **Where:** `src/orchestrator/mcp/subprocess_trust.py` (new fn + a `MAX_RESULT_BYTES`-bounded reader); `src/orchestrator/mcp/_async_bridge.py` reused (`run_sync`) for the sync wrapper.
- **Why:** ADR-034 D2/D4; carry-forward #4 (reuse, don't rebuild).
- **Acceptance:**
  - Signature ≈ `run_scoped_command(argv: list[str], *, cwd: Path, env: dict[str,str], timeout_s: float, max_bytes: int) -> SubprocessResult` where `SubprocessResult` carries `exit_code: int`, `output: str` (combined stdout+stderr, truncated at `max_bytes`), `truncated: bool`.
  - Spawns via `anyio.open_process([...], cwd=..., env=..., start_new_session=True)` — argv is a **list**; **never** `shell=True`, **never** a shell string.
  - Bounded read: stops accumulating at `max_bytes` (does not buffer an unbounded child log into the single writer).
  - Timeout: a hung child is killed via the **reused** `_terminate_subprocess(process, pid)` + `_kill_watchdog(pid)` (process-group SIGTERM→SIGKILL→watchdog); a timeout raises (`MCPTimeoutError` via `run_sync`, or a local `SubprocessTimeout`) — caller turns it into `TOOL_FAILED`.
  - Scoped env is the caller's responsibility (Task B3-2 builds it via `build_scoped_env`); this fn does not add `os.environ`.
  - Tests (`tests/mcp/`): echo round-trip (exit 0, output captured); non-zero exit captured (no raise); output > `max_bytes` → truncated + flag; timeout → child killed, no orphan (assert PID reaped); a spawned child that forks a grandchild is group-killed (no-orphan under the watchdog).
- **Out of scope:** changing `subprocess_mcp_stdio` / the MCP path (behaviour-unchanged); any `shell=True` convenience.

### B3-2 — the five subprocess tool closures + `tools/subprocess_tools.py`

- **What:** A new module building the five `LocalToolFn` closures, each: validates its param allowlist, resolves the path via `_check_path`, builds the fixed argv, calls `run_scoped_command` with a scoped env, and formats the result into `LocalToolOutput`. Each closure carries `_is_posture_b_subprocess = True`.
- **Where:** new `src/orchestrator/tools/subprocess_tools.py` exporting `build_subprocess_tool_registry(sandbox_root: Path) -> dict[str, LocalToolFn]`. **Do NOT** add these to `tools/local.py` (constitution t6 forbids subprocess there — keep `local.py` in-process-pristine).
- **Why:** ADR-034 D1/D3/D5; brief carry-forward #6.
- **Pinned per-tool argv + param allowlist** (path = resolved absolute under `sandbox_root`):

  | Tool | Params (allowlist) | argv |
  |---|---|---|
  | `run_tests` | `path` (optional, sandbox-rel test file/dir) | `[sys.executable, "-m", "pytest", "-q", <abs_path?>]` |
  | `run_lint` | `path` (optional, default `sandbox_root`) | `["ruff", "check", <abs_path>]` |
  | `git_blame` | `path` (**required**) | `["git", "blame", "--", <abs_path>]` |
  | `git_log` | `path` (optional), `max_count` (optional int, clamp `[1,100]`, default 50) | `["git", "log", "-n", <count>, "--", <abs_path?>]` |
  | `git_diff` | `path` (optional) | `["git", "diff", "--", <abs_path?>]` |

- **Acceptance:**
  - Any param key **not** in a tool's allowlist → raise `LocalToolError` (→ `TOOL_FAILED`). No flag passthrough (`-p`/`--pdb`/`-c`/refs/…) on any tool.
  - Path params resolved via the **reused** `_check_path(path_str, resolved_root)` (escape → `LocalToolError`); the **resolved absolute path** enters argv (never the raw string). git commands place `--` before the path.
  - Env: `build_scoped_env`-derived, only `_SAFE_ENV_KEYS`, **no** `api_key_env`, no secrets. (Construct a minimal `MCPServerConfig(env={})` to reuse `build_scoped_env`, **or** lightly factor a `scoped_env()` core out of `build_scoped_env` that preserves its existing behaviour — junior's call; the requirement is: scoped, `PATH` present so `git`/`ruff`/`pytest` resolve, zero secrets.)
  - **Result semantics:** normal completion at **any exit code** → `LocalToolOutput` (content includes the exit code + bounded combined output) → lands as `TOOL_RESULT`. A failing test suite / lint finding (non-zero exit) is **expected output, NOT** `TOOL_FAILED`. Only timeout / spawn-failure / path-validation / disallowed-param raise → `TOOL_FAILED`. (Rides `_execute_local_call` unchanged.)
  - Output bounded at `MAX_RESULT_BYTES`; `output_truncated_at` set on truncation.
  - Each closure has `_is_posture_b_subprocess = True` readable via `getattr` (function attribute or a small callable class — match the `_PostureBFn` precedent in `plugins/code.py`).
  - Tests (`tests/tools/`): per-tool happy path (stub a tiny git repo / pytest file under a tmp sandbox); param-allowlist rejection; path-escape rejection; non-zero exit → `TOOL_RESULT` not `TOOL_FAILED`; `git_log max_count` clamp; a path starting with `-` cannot become a flag.
- **Out of scope:** configurable runner (non-pytest/non-ruff/non-Python workspaces — see §5); arbitrary git refs; line-range params.

## 5. Where I'd push back / surface (architect routes; I do not)

All claims below carry cites (claims-with-cites discipline).

1. **`run_tests` / `run_lint` runner argv0 is hardcoded** (`python -m pytest`, `ruff check`). This assumes a **Python + pytest + ruff** workspace — the project's own bug-fix loop (`config_dir.parent` sandbox, `api/app.py:206`). A non-Python or non-pytest sandbox would get a spawn-failure `TOOL_FAILED`. I scoped a configurable runner **out** (ADR-034 Reversibility: additive later). **Surface:** accept the Python-MVP hardcode, or do you want a config-driven runner in B3? (Lean: hardcode now.)

2. **Output-untrusted reconcile uses tool-name matching, not a `ToolResultMeta.external_output` flag.** The flag is the more "producer-declares-untrust" design, **but** the only TOOL_RESULT appender for local tools is `_execute_local_call`, which the architect ratified as **byte-unchanged** (brief carry-forward #5 / ADR-031 HR#2 / t3b, `executor.py:338-388`). Writing a flag there would break empty-executor-diff. So I key the excerpt exclusion on the `TOOL_CALL.tool_name` (as `mcp__` already does, `selection.py:99-104`), drift-guarded by a sync-test. **This is a senior design call I made, not an architect decision** — surfaced so you + R0-B can validate the constraint-interaction. If you'd rather pay an executor-diff for the flag, that reverses the placement decision.

3. **Extending `run_scoped_command` into `subprocess_trust.py` lightly extends the ADR-031 D2 contract** ("one subprocess protocol"). I planned a one-line `[Extended P4.2-B3 → ADR-034]` annotation on ADR-031 D2 (B3-6 out-of-scope note). **Surface:** is a light cross-ref annotation sufficient, or do you want a fuller ADR-031 amendment block? (Lean: one-line cross-ref — ADR-034 carries the substance.)

4. **The cap rename (B3-4) touches two plugin test files** (`test_posture_b.py`, `test_p3_7_remote_plugins.py`) that assert `error_class="turn_posture_b_cap_exceeded"`. This is the generalisation you blessed (brief decision 4), but it does edit tests outside the B3 tool surface. **Surface:** confirm the full rename (constant+var+error_class) is in-scope vs. renaming only the public constant.
