# P6.4 — descriptive doc-pin: inscribe the E/F egress residuals into ADR-037 D5 (no behaviour change)

## 1. Context

The architect-partner ran a **verify-first** determination on two "sandbox egress residuals"
(`docs/process/architect-briefs/P6.4.md`, ratified 2026-06-12) and answered the question the
dispatch posed: **E and F are both intentionally-accepted, security-safe P4.3 residuals — NOT
open bugs.** Both surfaced in the same P4.3 impl-stage dual-lens round whose clean verdict the
architect Accepted (PR #58, merge `cb57019`), both were graded **non-blocking** by their own
reviewer, and **both persist byte-identical in current `main`**. **No behaviour fix is owed or
permitted** — a behaviour fix to either would touch the load-bearing ADR-037 D2 egress contract
and is explicitly out of scope (see §5 red line).

The architect chose **option 2 — the light doc-pin** to close the one real gap: P4.3's *own*
honest-residual-inscription thesis (D5 ⭐) requires the ledger to carry the enforced surface, but
E and F were graded non-blocking and **never inscribed into the ADR-037 D5 ledger**. This slice
is therefore **descriptive-only**: it inscribes what already ships, corrects one over-claiming
docstring, and pins F's already-live fail-closed behaviour with a regression test. **It changes
the ADR text + a docstring + adds a test — it does NOT change any egress semantic, mechanism, or
code path.** No new ADR (`plan_has_adr=false`); the D5-ledger note is the same weight as
Amendment-1 **A1-5** (a D5 inscription-correction) → no Accept gate. `requires_cross_family_review=true`
makes it a (very light) dual-lens.

**The two residuals (verify-cited against current `main`):**

- **F — CONNECT-only proxy → plain-`http://` fetches 405 / fail-closed.** The host-side egress
  proxy handles **only** `CONNECT` (`egress_proxy.py:140-141`: a non-CONNECT first line →
  `405 Method Not Allowed`). In-container `urllib` uses `CONNECT` for `https://` ✓ but emits an
  **absolute-form GET** for `http://` (no CONNECT) → `405` → the plain-http fetch **fails closed**
  (loud `TOOL_FAILED`, **no exfil; https unaffected** — the dominant path). This is **exactly**
  ADR-037 **D4** ("never silently unsandboxed; fail-closed default") — the egress contract is
  *honoured*, not breached. The only honest gap is documentary: (i) the `egress_proxy.py:14-16`
  docstring still says `http(s): … → CONNECT`, slightly over-claiming plain-http, and (ii) the
  405 fail-closed is **not** inscribed in D5.

- **E — per-call bridge created without `--internal`.** `_create_network`
  (`spawn.py:226-230`: `network create --driver bridge <name>`, **no `--internal`**) leaves the
  bridge internet-reachable via Docker NAT. This is the **bounded tail** of the round-1 🔴 that the
  CONNECT-proxy rework (Amendment 1 A1-1) already retired — the proxy, not the bridge firewall, is
  now the enforcement and all tool paths route through it. The residual is bounded by **DNS disabled**
  (`--dns 0.0.0.0`) + **`--cap-drop=ALL`** (no raw sockets) + runs as **`nobody`** + an
  **operator-controlled image**. `--internal` is **withheld** because it can break
  `host.docker.internal`→proxy reachability — i.e. it can break the very egress hop the boundary
  depends on. Left intentionally; never inscribed into D5.

**Verify-cites for the §1 claims** (pre-investigation discipline):
- `egress_proxy.py:140-141` — non-CONNECT first line → `_send_response(client, b"405 Method Not Allowed")` (read, live HEAD).
- `egress_proxy.py:14-16` — the `Both transports:` block still reads `http(s): … → CONNECT <host>:<port>` (the over-claim).
- `spawn.py:226-230` — `_create_network` runs `network create --driver bridge` with no `--internal` (read).
- ADR-037 D5 (`docs/decisions/ADR-037-syscall-egress-sandbox.md:74-85`) — the residual bullet list carries R9 / R8-broad-allowlist / sandbox-escape / seccomp-blocklist / degraded-posture / per-call-latency / cross-platform-tails; **neither E nor F appears.** Amendment-1 A1-1 "Honest D5 tails" (`:92`) lists only the `nc`/`socat` image dep + the non-loopback proxy-bind — also neither E nor F.
- Amendment-1 **A1-5** (`:100`) — precedent: a dated D5 *inscription-correction* note, `plan_has_adr=false`, no Accept gate. The P6.4 ledger note matches its weight.

### P6.4-1 — inscribe E+F into the ADR-037 D5 ledger + correct the egress_proxy docstring + pin F's fail-closed behaviour

**(a) ADR-037 D5 ledger inscription (E + F).**
- **Where**: `docs/decisions/ADR-037-syscall-egress-sandbox.md`.
- **What**: inscribe the two residuals into the **D5 honest-residual ledger** (the one real gap),
  in the same shape/weight as Amendment-1 **A1-5**. Concretely:
  1. Add **two bullets** to the D5 residual list (`:74-85`, the `### D5 — P4.3's own honest
     residuals` block) — one for F, one for E — matching the existing bullet style
     (**bold lead-in** + one honest sentence). Illustrative content (not prescriptive on wording):
     - **F:** *"Plain-`http://` in-sandbox fetch unsupported (fail-closed). The host-side proxy is
       CONNECT-only (`egress_proxy.py:140-141`); in-container `urllib` sends an absolute-form GET for
       `http://` (no CONNECT) → `405` → the fetch fails closed (loud `TOOL_FAILED`, no exfil).
       `https://` is unaffected (CONNECT path). Consistent with D4's fail-closed default — a minor
       functional limitation, not a security hole."*
     - **E:** *"Per-call bridge created without `--internal` (`spawn.py:226-230`) — bounded residual.
       The CONNECT proxy (A1-1), not the bridge firewall, is the egress enforcement; the un-`--internal`'d
       bridge is bounded by DNS-disabled (`--dns 0.0.0.0`) + `--cap-drop=ALL` + `nobody` +
       operator-controlled image. `--internal` is withheld because it can break
       `host.docker.internal`→proxy reachability (the egress hop itself)."*
  2. Add a short dated **audit note** recording the inscription, mirroring A1-5's weight — append an
     **`## Amendment 2 — P6.4 (D5 egress-residual inscription)`** section after Amendment 1
     (`:88-102`). It states: P6.4 is a **descriptive doc-pin** that inscribes the E/F egress
     residuals (both P4.3-accepted, non-blocking, security-safe per D4 / A1-1) into the D5 ledger —
     **no behaviour change, no semantic change**, `plan_has_adr=false`, no Accept gate. Point it at
     the two new D5 bullets. (This is the audit-trail half; the D5 bullets are the canonical
     inscription, exactly as A1-5 carried the audit note for an in-place D5 correction.)
- **Why**: closes the one real gap — D5's honest-residual discipline (`:35`, D5 ⭐) requires the
  ledger to carry the enforced surface; R0-A flagged N2 *precisely because* P4.3's whole thesis is
  honest-residual inscription. Descriptive-only; the egress mechanism is untouched.

**(b) Correct the `egress_proxy.py` docstring over-claim (F).**
- **Where**: `src/orchestrator/sandbox/egress_proxy.py:14-16` (the `Both transports:` block).
- **What**: replace the over-claiming `- http(s): … → CONNECT <host>:<port>` line so it states the
  **real** surface: **`https://` is tunnelled via `CONNECT`; plain-`http://` is NOT supported**
  in-sandbox — in-container `urllib` sends an absolute-form GET → the proxy returns `405` →
  fail-closed (no exfil; consistent with ADR-037 D4). Keep the `ssh git_push` line unchanged.
  Illustrative (not prescriptive):
  - `- https: urllib/httpx in-container honors HTTPS_PROXY → CONNECT <host>:<port> (tunnelled).`
  - `- plain http: NOT supported in-sandbox — urllib emits an absolute-form GET (no CONNECT) → proxy 405 → fail-closed (no exfil; ADR-037 D4). https is the supported web_fetch path.`
- **Why**: the docstring is the only place that currently *claims* plain-http works via CONNECT;
  the code (`:140-141`) does not. **Docstring-only — zero executable change.**
- **Strict bound**: touch **only** the module docstring comment lines. Do **not** touch any
  `_handle` / `_serve` / allowlist / `_send_response` logic. The `405` branch stays byte-identical.

**(c) Regression test pinning F's fail-closed behaviour.**
- **Where**: `tests/sandbox/test_egress_proxy.py` (add one test; the module already drives the
  `EgressProxy` object directly — **no live Docker** — which is the correct boundary).
- **What**: add a test that sends a **non-CONNECT, absolute-form GET** (exactly what in-container
  `urllib` emits for a plain-`http://` URL) straight to the proxy and asserts it is **refused with
  `405`** — i.e. the plain-http path **fails closed, no tunnel is established, no bytes are relayed
  to any upstream**. Illustrative request line: `GET http://allowed.internal/ HTTP/1.1\r\nHost: allowed.internal\r\n\r\n`
  → assert `b"405"` in the response. Factor a small raw-request sender (or generalise the existing
  `_send_connect` helper) so the GET request line can be sent verbatim.
- **Why / the fail-on-LOOSEN guard** (the contributing.md Q5 analogue for a doc-pin slice):
  there is **no behaviour to revert** here (the 405 already ships) — instead this test **pins the
  current fail-closed semantic** so a **future loosening** breaks loudly. If anyone later teaches
  the proxy to handle non-CONNECT methods (forward an absolute-form GET = flip F from *fail-closed*
  to *fail-open-for-http*, the **prohibited** behaviour change of §5), the `405` assertion **FAILS**
  — the test is the tripwire on the ADR-037 D2/D4 egress boundary.
- **Coverage note**: "https unaffected" is **already** pinned by the existing
  `test_rw8_proxy_allows_pinned_host` / `test_rw8_proxy_allows_ssh_port_connect` (CONNECT → 200);
  reference that in a comment rather than duplicating. The new test adds only the **plain-http →
  405** leg.

**Out of scope (the whole slice):**
- **Any egress behaviour / mechanism change.** Do **NOT** modify `egress_proxy.py`'s CONNECT /
  allowlist / relay logic (only its docstring). Do **NOT** modify `spawn.py`'s `_create_network`
  or add `--internal` (E stays exactly as built — it is *inscribed*, not changed). Do **NOT** make
  plain-http work (that LOOSENS egress — see §5).
- **Any constitutional-spine touch** — `_execute_local_call`, the autonomy gate, `LLMPurpose`,
  `run_pipeline`, COUNTDOWN spine are all untouched (this slice adds zero call paths).
- **Re-litigating the verdict** — E/F are architect-ratified accepted residuals; this slice does
  not re-open whether they "should" be fixed.
