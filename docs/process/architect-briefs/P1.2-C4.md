## Architect-settled design decisions

### 1. R0-A-1 resolution = (a) ADR-005 §5(c) narrative addition (no validator)

Architect-partner adds one sentence to ADR-005 §5(c) immediately after the existing clamp rationale. Suggested text (refine if better wording surfaces):

> *"The asymmetric absence of a floor on `effective_threshold_auto` is intentional: by symmetry, when `user_intent_modifier >= threshold_auto`, `eff_auto` can go non-positive and AUTO_EXECUTE absorbs the full score range. This is the AUTO-side counterpart of the HARD_CONFIRM-unreachable case above — Hard Guards (P1.3) remains the destructive-action refusal layer regardless of which side of the band collapses. Adding a validator constraining `user_intent_modifier < threshold_auto` is deferred to P1.5 tuning unless dogfooding surfaces a real misconfiguration."*

Architect-partner pushes this to main as a small standalone commit (similar to event-model.md `64bfd1b` precedent). Your plan does not include this task; reference it in plan §1 Context.

### 2. UnknownToolError emission = (ii) new event type via ADR-007

Architect chose (ii) over (i) reuse / (iii) silent omission. Reasoning recorded in chat-history v3 (when added) and in this brief's predecessor discussion: (i) requires Optional fields or sentinel values in `AutonomyDecisionMetadata` (smelly) AND breaks the constitutional sync test elegance; (iii) accepts an audit gap the architect explicitly flagged in C3 brief as worth addressing.

**Your ADR-007 must decide and record:**

- Event type name (suggested: `autonomy_refusal` — generic so P1.3 Hard Guards can reuse with different `refusal_reason`; alternative `unknown_tool_attempted` is more specific but less reusable).
- Metadata schema field set. Senior decides; architect-partner's lean:
  - `operation_tool_id: str`
  - `operation_initiating_agent: str`
  - `user_explicit_intent: bool`
  - `refusal_reason: Literal["unknown_tool"]` — discriminator for future refusal types; P1.2-C4 only writes `"unknown_tool"`; future ADRs may extend the Literal
  - That's 4 fields, deliberately lighter than `AutonomyDecisionMetadata`'s 12 — the refusal has less to record because there's no decision trace to mirror.
- Constitutional test that pins the metadata field set — analog to `test_constitution_autonomy_decision_event_carries_trace` but for refusal. Suggested name: `test_constitution_autonomy_refusal_metadata_field_set`. It does NOT need to sync with any other class (there's no `RefusalTrace`) — just lock the field names.
- Whether `refusal_reason` Literal is extensible by future ADRs without breaking existing event records (yes by design; extending a Literal is additive for new records but doesn't invalidate old ones since they only ever wrote `"unknown_tool"`).

## Constraints (do not violate)

- **No LLM imports in autonomy module** — still load-bearing.
- **Layering: `orchestrator.autonomy` may import from `orchestrator.core`** (for event types, store interface). This is the **first time** autonomy imports from core. Verify no existing constitutional test forbids it. The reverse (`core` importing from `autonomy`) remains forbidden per the C2-freeze deliberate-duplication design.
- **decision_trace mandatory on every gate decision** — already enforced by C3 impl. Emission code must not strip the trace.
- **Synchronous emission** — ADR-005 Decision 6 says `autonomy_decision` event is emitted *synchronously before tool execution proceeds*. C4 emission layer must respect this ordering — not "fire-and-forget" or "async best effort". Same applies to `autonomy_refusal`: emit before raising upward to caller.
- **Pre-edit grep sub-rule** (P1.2-RC-1) for any 5-surface edit. Especially: `docs/architecture/event-model.md` 17→18 type count update + new row in the types table; verify ALL "17 types" mentions get bumped (the C3 ADR-005 §5(c) revision didn't touch event-model.md, but C4-3 does).
